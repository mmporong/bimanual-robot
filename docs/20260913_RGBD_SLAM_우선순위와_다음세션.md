# 다음 세션: 임시 장착 RGB-D SLAM → LiDAR·RGB-D 통합

결정일: 2026-09-13. 작업 브랜치: `feat/jdamr-base-migration`.
상태: 사용자 우선순위 확정, 구현·센서 실행·실기체 검증 전.

## 1. 확정 순서

1. **P0 — 기존 차체 임시 위치에 RGB-D 카메라를 고정해 카메라 단독 Visual SLAM을 검증한다.** 새 양팔 차체 완성은 선행 조건이 아니다.
2. **P1 — LiDAR 기반 위치 추정과 RGB-D 3D 인식을 함께 사용한다.** 첫 통합은 역할 분담이며, 위치 추정의 긴밀한 센서 융합은 필수가 아니다.
3. **P2 — 같은 RGB-D 입력을 작업대 정렬·도달 가능한 정차 위치·기존 IK 조작에 연결한다.** ACT 비교는 같은 조작 과제의 기준선과 평가 조건을 확보한 뒤 진행한다.

P0/P1은 사용자가 지정한 다음 작업이다. 채용 분석은 이후 투자 범위를 판단하는 근거이며 이 순서를 자동으로 취소하지 않는다.
새 RL 과제, 여러 Visual SLAM 백엔드의 전면 비교, 시각화 재편집은 P0의 선행 작업으로 추가하지 않는다.

## 2. 현재 기준선과 확인 사항

- 기존 LiDAR 프로젝트: Cartographer 지도 작성, 저장 지도+AMCL+Nav2 주행. [이식 원본 고정과 경계](20260912_JDAMR_SLAM_실기체이식.md)를 보존한다.
- 새 차체용 모터는 같은 모델의 다른 개체이며 ID는 미확정이다. 기존 제어보드·Pi·G4 LiDAR를 사용한다. LiDAR 높이·위치·방향은 실장 후 측정한다.
- 카메라 설계 후보는 Astra S이며 최종 설계 광학 중심은 z=970 mm, 하향각은 35°다. 이는 [설계값](../design/mechanical/hold_flow_mechanical_v0_3.yaml)이고 임시 장착 실측값이 아니다.
- 실제 연결 장치·드라이버·RGB/Depth 지원·보정 정보·USB 처리량은 확인 전이다. 다른 Astra 모델의 사양을 가져와 확정하지 않는다.
- 이 문서의 ‘카메라 단독’은 RGB와 Depth를 함께 이용하되 LiDAR·바퀴 정보를 Visual SLAM의 위치 추정 입력에서 제외하는 비교 구성을 뜻한다. 깊이 영상만 사용하는 ICP 방식과 구분한다.

## 3. 다음 세션 첫 작업

작업 시작 시 현재 디렉터리·브랜치·미커밋 변경을 다시 확인한다.

```bash
cd "$HOME/bimanual-robot"
git status --short --branch
```

### A. 비구동 입력 확인

- 연결된 RGB-D 모델과 사용 가능한 ROS 2 드라이버를 확인한다. 라이브 센서 스트림을 확인하되 베이스·팔 구동 launch는 실행하지 않는다.
- RGB·Depth·각 CameraInfo의 실제 토픽명, frame_id, 인코딩, 깊이 단위, 유효 깊이 비율과 timestamp를 확인한다.
- 깊이 영상의 컬러 정렬 여부와 두 광학 프레임 변환을 확인한다. RGB와 Depth가 같은 좌표라고 가정하지 않는다.
- 실제 입력 주기·누락·시간 차이를 측정한다. 동기화 허용치는 센서 주기·관측 결과에 근거해 정하고 결과에 함께 저장한다.
- 장착 위치·높이·방향·고정 상태·자체 차체 가림을 사진과 측정 기록으로 남긴다. 임시 위치가 바뀌면 새 설정 ID를 부여한다.
- 초기 처리는 노트북에서 검증한다. Pi에 동시에 추가 부하를 가하거나 현재 주행 그래프의 DDS 설정을 바꾸지 않는다.

### B. 기록과 오프라인 기준선

- RTAB-Map RGB-D 단독을 첫 후보로 사용한다. 설치된 ROS/드라이버와 호환성을 확인한 후 실행 구성을 고정한다.
- RGB·Depth·CameraInfo·TF/TF_STATIC·관련 상태를 같은 시간축으로 기록한다. LiDAR·odom·IMU가 함께 기록되더라도 단독 기준선의 추정 입력에서는 제외한다.
- 원본 기록, 보정값, 장착 설정, 알고리즘 버전·파라미터, 로그·결과물의 경로와 해시를 연결한다. 대용량 bag·영상은 Git에 넣지 않는다.
- 기록을 재생해 카메라 궤적·색상 3D 지도·추적 상태·재방문 보정 이벤트를 산출한다.
- 기존 외부 촬영 MOV나 LiDAR 전용 bag을 동기화된 탑재 RGB-D 기록의 대체물로 취급하지 않는다. 새 데이터가 없으면 공개 RGB-D 데이터로 소프트웨어 경로만 검증하고 자체 센서 결과와 분리한다.

### C. 필요한 실물 기록의 경계

차체 이동·팔 이동은 그 시점의 사용자 명시적 실행 요청 범위에서만 수행한다. 이번 ‘기록·푸시’ 요청은 이동 승인이 아니다.
추가 실차 3회 주행을 완료 조건으로 만들지 않는다. 우선 확보한 동일 기록을 반복 재생한다.
움직이는 카메라의 새 기록이 필요하면 실제 실행 범위와 주변 공간·비상 정지 수단을 확인한 뒤 진행한다.

## 4. P0 완료 기준

- 실제 카메라 입력·정렬·보정·장착 설정을 근거로 재생 가능한 기록을 확보한다.
- 같은 기록·설정으로 궤적과 3D 지도를 다시 생성할 수 있다. 비트 단위 동일성은 별도 결정성 검증 없이 주장하지 않는다.
- 추적 유효 비율, 추적 실패 구간·지속시간, 재방문 보정/재위치 추정 여부, 처리 지연·CPU/RAM을 보고한다. 재방문 보정과 추적 복구는 별도 이벤트로 기록한다.
- 독립 기준 궤적이 있으면 ATE/RPE를 평가한다. 없으면 실측 치수 오차·시작/종료 일관성 등으로 제한하고 AMCL을 정답 좌표로 사용하지 않는다.
- 낮은 특징량·영상 흔들림·사람 통과·가림 등 실제 포함된 조건을 구분한다. 평가하지 않은 조건을 성공으로 기록하지 않는다.
- 실패 시 원인을 입력/보정/추적/부하로 분리해 수정·재생 비교한다. 입력 문제를 해결할 수 없는 경우 근거와 필요한 하드웨어 조건을 기록하고, 백엔드를 무한히 추가하지 않는다.

## 5. P1 통합과 완료 기준

- LiDAR·바퀴·IMU 기반 기존 위치 추정은 주행 기준으로 유지한다. RGB-D는 3D 장애물·작업 공간 관측을 추가한다.
- 동일 TF 변환의 발행 주체를 하나로 정한다. 독립 Visual SLAM 비교 궤적은 별도 토픽·프레임에 두며 AMCL/Cartographer와 같은 TF를 중복 발행하지 않는다.
- 시간 동기화와 외부 보정을 확인하고 센서별 관측 출처를 보존한다. 정적 지도와 이동 물체·일시 관측을 구분한다.
- 대표 장면은 ‘낮은 LiDAR에는 비어 보이는 상판·돌출물 때문에 로봇 전체 외형의 통과 공간이 부족한 경우’다. 카메라가 실제 관측 가능한 위치에서 검증하고 보지 못한 공간을 빈 공간으로 지우지 않는다.
- LiDAR만 사용한 구성과 RGB-D 추가 구성을 같은 기록/시나리오로 비교한다. 누락·오검출·관측→판단 지연·경로 변경 근거를 기록한다. 기록 재생은 폐루프 실제 회피 성공의 증거로 쓰지 않는다.
- 센서 가림·끊김·오래된 관측에 대한 기능별 감속/정지/보류 정책을 정한다. 카메라 실패 시 무조건 LiDAR 주행을 계속하는 정책을 기본으로 두지 않는다.
- 팔 충돌 검사는 2D Nav2 코스트맵과 별개다. 주행 중 팔 수납, 조작 중 베이스 정지 원칙을 유지한다.

## 6. 완료 이후의 범위

P0/P1 결과를 근거로 RGB-D 작업대 정렬과 IK 파지 기준선을 강화한다. 같은 과제에서 데이터 분할·시연량·checkpoint·평가 분모를 고정한 ACT 비교로 이어갈 수 있다.
카메라 위치 추정이 실제 이점을 보였을 때만 LiDAR–Visual 위치 추정 융합을 별도 심화 과제로 채택한다.
바퀴/영상/라이다 추정의 불일치는 미끄럼 후보 신호이지 마찰 문제의 확정 증거가 아니다.
