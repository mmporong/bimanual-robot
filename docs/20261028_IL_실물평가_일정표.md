# IL 실물 평가 일정표와 기록 방법 (GR00T·SmolVLA·ACT)

2026-10-28 작성. [평가 계획](20261028_IL_모델평가계획과_일반화_발표전략.md)을 실제로 돌릴 순서와 기록 칸으로 옮긴 문서다.
**π0는 실물 평가에서 뺐다.** π0만 서버 원격·비동기 경로로 돌아 공정 비교가 되지 않고, 준비 비용이 가장 크기 때문이다. 대신 eval_loss와 배치 가능성(노트북 8GB 불가) 표로만 남긴다.

- **기록 시트**: [`eval/20261028_실물평가_기록시트.md`](eval/20261028_실물평가_기록시트.md) — VS Code에서 열어 회차마다 표의 빈칸을 채운다. 기록하는 파일은 이것 하나다.
- **도구**: `tools/eval/eval_sheet.py`
  - 회차별 실행 명령 출력
  - 1등 모델 채우기
  - 필요한 체크포인트 받기 명령
  - 집계(표와 그래프)
- 무게는 재지 않는다(저울 없음). 붓기 품질은 **흘림 정도를 눈으로** 판정한다.

## 0. 한눈에 보기

| 단계 | 질문 | 모델 | 데이터 수 | 과제 | 반복 | 회차 |
|---|---|---|---|---|---|---|
| **A** | 어떤 모델이 가장 좋은가 | GR00T · SmolVLA · ACT | 80 | 물따르기 · 컵배치 | 10 | **60** |
| **B** | 데이터가 늘면 얼마나 좋아지나 | A의 과제별 1등 | 20 · 40 · 60 (80은 A 결과) | 물따르기 · 컵배치 | 5 | **30** |
| **OOD** | 학습 위치에서 몇 cm까지 버티나 | 물따르기 1등 + 비교 모델 1개 | 80 | 물따르기 | 3 | **최대 36** |

- 합계 최대 126회다. 롤아웃 1회와 원위치에 약 2~3분이 걸리면 A는 하루, B와 OOD는 하루면 끝난다.
- 결과 수치에는 반복 횟수 n을 같은 줄에 적는다(저장소 규칙). 10회면 성공률 해상도가 10%, 5회면 20%, 3회면 33%다.
- **회차 번호**: `A-P01`(A 물따르기 1번), `A-C01`(A 컵배치), `B-P01`, `B-C01`, `OOD-01`. P는 물따르기, C는 컵배치다.

## 1. 시작 전에 고정할 조건
매 회차 같게 맞춘다. 바뀌면 시트의 `메모`에 적는다.

- **물체 위치**: 컵·병 바닥 위치를 테이블에 테이프로 표시한다. OOD의 기준점(0cm)이 된다.
- **내용물 양**: 병에 매번 같은 높이까지 채운다. 병에 선을 그어 두면 편하다.
- **시작 자세**
  - 물따르기: `--start.pose=pour`(명령에 이미 들어 있다)
  - 컵배치: 컵을 왼손에 쥐고 차체 위 적재 자세에서 시작한다. 직전 물따르기가 5단계까지 성공했으면 그 상태를 그대로 쓴다. 아니면 텔레옵으로 맞춘다.
  - 권장: `python tools/rollout/save_start_pose.py --name place_start`로 이 자세를 한 번 저장한다. 그 뒤 `cmd` 출력에 `--extra=--start.pose=place_start`를 붙이면 매번 같은 자세에서 시작한다. 그리퍼는 건드리지 않으므로 쥔 컵은 그대로다.
- **조명·카메라**: 커튼과 실내등 상태를 고정한다. 카메라 번호는 `{left}` 같은 자리표시자를 실행기가 자동으로 맞춘다.
- **GPU**: 롤아웃은 한 번에 하나만 돌린다. 다른 프로그램이 GPU를 쓰면 GR00T 추론이 0.5초에서 8~10초로 느려진다.
- **로딩 시간**: 회차마다 새로 실행하므로 모델 로딩을 매번 기다린다.
  - GR00T: 로딩 약 25~95초, 첫 추론 10~40초
  - ACT·SmolVLA: 몇 초
  - 모델 순서를 섞어도 추가 비용은 없다.
- **영상**: 휴대폰으로 촬영한다. 촬영을 시작할 때 회차 번호를 적은 종이를 몇 초간 비추면, 나중에 영상과 회차를 짝짓기 쉽다.

## 2. 실행 명령
회차 번호를 주면 그 회차의 모델·과제에 맞는 전체 명령을 출력한다. 저장소 폴더에서 실행한다.
```
"C:\Users\USER\miniconda3\envs\so101_env\python.exe" tools\eval\eval_sheet.py cmd A-P01
```
출력된 마지막 줄(`"...python.exe" tools\rollout\rollout_handoff.py ...`)을 복사해 실행한다.
- 로컬에 체크포인트가 없으면 다운로드 명령을 먼저 보여 준다.
- 명령 형식은 [로컬 추론 점검](experiments/20261028_노트북_로컬추론_GR00T_pi0_ACT_점검.md) 5절과 같다.

## 3. A단계 회차 순서
한 모델을 몰아서 돌리지 않고 라운드마다 순서를 한 칸씩 돌린다. 시간이 지나며 조명·배터리·서보 온도가 바뀌어도 그 영향이 한 모델에 몰리지 않게 하기 위해서다.
물따르기 30회(`A-P01`~`A-P30`)를 먼저 하고, 컵배치 30회(`A-C01`~`A-C30`)를 한다. 시트의 `순서` 칸이 전체 순서다.

| 라운드 | 물따르기·컵배치 모두 (1→2→3번째) |
|---|---|
| 1, 4, 7, 10 | GR00T → SmolVLA → ACT |
| 2, 5, 8 | SmolVLA → ACT → GR00T |
| 3, 6, 9 | ACT → GR00T → SmolVLA |

## 4. 회차마다 적는 것 (시트 칸)

| 칸 | 적는 값 | 비고 |
|---|---|---|
| 일시 | `10-29 14:05` | |
| 단계 칸 (물따르기 5개, 컵배치 3개) | `O` 통과 / `X` 실패 | 앞 단계가 X면 뒤 단계도 X |
| 흘림 | `없음` / `조금` / `많음` | 물따르기만. 아래 기준으로 눈으로 판정한다. 붓기 전에 실패했으면 비운다 |
| 시간(초) | 시작부터 끝까지 초 | 자동 종료 시각이나 영상 기준 |
| 개입 | 사람이 손댔으면 `예` | 없었으면 비운다 |
| 비상정지 | 비상정지했으면 `예` | 없었으면 비운다 |
| 실패 증상 | **본 것만** 짧게 (예: `병 미끄러짐`, `컵 앞에서 멈춤`, `붓다가 흘림`) | 원인 추정은 `메모`에 따로 적는다(저장소 규칙) |
| 영상 | 휴대폰 영상 파일 이름 | |
| 메모 | 그 밖의 관찰, 조건 변화 | |

성공 여부와 진행 점수는 **적지 않는다.** 집계 도구가 단계 칸으로 계산한다.

### 단계 판정 기준

**물따르기**

| 단계 | O로 보는 조건 |
|---|---|
| 1 컵 파지 | 왼손이 컵을 들어 테이블에서 떨어뜨렸다 |
| 2 병 파지 | 오른손이 병을 들어 테이블에서 떨어뜨렸다 |
| 3 붓기 | 내용물이 컵 안으로 들어갔다(일부라도). 양은 흘림 칸으로 따로 본다 |
| 4 병 내려놓기 | 병을 세운 채 테이블에 놓고 손을 뗐다 |
| 5 컵 적재·유지 | 컵을 차체 위 적재 위치로 옮겨 쥔 채 끝났다(자동 종료 감지 또는 duration 끝) |

**흘림 (물따르기)**

| 값 | 기준 |
|---|---|
| 없음 | 컵 밖으로 떨어진 내용물이 없다 |
| 조금 | 몇 알·몇 방울이 컵 밖에 떨어졌다. 대부분은 컵 안에 들어갔다 |
| 많음 | 눈에 띄게 많이(대략 절반 가까이 이상) 컵 밖으로 쏟아졌다 |

**컵배치**

| 단계 | O로 보는 조건 |
|---|---|
| 1 테이블로 이동 | 컵을 쥔 채 테이블 위 놓을 위치 근처까지 왔다 |
| 2 컵 내려놓기 | 컵을 세운 채 테이블에 놓았다(넘어지면 X) |
| 3 팔 빼기 | 그리퍼를 열고 팔을 빼서 컵이 그대로 서 있다 |

## 5. B단계 (A가 끝난 뒤)
1. A 결과로 과제별 1등을 정한다. 기준 순서:
   1. 성공률
   2. 동률이면 평균 진행 점수
   3. 그래도 같으면 흘림이 적은 쪽(물따르기)이나 평균 시간이 짧은 쪽
2. 시트에 1등 모델을 채운다(예: 물따르기 GR00T, 컵배치 SmolVLA).
   ```
   python tools/eval/eval_sheet.py fill --pour groot --place smolvla --ood groot,act
   ```
   - B 줄의 `A 1등(미정)`과 OOD 줄의 `비교1(미정)`·`비교2(미정)`이 모델 이름으로 바뀐다.
   - `--ood`에는 물따르기 1등과 ACT를 넣는다. ACT가 1등이면 2등을 넣는다.
3. 아직 로컬에 없는 체크포인트의 다운로드 명령을 출력해 실행한다. 20·40·60개 모델은 아직 받지 않았다. GR00T는 하나에 12.6GB다.
   ```
   python tools/eval/eval_sheet.py downloads
   ```
4. 시트의 `B-...` 줄 순서대로 돌린다. 라운드마다 데이터 수 순서가 20→40→60, 40→60→20, 60→20→40으로 바뀐다.

## 6. OOD 위치 시험 (물따르기)
- **무엇을 옮기나**: 컵과 병을 **함께** 좌우로 옮긴다(로봇에서 테이블을 볼 때 + = 오른쪽). 로봇과 차체 위치는 그대로 둔다.
  - 이는 "이동 로봇이 테이블 앞에 도킹할 때 좌우로 그만큼 어긋난 상황"을 흉내 낸 것이다. 결과를 도킹 정밀도 요구사항으로 바로 바꿔 말할 수 있다([평가 계획](20261028_IL_모델평가계획과_일반화_발표전략.md) 3절 ②).
  - 기준 테이프에서 ±2·±5·±10cm 지점을 미리 표시해 둔다.
- **순서**: +2 → −2 → +5 → −5 → +10 → −10 cm. 거리마다 두 모델을 번갈아 3회씩 돌린다. 0cm는 A 결과를 쓴다.
- **생략 규칙(시간 절약)**: 한 방향의 어떤 거리에서 어떤 모델이 0/3이면, 그 방향의 더 먼 거리는 그 모델에서 생략한다.
  - 시트에는 단계 칸을 비우고 메모에 `생략(+5cm 0/3)`처럼 적는다. 집계는 단계 칸이 빈 줄을 세지 않는다.
- 시작 자세(`--start.pose=pour`)는 그대로다. 물체만 옮긴다.

  - A에 쓰는 6개 체크포인트는 모두 로컬에 있다.
  - GR00T·ACT는 팔 없이 로딩·추론만 확인했다. SmolVLA는 그동안 롤아웃에 써 온 모델이다.
- 남은 것:
  - GR00T·ACT의 첫 실물 롤아웃. `A-P01` 전에 한 번 짧게 시험한다.

  - 공통 시험 에피소드 녹화와 행동 MAE 계산은 이 일정과 별도로 진행한다([평가 계획](20261028_IL_모델평가계획과_일반화_발표전략.md) 1-2절).
