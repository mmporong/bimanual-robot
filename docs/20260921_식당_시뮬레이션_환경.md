# 식당 시뮬레이션 환경

## 현재 범위

발표용 식당 공간과 주행 지도를 같은 배치 설정에서 생성한다. 주방 작업대, 손님 테이블
총 네 개, 의자 여덟 개, 벤치, 충전 구역을 배치했다. 방은 8.5×7 m 설계안이며 실측한 식당을
복원한 모델은 아니다. 작업대 높이 720 mm와 로봇 기준 작업 위치는 기존 물붓기 실험을 따른다.

정적 산출물은 식당 USD, 다섯 시점의 렌더, ROS 지도 형식의 PGM/YAML, 열두 구간의 A* 경로다.
정적 USD의 로봇은 정지 참조 모델이다. 별도 `simulate_restaurant_mobile.py`는 자유 베이스를
새로 import해 바퀴 속도로 주행하고, 빈 컵을 손님 테이블에 내려놓는다. 물붓기는 기존 고정
베이스 실행기에서 검증한 별도 단계다. Nav2·ROS Behavior Tree·액체를 담은 컵 운반·복귀까지
연결된 전체 서빙 성공으로 표시하지 않는다.

4테이블 `four_tables01`에서 다섯 렌더를 생성했다. 가구 충돌체 81개의 월드 XY 외곽이
지도 장애물 안에 들어가는지 검사했다. 컵은 입구가 넓어진 형상이며 로봇은 초기 정지 자세다.
최종 자산 경로와 실행 해시는 각 출력 폴더의 `manifest.json`에 남긴다.
로컬 산출물은 데이터 파티션의 `robot-artifacts/restaurant/four_tables01/`에 있다.
`overview.png`는 전체 공간, `cup_detail.png`는 새 컵, `floorplan.png`는 상부 시점이다.
원본 URDF import에서 빈 base_link/base_footprint visual 참조 경고 두 건은 남아 있다.
로봇의 실제 메쉬 렌더와 컵·병 참조는 확인했으나, 이를 경고 없는 독립 배포 패키지로 표시하지 않는다.

## 물 서빙의 완료 조건

빈 컵을 쥐고 주행하는 기존 시험을 최종 서빙으로 사용하지 않는다. 연속 실행의 순서는 다음과 같다.

1. 주방에서 왼팔은 컵, 오른팔은 병을 잡아 물을 붓는다.
2. 오른팔이 병을 작업대에 놓고 손을 뺀다.
3. 왼팔이 물을 담은 컵을 로봇 상판 중앙에 놓고 그리퍼를 연 뒤 물러난다.
4. 컵이 상판에 지지된 상태로 손님 테이블까지 주행한다. 그리퍼로 잡거나 고정 조인트로 붙이지 않는다.
5. 차체가 정지한 것을 확인하고 왼팔이 컵을 다시 잡아 들어 올린다.
6. 손님 테이블의 지지를 확인한 뒤 컵을 놓고 손을 뺀다.

`--mode water-service`는 이 순서를 시험하는 개발 모드다. 기존 병·컵의 속 빈 충돌체와 PBD
입자를 사용하며, 입자는 컵으로 이동하거나 베이스를 따라가도록 위치를 덮어쓰지 않는다.
주행 중 상판 지지·그리퍼 열림·손 이격·컵 위치·물 입자 잔류를 확인한다. 재파지는 마지막
1초 동안 양쪽 손가락 접촉과 상판에서 들어 올려진 위치를 함께 확인한다.

컵을 항상 수직으로 유지하는 정확한 중앙 자세는 IK 탐색 기준을 통과하지 못했다. 다중
초기값 탐색 실패는 수학적 도달 불가능 증명이 아니다. 중심에서 왼쪽 100 mm인 옛 후보도
끝점만 수직이었고, 손목이 반대 분기로 전환되는 중간에 컵이 약 90° 기울어 기각했다.
`water05`에서는 물붓기·병 복귀 후 적재를 시작하다 컵 기울기 15.39°에서 중단됐다.
물붓기 종료 시 컵 684개·병 233개·외부 1개 입자였다. 이 실행은 전체 서빙 성공이 아니다.

새 실험 후보는 같은 손목 분기를 유지한다. 중앙은 상판 원점에서 XY 반경 20 mm 이내로
판정한다. CPU 계산의 안착 전 컵 중심은 약 (−0.8, −11.1, 784.3) mm, 최대 기울기는
12.80°다. 기울어진 컵 바닥 모서리의 지지를 확인한 뒤 열고, 해제 후에는 수직에서 3°
이내로 안정돼야 한다. 운반 중에는 손 접촉이 없고 중앙 영역에 남아 있어야 한다.
바닥 모서리의 예상 중심 높이는 `상판 높이 + 반높이×cos(기울기) + 바닥반경×sin(기울기)`로
계산한다. 이 옵션은 내려놓기 전 지지 확인에만 사용하고 최종 수직 안착 기준을 완화하지 않는다.
CPU 자세 검사와 GPU 물리 검증을 구분한다. `water06`은 물붓기·병 복귀 후 122.725초의
`TRAY_LOWER`에서 왼쪽 손목과 어깨 접촉 신호 17.13 N을 검출해 실패했다. 컵 687개·병
228개·외부 3개 입자는 유지됐으나 적재는 완료되지 않았다. `center_endpoint_probe`에서는
같은 목표 관절값으로 초기화하고 바퀴 명령 없이 검사했으며, 첫 물리 스텝에서 왼쪽 하완·손목과
어깨의 겹침을 검출했다. 초기 관통 해소 충격을 실물 힘으로 해석하지 않는다.

현재 중앙 후보는 기각 상태다. 이 결과만으로 가능한 모든 경로의 부재를 증명하지는 않는다.
팔 배치와 컵 거치 높이를 유지한 채 다른 충돌 없는 해를 찾거나, 별도 설계 변경을 검토해야 한다.
중앙 적재 이후 주행·재파지·서빙 분기는 코드에 연결돼 있지만 물리 성공은 미검증이다.
`sequence_pass`, `center_requirement_pass`, 전체 `task_pass`를 구분해 확인한다.

로컬 증거는 `/data/lim/robot-artifacts/restaurant/`에 보존한다.

- `water01`~`water04`: 초기 스냅샷·접촉 설정·안정화 관측을 점검한 실패 기록.
- `water05/result.json`: 물붓기·병 복귀 후 손목 반전 경로의 기울기 중단.
- `water05/water_pour_then_rejected_transfer.mp4`: 같은 실패 실행의 119초·238프레임 영상. 완성 시연이 아니다.
- `water06/result.json`: 같은 손목 분기를 유지한 후보의 자체 충돌과 접촉 링크 기록.
- `center_endpoint_input/plan.json`, `center_endpoint_probe/result.json`: 목표 자세 자체의 겹침 대조 시험.

각 실행의 코드·입력 해시와 `transfer_plan.json`을 기준으로 버전을 구분한다. 실행 뒤 문구·검증
항목·사용하지 않는 솔버를 정리했으므로 과거 결과를 현재 파일 해시의 전체 성공으로 인용하지 않는다.
`water06`의 `center_requirement_pass`는 당시 계획 목표 위치만 확인한 값으로, 실제 중앙
안착 증거가 아니다. 현재 코드는 안착 관측 창을 확인해야 이 값을 true로 바꾸도록 수정했다.
해당 과거 실행의 전체 `task_pass`는 false였으며 원본 결과를 덮어쓰지 않았다.

기존 실행 명령에서 `--mode water-service --duration 350`으로 바꾸고 새 출력 폴더를 사용한다.
이 모드는 컵뿐 아니라 병도 원본 USD에서 참조하고 물 입자를 초기 생성한다.

## 배치와 재질

원본은 [`restaurant_layout.json`](../config/simulation/restaurant_layout.json)이다.
X 전방, Y 왼쪽, Z 위이며 거리 단위는 m다. 장면과 지도 모두 이 좌표계를 사용한다.

| 항목 | 설계값 / 범위 |
|---|---|
| 방 | X −7.0~1.5, Y −3.5~3.5, 벽 높이 2.8 |
| 주방 작업대 | 중심 (0.62, 0, 0.705), 크기 0.65×1.0×0.03 |
| 손님 테이블 | 중심 (−2.65, ±2.25), (−5.15, ±2.25), 크기 1.2×0.75, 윗면 높이 0.72 |
| 지도 | 0.05 m/cell, 170×140 cell, 장애물 팽창 전 원본 |
| 경로 계획 | 반경 0.40 m 차체 근사, 가구 상판 투영까지 장애물 처리 |
| 카메라 | 전체 조감, 손님 시점, 작업대 근접, 컵 근접, 평면 |

마루는 Poly Haven의 `wood_floor` 1K 색상 텍스처를 사용한다. 가구·조명·벽은 장면 생성
코드의 기하 모델이다. CC0 재질을 제외한 외부 가구 에셋은 현재 장면에 넣지 않았다.
두 벽은 조감 렌더에서만 숨기고 충돌 경계는 남긴다. 컵과 병은 기존 물붓기 USD를 참조한다.

## 지도와 주행 연결

`tools/restaurant_layout.py`는 충전 구역→주방→테이블→충전 구역을 테이블별로 계획한다.
반경을 더한 장애물에서 A*를 실행하고 대각선 모서리 통과를 금지한다. 이 검사는 정적 2D
경로 존재 여부에 한정한다. 팔·병·컵의 전체 외곽, 동적 장애물, 미끄러짐, 정지 오차는 미검증이다.

주방 목표 (−0.20, 0, 0)는 사전 정렬 위치다. 기존 붓기 실험의 베이스 원점 (0, 0, 0)과
같지 않으므로 Nav2 도착만으로 기존 팔 경로를 실행하면 안 된다. 최종 정렬 후 베이스와
작업대의 상대 변환을 확인해야 한다. 테이블 목표도 접근 후보이며 팔 도달성 승인을 뜻하지 않는다.

현재 이동 실행기는 A* 경로와 시뮬레이터의 실제 차체 좌표를 사용한다. 차동구동 추종기가
양쪽 바퀴 속도를 명령하고, PhysX가 지면 접촉과 차체 이동을 계산한다. 시작 배치 뒤 로봇·컵
좌표를 덮어쓰거나 컵을 손에 고정하는 조인트를 만들지 않는다. RGB 인식·SLAM·Nav2 결과는 아니다.

남은 ROS 통합 순서는 다음과 같다.

1. 이동 베이스의 바퀴 관절·충돌체·질량을 검증하고 `/clock`, TF, odometry, scan을 연결한다.
2. 생성 지도에서 Nav2의 `NavigateToPose` 실행과 목표 정지 오차를 측정한다.
3. Behavior Tree가 주방 정렬·파지·붓기·컵 적재의 실제 결과를 받아 다음 단계로 전이하게 한다.
4. 이동 중 컵 지지·액체 유출을 검사하고 테이블 내려놓기 동작을 연결한다.
5. 실패·취소·복귀를 포함한 전체 미션을 녹화한다. 조건 없는 SUCCESS 노드로 통과시키지 않는다.

## 바퀴 주행과 빈 컵 내려놓기

최종 코드의 `service05` 한 번에서 다음 순서를 연속 실행했다. 시뮬레이션 시간은 115.6초,
종료 코드는 0이다. 실행 코드·12개 도구·5개 입력 해시를 현재 파일과 대조했다.

1. 주방 작업대에서 왼손으로 컵 가운데를 파지하고 들어 올린다.
2. 컵을 유지한 채 후진해 작업대에서 빠져나온다.
3. A* 경로를 따라 `table_1` 접근 위치로 주행한다.
4. 차체 중심 (−1.75, −2.25), 방향 π rad를 목표로 최종 정렬한다.
5. 실제 차체 선속도·각속도가 정지 조건을 0.5초 유지하면 팔을 내린다.
6. 테이블의 위쪽 지지력을 확인한 뒤 그리퍼를 열고 손을 뺀다.
7. 컵의 위치·기울기·지지·그리퍼 열림·손 이격이 마지막 1초 동안 유지돼야 통과한다.

판정은 기존 `cup_contact_place.py`의 지지·해제·후퇴 검사를 재사용한다. 마지막 컵 중심은
(−2.13435, −2.41170, 0.78000) m, 목표 XY 오차는 약 10 mm이며 손과 컵의 접촉 중심 거리는
약 103 mm다. 최종 양쪽 손가락 접촉은 없고 컵은 테이블에 지지됐다.

충돌 감시는 다음처럼 분리한다.

- 로봇과 가구, 가동 링크끼리의 접촉을 물리 스텝마다 검사한다.
- 컵과 양쪽 손가락, 작업대, 서빙 테이블, 나머지 가구·바닥·로봇 링크의 접촉을 구분한다.
- 바퀴 둘과 캐스터 둘만 지면 접촉을 허용한다. 차체나 팔이 바닥에 닿으면 실패한다.
- 양쪽 바퀴 각각과 두 캐스터 중 하나의 지지를 10 Hz 관측의 0.5초 이동평균으로 검사한다. 한 번의
  solver 접촉 충격과 지속적인 지지 상실을 구분하며, 차체 높이·기울기 조건도 함께 적용한다.
- URDF의 fixed joint로만 이어진 동일 강체 조립체 내부와 기존 랙 프록시 한 쌍만 충돌에서
  제외한다. 가동 관절 경계를 넘는 다른 쌍이나 외부 물체는 제외하지 않는다. 이 설정은
  볼트 체결 구조의 내부 접촉을 정리하는 것이며, 제작 부품 간 간섭 검증을 대신하지 않는다.

`probe02`에서는 진행 경로에 별도 장애물을 넣었다. 앞 프레임과 그 장애물의 접촉 신호
약 50.29 N을 감지해 `environment_collision`으로 멈췄다. 미션 성공은 false,
충돌 검출 대조 시험만 true다. 접촉 검출 뒤 추가 주행을 중단하고 시뮬레이션을 종료한다.
제동 거리·물리 정지 시간이나 동적 장애물 회피 성공을 검증한 것은 아니다.

검증 범위는 `table_1`의 빈 컵 1회 서빙이다. 나머지 테이블 세 개는 정적 경로 검사만
통과했다. 모터·캐스터·마찰·강체 그리퍼는 미보정 가정이며 실물 성능으로 환산하지 않는다.
바퀴 반경 32.9 mm, 윤거 510 mm를 사용하는 실험 사본이고 원본 URDF는 변경하지 않는다.

로컬 결과는 `/data/lim/robot-artifacts/restaurant/` 아래에 있다.

- `service05/result.json`: 지면 충돌·접지 창을 포함한 최종 실행 결과와 관측.
- `service05/cup_service.mp4`: 같은 실행의 1280×900, 2 fps, 232프레임, 116초 녹화.
- `service05/final.png`: 컵을 놓고 손을 뺀 마지막 화면.
- `probe02/result.json`: 주입 장애물 접촉 쌍과 중단 근거. 같은 코드 버전이며 종료 코드 0이다.

각 실행의 코드 사본은 `executed_runner.py`, 입력·코드 해시는 `result.json`에 보존한다.
앞선 `service03/04`와 초기 실패 기록도 덮어쓰지 않고 보존한다.

## 이동 실행기 사용

앞선 `flared03` 출력의 `plan.json`, `replacement_hypothesis.urdf`, `scene.usda`가 필요하다.
URDF의 메쉬 경로도 유효해야 한다. 다른 PC에는 이 입력 자산을 함께 전달하거나
`tools/simulate_bimanual_pour.py`로 먼저 생성한다. `scene.usda`에서는 컵 형상만 참조하며
고정 베이스 로봇이나 물 입자는 가져오지 않는다.

```bash
cd "$HOME/bimanual-robot"
ISAAC_PY="/data/$USER/conda-envs/leisaac/bin/python"
ARTIFACT_ROOT="/data/$USER/robot-artifacts"
"$ISAAC_PY" tools/simulate_restaurant_mobile.py --headless --record \
  --mode service --duration 160 \
  --source-dir "$ARTIFACT_ROOT/pour_20260921/runs/flared03" \
  --output-dir "$ARTIFACT_ROOT/restaurant/new_service"
```

`--headless`를 빼면 시뮬레이터 화면을 띄운다. `--record`는 2 fps PNG와 마지막 화면을
남긴다. `--mode drive-smoke`는 빈 로봇의 0.5 m 주행, `--mode collision-probe`는 장애물
접촉 검출, `--mode pick-only`는 자유 베이스 컵 파지 시험이다. 각 시험에 새 출력 폴더를 쓴다.
`result.json`의 `task_pass`, `negative_control_pass`, `failure`를 구분해서 확인한다.
이 실행기는 하드웨어 포트·카메라·ROS 토픽을 열지 않는다.

## 생성과 실행

Isaac Sim 5.1이 설치된 Python 환경에서 실행한다. GPU 실행은 물붓기 실험과 겹치지 않게 한다.
출력 경로는 새 디렉터리여야 하며 기존 결과를 덮어쓰지 않는다.

```bash
cd "$HOME/bimanual-robot"
ISAAC_PY="/data/$USER/conda-envs/leisaac/bin/python"
ARTIFACT_ROOT="/data/$USER/robot-artifacts"
"$ISAAC_PY" tools/build_restaurant_scene.py --headless \
  --robot-scene "$ARTIFACT_ROOT/pour_20260921/runs/flared03/scene.usda" \
  --floor-texture "$ARTIFACT_ROOT/restaurant/assets/wood_floor_diff_1k.jpg" \
  --output-dir "$ARTIFACT_ROOT/restaurant/new_preview"
```

다른 PC에서는 `ISAAC_PY`, `ARTIFACT_ROOT`를 해당 환경의 경로로 바꾼다.
GUI에서는 생성된 `restaurant.usda`를 열고 `/Cameras` 아래 시점을 선택한다.
이 USD는 로봇 USD와 텍스처를 외부 참조하므로 파일 하나만 복사하면 완전한 장면이 되지 않는다.
`manifest.json`의 참조 경로와 SHA-256을 함께 확인한다. 대용량 USD·렌더·실험 로그는 Git 밖에 둔다.
