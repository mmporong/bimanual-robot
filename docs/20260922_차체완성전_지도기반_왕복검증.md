# 차체 완성 전 지도 기반 서빙 왕복 검증

## 목적

완성 전 양팔 로봇 대신 현재 JD-AMR 베이스로 최종 서빙 미션의 이동 구간을 먼저 검증한다.
이 시험은 가상 시뮬레이션이 아니라 실제 LiDAR·오도메트리·RGB-D와 실제 공간을 사용하는
선행 기능 시험이다. 상부 차체, 양팔 조작, 충전 접점은 아직 포함하지 않으므로 최종 기체의
전체 성능으로 해석하지 않는다.

검증할 흐름은 다음과 같다.

```text
새 2D 지도 생성·저장
  → 시작 위치·방향을 home_dock으로 교시
  → 박스 앞 서비스 위치를 kitchen_station, table_01로 교시
  → 저장 지도 + AMCL + Nav2로 지정 station을 순서대로 이동
  → 각 station에서 RGB-D 전면 박스를 안정적으로 확인하며 20초 대기
  → home_dock의 원래 위치·방향으로 복귀
```

## 최종 시스템과의 대응

| 선행 검증 | 완성 기체에서의 의미 | 이번에 검증하지 않는 것 |
|---|---|---|
| `home_dock` map pose | 충전소 staging·복귀 자세 | 충전 접점 체결, 충전 전류 확인 |
| `kitchen_station`, `table_01` | 주방·손님 테이블의 서비스 pose | 장소 의미 자동 인식 |
| LiDAR Cartographer 지도 | 반복 운용용 2D 지도 | 양팔 장착 뒤 가림·외곽 변화 |
| 저장 지도 + AMCL + Nav2 | 반복 서빙 이동 | 완성 기체의 하중·정지거리 |
| RGB-D 박스 전면 관측 | station에 작업 대상이 있는지 확인 | 박스 종류·내용물 분류, 팔 작업 성공 |
| 20초 안정 관측 | 조작 태스크 시간을 대신한 대기 phase | 실제 조작 완료 판정 |

최종 기체에서도 station은 물체 자체의 위치가 아니라 로봇의 `base_link`가 정차해야 하는
`map` 좌표의 위치·방향으로 관리한다. 지도나 Keepout 마스크가 달라지면 파일·격자 해시가
달라지므로 이전 station을 자동 재사용하지 않는다.

## 상태기계와 실패 경계

```text
HOME_READY
  → [NAVIGATING_TO_STATION
     → STATION_POSE_CONFIRMED
     → BOX_DWELL] × 선택한 station 수
  → RETURNING_HOME
  → HOME_POSE_CONFIRMED
```

- 목적지와 home 경로는 실제 이동 전에 모두 계획만 해볼 수 있다. `--execute`가 없으면
  속도 명령을 시작하지 않는다.
- station 도착은 내부 추정 위치 오차 0.05m 이하, 방향 오차 3° 이하, 최종 정지 1초를
  모두 만족해야 한다. 이는 외부 계측으로 확인한 물리 정확도가 아니다.
- 박스는 `/box_parking/perception_status`의 전면 평면이 최신이고 `stable=true`인 상태를
  20초 연속 유지해야 한다. 관측이 끊기면 대기를 처음부터 다시 센다.
- 박스를 45초 안에 확인하지 못하면 그 자리에서 실패로 끝낸다. 박스 확인을 생략한 채
  성공이나 복귀 단계로 넘어가지 않는다.
- home 복귀도 같은 0.05m·3°·정지 조건을 적용한다. 과거의 단순 `후진 → 회전 → 후진`은
  목적지 이탈 동작일 뿐이며 충전소 복귀 성공으로 세지 않는다.

## 실차 진행 순서

1. 충전소로 사용할 출발 위치와 방향을 먼저 정하고 그 자세에서 Cartographer 지도를 만든다.
2. `/autonomy/stop` 뒤 `save=succeeded`와 YAML·PGM 생성을 확인한다.
3. 같은 지도 크기·해상도·원점의 Keepout 마스크를 만들고 검증한다.
4. 저장 지도, AMCL, Nav2와 속도를 발행하지 않는 RGB-D 박스 관측기를 기동한다.
5. 출발 자세를 `teach-home`으로 저장한다.
6. 박스 앞에서 `kitchen_station`, `table_01` 같은 목적지를 교시한다.
7. `roundtrip`을 `--execute` 없이 실행해 목적지·복귀 경로가 모두 계획되는지 확인한다.
8. 작업자가 기체 옆에서 중단 수단을 확보한 상태에서 지정 station 전체의 실제 왕복을 실행한다.
9. 지도·AMCL·계획 경로·박스 관측·Nav2 action·정지 판정과 JSONL을 같은 실행 ID로 보존한다.

## 완료 판정

선행 검증 완료는 다음 조건을 한 실행에서 모두 만족한 경우다.

- 저장 지도와 Keepout 신원 검증 통과
- 지정한 모든 station까지 순서대로 Nav2 도착 및 최종 자세 확인
- 각 station에서 박스 안정 관측 20초 완료
- 새 목표를 발행해 `home_dock`으로 귀환
- home 위치 오차 0.05m 이하, 방향 오차 3° 이하, 정지 1초
- 중간 goal 취소 미확인, 지도 변경, 센서 stale, 충돌 감시 이탈 없음
- 등록부·JSONL·필수 rosbag이 실행 ID와 해시로 연결됨

현재 상태는 코드·문서·단위 시험 완료이며, 새 지도의 생성과 실차 왕복은 남아 있다. 완성
기체로 이식할 때는 같은 상태기계와 station 스키마를 유지하되 실제 footprint, 센서 TF,
바퀴 유효 간격, 하중 상태의 정지거리와 충전 판정을 다시 검증한다.
