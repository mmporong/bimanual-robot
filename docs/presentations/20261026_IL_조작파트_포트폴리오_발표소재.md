# 조작(IL) 파트 — 포트폴리오·최종발표 소재 정리

최초 작성 2026-10-26 · 조작(IL) 담당자 작성 · 기준 시점 2026-10-26

이 문서는 슬라이드에 바로 옮길 수 있게 **숫자·그림·문제해결 사례**만 모았다. 모든 수치에는 조건과 출처 문서를 같이 적었다. **아직 측정하지 않은 것은 "미측정"으로 표시했으니, 발표에서 성공률처럼 말하지 않는다.**

---

## 1. 한 장 요약 (표지·개요 슬라이드용)

- **과제:** 양팔 SO-101 로봇이 ① 왼손으로 컵을 집고 ② 오른손으로 병을 들어 물(자갈)을 붓고 ③ 병을 내려놓은 뒤 ④ 컵을 차체 상판에 싣는다. 이어서 ⑤ 컵을 테이블로 옮겨 내려놓는다(물따르기 → 컵배치 핸드오프).
- **방법:** 텔레옵 시연 데이터 → VLA 모방학습(SmolVLA, pi0) → 실기체 롤아웃. 사람의 시연을 그대로 따라 하는 방식이다.
- **규모(차체 결합 데이터):** 물따르기·컵배치 각 80 에피소드. 물따르기 131,953프레임, 컵배치 61,800프레임, 30fps, 카메라 3대(손목 2 + top 1).
- **결과:** SmolVLA 물따르기→컵배치 전체 시나리오를 실기체에서 완주했다.
  - 10-22 테이블 거치 상태에서 처음 완주했다.
  - 10-25 차체 결합 모델은 "굉장히 잘 동작"한다고 사용자가 확인했다.
  - 반복 성공률은 **미측정**이다.

## 4. 문제해결 사례 (상황 → 원인 → 조치 → 결과)

포트폴리오의 "문제해결 능력" 항목에 쓰기 좋은 순서로 골랐다.

### ① 정책이 제자리에서 떨기만 함 → 원인 2개를 차례로 규명 (10-15, 10-16)
- **상황:** 학습은 잘 됐는데 실기체에서 팔이 제자리에서 떨었다.
- **원인:**
  1. USB 재연결로 손목캠 좌우가 뒤바뀌었고, top 카메라 좌우 반전이 빠져 있었다.
  2. 이를 고친 뒤에도 남은 떨림은 사람이 손으로 맞춘 **시작 자세가 학습 분포 밖**(shoulder_lift +26°)이었기 때문이었다.
- **조치:**
  - 장치 고유 경로(DevicePath)로 카메라를 매번 다시 찾는 리졸버를 만들었다.
  - 학습 분포 중앙의 시작 자세로 이동하는 도구를 만들었다.
  - 10-26에는 텔레옵으로 저장한 자세로 추론 전에 이동하는 기능까지 확장했다.
- **교훈:** 하나를 고치고 "이게 원인"이라고 단정했던 실수가 있었다. 고친 뒤에도 재현되는지 확인해야 한다.
- 출처: `docs/experiments/20261014_로컬_SmolVLA_배포전_검증과_건식롤아웃.md`, `20261016_SmolVLA_제자리떨림_시작자세_OOD_원인규명.md`

### ② 붓기를 끝까지 안 함 → 정책이 "자갈의 시각 상태"에 의존 (causal confusion, 10-21)
- **상황:** 병을 90° 부근까지만 기울이고 망설였다.
- **원인:** 조건을 바꾼 통제 실험(뚜껑 닫힘·빈 병)으로 좁혔다. 정책이 병 안 자갈이 빠지는 모습을 붓기 완료 신호로 학습한 것이었다. 모방학습의 전형적 실패(지름길 학습)다.
- **조치:** 붓기 훅을 만들었다. 손목 roll이 75°를 넘으면 기울이기·유지·복귀를 코드가 맡고 정책에 다시 넘긴다.
- 출처: `docs/experiments/20261021_물따르기_정책_자갈_시각의존_causal_confusion.md`

### ③ 롤아웃 사이 그리퍼 과부하로 다음 연결 실패 (10-22)
- **상황:** 컵을 쥔 채 대기하다 왼 그리퍼 서보의 과부하 보호가 걸렸고, 다음 실행이 "Missing motor ID 6"으로 실패했다.
- **조치:** 실행 전과 종료 직전에 그리퍼 목표를 실제 위치 쪽으로 당겼다. 손가락 위치는 유지하고 미는 힘만 뺀다.
- **결과:** 전체 시나리오를 연속으로 완주했다.

### ④ 차체 결합 후 top 카메라 조명 줄무늬 (10-23)
- **원인:** 새 뎁스 카메라의 자동 노출 2.5 ms가 조명 깜빡임 주기 8.3 ms보다 짧았다.
- **측정:** 노출 스윕 도구로 83·167·250(×0.1 ms)에서 줄무늬가 사라지는 것을 찾았다.
- **함정 발견:** 드라이버는 같은 값을 다시 쓰면 무시한다. 그래서 한 칸 다른 값을 먼저 쓰도록 고쳤다.
- **결정:** 새 카메라는 노출 고정 시 과노출(55% 날아감)이었다. 그래서 학습 데이터와 같은 기종으로 되돌렸다. 데이터 분포 일치를 우선한 결정이다.

### ⑤ 학습 화면과 지금 화면을 픽셀 단위로 맞추는 도구 (10-23)
- 학습 에피소드 화면을 겹쳐 보면서 어긋난 정도를 숫자로 보여 주는 라이브 뷰어를 만들었다.
- 처음 측정은 (+16.8, +17.6)px였다. 이 측정으로 "오른팔이 화면에서 잘리는 이유"가 소프트웨어가 아니라 카메라 방향이라는 것을 수치로 보였다.

### ⑥ HF 시각화에서 64번부터 에피소드가 사라짐 (10-23)
- **원인:** 데이터 문제가 아니었다. 시각화 라이브러리가 메타 파일을 64개까지만 읽고, 수집 방식상 라운드마다 메타 파일이 하나씩 생겼다.
- **조치:** 메타를 파일 하나로 다시 묶었다.
- 데이터셋 병합 도구가 메타 인덱스를 잘못 쓰는 버그도 찾아서 고쳤다.

### ⑦ 같은 조건 비교를 설계해서 공정하게 평가 (10-25)
- 데이터를 part2 → v1 순서로 붙여서, 60개와 80개 모델이 **똑같은 검증 에피소드 6개**로 평가되게 했다.
- 이미 검증된 설정에서 근거 있는 두 가지(step 비례 확장, 이미지 증강)만 바꿔서 변수를 통제했다.

### ⑧ "사전학습 없이 학습됐다"는 사실을 설정 파일로 찾아냄 (10-26)
- pi0 가능성을 검토하다가 기존 SmolVLA와 pi0가 모두 랜덤 초기화로 학습된 것을 학습 설정과 로그로 확인했다.
- pi0는 사전학습 가중치로 다시 시작해 첫 eval loss가 4.6배 낮게 출발했다(0.0805 vs 0.373).

## 6. 정직하게 밝힐 한계 (Q&A 대비)
- **실기체 반복 성공률은 아직 측정하지 않았다.** "완주했다"와 "잘 동작한다"는 관찰이고 통계가 아니다. 발표 전에 같은 조건 N회 측정을 권장한다.
- eval loss는 학습 때와 같은 환경의 검증 에피소드로 잰 값이다. 실기체 성공률과 1:1로 대응하지 않는다.
- 이미지 증강이 조명·카메라 변화에 얼마나 강건한지는 아직 실기체로 비교하지 않았다.
- 팔 장착 위치는 아직 설계값이다(실측 전).
- pi0는 학습 중이라 실기체 결과가 없다.

## 7. 발표 전에 하면 좋은 것
1. 80개 SmolVLA 모델로 물따르기→컵배치 **10회 연속** 시도하고, 성공·실패와 실패 단계를 기록한다(같은 위치 격자).
2. 60개 모델도 같은 조건으로 돌려 **데이터 양 효과를 실기체로 확인**한다.
3. pi0가 끝나면 같은 조건으로 SmolVLA와 비교한다(모델 비교 슬라이드).
4. 성공 1회, 대표 실패 1회 영상을 촬영한다.
