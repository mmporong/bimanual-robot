# HOLD THE FLOW 양팔 로봇 — 프로젝트 인계

작성 2026-09-04. 다른 세션이 이 문서에서 시작해 어느 갈래로든 들어갈 수 있게 쓴다.
세부는 각 절이 가리키는 문서에 있다. 여기서는 **무엇이 확정이고 무엇이 열려 있는지**만
정확히 적는다.

## 0. 한 줄

250 × 250 mm 이동형 양팔(SO-101 ×2) 로봇이 병을 들어 컵에 물을 붓는다.
내 담당은 **IK + Depth, 그리고 모방학습**이다.

## 1. 절대 어기지 않는 것

| 규칙 | 근거 |

| 대용량 바이너리(rosbag·모델·데이터셋) 커밋 금지. 데이터는 HuggingFace Hub 비공개 | — |
| ggao50 상류에 LICENSE 없음 → **STL·STEP·G-code 리포 반입 금지** | 산출물은 `~/gcode/` 에 둔다 |

## 3. 갈래별 현재 상태

### 3.1 기구·질량 — 확정

| 항목 | 값 |
|---|---|
| 로봇 총질량 | 5.092 kg (목표 4.8~5.3) |
| 붓기 시 | 5.212 kg |
| 컵 유지 중력토크 | 0.769 N·m, 정격의 **78.4%** |
| 초기 페이로드 | 팔당 60 g (게이트 통과 시 120 g) |
| 소스 병 | 200~330 mL, 지름 50~62 mm, 충전율 40% 이상, 물 50 mL 이하 |

병 규격이 좁은 것은 의도다. 500 mL 병에 물 95 mL 는 하중은 만족하지만 충전율 19% 라
임계각 근처에서 급격히 쏟아진다. 작은 병이 붓기 제어가 쉽다.

### 3.2 그리퍼 — 확정, 출력 대기

**ggao50 SO101-Parallel-Gripper**. 2026-09-04 norma-core `pgripper` 와 대조 후 유지 결정.
개구 105 mm 대 54 mm 가 갈랐다(우리 병이 50~62 mm).

출력 준비는 끝났고 사용자가 `bash ~/gcode/build_plates.sh` 를 실행하면 된다.
→ `docs/20260904_그리퍼_출력_인계.md`

### 3.3 URDF·IK — 설계 검증까지 완료

| 항목 | 상태 |
|---|---|
| SO-101 팔 체인 | **완료** — 관절 규약 정합 |
| `tool0` / `bottle_tcp` / `cup_tcp` | **완료** |
| 설계 검증 IK (`solve_task_poses.py`) | **완료** — URDF FK + 감쇠 최소자승 |
| 운반 자세 | **완료** — 간섭 통과 |
| **붓기 자세** | **미해결** — 아래 4.1 |
| 웨이포인트 경로 검증 도구 | 미착수 |
| 해석적 IK 이식 | 미착수 |

오늘의 큰 교훈이 여기 있다. 붓기 자세 관절 한계 위반, 자가충돌 18 쌍, 팔↔라이다
4.33 mm, 팔 사이 18.78 mm — **네 개가 전부 하나의 원인**(벤더링한 Robonine 팔 체인)이었다.
검증된 SO-101 체인으로 되돌리자 넷이 동시에 풀렸다.
**여러 검사가 같이 실패하면 각 항목이 아니라 공통 입력을 의심한다.**

### 3.4 IK / IL 경계 — 문서화 완료, 구현 미착수

→ `docs/20260903_IK_IL_경계와_결합.md` (264 행)

경계를 정하는 기준 셋, 구간별 배정, 명령 중재기 하나로 합치는 방식, IK 세 가지 구현
(설계 검증용 / 실행용 웨이포인트 보간 / 실시간 해석적)이 들어 있다. MoveIt 은 쓰지 않기로
해서 관련 내용을 뺐다.

정책 리서치는 → `research/R32_IL과_IK_결합구조_정책선택_실행모드.md` (246 행).
ACT 를 쓰되 시간 앙상블이 아니라 `--replan 10~15` 청크 모드로 간다. 근거는 실물 롤아웃에서
앙상블이 정지 구간에 갇혔던 관찰이고, PACE 논문이 그 모호성을 설명한다.

### 3.5 온보드 컴퓨트·배선 — 결론 남

→ `docs/20260903_온보드컴퓨트_USB대역폭_전원_검토.md` (9 절)

- SBC 는 **Pi 4 유지**. Pi 5 로 안 가는 이유가 2 절에 있다
- 학습은 외부, 실행은 노트북 1 대 무선. ACT 청크 덕에 WiFi 오프보드가 성립한다
- **USB 대역폭은 포트가 아니라 호스트 컨트롤러 단위로 나눈다.** Pi 4B 는 VL805 하나뿐이라
  포트 4 개가 같은 예산을 나눠 쓴다
- 수집과 자율 실행은 **배선이 다르다**(4-2 절). 수집은 노트북 유선 단독, 실행만 Pi 무선

### 3.6 팀

리더 2 대 확보로 양팔 동시 텔레옵 미검증 항목이 닫혔다. 캘리브레이션과 모터 번호는
전부 되어 있다.

## 4. 열려 있는 결정 — 막고 있는 순서대로

### 4.1 작업 셀 거리 (최우선, 다른 것들을 막고 있다)

붓기 좌표가 팔 베이스에서 443~492 mm 인데, 4,000 회 랜덤 샘플로 측정한 최대 도달이
tool0 486.9 / cup_tcp 490.7 / bottle_tcp 513.9 mm 다. **도달의 96~97% 지점**이라
기하학적으로 닿아도 팔이 거의 펴진 특이자세라 IK 해가 사실상 없다. 중력토크도 정격
96.6% 로 같은 지점에서 최대가 된다.

**필요한 것**: 작업 셀을 팔 베이스에서 **400 mm 안쪽**으로 당기거나 Nav2 정지 위치를
앞으로 옮긴다. 값이 정해지면 `solve_task_poses.py` 로 붓기 자세를 다시 푼다.

이게 닫혀야 경로 검증 도구 → 수집 파이프라인으로 넘어간다.

### 4.2 행동 공간 규약 (데이터 수집 전에 반드시)

절대 관절값이냐, 컵 팔 기준 상대 좌표냐. **수집을 시작한 뒤에 바꾸면 데이터가 전부
못 쓰게 된다.** 아직 안 정했다.

### 4.3 서보 변종 감사

C001 인지 C018 인지 24 개 전부 확인해야 한다. **리더 12 개를 빼먹지 말 것.**

### 4.4 LDS-03 인터페이스

USB2LDS 를 쓸지 MCU UART 로 받을지. USB 포트 예산과 직결된다(3.5 절).

### 4.5 로컬 LLM 태스크 플래닝 — 사용자가 보류

강사가 Qwen3 하네스로 태스크 플래닝을 맡는다는데 범위가 불명확하다. 사용자 판단은
"일단 보류". 먼저 제안하지 말 것.

## 5. 확인된 사실과 추정의 구분

**실측·계산으로 확인된 것**
- 질량 5.092 kg, 컵 유지 토크 0.769 N·m / 78.4%
- 최대 도달 486.9 / 490.7 / 513.9 mm (랜덤 4,000 자세 샘플)
- 운반 자세 관절값과 간섭 통과
- ggao50 죠 접촉면은 연속 테이퍼 `높이 = 0.682·Y + 67.5` (평면 절단으로 재측정)
- 출력 6 종의 방향별 서포트·접지 면적

**추정이거나 미검증인 것**
- ggao50 반복정밀도 — 상류 미공개, 실물에서 확인해야 한다
- norma pgripper 총질량 146 g — 출력 부피에서 계산한 값
- V홈 인서트가 실제로 병을 무는지 — 세 종류를 다 뽑아 비교하려는 이유가 이것이다

## 6. 함정 기록

- **OrcaSlicer CLI 는 필라멘트 `inherits` 를 못 푼다.** PETG·TPU 가 PLA 200 °C 로 나온다.
  `design/cad/slice_k1max_petg.py` 가 파이썬에서 미리 풀어 주입한다. 항상 이쪽을 쓴다
- **삼각형 중심으로 면을 분류하면 틀린다.** 52 개 삼각형 메시에서 죠 접촉면을 "분리된 패드
  두 개"로 잘못 읽었다. 평면 절단으로 다시 재야 한다
- **`s[s.index(A):s.index(B)]` 에서 A 가 B 뒤에 있으면 빈 문자열**이 나오고,
  `s.replace("", new)` 는 글자마다 끼워 넣는다. 문서 하나를 369,114 행으로 만든 적 있다.
  줄 인덱스로 자를 것
- 파일명의 `45infill` 은 틀렸다. pinion 만 45%, 나머지 25% 다. **이름 말고 G-code 안의 값**
