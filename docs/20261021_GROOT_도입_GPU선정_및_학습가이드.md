# GR00T 도입 — GPU 선정 및 학습·배포 가이드 (팀 의사결정 문서)

최초 작성 2026-10-21 · 조작(IL) 담당자 작성

## 0. 한 줄 요약 (TL;DR)

- **엔비디아 쿠폰(팀원 보유)으로 클라우드 GPU에서 GR00T를 파인튜닝**하고, **추론은 학교
  서버(RTX 4090, 24GB)에서 ZMQ 원격으로** 돌리는 구성이 가능하다. 로봇 USB·카메라는
  로컬에 두고, 관측/행동만 네트워크로 주고받는다.
- **학습 GPU 권장: A100 80GB**(실용적 최적) 또는 **H100 80GB**(NVIDIA가 말하는 성능 최적).
  **V100은 지원 안 됨**(Ampere 이상 필수).
- **버전**: 처음엔 **N1.5**(가볍고 SO-101 공식 경로 검증됨), 성능 더 원하면 **N1.7**
  (백본 업그레이드로 기본 손재주↑, 단 학습에 40GB+ 필요).
- **데이터는 기존 LeRobot 핸드오프 데이터셋 재사용** 가능 — `meta/modality.json`만 추가.
- **전제조건**: 추론은 16GB+ GPU가 있는 곳에서만 된다(현 8GB 노트북 단독 불가 → 원격 서버로 해결).

> 이 문서는 조사 기반 **의사결정 가이드**다. 수치는 버전에 따라 다르며 출처는 11절.

---

## 1. 왜 GR00T를 고려하나 (맥락)

현재 SmolVLA(450M) 핸드오프 모델이 **서브동작 전환점**(끝까지 기울이기 커밋, 붓고 복귀)에서
망설이는 문제가 있다. 원인이 **모델 용량**이면 GR00T(2~3B, 대규모 사전학습)가 도움이 될 수
있다. 단, 원인이 **데이터 품질(전환 결정성)**이면 GR00T도 같은 걸 학습하므로 크게 나아지지
않는다 → **ACT 비교로 "모델이냐 데이터냐"를 먼저 가른 뒤** GR00T 투자를 결정하는 게 안전하다.
(GR00T는 만능이 아니다.)

## 2. 버전 선택 — N1.5 vs N1.7

| 항목 | **GR00T N1.5** (~2B) | **GR00T N1.7** (~3B) |
|---|---|---|
| 백본 | VLM을 **학습 중 동결(frozen)** | Cosmos-Reason2-2B / Qwen3-VL로 **업그레이드**, EgoScale 사전학습 |
| 강점 | 가볍고, **SO-101 공식 파인튜닝 경로 검증됨**(HF 블로그) | out-of-box 손재주·일반화 더 좋음 |
| 학습 VRAM(기본) | **~25~33GB** | **~35GB peak, 최소 40GB+** |
| 추론 VRAM | ~16GB | ~16GB |
| 24GB(4090)에서 학습 | 빠듯(플래그 필요) | **불가**(40GB+ 필요) |

**권장**: **1차는 N1.5**로 검증된 SO-101 경로를 그대로 밟아 파이프라인을 세운다(실패 지점이
적다). 결과가 유망하고 더 밀어붙일 때 **N1.7로 교체**(N1.6→N1.7은 `--model-path`만 바꾸는
드롭인). 쿠폰 GPU가 넉넉(80GB)하면 처음부터 N1.7도 무방.

## 3. 학습 GPU 선정 — "A100이 최적인가?" 조사 결과

**결론: A100 80GB는 매우 좋은 실용적 최적이다. 다만 "유일한 최적"은 아니다** — NVIDIA 공식
권장은 **H100/L40**를 "성능 최적"으로 든다. A100은 공식 목록에 명시돼 있진 않지만 Ampere라
**정상 지원**되고 80GB 변형이면 N1.5·N1.7을 모두 여유 있게 돌린다.

| GPU | VRAM | N1.5 학습 | N1.7 학습(기본) | 비고 |
|---|---|---|---|---|
| **H100 80GB** | 80 | ✅ | ✅ (풀튜닝까지) | NVIDIA 성능 최적, 가장 빠름 |
| **A100 80GB** | 80 | ✅ | ✅ | **실용적 sweet spot**, 가용성·가성비 ◎ |
| **A100 40GB** | 40 | ✅ 여유 | ⚠️ 최소 충족(배치 작게) | N1.7 빠듯 |
| **L40 / L40S** | 48 | ✅ | ✅ 기본 | 저렴·효율적 대안 |
| RTX 4090 / A6000 | 24 / 48 | 4090 빠듯 / A6000 ✅ | 4090 ❌ / A6000 ✅ | 4090은 N1.5도 플래그 필요 |
| **V100** | 16/32 | ❌ | ❌ | **Volta — 지원 안 함** |

**선택 지침:**
- **쿠폰이 H100을 주면 → H100 80GB** (가장 빠르고 여유, 미래 대비).
- **그 외 일반적 → A100 80GB** (N1.5·N1.7 다 소화, 가장 무난한 권장).
- **N1.5만 할 거면 → A100 40GB 또는 L40 48GB**로도 충분.
- **단일 GPU면 충분**하다(에피소드 40~80개 규모 파인튜닝). 멀티 GPU(4~8x)는 대규모·실로봇
  대량 워크플로용이라 지금은 불필요.

## 4. 추론 GPU / 배포 — 원격(ZMQ) 구조

**추론 최소 ~16GB VRAM.** 지원 하드웨어: RTX 4090, L40, H100, **Jetson AGX Orin**.

**핵심: GR00T는 ZMQ 서버-클라이언트 원격 추론을 공식 지원한다.** 따라서:
- **추론 서버(PolicyServer+GPU) = 학교 서버 RTX 4090(24GB > 16GB → 충분)**
- **제어 클라이언트(가벼움) = 로봇 꽂힌 로컬 노트북** — 카메라·관절 관측을 서버로 보내고
  행동을 받아 실행. 로봇 USB·카메라는 로컬 유지, 무거운 추론 의존성은 서버에만 설치.
- → **현 8GB 노트북 단독으론 GR00T 추론이 안 되지만, 이 원격 구조로 우회된다.**

**반드시 확인/설정할 3가지:**
1. **네트워크 지연**: 로봇 노트북과 학교 서버가 **같은 교내망(LAN)**이면 이상적. 인터넷
   경유면 지연·지터 발생 — GR00T의 액션 청킹(한 번에 ~1.67초치 행동)이 어느 정도 흡수하나,
   **먼저 왕복 지연을 측정**해야 한다.
2. **서버 GPU 점유**: 팀 공용이므로 롤아웃 동안 그 4090이 비어 있어야 한다(학습과 충돌 금지).
3. **안전 — 통신 두절 정지**: 원격 추론은 제어 루프가 네트워크 의존 → **끊기면 로봇이
   멈추도록** 클라이언트에 comms-timeout 정지를 둔다(움직이는 팔, 안전 규칙). 마지막 행동을
   계속 밀면 위험.

## 5. 데이터 준비 — 기존 LeRobot 데이터 재사용

- **포맷**: LeRobot Dataset **v3** 스키마(상태·행동·task 텍스트·에피소드 메타·비디오). 우리
  핸드오프 데이터셋이 이미 이 포맷이다 → **재수집 불필요.**
- **추가 작업**: `meta/modality.json` 한 개 추가(SO-100/101 dual-cam 예시 복사·수정 →
  `<DATASET>/meta/modality.json`).
- **카메라 일관성(치명적)**: 카메라 **개수·이름·순서**가 수집·학습·롤아웃에서 **모두 같아야**
  한다. 우리는 `left_wrist`·`top`·`right_wrist` 키를 쓰므로 modality.json·롤아웃에서 동일하게
  유지한다. (SmolVLA 떨림이 카메라 오정렬이었던 전례 상기.)
- **에피소드 수**: 고정 최소치는 없다 — 과제 다양성·초기상태 변동·조작 일관성·성공률에 따라.
  공식 예시는 50~80개. **파일럿(소량)으로 로딩·학습이 되는지 먼저 검증 후 확장**.

## 6. 소프트웨어 스택 (버전 고정 — 어긋나면 깨짐)

- Python **3.12**
- CUDA **12.8+**, 드라이버 **580.95.05+**
- **FFmpeg 4~7** — ⚠️ **FFmpeg 8은 TorchCodec을 깨뜨림**(설치 금지)
- LeRobot **소스 체크아웃**(현행), 정책 타입 `groot`
- 베이스 체크포인트: N1.5 `nvidia/GR00T-N1.5-3B` / N1.7 `nvidia/GR00T-N1.7-3B`
- Isaac-GR00T 레포(`NVIDIA/Isaac-GR00T`)의 `gr00t_finetune.py` / 추론 서비스 사용

## 7. 파인튜닝 설정 — 무엇을 튜닝하나

- **기본(권장)**: projector + diffusion action head만 튜닝(LLM 백본 동결) → VRAM 절감,
  40~80개 규모에 적합.
- **풀 튜닝**(`--tune-llm` / `--tune-visual`): VRAM **80GB+** 필요. 데이터 많고 일반화가
  필요할 때만. 우리 규모엔 불필요.
- **저VRAM 완화**: `--no-tune_diffusion_model` 플래그로 추가 절감(24GB급에서 N1.5 돌릴 때).
- **배치/스텝**: 공식 SO-101 예시가 `--max-steps 10000`. 배치는 GPU 메모리에 맞춰(단일
  80GB면 넉넉). 우리 서버 학습처럼 **patience 기반 조기종료/eval**을 쓸지 결정(Isaac-GR00T
  기본 루프 확인 필요).

## 8. 결정해야 할 사항 — 체크리스트

- [ ] **버전**: N1.5(1차 검증) vs N1.7(성능) — 쿠폰 GPU VRAM과 함께 결정
- [ ] **학습 GPU**: 쿠폰이 주는 목록 확인 → H100 80GB / A100 80GB / L40 중 선택
- [ ] **클라우드 플랫폼**: 쿠폰이 어디서 쓰이는지(NVIDIA Brev/DGX Cloud/파트너 등) + 가용 GPU
- [ ] **추론 위치**: 학교 서버 4090 원격(권장) vs 로컬 GPU 증설 vs Jetson AGX Orin
- [ ] **네트워크**: 로봇 노트북 ↔ 학교 서버가 같은 LAN인가? (지연 측정)
- [ ] **튜닝 범위**: head-only(기본) vs 풀튜닝(80GB)
- [ ] **데이터**: modality.json 작성, 카메라 키 일관성 확정, 파일럿 데이터 크기
- [ ] **ACT 비교 선행**: 모델이냐 데이터냐 결론 — GR00T 투자 전 근거 확보

## 9. 실행 로드맵

1. **(선행) ACT vs SmolVLA 롤아웃 비교** — 전환점 문제가 모델인지 데이터인지 판정.
   모델이면 GR00T 가치↑, 데이터면 먼저 시연 품질 개선.
2. 쿠폰 플랫폼·가용 GPU 확인 → 학습 GPU 확정(§3).
3. Isaac-GR00T 환경 구성(§6), 베이스 체크포인트 다운로드.
4. 핸드오프 데이터셋에 `modality.json` 추가, 로딩 검증(파일럿).
5. 클라우드 GPU에서 파인튜닝(§7, N1.5 기본).
6. 체크포인트 → 학교 서버로 배포, **ZMQ 추론 서버** 기동.
7. 로봇 노트북에서 **제어 클라이언트**로 롤아웃(§4), 지연·안전 확인.
8. 결과 평가 → 필요 시 N1.7/풀튜닝/데이터 보강.

## 10. 리스크·주의

- **GR00T는 만능이 아니다**: 전환점 문제의 근본이 데이터 품질이면 큰 모델도 그 애매함을
  학습한다. 반드시 ACT 비교로 원인부터 가른다.
- **추론 하드웨어가 실질 전제**: 학습은 쿠폰으로 공짜여도, 16GB+ 추론처가 없으면 못 쓴다.
  원격 서버 구조가 이걸 해결하되 네트워크 지연·두절 안전을 반드시 설계한다.
- **FFmpeg 8 금지**(TorchCodec 파손), 카메라 키 일관성, V100 불가 — 사소해 보이나 전부
  실패 지점이다.
- **공용 서버 조율**: 추론 중 서버 GPU 점유를 팀과 맞춘다.
