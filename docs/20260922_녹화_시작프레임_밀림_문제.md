# 녹화 영상이 에피소드 시작 동작부터 안 찍히는 문제

작성 2026-09-22. `lerobot-record`로 텔레옵 데이터를 모을 때 생긴 문제와 해결책을 정리한다.

## 증상

조작자는 항상 **에피소드가 시작되면 곧바로 시작 자세에서 동작을 시작**해서 끝 자세까지 마친 뒤 다음 에피소드로 넘어간다. 그런데 나중에 저장된 영상을 확인해보면, 몇몇 에피소드는 **동작이 이미 중간쯤 진행된 시점부터 영상이 시작**돼 있다 — 즉 시작 자세나 동작 초반부가 영상에서 통째로 빠져 있다.

## 원인

`lerobot-record` 명령에 `--dataset.streaming_encoding=true` 옵션이 켜져 있었기 때문이다.

이 옵션은 "녹화하면서 동시에 영상을 압축(인코딩)"하는 방식인데, 압축 엔진(SVT-AV1)이 매 에피소드마다 **처음 시작할 때 워밍업(준비 시간)이 필요**하다. 이 워밍업이 끝나기 전까지는 들어오는 화면을 제대로 못 받아서, 조작자는 이미 로봇을 움직이기 시작했는데 영상 녹화는 아직 준비 중인 상태가 된다. 그 결과 실제 동작 시작 시점과 영상에 찍힌 시작 시점이 어긋나서, 영상만 보면 "동작 중간부터 시작한 것처럼" 보이게 된다.

## 확인 방법

`--dataset.streaming_encoding=false`로 바꿔서 몇 개 에피소드를 다시 녹화해봤더니 증상이 사라졌다 — 원인이 맞다는 게 확인됐다.

## 해결책

`lerobot-record` 명령에 아래 옵션을 추가한다(기존엔 `true`였다면 `false`로 바꾼다):

```
--dataset.streaming_encoding=false
```

이러면 녹화 중엔 원본 화면만 그대로 저장해두고, **에피소드가 끝난 뒤에 한꺼번에 영상으로 압축**하는 방식으로 바뀐다. 인코더가 녹화 도중에 실시간으로 못 따라가서 초반 프레임을 놓치는 일이 없어진다.

## 부작용

기능적으로 문제되는 부작용은 없다. 다만 **에피소드가 끝난 뒤 다음 에피소드로 넘어가기 전에 인코딩하는 시간이 추가로 걸린다** — 녹화 자체가 실시간으로 압축까지 끝내던 것을, 끝나고 나서 따로 압축하는 것으로 바꿨기 때문이다. 데이터 양이 많을수록(에피소드가 길거나 카메라가 많을수록) 이 대기 시간이 좀 더 늘어날 수 있다. 데이터의 정확성(프레임이 실제 시점과 맞는지)에는 오히려 이쪽이 더 안전하다.

## 참고 — 추가로 같이 쓰면 좋은 안전장치

`streaming_encoding=false`로 근본 원인은 해결되지만, 혹시 모를 여유를 위해 "Recording episode N" 표시가 뜬 직후 바로 움직이지 말고 **시작 자세에서 0.3~0.5초 정도만 살짝 멈췄다가** 동작을 시작하는 습관을 들이면 더 안전하다. 다만 정지 구간이 너무 길면 학습 데이터 품질에 오히려 안 좋으니([`data/schema/에피소드_포함제외_기준.md`](../data/schema/에피소드_포함제외_기준.md) 참고), 짧게만 두는 게 좋다.
