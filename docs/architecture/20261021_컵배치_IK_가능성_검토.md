# 컵 테이블 배치를 IK로 할 수 있는가 (가능성 검토)

최초 작성 2026-10-21 · 조작(IL) 담당자 작성

## 0. 결론 (요약)

**가능하다. 그리고 이 구간은 오히려 IK가 맞는 자리다.** 단, 실물 정밀도는 아직 검증되지 않아서
작은 단계부터 실측으로 확인해야 한다.

- 팀 설계 문서([IK와 IL의 경계](20260903_IK_IL_경계와_결합.md))는 원래부터 **놓기(PLACE)를 IK 담당**으로
  정했다. 접촉이나 물성(붓기 유량 등)이 개입하지 않고 기하로 결정되는 구간이기 때문이다.
- 핸드오프 설계 덕분에 더 쉬워졌다. 컵배치가 시작될 때 **컵은 이미 왼손에 쥐어져 있다.** 그래서
  "컵이 어디 있는지 찾기"가 필요 없다. 지금 관절값(엔코더)에서 출발해 **들기 → 옮기기 → 내리기 →
  놓기**를 상대 이동으로 계산하면 된다.
- 저장소에 쓸 수 있는 IK 자산이 이미 있다. 2026-09-30에는 왼팔 **상대 IK로 컵 접근·닫기·15 mm 들기**를
  실물에서 실행했다(영상상 컵이 함께 올라감, 책상에서 완전히 떨어졌는지는 미확인).
- 남은 과제는 4가지다. ① 실물 위치 정밀도 미검증 ② 무거운 컵을 들 때 어깨가 처지는 문제
  ③ 그리퍼 보호 설정 때문에 컵이 미끄러질 위험 ④ 테이블 높이·위치를 로봇 기준으로 확정하기.

## 1. 판정 기준을 컵배치에 적용

팀 문서의 3문항에 모두 "예"면 IK가 맞다.

| 질문 | 컵배치의 답 | 근거 |
|---|---|---|
| 목표 자세를 좌표로 쓸 수 있는가 | **예** | 시작 = 지금 쥐고 있는 자세(엔코더로 앎). 끝 = 테이블 위 정한 지점 |
| 그 좌표가 매번 같거나, 한 번 재면 확정되는가 | **조건부 예** | 들기·내리기는 매번 같다. 테이블 위치는 **도킹(주차)이 매번 같은 곳에 서는지**에 달려 있다 |
| 실패해도 원인이 기하로 설명되는가 | **예** | 도달 범위, 충돌, 높이 오차로 설명된다 |

참고로 **물따르기는 IL을 유지**하는 게 맞다. 붓기는 물성(유량·잔량)이 개입하는 구간이라 팀 문서에서도
학습 비교 후보로 남겨뒀다.

## 2. 이 구간에서 IK가 유리한 이유

1. **데이터가 필요 없다.** 컵배치 시연 수집을 줄이거나 생략할 수 있어 시간이 절약된다.
2. **물이든 자갈이든 상관없다.** IK는 카메라로 판단하지 않으므로, 정책이 자갈 모습에 의존하던
   문제([causal confusion 기록](../experiments/20261021_물따르기_정책_자갈_시각의존_causal_confusion.md))가 생기지 않는다.
3. **망설임·떨림이 없다.** 같은 궤적을 매번 똑같이 재생한다. 천천히 매끄럽게 움직이게 할 수 있어
   컵 속 물이 덜 출렁인다.
4. **GPU 추론이 필요 없다.** 계산이 가벼워 로봇 노트북(8GB)에서 그대로 돈다. 큰 모델의 원격 추론 문제와 무관하다.
5. **재현·디버깅이 쉽다.** 실패하면 어느 관절이 어디서 어긋났는지 수치로 바로 보인다.

- 25 mm 수평 접근: 목표 ±3 tick 이내 도달
- 그리퍼 닫기: 추종 차이로 멈춤. 모터 닫힘값을 파지 성공으로 쓰지 않음

- 판정: **영상상 컵 동반 상승 확인, 책상 완전 분리 미확인.** 위치 정밀도·안정 운반·놓기는 미검증

## 4. 넘어야 할 것 (리스크)

**① 실물 위치 정밀도 미검증**
모델상 오차(0.3~0.5 mm)는 계산 모델 안의 오차일 뿐, 실제 손끝 위치 정확도가 아니다
(`physical_mapping_precision_verified=false`).
→ **절대 좌표보다 "지금 자세에서 얼마나 움직일지"(상대 이동)를 쓰면** 보정 오차의 영향이 줄어든다.
실제 이동량은 줄자로 대조한다.

**② 무거운 컵에서 어깨 처짐·미도달**
위치 게인 P16에서는 작은 목표에 도달하지 못하고 멈췄고, 멈춘 뒤 어깨가 3 tick 처지는 것도 관측됐다.
자갈이나 물을 담은 컵이면 더 심해질 수 있다.
→ 엔코더 피드백 실행기를 쓰고, **빈 컵 → 가득 찬 컵** 순서로 시험한다.

**③ 그리퍼 보호 설정으로 인한 미끄러짐**
보호 설정이 켜져 있으면 왼그리퍼는 최대 50% 힘만 쓰고, 과부하로 판단하면 25%로 떨어진다.
이번 세션에서 자갈 컵을 운반하다 실제로 놓쳤다.
→ 가득 찬 컵을 들고 운반하는 시험을 먼저 한다. 설정을 바꾸면 IL 쪽과 같은 값으로 맞춘다.

**④ 테이블 위치·높이**
놓을 지점은 로봇 기준 좌표다. 그래서 도킹이 매번 같은 곳에 서야 하고, 테이블 높이는 줄자로 확정한다
(CLAUDE.md: 기하는 실물 대조로 확정).
→ 높이 오차에 대비해 **테이블 근처까지는 빠르게, 그다음은 천천히 내리면서 닿는 순간을 감지**한다.
닿으면 내려가지 못해 위치 오차가 커지므로, 그 신호로 정지 후 그리퍼를 연다.
이동 실패(스톨)를 감지하면 반드시 정지 명령을 보낸다(CLAUDE.md 안전 규칙).

**⑤ 컵 직립 유지**
SO-101은 팔 관절이 5축이다. **위치 3 + 축방향 2 = 5구속**으로 풀면 컵을 세운 채 옮길 수 있다
(팀 문서 4.1 방식). 손목 roll은 가동 범위 안에 드는 분기(약 +92.8°)를 쓴다.

**⑥ 충돌**
차체 상판, 오른팔, 테이블 모서리와 부딪힐 수 있다.
→ 옮기는 경로는 미리 계산·검증한 웨이포인트만 재생한다(팀 문서 4.2).

**⑦ 보정 변경 이력**
관절 규약·보정이 바뀐 이력이 있다. IK는 **현재 활성 보정 파일과 같은 것**으로 계산하고,
보정이 바뀌면 다시 검증한다.

## 5. 제안 실행 순서 (컵배치 IK 시퀀스)

0. **시작 조건:** 물따르기 정책이 끝난 상태. 컵이 상판 위에 있고 왼팔이 살짝 쥐고 있으며, 팔이 정지해 있다.
   (팀 문서 전이 규약: **IL이 끝나는 상태 = IK가 시작하는 상태**, 전환은 정지 상태에서만)
1. **재파지:** 그리퍼를 세게 닫는다. 팔 위치는 그대로.
2. **수직 들기:** 상대 IK로 +30~50 mm 위로. 컵은 세운 채.
3. **운반:** 미리 검증한 웨이포인트로 테이블 위 지점까지 이동. 상판·오른팔은 피한다.
4. **내리기:** 테이블 높이 + 여유까지는 보통 속도로, 그 아래는 천천히 내리며 닿는 순간을 감지한다.
5. **놓기:** 그리퍼를 연다.
6. **빼기:** 위로 올린 뒤 대기 자세로 복귀한다.

조작 중에는 차체가 정지해 있어야 한다(팀 안전 게이트 `base_motion_during_manipulation: prohibited`).

## 6. 검증 순서 (작게 시작)

1. **오프라인:** 위 시퀀스의 관절 목표를 계산하고, 가동 범위·자가충돌·상판/테이블 간섭을 검사한다. 팔은 움직이지 않는다.
2. **빈 컵, 들기만:** 30 mm 들기를 실행하고 실제 상승 높이를 줄자로 잰다.
3. **가득 찬 컵, 들기 + 짧은 운반:** 어깨 처짐과 미끄러짐을 확인한다.
4. **테이블에 놓기:** 닿음 감지 → 정지 → 열기가 되는지 확인한다.
5. **전체 시퀀스 반복:** 같은 조건 3회 + 컵 위치·도킹을 바꾼 조건 3회. 성공 수치는 조건과 함께 적는다(CLAUDE.md).

팔을 움직이는 단계(2~5)는 모두 사용자 확인 후 실행한다.

## 7. 시간을 고려한 권고

- **컵배치는 IK를 메인 후보로 시험한다.** 데이터·GPU가 필요 없고, 물/자갈 문제와 망설임 문제가 동시에 사라진다.
- **물따르기는 IL을 유지한다.** 붓기의 끝 판단은 시연 방식 개선([시연 가이드](../guides/20261021_핸드오프_시연_가이드_쉬운설명.md))으로 보완하고,
  필요하면 붓기 구간만 코드가 맡는 롤아웃 hook(미구현)을 추가한다.
- **컵배치 데이터는 일단 계속 모은다.** 지금 녹화 스크립트는 한 라운드에 두 task를 같이 찍으므로 추가 비용이 작다.
  IK 검증이 1~4단계를 통과하면 IK를 채택하고, 막히면 IL을 대안으로 쓴다.
