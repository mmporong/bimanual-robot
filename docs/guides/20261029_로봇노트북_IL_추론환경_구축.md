# 로봇 탑재 노트북 IL 추론 환경 구축 (Claude Code 실행용)

2026-10-29 작성. 로봇 차체에 싣는 **새 Windows 노트북**에서 양팔 정책(운용 SmolVLA 80, 평가용 GR00T·ACT)을 실물로 추론할 수 있게 만드는 절차다.
기존 IL 노트북(사용자 이름 `USER`)에서 실제로 쓰던 경로·버전·명령을 그대로 옮겼다.

> **이 문서를 받은 Claude Code에게**
> - 위에서부터 순서대로 수행하고, 각 단계의 **확인** 항목이 통과해야 다음 단계로 간다.
> - 🙋 표시는 사용자가 직접 해야 하는 일이다(설치 마법사, 케이블 연결, 눈으로 확인). 사용자에게 정확히 무엇을 할지 알려 주고, 끝났다고 답하면 확인 명령으로 검증한다.
> - 답변은 **한국어**로 한다.

> **운용 모델: SmolVLA 80 (2026-10-29 확정)**
> - 물따르기 `jun-seo/water_pour_chassis_smolvla_80_16000S`, 컵배치 `jun-seo/cup_place_chassis_smolvla_80_7000S`. 둘 다 HF **비공개**라 4-4 로그인이 필요하다.
> - 로봇 운용은 두 정책을 미리 올려 두고 호출하면 바로 실행하는 **상주형 실행기**(8-4)로 한다. 단건 실행(8-2)은 점검·디버깅용이다.
> - GR00T·ACT와 다른 데이터 수 모델은 평가용 선택 사항이다. 시간이 없으면 건너뛴다.

## 0. 꼭 지킬 규칙

저장소 [CLAUDE.md](../../CLAUDE.md)가 기준이다. 이 작업에서 특히 중요한 것만 적는다.

- **팔을 움직이는 모든 동작은 실행 전에 사용자 확인을 받는다.**
  - 대상: 롤아웃, `save_start_pose.py`, 토크 ON, 캘리브레이션
  - 읽기 진단(포트 열기·관절 값 읽기)만 예외다.
  - 롤아웃 명령은 사용자에게 보여 주고, 사용자가 직접 실행하게 하는 것을 기본으로 한다.
- 팔이 이상하게 움직이거나 토크가 걸린 채 멈추면 `python tools/rollout/emergency_torque_off.py`로 토크만 끈다. 이 스크립트는 팔을 움직이지 않는다.
- **HuggingFace의 데이터·모델은 절대 삭제하거나 덮어쓰지 않는다.** 받기만 한다.
- 커밋·푸시는 사용자에게 먼저 묻는다. 스테이징은 파일 단위로만 한다(`git add .`·`-A` 금지).
- 이 노트북에만 해당하는 값(COM 번호, 카메라 경로, 사용자 이름이 들어간 경로)을 코드에서 바꿨다면, 커밋하기 전에 사용자에게 물어본다. 기존 IL 노트북 설정을 덮어쓰게 되기 때문이다.
- 실패하면 [CLAUDE.md](../../CLAUDE.md)의 L1 하드웨어·연결 → L2 좌표 → L3 로직 → L4 데이터 순서로 원인을 좁힌다. 모델 탓은 마지막에 의심한다.

## 2. 사전 확인

PowerShell에서 실행한다. 여러 줄 파이썬은 `@' ... '@ | & $PY -`처럼 표준 입력으로 넘긴다(스크립트 안에는 한글을 넣지 않는다. PowerShell 5.1이 파이프로 넘길 때 깨진다).

```powershell
nvidia-smi                                   # GPU 이름, 메모리, 드라이버 버전
(Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory / 1GB   # RAM(GB)
$env:USERNAME                                 # 윈도우 사용자 이름
Get-PSDrive C | Select-Object Used,Free       # 남은 디스크
```

| 항목 | 기준 | 미달이면 |
|---|---|---|
| GPU 메모리 | 운용(SmolVLA 80 두 개 상주) 약 2.6GB라 **6GB 이상이면 충분**. GR00T(평가용 선택)는 8GB 이상 필요(실사용 6.4GB) | 6GB 미만이면 사용자에게 알린다. 8GB 미만이면 GR00T는 받지 않는다 |
| NVIDIA 드라이버 | CUDA 12.8 지원(570 이상). `nvidia-smi` 오른쪽 위 `CUDA Version`이 12.8 이상 | 🙋 사용자가 NVIDIA 드라이버를 업데이트한다 |
| RAM | 32GB 권장. GR00T를 불러올 때 CPU 메모리를 많이 쓴다 | 16GB면 GR00T 로딩이 실패할 수 있다(9절 참조) |
| 디스크 | 여유 60GB 이상 | GR00T 80 모델 2개만 해도 24GB, 기본 모델 6.5GB, 환경 약 10GB |
| 사용자 이름 | `USER`면 아래 경로를 그대로 쓴다 | 다르면 5-3절의 하드코딩 경로를 바꾼다 |

이 문서에서 쓰는 경로 표기는 다음과 같다. 사용자 이름이 `USER`가 아니면 모두 실제 이름으로 바꿔 읽는다.
- `<REPO>` = `C:\Users\<사용자>\Desktop\프로젝트\최종프로젝트\bimanual-robot-git` (권장 위치)
- `<LEROBOT>` = `C:\Users\<사용자>\Desktop\so101-mobile-manipulation-main\lerobot` (기존 노트북과 같은 위치)
- `<PY>` = `C:\Users\<사용자>\miniconda3\envs\so101_env\python.exe`
- `<OUTPUTS>` = `C:\Users\<사용자>\lerobot-training\outputs`

## 3. 🙋 사용자가 먼저 설치·준비할 것

Claude Code가 대신할 수 없는 일이다. 아래 목록을 사용자에게 보여 주고, 끝났는지 하나씩 확인한다.

1. **Git for Windows**: https://git-scm.com/download/win
2. **Miniconda** (64-bit): https://docs.conda.io/en/latest/miniconda.html. 기본 위치인 `C:\Users\<사용자>\miniconda3`에 설치한다.
3. **NVIDIA 드라이버**: 2절 기준에 맞춘다.
4. **OBS Studio**: https://obsproject.com. 설치만 하면 되고 실행할 필요는 없다. Astra 영상을 내보낼 가상 카메라 드라이버를 등록하는 용도다.
5. **Astra 파일 2개를 기존 노트북에서 USB로 복사**한다. 둘 다 기존 노트북의 `C:\Users\USER\Downloads\` 안에 있다.
   - `AstraSDK-v2.1.3-94bca0f52e-20210608T034051Z-vs2015-win64` 폴더 → 새 노트북의 `C:\Users\<사용자>\Downloads\`에 그대로 둔다.
   - `astra-win32-driver-4.3.0.22` 폴더 → 안의 `astra-win32-driver-4.3.0.22\SensorDriver_V4.3.0.22.exe`를 실행해 드라이버를 설치한다.
6. **하드웨어 연결**: 왼팔·오른팔 USB, 손목 카메라 2개, Astra를 꽂는다.
   - 팔 전원도 켠다. 팔 전원이 꺼져 있으면 COM 포트는 잡혀도 모터 응답이 없다.

## 5. 모델 받기

### 5-1. 모델 목록
HF 이름 규칙은 `jun-seo/<과제>_chassis_<모델>_<데이터 수>_<step>S`이다. 각 모델은 아래 로컬 폴더에 받는다.
`<OUTPUTS>\<과제>_chassis_<모델>_<데이터 수>\checkpoints\<step 6자리>\pretrained_model`

| 모델 | 과제 | 80 | 60 | 40 | 20 |
|---|---|---|---|---|---|
| GR00T | water_pour | 17500 | 12000 | 8500 | 4000 |
| GR00T | cup_place | 13000 | 6000 | 4500 | 1500 |
| SmolVLA | water_pour | 16000 | 12500 | 7000 | 4000 |
| SmolVLA | cup_place | 7000 | 7000 | 3000 | 500 |
| ACT | water_pour | 8500 | 10000 | 7500 | 4000 |
| ACT | cup_place | 3500 | 5500 | 7000 | 2500 |

(최적 step 근거: [32개 모델 학습 결과 종합](../experiments/20261028_차체결합_32개모델_학습결과_종합.md). π0는 노트북 GPU에 들어가지 않아 실물 평가에서 제외했다.)

**우선순위**
1. **필수: SmolVLA 80 두 개**(물따르기 16000, 컵배치 7000). 로봇 운용 모델이다.
2. 선택(평가용): GR00T·ACT 80, SmolVLA 20·40·60. 사용자가 요청할 때만 받는다.

크기는 GR00T 하나가 약 12GB, SmolVLA 1.2GB, ACT 0.2GB다.

### 5-2. 받기 명령
5-1의 표를 아래 `$list`에 옮겨 적고 실행한다. 이미 받은 폴더는 건너뛴다.
```powershell
$HF = "$env:USERPROFILE\miniconda3\envs\so101_env\Scripts\hf.exe"
```

### 5-3. ⚠️ SmolVLA 토크나이저 경로 고치기 (필수)
학교 서버에서 학습한 SmolVLA는 `policy_preprocessor.json`에 `"tokenizer_name": "tokenizer"`라는 **상대 경로**를 저장한다. 그대로 실행하면 다음 오류로 바로 멈춘다.
```
ValueError: Failed to instantiate processor step 'tokenizer_processor' ... tokenizer is not a local folder and is not a valid model identifier
```
아래 스크립트는 모든 모델 폴더를 돌면서 다음을 처리한다. 원본은 `.bak`으로 남긴다.
- 상대 경로로 적힌 토크나이저 경로를 같은 폴더 안 `tokenizer` 폴더의 절대 경로로 바꾼다.
- 다른 노트북(예: `C:\Users\USER\...`)의 절대 경로가 적혀 있어도 이 노트북 경로로 바꾼다.

```powershell
@'
import json, os, shutil
from pathlib import Path
out = Path(os.environ["USERPROFILE"]) / "lerobot-training" / "outputs"
for pre in out.glob("*/checkpoints/*/pretrained_model/policy_preprocessor.json"):
    tok = pre.parent / "tokenizer"
    data = json.loads(pre.read_text(encoding="utf-8"))
    changed = False
    for step in data.get("steps", []):
        for part in ("config", "artifacts"):
            d = step.get(part) or {}
            name = d.get("tokenizer_name")
            if name and tok.is_dir() and Path(name) != tok and not Path(name).is_dir():
                d["tokenizer_name"] = tok.as_posix()
                changed = True
    if changed:
        bak = pre.with_name(pre.name + ".bak")
        if not bak.exists():
            shutil.copy2(pre, bak)
        pre.write_text(json.dumps(data, indent=4, ensure_ascii=False), encoding="utf-8")
        print("fixed", pre.parent)
print("done")
'@ | & $PY -
```
GR00T·ACT 폴더에는 `tokenizer` 폴더가 없으므로 이 스크립트가 건드리지 않는다.

**확인**: 전처리 파이프라인이 모든 모델에서 뜨는지 본다. 로봇은 필요 없다.
```powershell
@'
import os
from pathlib import Path
from lerobot.configs.policies import PreTrainedConfig
from lerobot.policies.factory import make_pre_post_processors
out = Path(os.environ["USERPROFILE"]) / "lerobot-training" / "outputs"
for p in sorted(out.glob("*/checkpoints/*/pretrained_model")):
    if "_pi0_" in str(p):
        continue
    cfg = PreTrainedConfig.from_pretrained(str(p)); cfg.pretrained_path = str(p)
    make_pre_post_processors(cfg, pretrained_path=str(p))
    print("OK", p.parents[2].name, p.parent.name)
'@ | & $PY -
```

## 7. 로봇 없이 모델 점검
팔을 연결하지 않고 모델만 GPU에 올려 추론이 되는지 본다. 롤아웃 전에 반드시 한다.

```powershell
cd <REPO>
@'
import os, sys, time, torch
from pathlib import Path
sys.path.insert(0, r"tools\rollout")
import rollout_handoff as rh
from lerobot.configs.policies import PreTrainedConfig
from lerobot.policies.factory import make_pre_post_processors
from lerobot.rollout.context import _load_pretrained_policy
rh.install_groot_bf16()  # patches GrootPolicy only; call once
out = Path(os.environ["USERPROFILE"]) / "lerobot-training" / "outputs"
for path in sorted(out.glob("*_80/checkpoints/*/pretrained_model")):
    path = str(path)
    if "_pi0_" in path:
        continue
    cfg = PreTrainedConfig.from_pretrained(path); cfg.device = "cuda"; cfg.pretrained_path = path
    t = time.time(); policy = _load_pretrained_policy(cfg).eval(); load_s = time.time() - t
    pre, post = make_pre_post_processors(cfg, pretrained_path=path)
    obs = {k: (torch.rand(f.shape) if k.startswith("observation.images") else torch.zeros(f.shape)) for k, f in cfg.input_features.items()}
    obs["task"] = "test"
    for i in range(2):
        policy.reset(); torch.cuda.synchronize(); s = time.time()
        with torch.inference_mode():
            a = post(policy.select_action(pre(dict(obs))))
        torch.cuda.synchronize()
        print(f"{Path(path).parents[2].name}: load {load_s:.0f}s infer{i} {time.time() - s:.2f}s shape {tuple(a.shape)} finite {bool(torch.isfinite(a).all())} GPU {torch.cuda.max_memory_allocated() / 1e9:.2f}GB")
    del policy; torch.cuda.empty_cache(); torch.cuda.reset_peak_memory_stats()
'@ | & $PY -
```
기존 노트북(RTX 5050 8GB)에서 2026-10-29에 이 스크립트를 그대로 돌린 결과다.

| 모델 | GPU 메모리 | 추론 1회(두 번째부터) | 출력 |
|---|---|---|---|
| GR00T | 6.3~6.4GB | 0.45~0.58초 (첫 회 7~11초) | `(1, 12)`, finite True |
| SmolVLA | 약 1.3GB | 0.8~0.9초 (50스텝 묶음을 한 번에 계산) | `(1, 12)` |
| ACT | 0.3GB | 0.05초 (첫 회는 수 초) | `(1, 12)` |

- GR00T를 처음 실행하면 `nvidia/GR00T-N1.7-3B`(약 6.5GB)를 받느라 오래 걸린다.
- GR00T가 `[groot] bf16으로 불러옴 (GPU 6.31GB)`를 출력하면 정상이다.

### 8-2. 단건 실행 명령 (점검·디버깅용)

컵배치:

- `{left}`, `{right}`, `{depth}`는 **그대로 둔다.** 래퍼가 실행할 때 실제 번호로 바꿔 넣는다.
- `--task` 문장은 학습 때와 **글자 하나까지 같아야** 한다. 바꾸지 않는다.
- 평가 시트 회차별 명령은 `& "<PY>" tools\eval\eval_sheet.py cmd A-P01`로 출력할 수 있다. 5-4의 경로 수정이 먼저 돼 있어야 한다.
- 주요 옵션(자세한 설명은 `rollout_handoff.py` 맨 위 설명):
  - `--start.pose=pour`: 추론 전에 저장된 시작 자세로 이동한다.
  - `--end.pose=final|place_end|initial`: 끝난 뒤 자세를 정한다.
  - `--end.auto=pour|place`: 작업 끝을 자동으로 감지한다. `--duration`은 최대 시간(안전 상한)으로만 쓰인다.
  - `--display_data=false`: rerun 화면을 끈다. 메모리가 빠듯할 때 쓴다.
  - `--groot.fp32`: GR00T bf16 로딩을 끈다. 쓰지 않는다.

### 8-3. 실행 중 정상 로그
```
[camera resolve] left=1 right=0 depth=3
[grip] left(COM15) 실행 전: ...
[end] 끝 자세 = place_end, 자동 종료 = place
```

- 단건 실행은 매번 라이브러리·모델 로드와 팔·카메라 연결을 새로 해서 실제로 움직이기까지 1분 넘게 걸린다. 운용은 8-4로 한다.

### 8-4. 운용: 상주형 실행기 (SmolVLA 80 두 개를 미리 올려 둠)

```powershell
cd <REPO>
& "<PY>" tools\rollout\rollout_service.py --pour.policy="<OUTPUTS>\water_pour_chassis_smolvla_80\checkpoints\016000\pretrained_model" --place.policy="<OUTPUTS>\cup_place_chassis_smolvla_80\checkpoints\007000\pretrained_model" --stow.pose=place_end --policy.device=cuda --robot.type=bi_so_follower --robot.id=arms --robot.calibration_dir=calibration\bi_follower --robot.left_arm_config.port=COM15 --robot.left_arm_config.gripper_protection=true --robot.left_arm_config.disable_torque_on_disconnect=false --robot.left_arm_config.max_relative_target=15 --robot.left_arm_config.cameras="{ wrist: {type: opencv, index_or_path: {left}, width: 640, height: 480, fps: 30} }" --robot.right_arm_config.port=COM16 --robot.right_arm_config.disable_torque_on_disconnect=false --robot.right_arm_config.max_relative_target=15 --robot.right_arm_config.cameras="{ wrist: {type: opencv, index_or_path: {right}, width: 640, height: 480, fps: 30} }" --robot.cameras="{ top: {type: opencv, index_or_path: {depth}, width: 640, height: 480, fps: 30, mirror: true} }"
```
- `--policy.path`·`--task`·`--duration`·`--strategy.type`은 **넣지 않는다.** 작업별 task 문장과 시작·끝 자세, 자동 종료는 실행기에 기본값으로 들어 있다.
  - pour: 시작 `pour`, 끝 `final`, 100초
  - place: 끝 `place_end`, 50초
- 정책·task·시작/끝 자세·자동 종료·`max_relative_target=15`는 8-2 단건 명령과 같다. 끝 자세 판정 허용치도 기본 10°로 같다.
- `--stow.pose=place_end`는 이동 중 팔 자세다. 주문 시작 때 양팔을 접고, 물따르기 뒤 오른팔을 접는다([상주형 실행기 사용법](20261026_상주형_조작실행기_사용법.md) 7절).
- 실제 시연은 이 명령 대신 `tools\rollout\start_scenario.bat`(실행기 + 주문 서버)으로 켜고 [최종 시연 운영 절차](20261029_최종시연_운영절차.md)를 따른다. 사용자 이름·COM이 다르면 bat 맨 위 `set` 줄을 고친다.

**호출** (다른 PowerShell 창. 🙋 팔이 움직이므로 사용자 확인 후, 바퀴가 멈춘 상태에서):
```powershell
cd <REPO>
& "<PY>" tools\rollout\rollout_service.py status        # 상태가 ready인지 확인
& "<PY>" tools\rollout\rollout_service.py call pour     # 물따르기, 끝날 때까지 기다렸다 결과 출력
& "<PY>" tools\rollout\rollout_service.py call place    # 컵배치
& "<PY>" tools\rollout\rollout_service.py stop          # 진행 중 작업 중단(팔은 그 자리 유지)
& "<PY>" tools\rollout\rollout_service.py shutdown      # 연결 끊고 종료
```
- HTTP로도 같다: `POST http://127.0.0.1:8770/run/pour`, `/run/place`, `GET /status`.
- 미션 쪽 `src/mission/service_execution_backend.py`와 주문 웹 서버(`--manip-url`)가 이 주소를 부른다.
- 결과 JSON의 `reason`이 `auto_done`이면 작업 끝을 감지한 것이다. `duration`이면 시간 초과이므로 성공 여부는 사람이 본다.

⚠️ **상주형 실행기는 2026-10-26에 하드웨어 없이만 검증했다. 실물에서는 이 노트북이 처음이다.** 첫 실물 실행 때 확인할 것:
1. 준비 시간과 GPU 메모리(약 2.6GB 예상)
2. `call pour`의 `call_to_first_action_s`
3. 두 작업을 이어서 호출했을 때 팔·카메라 연결이 유지되는지
4. 단건 실행(8-2)과 동작이 같은지

결과는 사용자에게 보고하고 PROGRESS.md에 남긴다.

## 9. 문제 해결 (기존 노트북에서 실제로 겪은 것)

| 증상 | 원인 | 조치 |
|---|---|---|
| `ImportError: ... 'diffusers'` (GR00T) | GR00T 의존 패키지 누락 | `pip install "diffusers>=0.38.0,<0.40.0" "peft>=0.18.0,<1.0.0" "timm>=1.0.0,<1.1.0" "dm-tree>=0.1.8,<1.0.0"` |
| GR00T 로딩 중 아무 말 없이 종료. 이벤트 로그에 `python.exe` / `torch_cpu.dll` / `0xc0000005`. 또는 `OSError: ... (os error 1455)` | 커밋 메모리(RAM + 페이징 파일) 부족 | 이미 고친 래퍼(2026-10-29, 한 텐서씩 bf16 로딩)를 쓰는지 확인한다. 그래도 나면 다른 프로그램과 이전 rerun 창을 닫고, `--display_data=false`로 실행하고, 🙋 페이징 파일을 늘린다(시스템 속성 → 고급 → 성능 → 가상 메모리) |
| 마지막 줄이 `re_grpc_server: Error while receiving messages: h2 protocol error` | 본체가 죽으면서 rerun 연결이 끊긴 결과다 | 이 줄은 원인이 아니다. 위쪽 로그와 Windows 이벤트 로그(응용 프로그램)를 본다 |
| `tokenizer is not a local folder ...` | SmolVLA 토크나이저 상대 경로 | 5-3 스크립트를 실행한다 |
| `401 Client Error` (HF 다운로드) | 비공개 저장소, 미로그인 | 4-4를 한다 |
| `Could not open ... Failed to send a USB control request` (Astra) | Astra USB 통신 꼬임 | 6-2의 조치를 한다 |
| `[camera resolve]`에서 left/right 누락 | 손목 카메라 USB 경로가 힌트와 다름 | 6-3을 다시 한다 |
| 연결 시 `Missing motor ID 6` | 그리퍼 과부하 보호 | 래퍼가 실행 전에 자동으로 푼다. 그래도 나면 `emergency_torque_off.py`로 토크를 끈 뒤 다시 실행한다 |
| 실행 직후 `patch does not apply` (4-2) | lerobot을 CRLF로 받음 | `core.autocrlf=false`로 다시 받는다 |
| 상단 영상 좌우가 학습과 반대 | `mirror` 패치 미적용 또는 옵션 누락 | 4-3 마지막 확인과 `mirror: true` 옵션을 본다 |
