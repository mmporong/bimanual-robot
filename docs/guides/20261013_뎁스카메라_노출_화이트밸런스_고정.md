# 뎁스카메라(Astra S) 노출·화이트밸런스 고정 — 반드시 추론 때도 동일 적용

최초 작성 2026-10-13 · 조작(IL) 담당자 작성

## 0. 한 줄 요약

**데이터 수집용 카메라의 노출·화이트밸런스를 "자동"이 아니라 "고정값"으로 쓴다.
이 설정은 데이터 수집과 평가·추론(실제 로봇이 혼자 움직일 때) 양쪽에서
반드시 동일하게 적용해야 한다** — 다르면 그 자체가 학습-추론 불일치(train/inference
mismatch)를 새로 만든다.

## 1. 왜 고정하는가

- 자동 노출/화이트밸런스는 조명이 실제로 안 바뀌어도 카메라가 스스로 밝기·색감을
  미세하게 흔든다(hunting). 이건 "진짜 환경 다양성"이 아니라 카메라 자체가 만드는
  잡음이라, 학습에 넣어도 실제 조명 변화에 대한 강건성을 키워주지 못한다.
- 반대로 고정값을 쓰면 매 에피소드가 같은 조건으로 찍혀서 더 안정적인 데이터가
  된다. 실제로 조명이 날짜별로 달라지는 상황이 생긴다면, 고정 노출 쪽이 그 변화를
  보정해서 지워버리지 않고 데이터에 그대로 남겨주기 때문에 오히려 더 정직하다.

## 2. 왜 "추론 때도 똑같이"가 핵심 조건인가

노출/화이트밸런스는 과제(위치처럼) 자체의 변수가 아니라 **우리가 통제하는 카메라
파이프라인 설정**이다. 학습 때와 추론 때 설정이 다르면, 로봇은 학습 때 한 번도
못 본 방식으로 찍힌 영상을 보게 되는 것과 같다 — 이건 "진짜 다양성"이 아니라
그냥 불일치다. 그래서 설정 자체를 다르게 두는 게 문제가 아니라, **양쪽에서
다르게 쓰는 것**이 문제다.

## 3. 적용 위치

`tools/camera/astra_rgb_virtualcam_bridge.py` — Astra 컬러 스트림을 시작한 뒤
워밍업 프레임을 흘려보내고(현재 조명에 오토 설정이 수렴하도록), 그 다음
`color_stream.camera.auto_exposure = False`, `auto_white_balance = False`로
고정한다. (OpenNI2의 `CameraSettings` API, `primesense` 파이썬 패키지로 접근.)

이 스크립트가 실행될 때마다 콘솔에 고정된 `gain`, `exposure` 값을 출력한다.
**데이터 수집 세션과 평가 세션 모두 이 스크립트(또는 동일한 고정 로직)를 거친
가상 카메라를 써야 한다** — bridge를 거치지 않고 Astra를 다른 방식으로 직접
붙이면 이 고정이 적용 안 된다.

## 4. 조명이 실제로 바뀌면 어떻게 하나

촬영 세션이 여러 날에 걸쳐 진행돼 실내 조명이 눈에 띄게 달라졌다면:
- 값을 다시 고정하지 말고(세션마다 값이 바뀌면 그것도 또 다른 불일치가 된다),
  **가능하면 물리적으로 조명 조건 자체를 이전 세션과 비슷하게 맞춘다**(커튼,
  조명 켬/끔 등).
- 그래도 달라질 수밖에 없다면, 그건 "의도치 않은 변수가 하나 더 섞였다"는
  뜻이므로 이 문서에 그 사실과 날짜를 기록해두고, 나중에 평가 결과가 이상하면
  이 가능성부터 의심한다(이 저장소 실패 원인 귀속 규칙상 L4/L5에 해당할 수 있음).

## 5. 체크리스트

- [ ] 데이터 수집 시작 전: bridge 스크립트 콘솔 로그에 "노출/화이트밸런스 고정
  완료" 메시지가 찍혔는지 확인.
- [ ] 평가(4단계) 시작 전: 수집 때와 **동일한** bridge/고정 설정으로 카메라가
  떠 있는지 확인 — 수집 이후 bridge를 껐다 켰다면 자동으로 다시 워밍업+고정을
  거치므로 값이 완전히 똑같지 않을 수 있다. 크게 다르면(영상이 눈에 띄게
  밝기/색감 차이) 재확인한다.
- [ ] 여러 날에 걸쳐 수집한다면, 매 세션 시작 시 이 문서에 날짜·고정값(또는
  "조명 동일하게 유지함")을 한 줄 추가해 기록한다.
