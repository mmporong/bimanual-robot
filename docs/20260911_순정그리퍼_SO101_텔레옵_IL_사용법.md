# 텔레옵 · IL 녹화 사용법 — SO-101 + 순정 그리퍼 (두 번째 팔)

작성 2026-09-11. 이 문서만 보고 **보드 찾기 → 캘리브레이션 → 텔레옵 → 녹화 → 학습**까지 가도록 쓴다.

ggao50 평행 그리퍼를 단 팔은 [`20260910_텔레옵_IL_사용법.md`](20260910_텔레옵_IL_사용법.md)가 따로 있다.
두 문서를 섞어 쓰면 안 된다. 그리퍼 방향과 보호 설정이 정반대다.

## 0. ggao50 문서와 다른 점 — 먼저 이것만

| 항목 | ggao50 팔 | 순정 그리퍼 팔 (이 문서) |
|---|---|---|
| 팔로워 보드 | `5B3D046653` | **`5B3E088747`** |
| 리더 보드 | `5B3D047908` | **`5B61032979`** |
| 그리퍼 서보(ID 6) Phase | 76 (개체 특례) | **12 (공장값 그대로)** |
| 그리퍼 ID 6 한계 | 763 ~ 3600 | **1409 ~ 2784** |
| 캘리브레이션 `drive_mode` | 1 (방향 반전) | **0 (반전 없음)** |
| lerobot 그리퍼 보호 | 끈다 | **켠다 — `--robot.gripper_protection=true`** |
| 캘리브레이션 JSON | `calibration/so_follower`, `so_leader` | **`calibration/so_follower_stock`, `so_leader_b`** |

세 번째 줄이 제일 중요하다. **이 팔의 서보 Phase 를 76 으로 바꾸지 않는다.** 76 은 ggao50 팔의
ID 6 개체에만 해당하는 값이고, 그 경위는 [`20260909_그리퍼_서보_Phase반전_사고분석.md`](20260909_그리퍼_서보_Phase반전_사고분석.md)에 있다.
순정 서보는 공장값 12 가 정답이다.

## 1. 준비물

| 항목 | 값 |
|---|---|
| 팔로워 보드 | `/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3E088747-if00` (12 V) |
| 리더 보드 | `/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B61032979-if00` (7.6 V) |
| 파이썬 | `~/miniforge3/envs/lerobot/bin/python` (lerobot 0.6.1, `~/lerobot` 소스 설치) |
| 서보 도구 | `~/bimanual-robot/tools/servo/` (시스템 python3 + pyserial) |
| 캘리브레이션 JSON | `calibration/so_follower_stock/follower_stock.json`, `calibration/so_leader_b/leader_b.json` — **2절에서 처음 만든다** |

### 보드 대응표 (2026-09-09 실측)

| 시리얼 | 전압 | 정체 | ID 6 한계 |
|---|---|---|---|
| `5B3D046653` | 12 V | ggao50 그리퍼 팔로워 | 763 ~ 3600 |
| `5B3E088747` | 12 V | **팔로워 (순정 그리퍼) — 이 문서** | 1409 ~ 2784 |
| `5B3D047908` | 7.7 V | 리더 (ggao50 쌍) | 2047 ~ 3308 |
| `5B61032979` | 7.6 V | **리더 — 이 문서** | 1131 ~ 2373 |
| `5B3D041998` | — | 사망 (2026-09-09) | — |

`ttyACM0` 같은 번호를 고정하지 않는다. 꽂는 순서로 번호가 바뀐다. 항상 by-id 경로를 쓴다.
네 보드를 다 꽂으면 by-id 에 네 줄이 뜨므로 시리얼로 고른다. 서보 도구는 `--port` 를 생략하면
자동 탐색하지만, 보드가 둘 이상이면 목록만 보여주고 멈춘다. 이 구성에서는 **항상 `--port` 를 준다.**

계정이 `dialout` 그룹에 있어야 한다. `sudo` 는 쓰지 않는다.

```bash
cd ~/bimanual-robot/tools/servo
F=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3E088747-if00     # 팔로워 12 V
L=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B61032979-if00     # 리더 7.6 V
ls -l /dev/serial/by-id/
```

## 2. 캘리브레이션 — 이 팔은 JSON 이 아직 없다

ggao50 팔과 달리 이 쌍은 lerobot 이 읽는 JSON 이 리포에 없다. 서보 EEPROM 에는 오프셋과 한계가
들어 있지만, lerobot 은 관절별 범위가 적힌 JSON 을 따로 본다. 그래서 **처음 한 번은 직접 만든다.**

lerobot 의 `lerobot-calibrate` 는 이 버스에서 범위가 오염된다(깨진 패킷이 MIN 0 / MAX 4095 로 박힌다).
같은 절차에 검증을 붙인 도구가 `tools/servo/` 에 있고, 결과 JSON 은 lerobot 형식과 같다.

**한 팔씩 한다.** 아래는 팔로워 기준이고 리더는 포트와 JSON 경로만 바꾼다.

```bash
mkdir -p ~/bimanual-robot/calibration/so_follower_stock ~/bimanual-robot/calibration/so_leader_b
JF=~/bimanual-robot/calibration/so_follower_stock/follower_stock.json
JL=~/bimanual-robot/calibration/so_leader_b/leader_b.json
```

### ① 서보 상태부터 읽는다 (이동 없음)

```bash
python3 servo_read.py --port $F                 # 1~6번 위치·한계·온도·구동 상태
```

여섯 줄이 다 뜨고 무응답이 없어야 한다. ID 6 한계가 1409 ~ 2784 근처면 순정 그리퍼 보드가 맞다.

Phase(18번)는 전용 도구가 없으므로 버스에서 직접 읽는다. 이동 명령이 아니라 읽기다.

```bash
python3 -c "
import sts_bus
b = sts_bus.Bus('$F')
for sid in range(1, 7):
    print(sid, 'Phase =', b.read(sid, 18))
"
```

**여섯 개 모두 12 여야 한다.** 12 가 아닌 개체가 있으면 누군가 만진 것이므로, 원인을 확인하기
전에 진행하지 않는다. ggao50 팔의 ID 6 이 76 인 것은 그 개체에만 해당하는 특례다.

최대 토크 1000, 과부하 80 %, 보호 시간 200, 보호 전류 320 이 공장값이다. lerobot 이 연결할 때
그리퍼에 500 / 25 % / 250 을 다시 쓰는데, 이 팔에서는 그게 정상 동작이다(4절).

### ② 0점 — 각 관절을 양 끝 사이 중간으로

팔을 손으로 들어 상완 수직, 하완 수평, 손목 일직선, 그리퍼 반쯤 열림으로 만들고 실행한다.
정확할 필요는 없고 두 팔이 같을 필요도 없다. 값이 0 이나 4095 를 넘지 않게 하는 용도다.

```bash
python3 servo_home.py --port $F --execute
```

### ③ 범위 기록

실행하면 관절별 MIN / POS / MAX 표가 실시간으로 뜬다. 각 관절을 **끝에서 끝까지** 천천히 움직인다
(손목 롤은 제외). 그리퍼는 완전 열림에서 완전 닫힘까지. 다 훑었으면 Enter.

```bash
python3 servo_record_ranges.py --port $F --out $JF --execute
```

**`--gripper-drive-mode` 를 주지 않는다.** 기본값 0 이 순정 그리퍼의 정답이다. ggao50 문서의
`--gripper-drive-mode 1` 을 그대로 가져오면 리더를 쥘 때 팔로워가 열린다.

`--gripper-margin` 도 기본값 0 으로 둔다. 완전 닫힘에서 죠가 서로 눌려 스톨이 나면 그때만
`--gripper-margin 20` 정도를 준다.

`0~4095 오염` 표시가 붙은 관절은 ②에서 그 관절이 중간이 아니었던 것이다. 그 관절만 다시 한다.

```bash
python3 servo_home.py --port $F --only wrist_flex --execute
python3 servo_record_ranges.py --port $F --out $JF --only wrist_flex --execute
```

### ④ 리더도 같은 절차로

```bash
python3 servo_home.py --port $L --execute
python3 servo_record_ranges.py --port $L --out $JL --execute
```

**두 팔의 범위 끝을 같은 물리적 위치까지 훑는다.** lerobot 은 `use_degrees` 모드에서 기록된
범위의 한가운데를 0점으로 쓴다. 한쪽만 덜 훑으면 자세가 어긋난다. 관절별 폭이 서로 10 % 이상
다르면 어느 쪽이 덜 갔는지 확인하고 다시 훑는다.

### ⑤ 확인하고 커밋

```bash
python3 servo_check_calibration.py --port $F --json $JF
python3 servo_check_calibration.py --port $L --json $JL

git -C ~/bimanual-robot add calibration/so_follower_stock calibration/so_leader_b
git -C ~/bimanual-robot commit -m "chore(calibration): 순정 그리퍼 팔 캘리브레이션 추가"
git -C ~/bimanual-robot push
```

둘 다 `결과: 일치` 여야 한다. JSON 을 커밋해야 다음 사람이 캘리브된 상태로 받는다.

**오프셋을 바꿨으면 12 V 를 껐다 켠다.** 켜진 채로 오프셋을 쓰면 재부팅 전까지 제어가 꼬인다(실측).

## 4. 텔레옵

### 그리퍼 보호는 켠 채로 쓴다

이 리포의 `tools/servo/lerobot_gripper_protection.patch` 를 적용한 기기에서는 `gripper_protection`
기본값이 **false** 다. ggao50 을 위한 설정이다. 순정 그리퍼는 물건을 쥔 채 힘을 계속 주면 타므로
**이 팔에서는 반드시 `--robot.gripper_protection=true` 를 명시한다.**

켜면 lerobot 이 연결할 때 그리퍼에 최대 토크 500(50 %), 보호 전류 250, 과부하 25 % 를 쓴다.
패치를 적용하지 않은 기기에서는 이게 원래 기본값이라 결과가 같지만, 기기마다 다르게 동작하지
않도록 명령에는 항상 적어 둔다.

```bash
/home/lim/miniforge3/envs/lerobot/bin/lerobot-teleoperate \
  --robot.type=so101_follower --robot.port=$F --robot.id=follower_stock \
  --robot.calibration_dir=$HOME/bimanual-robot/calibration/so_follower_stock \
  --robot.gripper_protection=true \
  --teleop.type=so101_leader --teleop.port=$L --teleop.id=leader_b \
  --teleop.calibration_dir=$HOME/bimanual-robot/calibration/so_leader_b
```

`--robot.id` 와 캘리브레이션 파일 이름은 반드시 같아야 한다. lerobot 은 `calibration_dir / "<id>.json"`
을 연다. `--robot.id=follower_stock` 이면 파일은 `follower_stock.json` 이다.

- 켜지는 순간 팔로워 6축에 토크가 들어가 **리더 자세로 이동한다.** 시작 전에 리더를 팔로워와 비슷한
  자세로 두고 그리퍼는 편 채로 둔다
- `Mismatch between calibration values` 가 뜨면 서보와 JSON 이 다른 것이다. **여기서 `c` 를 누르지 말고**
  Ctrl+C 후 3절로 돌아간다
- **끝낼 때**: Ctrl+C 하면 토크가 풀려 팔이 떨어진다. 리더로 팔로워를 받침대에 얹은 뒤 끈다

정상 기준: 리더 그리퍼를 쥐면 팔로워도 닫히고, 자세가 리더와 같고, 여닫는 데 1초 안팎이다.
**리더를 쥐었는데 팔로워가 열리면** 캘리브레이션의 `drive_mode` 가 1 로 들어간 것이다.
서보를 만지지 말고 JSON 을 고친다(2절 ③).

## 5. IL 녹화 (`lerobot-record`)

### 카메라 확인

```bash
/home/lim/miniforge3/envs/lerobot/bin/lerobot-find-cameras opencv
```

외부 캠 2대의 `index_or_path`(예: `/dev/video4`)를 적어 둔다. 노트북 내장 캠(`ASUS FHD webcam`,
`IR camera`)은 쓰지 않는다. 경로를 고정하려면 `ls -l /dev/v4l/by-path/` 를 본다.

### 녹화

```bash
HF_USER=mmporong
/home/lim/miniforge3/envs/lerobot/bin/lerobot-record \
  --robot.type=so101_follower --robot.port=$F --robot.id=follower_stock \
  --robot.calibration_dir=$HOME/bimanual-robot/calibration/so_follower_stock \
  --robot.gripper_protection=true \
  --robot.cameras="{ front: {type: opencv, index_or_path: /dev/videoX, width: 640, height: 480, fps: 30}, wrist: {type: opencv, index_or_path: /dev/videoY, width: 640, height: 480, fps: 30} }" \
  --teleop.type=so101_leader --teleop.port=$L --teleop.id=leader_b \
  --teleop.calibration_dir=$HOME/bimanual-robot/calibration/so_leader_b \
  --dataset.repo_id=${HF_USER}/<데이터셋이름> \
  --dataset.single_task="<한 문장 과제 설명, 영어>" \
  --dataset.num_episodes=30 \
  --dataset.episode_time_s=30 --dataset.reset_time_s=10 --dataset.fps=30 \
  --dataset.push_to_hub=false \
  --dataset.streaming_encoding=true --dataset.encoder_threads=2 \
  --display_data=true
```

| 인자 | 뜻 |
|---|---|
| `single_task` | 데이터셋 전체에 붙는 과제 문장. 한 데이터셋 = 한 과제 |
| `num_episodes` | 에피소드 수. 처음엔 2~3개로 짧게 돌려 카메라와 프레임을 확인한다 |
| `episode_time_s` / `reset_time_s` | 한 에피소드 녹화 시간 / 물체를 되돌려 놓는 시간 |
| `push_to_hub=false` | 로컬(`~/.cache/huggingface/lerobot/${HF_USER}/…`)에만 저장. 올릴 땐 true + `huggingface-cli login` |
| `display_data=true` | rerun 창으로 카메라와 관절을 실시간 확인 |

녹화 중 키: **→** 에피소드 조기 종료, **←** 방금 에피소드 버리고 다시, **ESC** 전체 종료. 저장은 자동이다.

### 녹화 전 체크

- 3절 `servo_check_calibration.py` 가 두 팔 모두 `일치`
- 카메라 2대가 `find-cameras` 에 뜨고 프레임이 나옴
- 텔레옵으로 과제를 한 번 끝까지 해 봄 (그리퍼 방향, 자세, 도달 범위)
- **정지 프레임을 길게 남기지 않는다.** 팔로워가 멈춰 있는 구간이 길면 ACT 가 흔들린다.
  에피소드는 동작으로 시작해 동작으로 끝내고 `episode_time_s` 를 과제 길이에 맞춘다

## 6. 학습 (ACT)

```bash
/home/lim/miniforge3/envs/lerobot/bin/lerobot-train \
  --dataset.repo_id=${HF_USER}/<데이터셋이름> \
  --policy.type=act \
  --policy.device=cuda \
  --output_dir=outputs/train/<이름> \
  --job_name=<이름> \
  --steps=50000 --batch_size=8 --save_freq=10000 \
  --wandb.enable=false
```

- 데이터셋이 로컬에만 있으면 `--dataset.root=~/.cache/huggingface/lerobot/${HF_USER}/<데이터셋이름>` 을 함께 준다
- 체크포인트는 `outputs/train/<이름>/checkpoints/` 에 `save_freq` 마다 쌓인다. `last` 는 심볼릭 링크라
  **`rm -rf` 하지 않는다.** 대상까지 지워진다
- 0.6 부터 정규화는 정책 프로세서 안에서 한다. 롤아웃 코드에서 직접 정규화하지 않는다

## 7. 자율 실행

```bash
/home/lim/miniforge3/envs/lerobot/bin/lerobot-record \
  --robot.type=so101_follower --robot.port=$F --robot.id=follower_stock \
  --robot.calibration_dir=$HOME/bimanual-robot/calibration/so_follower_stock \
  --robot.gripper_protection=true \
  --robot.cameras="{ ...녹화 때와 같은 이름·경로... }" \
  --policy.path=outputs/train/<이름>/checkpoints/last/pretrained_model \
  --dataset.repo_id=${HF_USER}/eval_<이름> --dataset.single_task="<같은 문장>" \
  --dataset.num_episodes=5 --dataset.push_to_hub=false
```

카메라 이름(`front`, `wrist`)이 녹화 때와 같아야 정책이 입력을 찾는다.
첫 실행은 팔로워 옆에 손을 두고 12 V 를 바로 뽑을 수 있게 한다.

**정책이 그리퍼를 닫았다는 사실은 파지 증거가 아니다.** 정책은 학습 때 본 닫힘 값을 그대로
재생하므로 빈 손이어도 같은 값이 나온다. 성공 판정은 사람 눈, 닫기 프로브, 물체가 사라졌는지로 한다.

## 8. 이 팔에서 자주 걸리는 것

| 증상 | 먼저 볼 것 |
|---|---|
| 리더를 쥐면 팔로워가 열린다 | JSON 의 `gripper.drive_mode`. 순정은 0 이다. 서보를 만지지 않는다 |
| 그리퍼가 유난히 느리다 | 서보 SRAM 에 남은 `Goal_Velocity` 잔재. `b.read(6, 46)` 으로 판독한다. 느린 속도로 시험한 도구가 값을 남기면 그다음 텔레옵이 그 속도로 기어간다 |
| 목표 2~3도 앞에서 멈춘다 | P 게인부터 판독한다. 팔 관절은 32, 그리퍼는 16 이 기준이다 |
| 자세가 리더와 어긋난다 | 2절 ④. 두 팔의 범위 끝을 같은 물리적 위치까지 훑었는지 |
| `Mismatch between calibration values` | `c` 를 누르지 않는다. Ctrl+C 후 3절 |
| 팔이 목표에서 멀어지며 달아난다 | 즉시 12 V 를 끊는다. `servo_goto.py` 의 발산 감지(`--diverge-tol`)를 켜고 진단한다 |
| 보드가 안 보인다 | `dialout` 그룹, 전원 순서(어댑터 먼저, USB 나중), 그리고 `5B3D041998` 은 사망한 보드다 |

## 9. 두 쌍을 동시에 쓸 때

네 보드를 한 노트북에 꽂으면 by-id 에 네 줄이 뜬다. 시리얼로 구분하고, 두 쌍의
`--robot.id` 와 `--teleop.id` 를 서로 다르게 둔다. 캘리브레이션 디렉터리도 쌍마다 따로다.

| 쌍 | 팔로워 id / 디렉터리 | 리더 id / 디렉터리 |
|---|---|---|
| ggao50 | `follower` / `calibration/so_follower` | `leader` / `calibration/so_leader` |
| 순정 | `follower_stock` / `calibration/so_follower_stock` | `leader_b` / `calibration/so_leader_b` |

id 를 겹치게 두면 lerobot 이 같은 JSON 을 읽어 다른 팔의 범위로 움직인다.
양팔 동시 수집은 노트북 유선 단독 구성에서만 한다. 자율 실행만 파이 무선으로 넘긴다.
