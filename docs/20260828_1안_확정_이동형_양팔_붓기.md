# Plan A 확정: HOLD THE FLOW

작성: 2026-08-28 · 구현 아키텍처 갱신: 2026-09-01

상태: 메인 시나리오 확정, 실물 검증 전

## 결정

이동형 비정형 용기 붓기를 양팔 로봇 프로젝트의 Plan A이자 메인 시나리오로 확정한다. 현재 하드웨어 제작, 논문 적용, 실물 검증, 통합 일정은 이 시나리오에만 집중한다.

프로젝트 이름은 `HOLD THE FLOW`, 팀·시스템 표기는 `HANDOVER`를 사용한다. `HOLD THE FLOW`는 물의 흐름과 작업 상태의 흐름을 함께 다룬다는 뜻이고, `HANDOVER`는 두 팔 사이의 역할 인계와 사람에서 로봇으로 넘어가는 작업 인계를 함께 가리킨다.

## 목표

로봇이 병과 빈 컵을 운반 자세로 들고 SLAM/Nav2로 지정 위치에 접근한다. 베이스를 정지한 뒤 한 팔로 경량 병을 기울이는 동안 다른 팔로 받는 컵을 든다. 접촉 센서로 파지를 판정하고, 붓기 뒤 병과 컵을 낮은 로드셀 도킹 패드에 반환해 실제 유입량과 흘림을 검증한다. 실패가 기록되면 상태기계나 감독 에이전트가 검증된 복구 스킬을 고른다.

이 프로젝트는 이동, 로컬 정렬, 양팔 협응, 실물 판정, 실패 복구가 연결되는 과정과 각 단계의 실패 기록을 보여준다.

## 양팔이 필요한 이유

받는 컵을 고정 패드에 내려놓으면 붓기는 한 팔로도 끝난다. 이 프로젝트에서는 반대 팔이 컵을 들고 자세를 안정화한다. 한 팔은 병을 조작하고 다른 팔은 받는 용기를 유지하므로 역할이 겹치지 않는 비대칭 협응이 된다.

단팔 대조군은 같은 병을 낮은 고정 패드의 컵에 붓는 조건으로 둔다. 양팔 조건은 공중에서 컵을 유지한 채 붓는 조건으로 둔다. 두 조건은 성공 여부뿐 아니라 컵 자세, 유입량, 흘림, 작업 시간으로 비교한다.

## 작업 시나리오

1. 모바일 베이스가 병과 빈 컵을 운반 자세로 들고 SLAM/Nav2로 지정 목표 자세까지 이동한다.
2. Depth 카메라나 표식으로 작업 셀의 마지막 위치를 보정한다.
3. 병 쪽 팔과 컵 쪽 팔이 각 물체를 파지한다.
4. 컵 쪽 팔이 자세를 유지하고, 병 쪽 팔이 내용물을 붓는다.
5. 접촉값으로 파지 손실과 과압을 판정하고, 병을 세운 뒤 병과 컵을 각 로드셀 도킹 패드에 반환한다.
6. 컵 증가량과 병 감소량으로 실제 유입량과 흘림을 판정하고, 부족하면 작은 추가 붓기를 1회만 허용한다.
7. 실패 상태에 맞춰 재관측, 재파지, 추가 붓기, 중단 후 홈 복귀 가운데 허용된 행동을 실행한다.

## 시스템 경계

```text
slam_toolbox(mapping) 또는 AMCL(localization) + Nav2
  NavigateToPose로 지정 붓기 위치 staging pose 접근
        ↓
RGB-D / AprilTag / tf2
  base_link→workcell 로컬 좌표 인계
        ↓
MoveIt 2 / IK
  충돌을 검사한 파지·기울임 기준 궤적
        ↓
LeRobot ACT
  기준선 통과 뒤 양팔 조작 구간 학습
        ↓
접촉 센서 / 저울 / RGB-D
  성공·실패 상태 생성
        ↓
FSM 기본 복구 → 로컬 LLM 감독 확장
  검증된 스킬만 선택
```

SLAM과 AMCL은 동시에 실행하지 않는다. 지도 작성 때는 `slam_toolbox`, 반복 데모 때는 저장 지도와 `AMCL + Nav2`를 사용해 `map→odom` 발행자를 하나로 유지한다. MoveIt 2, ACT, 텔레옵은 모두 `command_mux → safety_guard → SO-101 hardware bridge`를 통과하며, 한 시점에는 하나의 명령 경로만 팔을 소유한다.

VLA는 현재 핵심 범위에서 제외한다. 로컬 LLM은 좌표, 토크, 모터 명령을 만들지 않는다. 정상 경로는 LLM 없이 상태기계로 먼저 통과시키고, LLM은 구조화된 실패 상태를 읽어 `REOBSERVE`, `REGRASP`, `POUR_MORE`, `ABORT_AND_HOME` 같은 허용된 스킬만 고르게 한다.

## 시뮬레이션

시뮬레이터는 **Isaac Sim 6.0과 ROS 2 Bridge**로 고정한다. SO-101 두 대와 모바일 베이스의 URDF를 USD로 변환하고, 실물과 같은 Action·Topic·TF 계약으로 Nav2와 MoveIt 2를 먼저 연결한다. Replicator는 조명, 배경, 병·컵 위치를 바꾼 합성 입력 생성에 사용한다.

현재 확인한 개발 노트북의 VRAM은 8GB이고 Isaac Sim 6.0의 공식 최소 VRAM은 16GB다. 따라서 `S0`에서 Compatibility Checker를 통과한 GPU 워크스테이션이나 원격 장비를 먼저 확보한다. 시뮬레이션 성공은 실물 성공으로 간주하지 않으며, 첫 ACT 기준선은 실물 시연만으로 만든다.

## 그리퍼와 센서

양쪽 팔에는 교체 가능한 평행 그리퍼를 사용한다.

| 위치 | 기본 구성 | 먼저 확인할 것 |
|---|---|---|
| 병 쪽 | V홈 TPU 패드, 접촉 센서 | 곡면 파지, 눌림, 미끄럼 |
| 컵 쪽 | 넓은 패드 또는 반원형 인서트 | 컵 자세 유지, 변형, 낙하 |
| 낮은 지정 패드 | 병·컵 로드셀 도킹 패드 | 붓기 전·후 유입량, 병 감소량, 흘림 추정 |
| 컵 홀더 확장 | 경량 로드셀 수신 모듈 | 컵을 든 상태의 실시간 유입량 폐루프 |
| 공통 | 퀵스왑 손목 어댑터 | 질량, 개구폭, 손목 모멘트 |

진공 그리퍼는 현재 시나리오의 선행 조건이 아니다. 두 팔 모두 교체 가능한 평행 그리퍼를 기준으로 검증한다.

## 하드웨어 전제

- 병·내용물과 컵·내용물은 각각 120g으로 시작하고 실측 통과 뒤 140g까지 올린다.
- 초기 내용물은 물 대신 비드나 쌀을 사용한다.
- 500ml 생수병은 현재 실험 대상에서 제외한다.
- 접촉 센서는 접촉 여부, 과도한 눌림, 좌우 불균형만 우선 판정한다. 유입량 추정에는 사용하지 않는다.
- 유입량과 최종 오차의 기준값은 붓기 전·후 병과 컵을 각 로드셀 도킹 패드에 놓고 측정한다.
- 컵을 든 상태의 실시간 폐루프는 로드셀 수신 모듈의 신호 안정성을 확인한 뒤 별도 게이트로 연다.
- 모바일 베이스는 조작 정밀도를 직접 만들지 않는다. 지정 패드 표식을 카메라 시야와 팔 작업공간 안에 반복해서 넣고 로컬 정렬 단계로 넘긴다.

## 구현 게이트

아래 항목은 측정 결과가 아니라 실험 순서와 통과 조건을 정하기 위한 계획이다.

| 게이트 | 시험 | 남길 증거 |
|---|---|---|
| S0 환경 | Isaac Sim 6.0·ROS 2 Bridge 실행 | 장비 사양·Compatibility Checker·topic/TF 로그 |
| N0~N4 이동 | TF·지도·AMCL·Nav2 반복 접근 | 지도·도달 오차·Action 결과·복구 횟수 |
| G0 파지 | 병과 컵 정적 파지 | 낙하·변형·접촉값 영상과 로그 |
| G1 기울이기 | 내용물 없이 붓기 자세 유지 | 관절 드리프트·파지 손실 기록 |
| G2a 붓기 | 건식 내용물과 병·컵 도킹 저울로 사후 판정 | 유입량·병 감소량·흘림 추정·작업 시간 |
| G2b 폐루프 | 로드셀 수신 모듈로 실시간 질량 판정 | 자세별 신호 안정성·정지 여유량 |
| D0/A0 학습 | 양팔 5회 수집·20회 과적합 기준선 | 시간축·학습 로그·IK/ACT 실물 대조 |
| G3 통합 | 이동, 정렬, 양팔 조작 연결 | 단계별 상태 전이와 실패 위치 |
| G4 복구 | 미끄럼·넘침·미검출 상태 주입 | 재시도 결과와 안전 중단 로그 |

첫 실물 게이트는 10회 중 7회 이상 안정 파지·기울임, 자동 판정 2종 이상, 실패 5회 중 3회 이상 안전 복구다. 이 수치는 목표 기준이며 아직 달성 결과가 아니다. 평가 방식과 논문 적용 근거는 R31에 정리했다.

## 바로 진행할 일

1. 병과 컵 후보의 무게, 지름, 표면 재질을 기록한다.
2. V홈 TPU 패드와 컵 인서트의 치수 초안을 만든다.
3. 정적 파지와 무수 기울이기 시험표를 만든다.
4. 병·컵 로드셀 도킹 패드의 시간값, 목표 유입량, 흘림량 기록 형식을 정한다.
5. 선택 확장인 로드셀 수신 모듈의 질량 예산과 자세 민감도를 계산한다.
6. Nav2 완료 상태에서 로컬 정렬로 넘길 인터페이스를 정의한다.
7. G0부터 순서대로 실물 영상과 로그를 남긴다.
