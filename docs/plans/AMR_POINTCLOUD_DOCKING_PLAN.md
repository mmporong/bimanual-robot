## 1. 프로젝트의 문제와 완료 결과

**문제:** 낮은 2D 라이다는 책상 다리를 보지만 높은 차체와 충돌할 상판의 돌출을 표현하지 못한다. 깊이 카메라를 쓰는 주차는 장착 자세·경계 가림에 따라 거리와 방향 추정이 달라질 수 있다. 이를 같은 책상에 대한 공간 모델과 상대 자세 추적으로 연결한다.

**완성할 시스템:** 깊이 점군에서 책상 상판과 접근면을 구분하고, 관측된 상판은 주행 장애물 지도에 반영하면서 지정 책상에는 면을 추적해 목표 간격 1 cm까지 주차하는 ROS 2 AMR 시스템.

핵심 질문은 세 가지다.

1. 장착 오차와 깊이 측정 오차를 구분해, 보정에 쓰지 않은 거리·책상에서도 상대 거리와 방향을 유지할 수 있는가?
2. 동일한 책상 모델로 주행 중 충돌 영역과 주차할 접근면을 표현할 수 있는가?
3. 근접 중 보이는 경계가 줄어들어도 대상 추적을 이어가 불필요한 정차·재접근을 줄일 수 있는가?

PCL 사용 여부는 위 질문을 해결하는 수단이다. Pi에서 측정한 병목이 있을 때만 C++·PCL 구현을 비교한다. AMCL·NavFn·RPP 교체, 3D SLAM, 사람 분류, 새 센서 구매, 후면 박스 인식기의 재개발은 이 프로젝트의 필수 범위가 아니다. 기존 후면 도크 복귀는 전체 왕복의 회귀 대상으로 유지한다.

## 3. 기준선과 브랜치 운영

1. 이 브랜치는 최신 main에서 시작한 점군 개발용이다. 원래 폴더의 주행 수정·배포 상태는 유지한다.
2. **S0에서 기준선 B0를 고정한다.** 실차 통합 전 기존 주행 브랜치의 변경 중 필요한 제원·TF·감시·주차 수정이 이 브랜치에 반영됐는지 대조한다. 검증한 주행 수정의 로컬 병합 또는 동등한 포팅을 별도 커밋으로 기록하고, 그 결과 SHA와 설정 해시를 B0에 넣는다. 사용자의 별도 요청 없이 main 병합·push·브랜치 삭제를 하지 않는다.
3. B0를 고정한 뒤 인식 변경을 시작한다. 선행 주행 수정을 수용할 수 없다면 그 사유를 남기고 기록 재생 개발까지만 진행하며, 오래된 실행기로 실차를 대체하지 않는다.
4. B0와 개선판은 지도·차체 외곽·주행 속도·명령 경로·입력 데이터를 같게 맞춘다. 비교 도중 바뀌면 새 실험 버전으로 나눈다. 외부 측정 없는 과거 주행은 정확도 정답으로 재사용하지 않는다.
5. 목적 브랜치 하나에서 단계별 한글 Conventional Commit을 남긴다. 기존 주행 수정, 점군 인식, 성능 개선을 각각 구분하고 경로별로 스테이징한다.
6. 출발 시 기존 실행기에 명령을 제출하는 운영 방식은 유지한다. 아래 실험·리뷰·기록기는 개발 단계의 도구이며 매 출발의 추가 절차가 아니다.

## 4. 데이터 흐름과 출력 계약

```text
depth Image + CameraInfo + 취득 시각의 TF
                 │
           XYZ 복원·차체 제거
                 ├─ 정밀 ROI 점군 → 상판/옆면/경계 → 동일 대상 추적
                 │                                  │
                 │                         상대 거리·각도·관측 근거
                 │                                  │
                 │                         기존 면 상대 주차 제어
                 │
                 └─ 장애물용 복셀 점군 → 높이별 점유 → Nav2 costmap / CM

2D LiDAR → 기존 AMCL·일반 주행·하단 장애물 감시를 유지
```

- 정밀주차에는 원본 또는 조밀한 ROI 점을 쓴다. 장애물 지도용 기존 4 cm 복셀 점군을 그대로 1 cm 주차의 거리 입력으로 쓰지 않는다.
- 새 내부 관측 구조에는 `target_id`, 취득 시각, 좌표계, 보정 버전, 상판 평면, 보이는 접근면/경계, 관측 지지 범위, 거리·방향 추정, `observed/predicted/unobservable` 상태를 둔다. 오차 공분산은 실제 추정 모델이 있을 때만 사용하고 임의 값을 확률로 부르지 않는다.
- 추적 좌표는 연속적인 odom 기준으로 두고 이미지 시각의 TF로 갱신한다. AMCL의 map 보정 점프가 같은 책상의 물리 이동으로 해석되지 않도록 한다. 전역 목표 연계에는 map↔odom 변환을 별도로 사용한다.
- 상판의 수평 평면 하나로 yaw, 앞 경계 위치, 면을 따라 이동한 위치를 모두 결정할 수는 없다. 얇은 옆면도 항상 충분한 점을 주지 않는다. 경계·옆면·이전 유효 관측 중 사용한 근거와 관측 불가능한 성분을 기록한다.
- 추적은 현재 시각으로 과거 영상을 재포장하지 않는다. 짧은 가림 예측의 시간·이동량 한도는 S1의 시야·오차 예산에서 정하고 S2의 드롭아웃 시험으로 검증한다. 한도를 넘으면 예측값을 새 관측처럼 제어에 넣지 않는다.
- 지도에는 실제 관측한 높이와 공간만 갱신한다. 시야 밖, 무효 깊이, 반사체, 입력 끊김을 빈 공간으로 처리하지 않는다. 관측하지 못한 keepout까지 일괄 제거하지 않는다.
- 접근 대상의 책상도 일반 이동 중에는 장애물이다. 주차 허용 처리가 필요하면 선택된 대상의 검증된 면·영역과 실제 차체의 접근 궤적에만 한정한다. 다른 물체나 테이블 내부를 전역 free 공간으로 바꾸지 않는다.
- 인식 노드는 속도 명령을 발행하지 않는다. 기존 속도·정지 명령 경로를 사용하며, 점군 추가로 기존 감속·정지 경로의 오류가 해결됐다고 판정하지 않는다.

## 5. 단계별 개발 계획

### S0. 기준선·재생 데이터·외부 측정 계약

작업:

- 3절의 세 기준, 즉 분기 main `795af64`, 보존 주행 수정 `b4500a9`, 실제 실행본의 배포 receipt·source/install 해시를 대조하고 B0의 소스·설정·실행 경로를 고정한다. 실제 실행본이 보존 커밋과 같다고 추정하지 않는다. `camera_mount_current.yaml`, 센서 frame, CameraInfo K/P, 깊이 단위, 차체 실제 외곽의 사용 경로를 확인한다.
- 과거 raw 깊이·CameraInfo·TF·odom이 함께 있는 기록을 재생 후보로 인덱싱한다. 상태 JSON만 있는 기록은 XYZ 재생이나 외부 거리 정답으로 인정하지 않는다.
- 데이터 manifest에 SHA-256, 수집 조건, 장착/책상 ID, 캘리브레이션 버전, 분할, 외부 측정 방법·불확실도, 제외 근거를 남긴다. 파일 단위가 아니라 수집 세션·책상·장착 단위로 보정/개발/최종 평가 데이터를 나눠 인접 프레임 누출을 막는다. 새 수집 데이터에는 기존 `data/schema/` 규격에 맞는 조건 메타데이터·포함/제외 기준·dataset card를 붙이고 `data/README.md` 인덱스와 연결한다.
- 기본 재생·평가 도구를 만들고 기존 검출기를 B0로 실행한다. 출력은 시행별 CSV와 집계 JSON이다. raw bag·영상은 Git에 넣지 않고 로컬 데이터와 저장소의 인덱스로 연결한다. 외부 업로드는 이 계획 실행에 포함하지 않는다.

산출 위치(신설): `N/evaluation/pointcloud_docking/`의 manifest schema·재생·평가 도구, `N/test/`의 입력·좌표·분할 회귀, 보정 provenance.

완료: 실제 읽을 수 있는 raw 기록을 1개 이상 끝까지 재생하고, 누락 입력과 거리 정답 부재를 각각 구분한다. 합성 기하로 좌표·단위 오차를 검출한다. B0와 데이터 분할의 해시가 고정돼야 S1을 시작한다. 새 수집이나 실물 이동은 해당 실행 요청을 받은 뒤 한다.

### S1. 기하 보정과 다중 근거 책상 관측

작업:

- 기존 XYZ/RANSAC/SVD를 재사용하고 상판·옆면·경계를 같은 대상에 연계한다. 옆면이 부족할 때 기존 경계 방식으로 추정 가능한 값과 불가능한 값을 나눈다.
- 장착 오차, 거리 의존 깊이 편향, 기존 작업용 offset을 분리해 단순한 모델부터 비교한다. 수평 평면만으로 전체 6자유도를 자동 보정하지 않는다. 관측 불가능한 값은 독립 기준면·실물 측정에서 얻거나 기존값으로 유지했다고 명시한다.
- 캘리브레이션 데이터에서만 보정값을 구한다. 장착 변경 시 보정 버전을 바꾸고, 같은 도출 데이터를 평가 정답으로 사용하지 않는다.
- 기존 검출기의 confidence를 보정된 성공 확률로 해석하지 않는다. 평면 잔차·지지점 수·관측 폭·보이는 면별로 실제 오차와의 관계를 평가한다.

주요 파일: `box_top_detection.py`, `table_edge_detection.py`, `table_edge_target.py`; 신규 순수 기하 모듈은 `N/jdamr_cube_navigation/table_surface_model.py`를 후보로 한다.

완료: 외부 기준을 갖춘 미사용 평가 장면에서 접근면 거리 절대오차 p95 ≤ 5 mm, 방향 절대오차 p95 ≤ 1°를 개발 목표로 평가한다. 적용 범위·장면별 실패·측정 불확실도를 함께 보고한다. 기준을 넘으면 원인을 분리해 보정·관측 방식을 수정하고, 통과했다고 바꾸지 않는다.

### S2. 같은 책상 추적과 주차 제어 인계

작업:

- 단순 연속 프레임 안정성 검사에 더해 odom 이동 보상·대상 연계·관측 가능한 성분의 갱신을 구현한다. 인접 책상, 보이는 선분 중점 변화, 경계 양끝 반전, AMCL map 점프, 경계 가림을 회귀로 넣는다.
- 지도 등록은 대상 책상을 관측할 근방을 지정하는 용도로 유지한다. 그 근방 안의 실제 면 위치는 관측으로 갱신하고, 등록 좌표를 정밀 거리 정답으로 쓰지 않는다. 탐색 근방 밖으로 옮긴 책상까지 자동 발견하는 전역 의미지도 기능은 범위에 포함하지 않는다.
- 짧은 가림은 검증된 시간·이동량 예산 안에서 이전 면과 odom으로 예측한다. 재관측과 입력 끊김을 구분하고 검출되지 않은 면을 만들어 내지 않는다.
- 기존 `box_service.py`, `surface_approach.py`에 선택형 어댑터로 연결한다. RPP 이동 중 확보한 최신 대상을 면 상대 제어에 넘겨, 같은 자리에서 불필요하게 검출 창을 다시 채우는 정차를 줄인다.
- 기존 명령 경로의 충돌 정지·통신 timeout을 유지한다. 외부에서 실패한 이동을 추적 성공으로 바꾸거나 큰 전후진 복구를 새로 추가하지 않는다.

산출 위치: 신규 `table_surface_tracking.py`와 대응 테스트, 기존 관측→목표→면 제어 어댑터. 기본 활성화는 통합 검증 뒤 별도 커밋으로 한다.

완료: 기록 재생에서 대상 교체·좌우 반전·AMCL 점프에 의한 잘못된 주차면 인계가 0건이어야 한다. 가림/지연 시험에서 예측 한도 초과 후 관측값처럼 사용하는 동작이 0건이어야 한다. 주차 정확도와 정차시간 목표는 S5에서 외부 측정으로 판정한다.

### S3. 높이를 반영한 상판 장애물 지도

작업:

- 기존 depth filter·VoxelLayer overlay를 확장한다. 현재 장착·취득 시각 TF에서 바닥·상판·차체 점이 실물과 맞는지 교차 센서 검증을 마친 뒤 통합한다.
- 라이다 광선이 상판 아래를 통과해도 상판 점유를 지우지 않는지 기존 격리 시험과 현재 입력으로 확인한다. 같은 높이의 유효 자유공간 관측으로만 대응 점유를 갱신한다.
- 선택된 대상의 접근면과 일반 장애물로 남아야 하는 상판 영역을 동일한 대상 모델에서 만든다. 실측 차체 외곽과 회전 궤적을 사용하고 등록 도크·비대상 책상·의자 다리의 점유를 보존한다.
- 관측으로 확인된 영역부터 수동 keepout 의존도를 줄인다. 후방·시야 밖의 상판은 기존 표현을 유지하고 전방 카메라가 360°를 본다고 설명하지 않는다.
- 기존 CM 입력·속도 출력의 연결, 일반 이동의 감속/정지 설정과 주차 예외 복원을 별도로 점검한다. 알려진 주행 감시 공백을 남겨둔 채 장애물 접근 실험을 하지 않는다.

주요 파일: `depth_obstacle_core.py`, `depth_obstacle_filter.py`, `depth_navigation_config.py`, `launch/depth_obstacle_navigation.launch.py`; 통합은 기존 선택 실행 경로를 사용한다.

완료: 관측 가능한 ROI의 외부 주석 기준에서 상판 점유 재현율 ≥ 95%, 통행 가능한 영역의 거짓 점유 비율 ≤ 5%를 목표로 평가한다. 격자 경계 오차·높이 범위·맵 해상도를 함께 명시한다. 입력 끊김을 빈 공간으로 처리하거나 다른 물체를 목표면 예외로 지우는 회귀는 0건이어야 한다. 실제 정지·회피 효과는 지도 검출 지표와 별도로 S5에서 검증한다.

### S4. Pi 자원 측정과 조건부 최적화

작업:

- 동일 해상도·입력률·설정으로 XYZ 복원, 공간 필터, 면 추출, 추적, ROS 발행·costmap 반영까지 단계별 시간을 잰다. Pi에서 CPU, 프로세스 RSS, 입력 나이, 처리 기한 누락을 함께 기록한다.
- 정밀 ROI와 장애물용 복셀 해상도를 나누고 기존 구현의 불필요한 복사·할당을 먼저 줄인다. 최종 주차에 필요한 거리·각도 정확도를 유지한 구성끼리 비교한다.
- 점군 처리 자체가 병목이면 해당 함수만 C++·PCL 후보로 구현한다. 버전·컴파일 옵션·스레드 수·입력 순서를 고정해 NumPy 기준과 같은 기록으로 비교한다. 새 의존성 도입은 실제 구현 시 별도 범위로 밝히고 승인된 경우에 수행한다.

산출물: Pi 프로파일 CSV/JSON, 점 수·복셀 크기·ROI에 따른 정확도/자원 곡선. C++ 후보는 필요할 때 별도 모듈로 두며 전체 Python 실행기를 교체하지 않는다.

완료: 기존 선택형 파이프라인의 5 Hz 처리 목표에서 계획한 처리 슬롯의 95% 이상이 유효 출력을 내고, 카메라 취득→costmap 반영 지연 p95 ≤ 200 ms를 목표로 평가한다. 센서 입력 부재·TF 지연도 별도 실패 수에 포함한다. 최적화 채택 기준은 전체 파이프라인 지연 p95 20% 이상 감소, S1 정확도 유지, 피크 RSS 5% 초과 증가 없음이다. 병목이 아니거나 기준에 못 미치면 C++를 채택하지 않고 비교 결과를 남긴다. 이 수치는 현재 측정 성과가 아니다.

### S5. 반복 실차 평가와 포트폴리오 근거 묶음

작업:

- 실물 실행 요청 뒤 소규모 예비 시행을 진행하고, 최종 평가 조건을 고정한다. 개발 중 실패와 최종 평가의 실패를 모두 보존한다.
- 아래 비교표대로 B0와 개선판의 차이를 한 요소씩 분리한다. 원인 분리를 위한 제거 실험은 우선 같은 기록 재생에서 수행하고, 실차는 B0와 최종 구성의 필요한 비교로 줄인다.
- 정밀주차·지도 반영·제어 동작·Pi 자원을 서로 다른 지표로 평가한다. 왕복 성공 하나로 센서 보정이나 장애물 정지까지 통과했다고 판정하지 않는다.
- 검증한 코드 SHA·설정·데이터 manifest·CSV·요약 JSON·영상 시간을 연결한다. 공개용 문구와 미디어 제작은 근거가 나온 뒤 별도 작업으로 한다.

완료: 6장의 반복 주차 기준과 전체 왕복 기준을 충족하고, 주요 개선 주장마다 B0와 최종 구성의 비교 결과 및 원본 위치가 있어야 프로젝트 완료로 판정한다. 구현·단위 테스트 완료와 실차 성과는 나눠 기록한다.

## 6. 실험 설계와 최종 판정

다음 숫자는 프로젝트 평가용 제안값이다. S0에서 물리 시야·측정 가능 범위를 확인하고 **평가 데이터 수집 전에** 버전으로 확정한다. 목표를 바꾸면 변경 이유와 비교 가능 범위를 남긴다.

| 실험 | 조건과 단위 | 비교·판정 |
|---|---|---|
| 정지 기하 평가 | 앞끝 간격 5/20/40 cm × 진입각 -10/0/+10° × 두 장착 설정의 18개 조건. 장착 변경은 실행 권한을 받은 뒤 수행. 보정·평가 세션 분리 | 거리·방향 오차 p50/p95, 검출률, 관측 불가능 조건을 포함한 조건별 결과. 반복 프레임을 독립 실험 횟수로 세지 않음 |
| 상판 지도 평가 | 돌출 상판, 다리만 보이는 상판, 인접 비대상 책상, 의자 다리, 바닥만 보이는 공간, 입력 가림의 6종 장면. 각 장면은 별도 clip으로 수집 | ROI 안 점유 재현율·거짓 점유율, 지도 갱신·clearing, 타임스탬프별 지연. 카메라가 못 본 영역은 별도 표기 |
| 상대 주차 평가 | 서로 다른 책상 2곳 × 초기각 -10/0/+10° × 각 5회 = 구성당 30회. B0와 최종 구성의 시행 순서를 섞고 속도·외곽·출발 거리를 맞춤 | 실행기의 자동 완료·정상 종료, 외부 측정 양 모서리 모두 10±5 mm, 좌우 간격 차 ≤ 5 mm, 접촉 없음, 정지 확인을 모두 충족하면 성공. 목표 성공률 ≥ 90%(27/30)이며 성공률 신뢰구간도 보고 |
| 부드러운 인계 | 위 주차 시행의 RPP→상대 제어 구간. 작업 대기 시간과 경로상 장애물 대기는 구분 | 주차 오차를 유지하면서 재관측으로 인한 비작업 정차시간 중앙값을 B0 대비 30% 이상 줄이는 목표. B0가 이미 0이면 감소율 대신 추가 정차 0 유지. 재접근 횟수·누적 회전량·전후진 횟수도 보고 |
| 전체 왕복 | 급수대→1번 테이블→기존 후면 도크 복귀, 동일 조건 연속 5회 | 충돌·운영자 개입·실행기 실패 0회, 두 테이블의 최종 간격 외부 확인, 기존 도크 완료 확인. 5회 결과를 양산 신뢰성으로 확대하지 않음 |
| Pi 성능 | 같은 기록·입력률·해상도의 B0/최종/조건부 C++ 비교 | 단계별 처리시간, 취득→지도 지연, CPU·피크 RSS, 누락률. 정밀도와 자원을 함께 비교 |

- 외부 간격 기준은 실측 지그 또는 검증한 외부 관측 장치를 사용한다. 측정 불확실도는 목표 허용오차보다 작아야 하며, 부족하면 더 정밀한 성과를 주장하지 않는다. 운영자가 매 출발마다 줄자로 재는 방식을 제품 절차로 넣지 않는다.
- 기존 내부 완료 기준 10±3 mm는 변경하지 않는다. 외부 10±5 mm는 별도 계측으로 확인할 프로젝트 목표이며 내부 허용범위를 넓히는 설정이 아니다. CSV에 `internal_completion`, `executor_exit_code`, `external_gap_left_mm`, `external_gap_right_mm`, `contact`, `stopped`, `overall_success`를 분리한다. 내부 실패/외부 간격 충족 또는 내부 완료/외부 간격 미달은 모두 전체 실패로 집계한다.
- 외부 5 mm 허용오차에는 깊이·장착·추적·제어 정지·외부 측정 오차가 함께 작용한다. S0에서 이 오차 예산을 나누고 S1의 정적 추정 목표만으로 최종 정확도를 보장하지 않는다.
- 한 상판의 평면 잔차나 같은 검출기의 재출력은 외부 거리 정답이 아니다. 내부 추정·외부 측정·사용자 육안 확인을 별도 열로 둔다.
- B0의 위험한 충돌을 비교 목적으로 재현하지 않는다. 그런 경우 B0는 기록·격리 시험으로 평가하고, 실차 비교 불가능 범위를 표기한다. 안전 때문에 중단한 시행을 통계에서 빼지 않는다.
- 평가 도중 튜닝한 데이터는 개발 분할로 이동하고 새 최종 평가 분할을 확보한다. 사후에 성공 조건에 맞는 시행만 고르지 않는다.

### 제거 실험

| 구성 | 고정할 것 | 확인할 기여 |
|---|---|---|
| B0 | 고정한 기존 검출·보정·주차·지도 | 기존 오차와 지연 |
| B1 | B0 + S1 보정/다중 근거 관측 | 기하 추정 개선 |
| B2 | B1 + S2 대상 추적/인계 | 가림 대응·정차 감소 |
| B3 | B2 + S3 높이 장애물 통합 | 상판 점유·경로와 접근 허용 영역 |
| B4(조건부) | B3와 같은 추정 결과·제어 설정, 처리 구현만 변경 | 자원·지연 개선 |

B1–B3의 기록 재생·격리 시험을 먼저 마친다. 지도 개선과 제어 수정이 동시에 들어간 결과만으로 어느 알고리즘이 주차를 개선했다고 설명하지 않는다.

## 7. 검증·실패 처리·포트폴리오 산출물

### 개발 검증

- 기존 회귀: `N/test/test_table_edge_detection.py`, `test_table_edge_target.py`, `test_depth_obstacle_core.py`, `test_depth_obstacle_filter.py`, `test_depth_navigation_config.py`를 변경 영향에 맞춰 실행한다. 실행기 어댑터 변경 시 관련 `test_box_service.py`, `test_parking_integration.py`, 기존 후면 주차·감시 회귀를 추가한다.
- 새 회귀: 알려진 3D 기하, 장착 오차, 얇은 옆면 부족, 근접 가림, 옆 책상으로 대상 교체, odom/map 분리, 입력 시각·TF 지연, 대상 밖 장애물, 장애물 전용 복셀과 주차 ROI 혼용 방지를 검증한다.
- Nav2는 기존 `N/evaluation/smoke_depth_voxel_layer.py` 등 격리 harness를 재사용한다. 테스트 결과·종료 코드·사용한 설정을 함께 보존한다. Pi 성능과 실물 정지는 격리 테스트만으로 완료 처리하지 않는다.
- 코드 작성 후 별도 리뷰·검증 패스를 거친다. 로컬 커밋까지 진행하고 사용자 요청 전에는 push·배포·main 병합하지 않는다. GitHub Actions는 새로 만들지 않는다.
- S1 목표에 못 미치면 S2의 오래된 관측 연장으로 감추지 않는다. 대상 추적이 불안정하면 인계를 기본 활성화하지 않는다. 자원 목표에 못 미치면 시야/정확도와 함께 ROI·주기를 재평가한다. 모두 정지 상태의 개발 단계에서 처리한다.

### 최종 근거 묶음

1. 문제·센서 역할·관측 가능 범위를 나타낸 구조 그림.
2. 원본 깊이/XYZ, 상판·옆면·경계, 추적 상태, 장애물 지도, 실제 주차가 같은 시간축으로 연결된 영상.
3. 조건·분모를 포함한 거리/방향 오차, 성공률, 정차시간, 회전·재접근 횟수, Pi 자원 비교표.
4. 고정된 코드·설정·데이터 해시와 재생 명령, 환경·의존성 정보.
5. 기존 기능 재사용, 이번 구현, 외부 측정, 해석의 범위를 구분한 기술 설명. 결과가 나온 항목만 성과 문구로 만든다.

보여줄 역량은 점군 복원·좌표 변환, 평면 분할·기하 추정, 대상 추적, ROS 2/PointCloud2·Nav2 통합, 실험 설계, 임베디드 자원 평가다. PCL 채택은 비교 결과가 있을 때만 추가한다.

## 8. 첫 구현 작업과 중단선

다음 개발 세션의 첫 작업은 **S0: 주행 기준선 차이 대조, 보존 raw 데이터 가용성 검사, 기존 검출기 재생과 평가 도구 구현**이다. 카메라가 꺼져 있어도 코드·기록 재생 개발은 진행할 수 있다. raw나 외부 정답이 부족하면 필요한 수집 조건을 구체화하고 독립적으로 가능한 합성·회귀 작업을 진행한다.

이번 계획 수립 작업은 문서·참조·정책 충돌 검증과 로컬 커밋에서 끝낸다. 이 문서는 출발 명령이나 실물 구동 권한으로 해석하지 않는다.
