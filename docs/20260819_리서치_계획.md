# 리서치 계획 — 금요일(2026-08-21) 마감분

킥오프 액션 아이템 중 내가 착수하는 리서치의 질문 목록과 판정 기준. 산출물은 `research/` 에 항목별 파일로 쓴다. **찾은 것을 나열하는 게 아니라, 아래 판정 질문에 답이 나왔는지로 완료를 판정한다.**

## R1. 양팔 동시 텔레오퍼레이션 (최우선)

데이터 수집 전체가 여기에 걸려 있다. 이게 막히면 태스크 선정도 학습 계획도 다시 세워야 한다.

판정 질문:
1. 양팔 동시 텔레옵의 공개된 구현이 실제로 있는가. 있다면 어떤 하드웨어 구성인가 (리더 2대 / 리더 없이 팔로워만 / 외골격 / VR 컨트롤러 / 모션 캡처).
2. 리더-팔로워를 좌우 각각 두는 방식에서 **동기화를 어떻게 맞추는가.** 두 팔의 명령이 서로 다른 주기로 들어가면 에피소드 타임스탬프가 어긋난다.
3. LeRobot이 양팔(bimanual) 구성을 공식적으로 지원하는가. 지원한다면 데이터셋 스키마에서 좌우 팔을 어떻게 표현하는가 (단일 액션 벡터에 concat / 별도 필드).
4. 리더 없이 팔로워 기준으로 구성하는 회의 제안이 실제로 성립하는가. 성립한다면 조작자는 무엇으로 명령을 주는가.
5. 사람 팔 하나로 로봇 팔 둘을 동시에 조작하는 건 물리적으로 불가능하다 — **조작자 2명 구성**이 전제인지, 아니면 순차 조작(한 팔씩 녹화 후 합성)인지. 후자라면 동시 협응 태스크는 데이터로 못 만든다.

5번이 이 리서치의 핵심이다. 답에 따라 태스크 후보 자체가 갈린다. 양팔이 **독립적으로** 물건을 옮기는 태스크(순차 조작 가능)와 두 팔이 **협응**해야 하는 태스크(동시 조작 필수)는 필요한 텔레옵 구성이 다르다.

## R2. 픽앤플레이스 기준선 정의

리서치라기보다 정의 작업이다. 금요일 논의에 제안서 형태로 가져간다.

정해야 할 항목:

| 항목 | 정해야 할 값 |
|---|---|
| 대상 물체 | 종류·크기·무게·표면(미끄러운지) |
| 시작 조건 | 물체 배치 범위(격자 몇 칸 × 몇 칸), 자세 랜덤 여부 |
| 목표 조건 | 놓을 위치의 허용 오차 |
| 성공 판정 | 무엇을 관측해 성공으로 세는가 (실좌표 기준, 로그 문자열 금지) |
| 통과 기준 | N회 중 M회. 조건별로 나눠서 표기 |
| 양팔 요소 | 1단계에서 두 팔이 각각 하는가, 협응하는가 |

## R3. 클라우드 GPU 학습 비용

판정 질문:
1. ACT / SmolVLA 파인튜닝 1회에 실제로 필요한 VRAM과 시간은 얼마인가 (에피소드 수 기준으로).
2. 후보 서비스별 시간당 단가와, 위 1회 학습의 예상 총액.
3. 가중치만 내려받아 실기에서 추론하는 구성이 성립하는가. 추론에 필요한 VRAM은 얼마인가.
4. 학습을 몇 번 돌릴 것으로 잡아야 하는가. 한 번에 끝나지 않는다는 전제로 반복 횟수를 곱한 총 예산.

4번을 빼먹으면 견적이 실제의 몇 분의 일로 나온다. 하이퍼파라미터 조정과 데이터 추가 수집을 감안해 최소 5회는 잡는다.

## R4. 양팔 로봇 적용 사례·회사 (A3 — 담당 미지정, 여력 있으면)

판정 질문:
1. 양팔 구성을 실제 제품·연구로 밀고 있는 곳은 어디이고, 어떤 태스크를 내세우는가.
2. 그들이 양팔이어야 한다고 주장하는 근거가 무엇인가. 단팔 두 대로는 안 되는 이유가 태스크에 있는가.

2번이 우리 발표의 논리에 그대로 쓰인다. "양팔로 했습니다"보다 "이 태스크는 양팔이어야 성립합니다"가 훨씬 강하다.
