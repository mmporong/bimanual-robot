# IK와 IL의 경계, 결합 방식, IK 구현 방법

> 목적: 어느 동작을 기구학으로 풀고 어느 동작을 학습에 맡길지, 둘을 어떻게 한 실행 경로에 합칠지, IK를 어떤 방법으로 구현할지를 구현 단위로 확정한다
> 기준일: 2026-09-03
> 선행: [R32 IL·IK 결합 구조](../research/R32_IL과_IK_결합구조_정책선택_실행모드.md) · [구현 아키텍처](20260901_구현아키텍처_ROS2_CPP_Python_ACT_IsaacSim.md)

## 1. 경계를 정하는 기준

**기하로 결정되면 IK, 실행할 때마다 달라지면 IL이다.**

구간마다 세 가지를 묻는다. 셋 다 "예"면 IK다.

1. 목표 자세를 좌표로 쓸 수 있는가
2. 그 좌표가 실행할 때마다 같은가, 또는 센서가 한 번 재면 확정되는가
3. 실패해도 원인이 기하로 설명되는가

하나라도 "아니오"면 IL 후보다. 여기서 IL이 실제로 값을 만드는 곳은 **접촉이 일어나거나 물성이 개입하는 두 구간**뿐이다.

## 2. 구간별 경계

R31의 상태기계에 담당을 붙인다.

| # | 구간 | 담당 | 근거 |
|---|---|---|---|
| 1 | `APPROACH` Nav2 이동 | **Nav2** | 학습 대상 아님. 조작과 동시 실행 금지 |
| 2 | `ALIGN` RGB-D·표식으로 상대 자세 갱신 | **결정론 인지** | 한 번 재면 좌표가 확정된다 |
| 3 | `REACH` 물체 앞까지 접근 | **IK** | 목표 = 물체 좌표 + 접근 오프셋. 기하로 결정 |
| 4 | **`GRASP_BOTH` 파지** | **IL** | 물체 위치·자세 오차, 접촉 순간의 미끄러짐. 좌표로 안 써진다 |
| 5 | `VERIFY_GRASP` 미세 들기·기울여 확인 | **IK + 규칙** | 정해진 10~20 mm 들기, FSR 임계 |
| 6 | `LIFT / TRANSPORT` 운반 자세로 전환 | **IK** | 목표 관절값이 이미 풀려 있다 |
| 7 | `PRETILT_SLOW` 예비 기울임 | **IK** | 각속도·목표각이 기하로 결정 |
| 8 | **`POUR` 붓기 미세조정** | **IL 또는 IK 기준선 + 잔차** | 잔량·매체에 따라 유량이 달라진다 |
| 9 | `RETURN_UPRIGHT` 직립 복귀 | **IK** | 기하로 결정 |
| 10 | `PLACE_BOTH` 도킹 반환 | **IK** | 패드 좌표 고정 |
| 11 | `WEIGH` 질량 판정 | **결정론 센서** | 로드셀 읽기 |

**IL은 4번과 8번 두 곳뿐이다.** 나머지 아홉 구간은 IK나 결정론이다.

### 왜 이렇게 좁히는가

전 구간을 IL로 배우면 IK로 이미 정확한 부분까지 데이터로 다시 배워야 한다. 우리 데이터 예산에서는 그 낭비가 곧 성능 차이가 된다. 반대로 4번과 8번을 IK로 밀어붙이면 접촉과 물성을 좌표로 표현해야 하는데, 그게 안 되니까 학습을 쓰는 것이다.

### 구간 4를 IL로 두는 이유

파지는 물체가 **어디 있는지**뿐 아니라 **어떻게 닿을지**의 문제다. 병 지름이 다르고, 라벨 때문에 마찰이 다르고, 죠가 닿는 순간 물체가 밀린다. 좌표를 아무리 정확히 줘도 그 순간의 보정은 시연에서 배우는 편이 빠르다.

### 구간 8을 잔차로 두는 이유

붓기는 목표 궤적이 대략 알려져 있고(기울임 각도-시간 보정표), 남는 문제는 잔량에 따른 미세 보정이다. 기준선이 있는 상태에서 보정만 배우면 탐색 범위가 기준선 근방으로 줄고 기준선 자체가 안전 경계가 된다. 다만 **잔차는 2차 목표다.** G2 결정론 기준선이 통과하기 전에 착수하지 않는다.

## 3. 결합 — 명령 중재기 하나를 지난다

IK든 IL이든 **같은 인터페이스로 같은 게이트를 지나 같은 실행기로 간다.** 둘을 다른 경로로 보내면 동시 명령과 모드 전환에서 사고가 난다.

```
상태기계 (skill sequencer)
   │
   ├─ ExecuteBimanualSkill(mode=IK)  ──┐
   ├─ ExecuteBimanualSkill(mode=IL)  ──┤
   └─ ExecuteBimanualSkill(mode=TELEOP)┤
                                       ▼
                            bimanual_command_mux
                              · lease 하나만 활성
                              · 모드 전환은 정지 상태에서만
                              · 안전 게이트 통과 후 통과
                                       ▼
                     both_arms FollowJointTrajectory (C++)
                              · 좌우를 하나의 goal 로
                              · 같은 time_from_start 기준
                                       ▼
                                  서보 버스
```

### 전이 규약

경계에서 **IK 구간의 종료 조건이 IL 구간의 시작 조건과 같아야 한다.** 다르면 정책이 학습 때 못 본 상태에서 시작한다.

| 전이 | 종료 조건 = 시작 조건 |
|---|---|
| 3 → 4 (IK → IL) | tool0 가 물체 접근점 허용오차 안, 속도 0, 그리퍼 개방 |
| 4 → 5 (IL → IK) | FSR 접촉 범위 안, 그리퍼 명령 정지 후 N 프레임 무변화 |
| 7 → 8 (IK → IL) | 병 기울임각이 예비 목표 도달, 각속도 0 |
| 8 → 9 (IL → IK) | 목표 유입량 도달 또는 시간 초과, 각속도 0 |

**전이는 항상 정지 상태에서 한다.** 움직이는 중에 모드를 바꾸면 두 제어기가 같은 관절에 다른 목표를 쓴다.

### 데이터 수집에도 같은 경계를 쓴다

텔레옵으로 4번과 8번만 기록한다. 3·5·6·7·9·10번은 IK로 자동 실행하고 그 구간은 **에피소드에서 잘라낸다.** 그래야 정책이 IK가 할 일을 배우지 않는다. 이건 R32의 스킬 3분할과 같은 이야기다.

## 4. IK 구현 방법

용도가 셋이라 구현도 셋이다. 하나로 다 하려 하면 실패한다.

### 4.1 설계 검증용 — URDF FK + 감쇠 최소자승 (구현 완료)

`src/hold_flow_description/scripts/solve_task_poses.py`

**핵심은 별도 기구 모델을 두지 않는 것이다.** 커밋된 URDF를 그대로 읽어 FK를 만들고 그 FK로 IK를 푼다. 모델이 하나뿐이라 FK와 IK가 어긋날 수 없다. 손으로 옮겨 적은 DH 파라미터가 URDF와 어긋나 몇 시간을 태우는 실패를 원천 차단한다.

**구속 수를 자유도에 맞춘다.** SO-101은 5축이다.

```
위치 3 구속        tool0 (또는 bottle_tcp / cup_tcp) 의 xyz
축방향 2 구속      tool0 의 Z축 방향 (병 축)
────────────────
합 5 = 자유도 5
```

6구속(완전 자세)을 걸면 해가 없고, 3구속(위치만)을 걸면 병 기울임이 제어되지 않는다. 실제로 위치만 건 첫 해는 관절 한계 안에 들었지만 병이 컵 바로 위에 서서 **양팔이 6쌍 충돌**했다.

축방향 오차는 3차원 벡터 차이를 그대로 쓰지 않고 목표 축에 수직인 평면으로 투영해 2성분만 남긴다. 그래야 구속 수가 정확히 5가 된다.

```python
basis = I - outer(axis_target, axis_target)     # 목표 축에 수직인 부분공간
tangent = basis 의 고유벡터 중 고윳값 > 0.5 인 2개
error[3:] = tangent @ (axis_target - axis_current)
```

**반복은 감쇠 최소자승이다.**

```python
J = 수치 야코비안 (전진차분, step 1e-5)
delta = J.T @ solve(J @ J.T + lambda * I, error)     # lambda = 1e-4
q = clip(q + 0.5 * delta, lower, upper)              # 관절 한계로 직접 클리핑
```

감쇠 `lambda`가 특이점 근처에서 발산을 막는다. 보폭 0.5는 진동을 줄인다. 한계 클리핑은 해를 항상 유효 범위 안에 둔다.

**seed 전략이 결과를 가른다.**

| 용도 | seed | 이유 |
|---|---|---|
| 운반 자세 | **zero 고정** | 좌우가 같은 분기(팔꿈치 위)로 풀려 대칭해가 나온다 |
| 붓기 자세 | 무작위 재시작 24회 | 기울임 구속이 있어 분기가 좁다 |

무작위 재시작으로 운반을 풀면 좌우가 다른 분기로 가서 팔이 서로 넘어간다. 실제로 첫 시도가 그랬고 충돌 4쌍이 났다.

**이 방법의 한계를 알고 쓴다.**

- 도달 한계 근처(95% 이상)에서는 사실상 해가 없다. 팔이 거의 펴져 야코비안이 특이해진다
- 자세 하나를 풀 뿐 **경로가 아니다.** 두 자세 사이를 어떻게 갈지는 답하지 않는다
- 충돌을 보지 않는다. 푼 뒤에 `audit_urdf_clearance.py`로 따로 검사한다

### 4.2 실행용 — MoveIt 2

실물 궤적은 MoveIt 2가 만든다. 위 스크립트는 설계 검증용이지 실행기가 아니다.

**`both_arms` 플래닝 그룹 하나로 푼다.** 좌우를 Python에서 순서대로 호출하면 안 된다. 그러면 두 팔이 서로를 장애물로 보지 않고, 시간축도 어긋난다.

```
both_arms planning group
  → 하나의 control_msgs/FollowJointTrajectory goal
  → C++ trajectory server 가 같은 time_from_start 기준으로 좌우 분리
  → bridge
```

피드백과 취소도 두 팔을 **하나의 실행으로 집계**한다. 한쪽만 멈추면 물체를 든 상태에서 자세가 깨진다.

MoveIt에 넘길 것:

- URDF/SRDF (좌우 그룹, `both_arms` 그룹, 충돌 허용 행렬)
- tool0 를 end effector 로 지정
- 관절 한계와 속도·가속 상한 (붓기는 낮게)
- 작업 셀 충돌 객체 (작업대, 도킹 패드)

### 4.3 실시간 보정용 — 해석적 IK (선택)

MoveIt 계획은 수십~수백 ms가 걸린다. 시각 서보처럼 매 프레임 목표를 갱신하는 구간에는 못 쓴다.

로컬에 이미 검증된 해석적 IK가 있다. `capstone_pick/kinematics.py`의 `ik(x, y, z, pitch, roll)`와 `ik_best`가 SO-101 5축을 닫힌 형태로 푼다. **TCP 오프셋만 ggao50 tool0 값으로 바꾸면 그대로 쓸 수 있다.** 관절 이름과 한계는 이미 우리 URDF와 같은 규약이다.

쓸 자리는 `ALIGN`의 미세 보정과 `VERIFY_GRASP`의 들기 정도다. 그 밖에는 MoveIt을 쓴다.

### 세 방법의 역할

| 방법 | 언제 | 속도 | 경로 | 충돌 |
|---|---|---|---|---|
| URDF FK + DLS | 설계 검증, 자세 후보 탐색 | 초 단위 | ✕ | 별도 검사 |
| MoveIt 2 | 실물 실행 | 수십~수백 ms | ○ | ○ |
| 해석적 IK | 시각 서보 미세 보정 | 마이크로초 | ✕ | ✕ |

### 구간별로 무엇을 쓰는가

2절의 번호와 맞춘 실행 도구다.

| # | 구간 | 도구 | 왜 |
|---|---|---|---|
| 1 | `APPROACH` | **Nav2** | 이동은 MoveIt 영역이 아니다 |
| 2 | `ALIGN` | OpenCV + tf2 | 좌표를 만들 뿐 움직이지 않는다 |
| 3 | `REACH` | **MoveIt 2** | 충돌을 피해 가야 한다. 경로가 필요하다 |
| 4 | `GRASP_BOTH` | **LeRobot 정책 서버** | 청크를 관절 목표로 직접 낸다 |
| 5 | `VERIFY_GRASP` | **해석적 IK** | 10~20 mm 직선 들기. 계획이 필요 없다 |
| 6 | `TRANSPORT` 전환 | **MoveIt 2** | 자세 전환에서 양팔이 교차한다 |
| 7 | `PRETILT_SLOW` | **해석적 IK** 또는 MoveIt | 단순 기울임. 충돌 위험이 낮으면 해석적으로 충분 |
| 8 | `POUR` | **정책 서버** (+ IK 기준선) | 잔차를 쓸 때 기준선은 해석적 IK 로 생성 |
| 9 | `RETURN_UPRIGHT` | **해석적 IK** | 7번의 역동작 |
| 10 | `PLACE_BOTH` | **MoveIt 2** | 도킹 패드 주변에 충돌 객체가 있다 |

**판별 규칙은 하나다 — 가는 길에 부딪힐 것이 있으면 MoveIt, 없으면 해석적 IK.** 3·6·10번은 양팔이 교차하거나 작업대가 근처에 있다. 5·7·9번은 이미 물체를 든 채 짧게 움직이는 구간이라 계획 비용이 아깝다.

### MoveIt 2 를 어디까지 설정하는가

**필요한 것**

| 항목 | 내용 |
|---|---|
| planning group | `left_arm`, `right_arm`, `both_arms` 셋. 실제 실행은 `both_arms` 만 쓴다 |
| end effector | 좌우 `tool0` |
| SRDF 충돌 허용 | 인접 링크쌍만 허용. 좌우 팔 사이는 절대 허용하지 않는다 |
| 관절 한계 | `joint_limits.yaml` 에 속도·가속 상한. 붓기 구간은 별도로 낮춘다 |
| 플래너 | OMPL RRTConnect 로 시작. 재현성이 필요해지면 Pilz 의 직선 명령으로 |
| 컨트롤러 | `both_arms` 하나의 `FollowJointTrajectory`. 좌우를 나누지 않는다 |
| 충돌 객체 | 작업대, 도킹 패드, 컵 트레이를 planning scene 에 올린다 |

**하지 않는 것**

- `ros2_control` 하드웨어 인터페이스를 처음부터 새로 쓰지 않는다. MoveIt 은 `FollowJointTrajectory` 서버만 있으면 붙는다. 서보 드라이버는 나중에 교체 가능한 계층으로 둔다
- 그리퍼를 MoveIt 의 gripper action 으로 만들지 않는다. 개폐는 상태기계가 직접 명령한다. 붙이면 파지 실패 복구가 MoveIt 상태기계에 묶인다
- 좌우를 각각 계획해서 순서대로 실행하지 않는다. 서로를 장애물로 보지 않고 시간축도 어긋난다

**검증 순서**

1. `check_urdf` 와 SRDF 생성 (`moveit_setup_assistant`)
2. RViz 에서 `both_arms` 로 운반 자세 → 붓기 자세 계획. 충돌 표시 확인
3. 같은 계획을 100회 반복해 실패율과 계획 시간 기록
4. 실물 없이 궤적을 `FollowJointTrajectory` 더미 서버로 받아 시간축 검증
5. 저속으로 실물 실행

### 왜 지금 MoveIt 이 아니라 DLS 로 풀었는가

MoveIt 은 **시작 자세에서 목표 자세까지 갈 수 있는지**를 답한다. 우리가 먼저 알아야 했던 건 **그 목표 자세가 존재하는지**였다. 목표가 도달 한계의 96%에 있으면 MoveIt 을 아무리 돌려도 답이 없고, 그 사실이 "계획 실패"로만 나와 원인을 못 찾는다.

그래서 순서가 이렇다. **자세가 존재하는가(DLS) → 그 자세가 안전한가(간섭 감사) → 거기까지 갈 수 있는가(MoveIt).** 앞의 둘을 건너뛰면 MoveIt 로그만 보며 헤맨다.

## 5. IL이 실제로 받는 것

정책이 학습·실행에서 보는 것을 고정한다. 이걸 바꾸면 이전 데이터가 무효가 된다.

| 항목 | 규격 |
|---|---|
| 관측 이미지 | 손목캠 2대, 320×240, 30 Hz. 뎁스는 G0 입력에서 제외 |
| 관측 상태 | 좌우 5관절 위치 + 그리퍼 개폐 |
| 행동 | 좌우 관절 목표 위치 + 그리퍼 |
| 상대좌표 규약 | 붓기에서 **병 팔의 목표를 컵 팔 그리퍼 기준 상대좌표로** 표현. 컵 팔이 흔들려도 목표가 따라간다 |
| 실행 모드 | 청크 `--replan 10~15`. 앙상블 금지 |
| 태스크 문자열 | R26 3문장 중 하나 |

**상대좌표 규약은 본수집 전에 확정해야 한다.** 나중에 바꾸면 이전 에피소드가 전부 무효다.

## 6. 안전 게이트는 공통이다

IK든 IL이든 **같은 게이트를 지난다.** 정책이 냈다는 이유로 면제되지 않는다.

| 게이트 | 기준 |
|---|---|
| 관절 한계 | URDF hard limit 안, 여유 마진 포함 |
| 자기 충돌 | 교차 팔 25 mm, 그리퍼↔반대팔 40 mm, 마스트 반경 55 mm |
| 속도·가속 | 붓기 구간 별도 상한 |
| 서보 전류·온도 | 경고 55 °C, 정지 60 °C |
| 통신 워치독 | 마지막 액션 청크 수신 후 타임아웃이면 정지 |
| 이동 금지 | 조작 중 base 정지 (`base_motion_during_manipulation: prohibited`) |
