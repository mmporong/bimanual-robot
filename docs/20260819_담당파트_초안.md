# 담당 파트 정리 초안 (2026-08-19)

> 액션 아이템 A1 제출본 초안. 팀 문서로 업로드하는 버전이라 내부 메모는 빼고 맡을 범위·산출물·일정만 적었다.

## 맡을 파트

**로봇 제어(IK + Depth)** 와 **이미테이션 러닝/학습** 두 축을 맡는다. 회의에서 "IK와 이미테이션 둘 다 되게 해두고 잘 되는 쪽을 채택한다"고 정했는데, 두 경로를 한 사람이 잡으면 같은 태스크·같은 평가 기준으로 비교할 수 있어 채택 판단이 빨라진다. 이미테이션이 기한 내 안 나올 경우 IK 경로가 그대로 플랜 B가 된다.

## 1. 로봇 제어 (IK + Depth)

| 항목 | 내용 |
|---|---|
| 목표 | 카메라가 준 물체 위치로부터 그리퍼 목표 자세를 만들고, 역기구학으로 관절값을 풀어 결정론적으로 파지 |
| 구성 | Depth 카메라(Orbbec Astra) → 물체 3D 위치 → hand-eye 변환 → IK → 관절 명령 |
| 양팔 확장 | 좌우 팔 각각의 베이스 프레임을 분리하고, 공통 월드 좌표계에서 목표를 배분. 팔별 캘리브레이션 파일을 따로 관리 |
| 재사용 자산 | 단팔(SO-101) 기준으로 hand-eye 캘리브레이션·IK 검증·파지 스크립트를 이미 만들어 둔 게 있어 양팔로 확장하는 형태로 진행 |

이미 부딪혀 본 함정이라 미리 공유해 둘 것:

- **Depth 카메라와 USB 카메라를 같은 버스에 물리면 교착이 난다.** Astra SDK와 UVC 웹캠이 같은 USB 컨트롤러를 쓰면 프레임이 멈춘다. 카메라를 여러 대 붙일 계획이면 버스 분리와 해상도·fps 고정을 처음부터 잡아야 한다.
- **파지 실패의 원인은 대체로 높이가 아니라 도달 검사다.** 그리퍼가 목표까지 실제로 내려갔는지 검사하는 조건이 리치 오프셋을 빠뜨리면, 좌표는 맞는데 계속 헛집는다.
- **성공 판정을 로그 문자열로 세면 안 된다.** 실좌표나 실물 관측으로 세야 수치가 신뢰된다.

## 2. 이미테이션 러닝 / 학습

| 항목 | 내용 |
|---|---|
| 목표 | 텔레옵으로 모은 시연 데이터로 정책을 학습시켜 픽앤플레이스 수행 |
| 1차 모델 | ACT (경량·실시간 추론 가능). SmolVLA는 2차 후보 |
| 파이프라인 | LeRobot 데이터셋 포맷 → 학습(클라우드 GPU) → 가중치만 내려받아 실기 추론 |
| 산출 | 학습 스크립트, 평가 프로토콜, 조건별 성공률 표 |

주의할 지점:

- **정규화 규약을 처음에 못 박아야 한다.** LeRobot의 각도 표현은 중점 기준이라 캘리브레이션 경계값을 잘못 넣으면 학습은 도는데 실기에서 엉뚱한 자세가 나온다. 범위 밖 값 감지는 정규화된 값이 아니라 raw 값으로 해야 잡힌다.
- **평가셋은 수집 전에만 뗄 수 있다.** 다 모으고 나서 "이건 평가용"이라고 나누면 이미 학습 조건과 섞여 있다. 수집 시작 전에 홀드아웃 조건(물체 위치·조명·시각)을 정해야 한다.
- **조건에 따라 성공률이 갈리면 코드가 아니라 데이터 문제다.** 같은 조건에서 항상 실패하면 코드, 조건 따라 갈리면 데이터 분포다. 이걸 구분하지 않고 코드를 고치면 그 조건에만 맞춘 수정이 된다.

## 3. 다른 파트와 겹치는 지점

- **데이터셋 담당**: 에피소드 포함/제외 기준과 수집 조건 메타데이터 항목을 같이 정하고 싶다. 학습 쪽에서 나중에 "이 에피소드는 왜 성능이 안 나오지"를 추적하려면 수집 시점 조건이 남아 있어야 한다. 스키마 초안을 만들어 뒀으니 검토받고 합치면 된다.
- **웹/풀스택**: 학습 정책의 추론 결과와 조건별 성공률을 API로 내보낼 수 있게 형식을 맞추면 대시보드에 바로 붙는다.
- **커스텀 코드**: LeRobot 기본 동작과 우리 방식의 차이를 비교할 때 같은 평가 기준을 쓰면 차별점이 수치로 보인다.

## 4. 이번 주 할 일

| 기한 | 항목 |
|---|---|
| 금요일 전 | 양팔 동시 텔레오퍼레이션 선례 리서치 (양팔 데이터 수집이 여기 걸려 있음) |
| 금요일 전 | 픽앤플레이스 기준선 정의안 — 성공 조건·반복 횟수·판정 방법 |
| 금요일 전 | 에피소드 메타데이터 스키마 초안 공유 |
| 다음 주 | LeRobot 파일럿 실행 (단팔 기준으로 먼저 파이프라인 관통) |

## 5. 제안 하나

**픽앤플레이스 "성공"의 정의를 팀 차원에서 먼저 문장으로 고정했으면 한다.** 어떤 물체를, 어느 범위에 놓았을 때, 몇 회 중 몇 회 성공해야 통과인지를 정하지 않으면 IK와 이미테이션을 비교할 수도, 마일스톤 통과를 판정할 수도 없다. 금요일 재논의 때 15분 정도 이 항목에 쓰면 이후 작업이 전부 이 기준을 향하게 된다.
