# 시뮬레이션·매니퓰레이션·AMMR 고도화 인계

기록일: 2026-09-13. 상태: 전략·관측 기록과 후속 제안이며 구현·학습 성공·실물 실행 승인이 아니다.
기존 [RGB-D 단독→LiDAR 역할 분담 우선순위](20260913_RGBD_SLAM_우선순위와_다음세션.md)를 유지한다.
AMMR은 이 대화에서 Autonomous Mobile Manipulation Robot(자율이동 매니퓰레이션 로봇)을 뜻하는 것으로 해석했다.

## 1. 시뮬레이션과 취업 전략 기록

- 지원 경로는 AMR/로봇 SW 시스템과 로봇 시뮬레이션·검증을 함께 검토하고, 실제 매니퓰레이션·IL 평가를 연결 역량으로 강화한다.
- 다른 분야 제품 개발 경력, 로보틱스 기업 실무 경력, 실물 로봇 프로젝트를 구분한다. 프로젝트 개수나 다른 분야 연차를 로봇 실무 연차로 바꾸지 않는다.
- 기존 Gazebo/Isaac 경험 위에 실제 3D 데이터 변환, 충돌 형상·센서/물성 설정 근거, 폐루프 시험 자동화, 실물과 시뮬 차이 분석을 추가한다. 단순 영상 재생·시각화와 소프트웨어가 센서 입력으로 판단하는 폐루프 실행을 구분한다.
- [로브로스 Simulation 공고](https://www.wanted.co.kr/wd/351944)는 9월 13일 열람 시 신입·상시 표기이나 본문은 관련 석박사 또는 동등 경험·3D 데이터·기구학/동역학·Python/C++를 요구한다. 신입 태그만으로 진입 요건이 낮다고 판단하지 않는다. 취업 효과는 공고와 프로젝트를 비교한 추론이며 합격을 보장하지 않는다.
- 목표 공고가 요구할 때 대표 장면 하나의 Isaac 구동·평가를 보강한다. 기존 Gazebo 결과 전체를 다른 엔진으로 이식하거나 새 프로젝트를 무조건 늘리지 않는다.

### 현재 생성기의 성공 판정 코드

`/data/lim/leisaac/source/leisaac/leisaac/tasks/pick_cube_into_box/mdp/observations.py`의 조건은 큐브가 박스의 XY·Z 범위 안에 있고 그리퍼가 열린 상태다. `pick_cube_into_box_env_cfg.py`와 `generate_dataset.py`가 별도 `success_term`으로 이 조건을 연결한다. 일반 RL reward/termination manager 표가 비어 있다는 이유로 성공 판정이 없다고 판단하지 않는다.

해당 최종 조건에는 일정 시간 안착 유지·속도 안정화·리프트 이력·손가락 접촉이 별도로 포함되지 않는다. `pick_cube` annotation의 grasp 신호와 최종 성공 조건도 구분한다. 따라서 ‘상자에 놓고 손을 뗀 뒤 유지’가 평가 목표라면 별도 안정성 검사를 추가할 가치가 있다. 이는 기존 생성 결과가 잘못됐다는 판정이 아니라 성공 지표의 범위를 명확히 하는 것이다. 실행 중인 생성기의 조건을 변경하지 말고, 기존 조건 결과와 후속 엄격 평가 결과를 버전별로 나눠 보존한다.

## 3. Mimic과 병렬 학습의 완료 주장을 분리

Mimic은 시연을 subtask로 나누고 새 물체 배치에 맞게 변환·연결해 추가 시연을 생성한다. 생성 데이터를 이용한 BC 등 정책 학습은 별도 단계다. [Isaac Lab 공식 워크플로](https://isaac-sim.github.io/IsaacLab/main/source/overview/imitation-learning/teleop_imitation.html)

`num_envs=1024`는 동시 시뮬레이션 환경 수다. 생성 성공률, 학습 보상, 독립 정책 성공률, 실물 성능은 서로 다른 수치다. 환경 수를 늘려도 항상 처리량·성능이 좋아지는 것은 아니다. [Isaac Lab RL 설명](https://isaac-sim.github.io/IsaacLab/develop/source/concepts/reinforcement_learning.html)

### 다음 읽기 전용 확인

1. 위 원격 기준선을 사용하되 새 실행이 있다면 commit·계약·checkpoint·평가 로그를 별도 연결한다. 현재 Windows 로그와 대용량 checkpoint의 실재 여부는 소유 세션에서 확인하며 Git 조회만으로 현재 프로세스 상태를 주장하지 않는다.
2. 이미지 정책인지 상태 벡터 정책인지 확인한다. 시뮬레이터가 제공하는 정답 물체 pose를 actor가 쓰면 실물 배포 시 대응하는 인식 입력이 필요하다. critic만 특권 상태를 쓰는 경우와 구분한다.
3. SO-101과 다른 로봇으로 학습 중이면 학습·평가 방법을 재사용하되 checkpoint를 그대로 SO-101에 이식할 수 있다고 가정하지 않는다.
4. 관절 순서·축·영점·단위, 절대/상대 행동, 주기·action repeat·정규화, 그리퍼 명령·TCP 정의를 대조한다. Mimic HDF5가 별도 PPO task에 즉시 호환된다고 가정하지 않는다.

## 4. 매니퓰레이션 고도화 순서

### M0 — 현재 생성·학습 결과를 보존하고 품질 확인

- 완료된 shard/닫힌 파일을 대상으로 원본 시연 계보, 이미지·관절·action 시간축, 누락·NaN·episode 길이·초기 상태 분포를 검사한다. 진행 중인 파일을 완성 데이터로 읽거나 합치지 않는다.
- 생성기의 성공 판정 함수가 무엇을 검사하는지 확인하고, 과제에 필요한 파지·들기·운반·배치·그리퍼 이탈·안착을 독립 평가와 대조한다. 생성기의 성공 플래그만으로 실제 배치 성공을 선언하지 않는다.
- 성공 시연만 학습에 쓰더라도 생성의 실패·시도 수는 보존한다. 정책 평가에서는 실패·시간 초과·사람 개입을 분모에서 제외하지 않는다.
- 실패는 인식/도달/파지/운반 중 낙하/배치/해제/충돌/시간 초과로 분리한다. 평가 목표는 다음 비교 전에 고정한다.

### M1 — 현재 학습 방식에 맞춰 비교 하나를 먼저 완성

- **IL 경로:** 기존 원본 시연만 쓴 정책과 원본+Mimic 보강 정책을 같은 모델·관측·평가 조건으로 비교한다. ACT는 BC 계열 정책이므로 ACT와 BC를 항상 별개 학습 범주처럼 표현하지 않는다.
- **RL 경로:** `so101-pick-rl`은 독립 ID 평가가 이미 있으므로 실패 계측→고정 checkpoint 진단→연장 기준선 대 보상 전환 비교가 먼저다. held-out·DR·MuJoCo 교차평가는 원격 기록상 미실행이며 학습 입력/성공 계약을 맞춘 후 별도로 다룬다.
- **분리 원칙:** Mimic 이미지 IL과 상태 기반 PPO를 당장 합치지 않는다. 원격 PPO 저장소의 BC/ACT 제외 범위를 유지하고, Mimic/ACT 비교는 해당 IL 저장소에서 진행한다. 향후 BC 초기화 PPO를 연구하려면 별도 범위 합의와 관측·행동·데이터 어댑터 검증이 먼저다.
- 기존 IK+시각 피드백은 같은 물체·작업 범위의 시스템 기준선으로 둔다. 센서 정보가 다른 경우 차이를 명시하고 순수 알고리즘 우열이라고 하지 않는다.
- 학습/validation/test는 원본 시연 계보와 초기 조건을 고려해 분리한다. 동일 원본에서 파생한 생성궤적의 무작위 분할만으로 미시연 일반화를 주장하지 않는다. 원본 하나뿐이면 그 제약을 밝히고 별도 초기 조건의 폐루프 평가를 사용한다.
- checkpoint 선택에는 validation을 쓰고 final test는 선택에 재사용하지 않는다. seed·시작 조건·성공 횟수/전체 횟수·실패 단계·시간·추론 지연과 학습 비용을 함께 남긴다.

### M2 — AMMR에서 실제 생길 오차를 조작 시험에 반영

- 물체 위치·방향, 베이스 정차 위치·yaw 오차, 카메라 가림·측정 지연, 그리퍼/접촉 조건을 시험 축으로 삼는다.
- 처음에는 한 축씩 변화시켜 실패 원인을 분리하고, 이후 조합 조건을 평가한다. 랜덤화 범위는 실측 분포·설계 허용치에 근거하며 임의값은 가정으로 표기한다.
- 정차 오차는 단순 물체 이동만이 아니라 로봇-작업대 상대 자세·카메라 시점·도달성·충돌 관계까지 함께 바꿔야 한다. 통합 로그가 없으면 가정 기반 시뮬 시험으로 표시한다.
- 팔이 닿지 않는 경우 무리하게 조작하지 않고, 팔 수납·베이스 재정렬·재관측으로 복구한다. 순차 제어로 검증하고 이동 중 팔 조작은 요구하지 않는다.

### M3 — 실물 이식 전 계약 확인과 제한된 검증

- 같은 로봇 모델·관절 방향·그리퍼·카메라 보정·행동 주기와 관측 입력을 맞춘다. 접촉/물성·지연 차이를 분리해 sim-to-real 오차를 보고한다.
- 실제 힘 센싱·토크 제어가 검증되지 않은 SO-101 구성에 고정밀 힘 제어·삽입 작업을 당장 추가하지 않는다. 위치제어 기반 파지·배치의 반복성을 먼저 확인한다.
- 실물 명령 발행은 사용자 실행 요청과 물리적 준비 확인 후 별도로 한다. 시뮬 평가 성공만으로 실물 실행을 자동 시작하지 않는다.

## 5. AMMR은 새 프로젝트보다 현행 물 서빙의 통합 단계

추천 1차 구조:

```text
Nav2 목표 접근 → 베이스 정지 확인 → RGB-D 재관측
→ 팔 도달성·충돌 여유 확인 → 조작 → 물체 배치·이탈 확인
→ 팔 수납 확인 → 다음 주행
```

- [물 서빙 단일 미션](20260907_물서빙로봇_회의결정과_실행범위.md)과 주행 중 팔 수납·조작 중 베이스 정지 원칙을 유지한다. 학습 정책은 현행 PLANNED/ACT/HYBRID 중 검증된 조작 구간에만 넣는다.
- AMMR 통합이 PPO 성공을 기다려야 하는 것은 아니다. 기존 IK·시각 피드백 조작부터 연결하고, 학습 정책은 동일 인터페이스에서 평가를 통과한 뒤 대체 후보로 넣는다. 상태 기반 PPO checkpoint를 RGB-D 이미지 입력에 직접 연결하지 않는다.
- 이동→정차→컵/물체 배치의 작은 통합 시험부터 하고, 물 붓기·도킹/충전까지의 최종 미션 성공과 구분한다. 작은 시험이 전체 미션의 대체 완료 조건은 아니다.
- 같은 `run_id`로 주행 결과·정차 오차·인식 품질·조작 backend/checkpoint·성공/실패·개입·재시도를 연결한다. 단계별 성공률과 전체 미션 성공률을 함께 보고하며, 단계별 수치를 독립이라고 가정해 곱하지 않는다.
- 통합 1차의 핵심은 ‘주행은 성공했는데 팔이 못 잡는 이유’를 로그와 상대 좌표로 설명하고 복구하는 것이다. 차체와 팔을 동시에 제어하는 end-to-end/whole-body RL은 이 필요성이 입증된 후 별도 심화 과제로 둔다.

## 6. 다음 세션 인계

1. 이 브랜치의 RGB-D P0/P1을 먼저 진행한다. 별도 학습 실행은 소유 세션에서 계속 관리한다.
2. `so101-pick-rl` 담당 세션은 원격 인계서에 따라 기존 0/600 checkpoint의 실패 계측부터 이어간다. Mimic 담당 세션은 완료 shard QC와 원본 대비 IL 평가를 준비한다. 이 브랜치가 다른 세션 학습을 덮어쓰지 않는다.
3. 차체 완성 전에는 시뮬레이션과 기존 단일팔의 조작 평가를 준비하고, 완성 후에는 M2의 정차 오차·관측 차이를 실제 통합 로그로 검증한다.
4. 취업용 완료 근거는 ‘병렬 수·생성량’이 아니라 원본 대비 개선/미개선, 미사용 조건 평가, sim-real 차이와 복구 과정으로 제시한다.
