# 컵 중간 높이 측면 파지와 오른손 병 파지 재설계

> 2026-09-22 이후 왼손은 SO-101 순정 회전식 죠를 사용한다. 이 문서의 FinRay 관련 제약은
> 과거 실패 분석으로만 보존하며, 새 파지 계획은 순정 죠 형상·TCP와 재캘리브레이션 범위를 사용한다.

## 바꾸는 이유와 목표

사용자 확인: 이전 Isaac 화면에서 그리퍼가 컵을 통과했고 접근 방식도 맞지 않았다.
요구하는 동작은 **컵 밖에서 그리퍼를 가로로 회전한 다음 컵 몸통 중간을 양옆에서 잡는 것**이다.
오른손도 같은 장면에서 병 몸통 파지 방향과 반대 팔 간섭을 검토한다.

이전 프리뷰는 접촉을 끈 상태에서 관절값을 순간 배치했다. 구형 계획은 공구축만
아래로 기울여 맞췄으며 손가락이 컵의 같은 높이를 감싸는 방향은 검사하지 않았다.
화면이 움직였다는 사실은 파지 로직의 검증이 아니었다.

## 새 동작 순서

| 단계 | 해야 할 일 | 다음 단계로 넘기는 조건 |
|---|---|---|
| 물체 정의 | 컵 중심 XY·책상 높이·컵 높이·몸통 지름과 각 값의 측정/가정을 분리 | 현재 장면과 같은 좌표계 |
| 중간점 지정 | `z_grasp = z_table + 0.5 × cup_height` | 컵 림이나 바닥, 영상 박스 중앙으로 대체하지 않음 |
| 회전 공간 확보 | 열린 그리퍼 전체가 컵 밖에 있는 접근 전 위치 확보 | 손목·손가락의 회전 swept volume 검사 필요 |
| 가로 방향 맞춤 | 접근 방향과 두 죠를 잇는 기준 방향을 수평으로 맞춤 | 위치·방향 오차와 관절 한계를 각각 통과 |
| 측면 접근 | 중간 높이를 유지하며 열린 손가락 사이로 컵이 들어오게 이동 | 매 구간 물체·책상·반대 팔 간섭 검사 |
| 닫기 | 컵 양쪽 접촉을 확인하며 그리퍼 닫기 | 끝점 도달만으로 파지 성공 판정하지 않음 |
| 짧은 들어올림 | 작은 수직 이동 뒤 컵 동반 이동·미끄럼 확인 | 양측 접촉/영상/물체 자세의 일관성 |
| 운반 자세 | 잡힌 컵을 수직으로 유지하며 이동 | 파지 검증 이후만 수행 |

닫기·들어올림은 아직 구현·검증 완료가 아니다. 접촉 정보가 없는데 컵을 그리퍼에
고정해서 따라오게 만들거나 성공 애니메이션으로 대신하지 않는다.

## 양팔 방향과 5축 IK

- 왼손: 기존 `left_tool0`의 +Z를 명목 접근축으로 사용한다. +X는 죠 평면의 가로 방향
  기준일 뿐, 회전식 죠/FinRay의 모든 개방각에서 실제 접촉점 이동 방향과 같지는 않다.
- 오른손: `right_tool0`의 −Y가 손가락 길이 방향 접근축이고 ±X가 평행 죠 개폐 방향이다.
  +Z는 이 구성에서 병이 서는 방향이다. 좌우 모두 공구 +Z를 접근축으로 쓰면 안 된다.
- 병 몸통 중간은 `right_tool0`를 맞춘다. +Z로 떨어진 `right_bottle_tcp`를 몸통 파지점으로 쓰지 않는다.
- 위치 3조건 + 접근축의 수직 성분 0 + 죠 가로 기준축의 수직 성분 0을 푼다.
  수평면 안의 접근 방위는 풀어 두며, 컵을 향하는 방향인지 별도로 확인한다.
- 해가 안 나오면 몸통 중간 높이를 바꾸거나 손목을 아래로 기울여 성공으로 처리하지 않는다.
  위치 오차·수평 오차·관절 여유를 실패 근거로 남긴다. 국소 수치 탐색 실패를 수학적인 도달 불가능 증명으로 부르지 않는다.

현재 가정 장면의 중간 높이는 컵 0.7531 m, 병 0.8031 m다. 이는 책상 높이 0.6931 m와
컵 높이 0.12 m·병 높이 0.22 m의 계산값이며 실측값이 아니다. 물체 위치를 바꾸면 재계산한다.

## 구현과 표시 범위

- `tools/plan_body_side_grasp.py`: 양팔 중간 높이 수평 IK 후보 생성. 접촉·연속 경로 미검증.
- `tools/workcell_envelopes.py`: URDF 각 collision 형상의 외곽을 월드 AABB로 감싼 뒤,
  컵/병 원기둥·책상 판·반대 팔과의 겹침 후보 및 팔 관절 한계를 검사한다.
- `tools/simulate_urdf_workcell.py --body-plan ...`: 양팔 후보를 한 팔씩 비교한다.
  실패 후보를 강제로 표시하지 않고 마지막으로 검사에 통과한 자세를 유지한다.
  컵과 병의 빨간 띠는 각각 몸통 중간 높이다. 기본 자동 재생은 꺼져 있다.

외곽 검사는 보수적이므로 실제 메시가 닿지 않아도 겹침 후보로 잡힐 수 있다.
반대로 이 검사는 로봇 자가충돌·로봇 상판/마스트·병목/뚜껑·컵 내부·접촉 변형까지 포함한
완전한 접촉 검사가 아니다. 검사 통과를 전체 충돌 안전 또는 실물 실행 승인으로 사용하지 않는다.
몸통 후보 모드는 경로가 아직 없으므로 재생 버튼으로 후보 사이를 자동 이동하지 않는다.

현행 왼손 순정 메시를 실물 순정 죠와 대조하고 ID 6 개방폭·TCP·접촉면·질량을 확인한다.
접촉 가능한 물체와 구동 모델을 연결해야 닫기·들어올림 검증으로 넘어갈 수 있다.

## 실행

```bash
cd ~/bimanual-robot
python3 tools/plan_body_side_grasp.py --output logs/body_side_review/plan.json
ISAAC_PYTHON="/data/$USER/conda-envs/leisaac/bin/python"
"$ISAAC_PYTHON" tools/simulate_urdf_workcell.py \
  --body-plan logs/body_side_review/plan.json \
  --output-dir logs/body_side_review/gui
```

기존 출력은 덮어쓰지 않는다. 새 실행에는 새 경로를 쓴다. 보고서와 현재 URDF의 해시가
다르면 표시 전에 거부한다. `accepted`는 stage의 `accepted_scope`에 적힌 **IK 끝점 조건만**
뜻한다. 이후 외곽 검사에서 다시 거부될 수 있고, 표시 통과도 파지 승인을 뜻하지 않는다.

## 현재 가정 장면의 계산 결과

- 왼손: 중간점 목표에서 위치 오차 약 5.77 mm·접근축 수평 오차 약 7.22°로 실패했다.
  reorient/pregrasp 후보도 조건을 충족하지 못했다. 현재 모델·수치 탐색 결과이며 기구학적 불가능 증명은 아니다.
- 오른손: 세 단계의 수평 IK 조건은 통과했다. 하지만 프리뷰 외곽 검사에서 pregrasp는
  그리퍼 링크와 병, 중간점 접근은 손목·그리퍼 본체와 병의 겹침 후보가 잡혔다.
  현재 표시 가능한 후보는 병에서 떨어진 reorient 자세다.
- 왼손은 순정 죠 실물 TCP·개방폭·재캘리브레이션 대조가 필요하고, 오른손도 형상/장착 변환/충돌 프록시 대조가 필요하다.
  허용 오차를 넓히거나 컵을 관통시키는 방식으로 성공 처리하지 않았다.

다음 구현은 실제 그리퍼 모델과 접촉 중심을 맞추고, 회전 공간을 포함한 연속 경로를 검증한 뒤
접촉 구동으로 닫기·들어올림을 확인하는 것이다. 이번 결과로 컵을 잡거나 병을 들었다고 보고하지 않는다.
