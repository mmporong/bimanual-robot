# SmolVLA 실물 롤아웃 "제자리 떨림" — 원인은 시작 자세 OOD (원인 규명 기록)

최초 작성 2026-10-16 · 조작(IL) 담당자 작성

## 0. 한 줄 요약

실물 롤아웃에서 양팔이 **제자리에서 떨기만 하고 태스크를 수행 못 하던** 증상의
진짜 원인은 **수동으로 맞춘 시작(리셋) 자세가 학습 데이터 분포에서 벗어난 것**이었다.
눈으로는 비슷해 보여도 왼팔 `shoulder_lift`가 약 +26°, `wrist_flex`가 약 -30°
어긋나 있었고, 정책이 "거의 본 적 없는 시작 자세"에서 무엇을 할지 몰라 초기 동작만
하고 그 자리에서 진동했다. 학습 데이터의 실제 시작 자세로 팔을 정밀 이동시키자
정상 수행됐다. 재발 방지 도구: [`tools/rollout/goto_train_start.py`](../../tools/rollout/goto_train_start.py).

> 이 떨림은 2026-10-15에 기록한 "카메라 인덱스·미러 오정렬" 떨림
> (`20261014_로컬_SmolVLA_배포전_검증과_건식롤아웃.md` 10절)과 **증상은 같지만
> 원인이 다른 별개 사건**이다. 떨림(정책이 제자리에서 비수렴)은 "관측 입력이
> 학습 분포와 다르다"는 공통 신호일 뿐, 그 '다름'의 출처(카메라 / 물체 배치 /
> 시작 자세)는 매번 따로 규명해야 한다.

## 1. 증상과 "왜 어제는 되고 오늘은 안 되나"

- 어제(10-15)는 같은 명령·같은 설정(sync, `max_relative_target=20`, 카메라 정상)으로
  태스크를 완주했는데, 오늘(10-16)은 같은 명령으로 양팔이 제자리에서 빠르고 미세하게
  떨기만 했다. 세션 단위로 일관(그날 안에서는 계속 되거나 계속 안 됨)했다.
- **핵심 추론**: calibration 파일은 어제와 동일하다(USB 재연결로 바뀌지 않는다).
  캘리브레이션이 같으면 "같은 읽기값 = 같은 물리 자세"다. 따라서 오늘 리셋 자세의
  관절 읽기값이 학습 분포와 다르다는 것은 **오늘 손으로 맞춘 리셋 자세가 물리적으로
  학습 때와 다른 위치**라는 뜻이다. 어제는 우연히 맞는 자세로 리셋했을 뿐이다.

## 2. 하나씩 배제한 것 (전부 "원인 아님"으로 확인)

추측으로 명령어만 바꿔 반복 재시도하지 않고, 구성요소를 각각 격리해 데이터로 배제했다.

| 확인 항목 | 방법 | 결과 |
|---|---|---|
| 정책·모델·GPU | 하드웨어 없이 같은 입력으로 `predict_action_chunk` 반복 | 어제와 동일 출력, 정상 |
| 지각(카메라 내용) | 오늘 실제 캡처 이미지로 정책 개루프 실행 | 여전히 큰 동작(net ~78°) 출력 → 지각이 정책을 "얼리지" 않음 |
| 모터 읽기·통신 | 토크 ON 고정 상태로 12모터 고주파 읽기 | 전부 std=0, 완벽 |
| 서보 실행 경로 | 정책 없이 직접 만든 부드러운 사인파 명령 | 추종 오차 1°, 완벽(떨림 없음) |
| 서보 내부 상태 | 12V 전원 완전 재투입 | 변화 없음(원인 아님) |

→ **개별 구성요소는 전부 정상인데 실제 폐루프 롤아웃만 실패**. 남은 변수는 "실제
루프에서만 생기는 것" = 시작 조건(관측 내용 + 시작 자세)으로 좁혀졌다.

## 3. 결정적 단서 — 실제 롤아웃에 계측을 심다

실제 롤아웃을 그대로 돌리되 매 틱 (1) 카메라 평균 밝기(frozen 탐지) (2) 정책 명령 vs
실제 관절값 (3) 실제 프레임 저장 — 을 기록했다(방법: `get_observation`/`send_action`
몽키패치). 두 가지가 드러났다:

1. **(처음엔) top 카메라가 얼어 있었다** — 445프레임 전부 동일(std=0). Astra 가상캠
   브리지가 freeze 상태에 빠져 마지막 프레임만 내보내고 있었다. **단, 이것을 떨림의
   유일한 원인으로 단정한 것은 성급했다** — USB 재연결로 브리지를 되살려 top이 라이브가
   된 뒤에도 떨림은 그대로였다. (브리지 freeze는 별개의 실재하는 문제다. 4절 참고.)
2. **팔은 초기 동작 후 "제자리 진동"했다** — 왼팔 `shoulder_lift`가 29°→55°로 들린 뒤,
   컵을 향해 내려가지 않고 **~20초간 53~57° 사이에서 ±2~3°로 진동**했다. gripper도
   열렸다 닫혔다(0.5↔10) 반복하며 못 잡았다. 들린 자세에서 멈춰 떤 것이 "제자리 떨림"의
   정체였다.

## 4. 왜 오래 헤맸나 — 두 가지 판단 실수

1. **top freeze 과잉 귀속**: 실재하는 문제였지만 떨림의 유일 원인으로 단정했다.
   고친 뒤에도 떨려서야 "별개 문제"임을 인정했다.
2. **시작 자세를 합산 거리로 성급히 기각**: 초반에 "12관절 합산 거리로는 크게 안
   벗어남"이라 리셋 자세를 배제했는데, **합산값이 개별 관절의 큰 편차를 가렸다.**
   관절별로 봤어야 했다 — 대부분 관절은 ±수 도인데 `shoulder_lift`·`wrist_flex`만
   20~30° 벗어나 있었다.

또한 검증 방법 자체의 함정: top 카메라를 `cv2.VideoCapture`로 열었다 닫았다 하면 매번
새 프레임을 받아 "라이브"로 보이지만, 실제 롤아웃은 카메라를 한 번 열어 **연속으로**
읽는다 — freeze는 그 연속 읽기에서만 드러난다. **검증은 롤아웃과 같은 읽기 경로로
해야 한다.**

## 5. 원인 확정과 수정

오늘 리셋 자세(왼팔)를 학습 데이터 전체 60개 시작 자세 분포와 **관절별**로 대조:

| 관절 | 오늘 리셋 | 학습 평균 | 편차 |
|---|---|---|---|
| left_shoulder_lift | ~29° | 2.4° | **+26°** |
| left_wrist_flex | ~-79° | -49.7° | **-30°** |
| left_wrist_roll | ~-91° | -99.6° | +9° |
| (나머지 관절) | — | — | 대체로 ±수 도 |

`shoulder_lift`·`wrist_flex`가 분포 꼬리/바깥에 있었다. 이 두 관절은 눈으로 자세를
맞출 때 넓은 범위에서 "비슷해" 보이기 쉬운 자리라, 수동 리셋에서 어긋나기 쉽다.

**수정**: 학습 60개 중 전체 평균에 가장 가까운 실제 에피소드(ep32)의 시작 자세로
양팔을 정밀 이동시켜 고정한 뒤 롤아웃 → **정상적으로 태스크 수행(붓기·적재까지)**.

## 6. 재발 방지

### 6.1 시작 자세를 항상 학습 분포 안으로 (도구)

[`tools/rollout/goto_train_start.py`](../../tools/rollout/goto_train_start.py): 양팔을
학습 시작 자세(ep32)로 4초간 부드럽게 이동시키고 토크로 고정한 채 종료한다. 매 롤아웃
전에 이것을 먼저 실행하면 눈대중 리셋의 OOD 문제를 원천 차단한다.

표준 워크플로:

```
python tools/rollout/goto_train_start.py   # 학습 시작 자세로 고정
lerobot-rollout ... (손대지 말고 바로)       # 이 자세를 캡처해 시작
```

### 6.2 에피소드 종료 후 복귀는 이미 자동이다

`lerobot-rollout`의 `return_to_initial_position`(기본값 True, `configs.py`
`RolloutConfig`)이 **에피소드 종료 시 "시작할 때 캡처한 자세"로 자동 복귀**한다
(`strategies/core.py` `_return_to_initial_position`, 초기 자세는 `context.py`에서
connect 시 캡처). 즉 6.1로 시작 자세를 학습 분포 안에 두면, 복귀 자세도 자동으로
학습 분포 안이 된다 — 복귀를 위한 새 코드는 필요 없다. (episodic 전략은 에피소드
사이에도 `reset_to_initial_position`으로 같은 복귀를 한다.)

### 6.3 Astra 브리지 freeze는 롤아웃과 같은 경로로 검증

top(Astra 가상캠)은 간헐적으로 freeze한다(워치독이 항상 복구하진 못함 — USB 재열거가
필요할 수 있다). 롤아웃 전 top 라이브 여부를 **OpenCVCamera 연속 읽기**(= 롤아웃과
동일 경로)로 확인한다. `cv2.VideoCapture` 개폐 방식으로는 freeze를 놓친다.

## 7. 방법론 교훈

- **떨림(제자리 비수렴)은 "관측/상태가 학습 분포와 다르다"는 신호다.** 원인의 출처는
  매번 달라질 수 있으니(카메라·물체 배치·시작 자세) 하나를 고쳤다고 단정하지 않는다.
- **분포 대조는 합산이 아니라 관절별로 한다.** 합산 거리는 소수 관절의 큰 편차를 가린다.
- **개별 격리가 전부 정상이면 폐루프를 계측한다.** 구성요소를 각각 "정상" 확인한 뒤에도
  실패하면, 실제 루프에 로그를 심어 데이터로 보는 것이 추측보다 빠르다.
- **검증은 실제 사용 경로와 같게 한다**(카메라 연속 읽기 등).
