# 차체 결합 데이터 32개 모델 학습 결과 종합 (실험 기록)

2026-10-28 정리. 차체 결합 핸드오프 데이터로 4개 모델 × 2개 과제 × 데이터 20·40·60·80개 = **32개 모델** 학습이 모두 끝났다.
여기서는 최적 체크포인트와 eval_loss, HF 저장소만 한곳에 모은다. 실물 성능 평가는 [평가 계획](../20261028_IL_모델평가계획과_일반화_발표전략.md)을 따른다.

## 0. 한 줄 요약
- 32개 모두 학습과 HF 업로드가 끝났다. GR00T 8개는 NVIDIA Brev A100, 나머지 24개는 학교 서버(RTX 4090)에서 학습했다.
- 모든 모델에서 데이터가 많을수록 eval_loss가 낮다. 컵배치 20개는 모든 모델에서 크게 나쁘다.
- eval_loss는 모델마다 계산 방식이 달라 **모델끼리(가로) 비교하면 안 된다.** 같은 모델의 데이터 수별(세로) 경향만 본다.

## 1. 학습 조건
- 데이터: `jun-seo/water-pour-position-jitter-gravel-chassis-mounted-handoff-v1(-part2)`, `jun-seo/cup-place-position-jitter-gravel-chassis-mounted-handoff-v1(-part2)` ([데이터 인덱스](../../data/README.md)).
  - 80개는 part2 20개를 v1 앞에 붙인 것이다. 20·40·60개는 그 앞부분을 잘라 쓴 부분집합이다.
- 4개 모델 모두 같은 데이터·검증셋 비율·조기 종료 규칙(eval_loss가 3번 연속 나아지지 않으면 종료)을 썼다.
  - 검증셋 비율: 80·60개 0.1, 40개 0.15, 20개 0.3
  - 데이터 수마다 검증 에피소드가 다르다. 그래서 같은 모델 안에서도 데이터 수 간 비교는 엄밀하지 않다.
- 최적 체크포인트 하나만 HF에 `jun-seo/<모델명>_<step>S` 이름으로 올렸다.
  - 2026-10-27부터 새 모델은 public이다(HF private 무료 한도 초과, 사용자 결정).

## 3. 관찰
- **데이터 수**: 모든 모델·과제에서 80 → 20으로 갈수록 eval_loss가 커진다. 순서가 뒤집힌 곳은 없다.
- **컵배치 20개**: 모든 모델이 크게 나쁘다.
  - SmolVLA 20과 π0 20은 500 step이 최적이었다. 사실상 처음부터 검증 손실이 나빠지기만 한 것이다.
  - 20개(검증 6개)로는 컵배치를 배우기 어렵다고 본다. 원인은 실물 평가 전이라 확정하지 않는다.
- **최적 step이 마지막인 모델**: GR00T 물따르기 80·40, π0 물따르기 80 근처가 이에 해당한다.
  - 최대 step까지 손실이 계속 내려갔다. step을 더 주면 더 낮아질 수 있다.
- **모델 간 순위는 이 표로 정하지 않는다.**
  - GR00T는 flow matching 손실, π0도 flow matching 손실이지만 정규화와 action 차원 처리 방식이 다르다.
  - ACT는 L1 + KL이다. 숫자 크기를 직접 비교할 수 없다.
  - 모델 간 비교는 실물 롤아웃 성공률이나, 같은 시험 에피소드에 대한 행동 MAE(도 단위)로 한다.
