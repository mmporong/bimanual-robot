# 차체 결합 상태 핸드오프 데이터 수집 — 레포 구성·HF 시각화 64개 한계·에피소드 정리 (기록)

최초 작성 2026-10-26 · 조작(IL) 담당자 작성 · 대상 기간 2026-10-23 ~ 10-25

## 0. 한 줄 요약

양팔을 차체에 결합한 상태로 물따르기→컵배치 핸드오프 데이터를 새 레포에 모았다. 최종 구성은 다음과 같다.
- **`-v1` 60개(학습 본편)**, **`-part2` 20개(추가분)**, 각각 물따르기와 컵배치 한 쌍씩이다.
- 수집 도중 HF 시각화 사이트가 에피소드 64번부터 못 찾는 문제가 생겼다. 원인은 사이트 라이브러리가 메타 파일을 64개까지만 읽는 한계였다.
- 병합(merge) 결과에서 메타 인덱스가 잘못 기록되는 문제도 찾아서 고쳤다.

  - `DATASET_SUFFIX` 한 줄로 두 레포 이름을 함께 바꾼다.
  - **Ctrl+C를 누를 때까지 라운드를 반복**한다. 이전에는 실행 1번에 1라운드였다.

  - 업로드가 실패해도 세션을 끊지 않는다. 다음 라운드 업로드 때 함께 올라간다.

## 2. HF 시각화 사이트가 64번 에피소드부터 못 찾음

- 증상: `huggingface.co/spaces/lerobot/visualize_dataset`에서 0~63번은 보이는데 64번부터 "Episode 64 not found"가 떴다.
- 원인:
  - 사이트가 쓰는 `@huggingface/lerobot` 0.0.11의 `readEpisodesV3`는 `meta/episodes/` 아래 파일을 **최대 64개(`MAX_INDEX_FILES = 64`)** 까지만 읽는다.
  - 라운드마다 데이터셋을 새로 열어 resume하는 수집 방식이라, 라운드마다 메타 파일이 1개씩 생겼다.
  - 데이터 자체는 정상이었다. lerobot 학습 로더는 전부 읽는다.
- 해결: 수집을 마친 뒤 `lerobot-edit-dataset`으로 메타를 파일 1개로 다시 묶어 올린다. 현재 4개 레포는 모두 메타 파일이 1개다.
- 앞으로 64라운드를 넘기면 같은 문제가 다시 생긴다. 녹화 스크립트 주석에 적어 뒀다.

## 3. 에피소드 이동·병합·정리 이력

| 날짜 | 작업 | 결과 (물따르기/컵배치 동일) |
|---|---|---|
| 10-23 | 64~67번 4개를 새 `-part2` 레포로 이동, 이후 수집은 `-part2`에 쌓음 | v1 64개, part2 4개 → 수집 후 23개 |
| 10-25 | part2 23개를 v1 뒤(64~)에 병합 | v1 87개 |
| 10-25 | 품질 검토 후 7개 삭제(7,10,13,14,17,21,30), 20개를 part2로 이동(28,34,46,49,50,52,53,57,66,67,69,71,73,74,77,78,80,81,84,86, 삭제 전 번호 기준) | **v1 60개, part2 20개** |

- 사용한 도구: `lerobot-edit-dataset`의 `delete_episodes`(`new_root`로 원본을 보존하고 새 폴더에 출력)와 `merge`(`concatenate_videos/data false`).
- **병합 메타 버그:** `merge` 결과의 `meta/episodes/.../file-000.parquet` 안 `meta/episodes/file_index` 열이 0..86으로 기록됐다. 실제 행은 전부 `file-000` 하나에 있었다. 이 상태로 `delete_episodes`를 돌리면 존재하지 않는 `file-001.parquet`을 찾다가 FileNotFoundError가 난다. 해당 열을 실제 파일(0)로 고친 뒤 다시 실행했다.
- HF 반영:
  - `upload_folder(delete_patterns=["data/**","videos/**","meta/**"])`로 원격에 남은 옛 파일을 지웠다.
  - 학습 로더가 `v3.0` 리비전을 읽기 때문에 `v3.0` 태그를 지우고 다시 만들어 main과 같게 맞췄다.
- 확인: 정리 후 각 에피소드의 action이 원본 에피소드와 같은지 대조했다.
- 로컬 백업 (`C:\Users\USER\lerobot-data\`):
  - `_backup_20261024`(68개)
  - `_backup_20261025_premerge`(v1 64 + part2 23)
  - `_backup_20261025_87eps`

## 4. 학습용 80개 데이터 (서버 전용)
- 서버에서 part2 20개 뒤에 v1 60개를 붙여 `...-v1-80`(물따르기 131,953프레임, 컵배치 61,800프레임)을 만들었다.
- **순서를 part2 → v1로 둔 이유:** lerobot의 eval split은 마지막 ceil(n×비율)개를 쓴다. 이 순서면 60개 모델(비율 0.1)과 80개 모델(비율 0.07)이 **똑같은 검증 6개(v1의 54~59번)** 로 평가된다.
- 이 데이터는 HF에 올리지 않았다. part2+v1로 다시 만들 수 있다.
