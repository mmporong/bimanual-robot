## 2. 오늘 확인된 것 (더 안 건드려도 됨)

- **카메라 타임아웃 → 토크 급정지 패치 정상 동작 확인.** `tools/rollout/lerobot_rollout_camera_timeout_resilience.patch`.
  이 패치 + `--robot.{left,right}_arm_config.disable_torque_on_disconnect=false`를 항상 같이 쓴다.
- **"끊김"의 진짜 원인은 카메라/하드웨어가 아니라 SmolVLA 청크 재계산 비용이었다.** 실제
  롤아웃에 타이밍 로그를 심어 측정: 50틱(`n_action_steps=chunk_size=50`, 이미 최대 재사용
  설정)마다 한 번 ~400-500ms GPU 재계산 → 그동안 멈췄다 쌓인 걸 몰아 처리하는 것처럼 보임.
  평균 실효 프레임레이트는 생각보다 높음(~23Hz) — "루프가 계속 느리다"는 초반 판단은 틀렸다
  (경고 로그가 느린 틱에만 개별로 찍히는 걸 "계속 느리다"로 오독했었음).
- **RTC(`--inference.type=rtc`) 비추천.** 한 번은 매끄럽게 잘 됐으나, 사용자 확인으로
  "RTC 켰을 때 더 과격해지는 건 이전 실험들에서도 항상 있었던 패턴" — 이 체크포인트 전용
  문제가 아니라 RTC 자체가 이 정책에 안 맞는 것으로 결론. **당분간 RTC 쓰지 말 것.**
- **`max_relative_target`(스텝당 각도 제한, 참고: `C:\Users\USER\Downloads\towel_act_smooth_motion.md`의
  `MAX_POLICY_RELATIVE_DEG`와 동일 메커니즘)는 원인이 아니었다.** 5°/10°/20° 전부 시도:
  - 5° → 그나마 "조용히" 시나리오를 수행(붓기 정렬은 부정확)
  - 10°, 20° → **양팔 다 제자리에서 떨기만 하고 태스크 수행 자체를 안 함** (둘이 똑같은
    증상이라 클램프 "크기"가 원인이 아님 — 클램프는 크기만 제한하지 방향이 계속 바뀌는 건
    못 막는다)
  - 단위 확인함: `ensure_safe_goal_position`에 들어가는 값은 `sync_read(..., normalize=True)`
    기본값이라 **degree 맞음**, tick 단위 혼동 아니었음 (코드: `so_follower.py` `send_action()`)

## 3. 안 풀린 문제 — 제자리 떨림

**증상**: 리셋 자세에서 시작하면 양팔이 명확한 방향으로 움직이지 못하고 그 자리에서 떤다.
태스크를 아예 시작하지 못함(5° 때와 다름 — 그때는 그나마 수행은 했음).

**현재 가설(미검증)**: 떨림은 보통 정책이 "낯선 입력"을 보고 확신을 못 해 틱마다 서로 다른
(상쇄되는) 방향을 내놓을 때 나타나는 패턴이다. 오늘 여러 차례의 수동 리셋(토크 OFF 상태에서
손으로 자세 맞춤)이 **학습 데이터의 실제 시작 자세와 정확히 일치하지 않았을 가능성**이 있다 —
"비슷해 보인다"만으로 확인했지, 학습 데이터 첫 프레임 이미지와 픽셀 단위로 대조한 적은
없다.

**다음 세션이 바로 시도해볼 것** (하드웨어 미접근, 이미지만 비교):
```python
from lerobot.datasets.lerobot_dataset import LeRobotDataset
dataset = LeRobotDataset("jun-seo/water-pour-position-jitter-v1", episodes=[14])
first_frame = dataset[0]  # top/left_wrist/right_wrist 이미지 키 포함
# 이 이미지들을 파일로 저장해서, 지금 리셋한 실물 자세와 나란히 비교
```
이 비교에서 뭐가 다른지(팔 각도, 물체 위치, 카메라 화각) 찾아서 리셋 절차를 교정하는 게
다음 핵심 작업이다. 이게 아니라면 다음으로 의심할 것: (a) 오른쪽/왼쪽 손목캠 인덱스가
정말 맞는지(오늘 두 번 바뀐 전력 있음 — 눈대중 구분이 어려운 자리), (b) 그리퍼 외형이
학습 때와 달라졌는지(그리퍼 재조립 이력 있음, `20261013_캘리브레이션_복구가능성_쉬운설명.md`
참고).

## 4. 오늘 겪은 안전 관련 사건 (참고용, 비난 아님)

- 토크 꺼진 채 방치된 팔이 중력으로 처져서, 그 낯선 자세로 바로 정책을 돌렸다가 과격한
  움직임 2회 발생 — **토크 끈 뒤 다시 켜기 전엔 반드시 수동으로 리셋 자세부터 맞출 것.**
- 왼팔 `configure()` 도중(토크 순서대로 켜는 중) 통신 끊김 2회(id=4, id=5) — USB 재연결
  직후 발생, 예외가 나면서 **일부 관절만 토크 ON인 채로 비정상 종료**될 수 있다. 이런 경우
  다음 실행 전에 꼭 수동 리셋부터.
- `lerobot-rollout`을 중간에 멈춰야 할 때, 터미널에서 직접 돌리면 `Ctrl+C`로 바로 끊을 수
  있다 — 그래서 지금은 **사용자가 직접 터미널에서 실행하고, Claude는 명령어(.ps1 파일)만
  준비하는 방식**으로 바꿨다. 이 방식을 유지할 것.

## 5. 환경 잡학 (오늘 또 밟았던 함정들)

- PowerShell에 `tail`/`head` 없음 — `Get-Content -Tail N` / `Select-Object -First N` 사용
- 긴 명령을 터미널에 직접 붙여넣지 말 것 — `.ps1` 파일로 저장해 실행
- 한글 경로 + `cv2.imwrite()`는 Windows에서 조용히 실패함(반환값 안 보면 성공한 줄 착각) —
  `cv2.imencode()` + `Path.write_bytes()`로 우회
- 모든 파이썬 실행 전 `$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"` 안 하면 한글
  경로 출력이 깨지고, 간헐적으로 파일 쓰기 자체도 깨짐
- `git diff --check`가 패치 파일(`.patch`)의 빈 컨텍스트 줄(공백 1칸)을 trailing whitespace로
  잡는다 — 새 `.patch` 파일을 커밋하기 전에 로컬에서 `git diff --check`로 미리 확인할 것
