# 프로젝트 정의 — 데스크톱 시료 취급 셀

작성 2026-08-20 · 근거: [R1](../research/R1_양팔_동시_텔레옵.md) · [R7](../research/R7_해외_양팔로봇_회사와_실배치.md) · [R8](../research/R8_하드웨어_제약과_태스크_확정.md)

## 한 문장

**실험실에서 사람이 하던 시료 용기 취급 작업을, 양팔 로봇이 시연 학습으로 수행하는 데스크톱 작업 셀.**

원본은 **ABB YuMi 기반 실험실 워크스테이션**이다. YuMi는 2015년 출시된 세계 최초 협동 양팔 로봇으로 소형 부품 조립과 의료·제약 실험실에 상용 배치돼 있고, Copan Wasp는 YuMi 기반 바이오세이프티 워크스테이션으로 조직·체액 샘플을 다룬다. 우리는 그 워크플로에서 **용기 개폐와 내용물 이송**만 떼어 테이블탑 규모로 축소한다.

## 왜 이것인가

| 기준 | 근거 |
|---|---|
| 원본이 뚜렷하다 | ABB YuMi가 10년째 같은 용도로 팔리는 상용 제품. "YuMi 워크스테이션의 데스크톱 버전"으로 한 문장 설명이 된다 |
| 양팔이 물리적으로 필수다 | 뚜껑을 돌리면 반작용 토크가 몸체에 걸린다. 한 손이면 용기가 같이 돌아 안 열린다. **고정을 놓는 순간 무너지므로 시간 분리가 불가능** — 단팔 두 대로도 순차 녹화로도 대체 불가 |
| 하드웨어가 이 동작을 지원한다 | `wrist_roll`이 `full_turn_motor`로 지정된 전회전 축. 대부분의 저가 팔은 손목 롤이 제한 각도만 돈다 |
| 제약을 통과한다 | 빈 용기 수십 g(페이로드 여유) · 나사산 자기정렬(백래시에 관대) · 뚜껑 축 수직이면 5축으로 충분 · 용기 하나가 양팔 교집합에 들어옴 |

## 시스템 구성

```
[명령 입력]  주문서 / 작업 지시 (팀 웹·음성 파트와 접속)
     ↓
[인식]      RGB-D → 용기 위치·자세, 뚜껑 개폐 상태
     ↓
[조정]      arbiter — 태스크 단계에 따라 IK 경로와 IL 정책을 선택
     ├─ IK 경로   : 접근·이송 (규칙으로 충분한 구간)
     └─ IL 정책   : 고정·회전·이송 (규칙으로 못 쓰는 구간)
     ↓
[실행]      양팔 제어 + 안전 래퍼(스톨 감지·도달 검사·토크 한계)
     ↓
[판정·기록] 성공 판정, 실패 유형 분류, 에피소드 메타데이터 기록
     ↓
[개선]      HIL 개입 수집 → 재학습 → 재평가
```

**IK와 IL을 같은 인터페이스로 감싸 단계별로 갈아끼운다.** 접근처럼 규칙으로 충분한 구간에 학습을 쓰지 않고, 고정·회전처럼 규칙을 못 쓰는 구간에만 학습을 쓴다. 이 구분 자체가 산출물이다.

## 태스크 계단

네 개를 같은 파이프라인·같은 프로토콜로 통과시킨다. 하나씩은 평범하지만 계단 전체는 "일반화가 어디서 무너지는가"라는 질문이 된다.

| # | 태스크 | 등급 | 무엇을 검증하나 |
|---|---|---|---|
| **T1** | 랙 → 작업대 용기 이송 | B0 | 파이프라인 관통, 인프라(캘리브·핸드아이·판정) |
| **T2** | **용기 고정 + 뚜껑 회전 개방** | **B2** | 양팔 협응. **단팔 대조군이 여기서 0%로 나온다** |
| **T3** | 내용물 이송 (용기 유지 + 반대 팔이 이송) | B1 | 한 팔이 상태를 유지하는 동안의 다른 팔 작업 |
| **T4** | 뚜껑 재체결 + 랙 복귀 | B2 + B0 | 역방향 협응, 나사산 정렬 |

T1~T4를 이어 붙이면 **하나의 완결된 워크플로**가 된다. 각각 독립 평가하고, 전체 연속 실행도 따로 평가한다.

### 난이도 손잡이

기한 압박에 대비해 각 태스크 안에서 조건을 단계로 나눈다.

| 수준 | 조건 |
|---|---|
| L1 | 용기 1종, 위치 고정 |
| L2 | 용기 1종, 위치 랜덤화(격자) |
| L3 | 용기 2~3종 혼합(지름·높이 다름) |
| L4 | 뚜껑 체결 강도 랜덤화 |

**어디서 멈추든 그 수준까지가 수치로 보고된다.** L1만 되어도 B2 협응을 보인 것이고, L2는 위치 일반화, L3는 물체 일반화, L4는 물리 조건 일반화다.

### 수집량이 기간에 들어가는가

기준선은 **태스크당 시연 50~60회**다 (Mobile ALOHA 50회로 80%, RoboTwin 공식 프로토콜 demo_clean 50개, ACT 60회로 80% — 세 출처가 일치).

- 4개 태스크 × 50회 = **200 에피소드**
- 에피소드당 순수 조작 30초 → 100분
- 리셋·재시도·불량 폐기를 포함해 실측 3~5배 → **5~8시간**

주말 하루씩 두 번이면 들어간다. **수집은 병목이 아니다.** 병목은 캘리브레이션 안정화와 학습 반복이다.

## 산출물과 측정

포트폴리오의 주어는 태스크가 아니라 **파이프라인**이다. 태스크는 그 검증 사례다.

### 측정 지표

| 지표 | 재는 방법 | 역할 |
|---|---|---|
| 조건별 성공률 | 격자 × 반복 N회, **실물 관측으로 판정**(로그 문자열 금지) | 모든 주장의 기반 |
| **단팔 대조군** | 같은 파이프라인에서 한 팔만 사용 | **양팔 필수성을 주장이 아니라 실측으로** |
| **귀무 정책 대조** | 관측 무시하고 평균 궤적만 재생 | 지표가 무언가를 재고 있음을 증명 |
| **HIL 재학습 전후** | 개입 데이터 추가 전/후 동일 격자 | **개선 폭이 곧 성과 수치** |
| 실패 유형 분포 | 아래 분류로 집계 | 진단 체계 |
| IK 대 IL | 같은 격자·같은 판정 | 담당 파트 두 축을 하나의 서사로 |
| 제어 루프 지터 | 틱 간격 분포 | 양팔 동시 제어 안정성 |

### 실패 유형 분류

실패를 "안 됨"으로 세지 않고 유형으로 나눈다. 조건별로 어느 유형이 늘어나는지 표가 나오면 이것이 진단 체계다.

| 코드 | 유형 | 의미 |
|---|---|---|
| F1 | 파지 실패 | 용기나 뚜껑을 잡지 못함 |
| F2 | **고정 실패** | 용기가 함께 회전 — **양팔 협응이 무너진 것** |
| F3 | 회전 중 미끄러짐 | 그리퍼가 뚜껑을 놓침 |
| F4 | 정렬 실패 | 재체결 시 나사산 어긋남 |
| F5 | 도달 실패 | 작업 영역 밖 / IK 해 없음 |

| 리스크 | 신호 | 대응 |
|---|---|---|
| **서보 토크 부족** | 고정하는 팔이 반작용에 밀림 | 가장 큰 리스크. 표준킷 16.5 kg·cm인지 프로킷 30인지 먼저 확인. 부족하면 뚜껑이 헐거운 용기로 교체하거나 지그로 보조 |

| 학습이 수렴 안 함 | 성공률 20% 미만 정체 | L1으로 내려 조건 고정 → 데이터 품질 필터 강화 → HIL 개입 데이터 추가 |

**축소 우선순위**: 태스크 개수 → 난이도 수준 → 측정 항목 순으로 버린다. **단팔 대조군과 실패 유형 분류는 마지막까지 지킨다** — 이 둘이 없으면 "뚜껑 딴 것"으로 남는다.

## 지금 확인할 것

| # | 항목 | 왜 급한가 |
|---|---|---|
| 1 | **표준킷(7.4V/16.5 kg·cm) vs 프로킷(12V/30 kg·cm)** | 고정 토크를 못 버티면 태스크가 성립하지 않는다. **모든 것의 선결 조건** |
| 2 | 두 팔 베이스 간격 실측 | 250~300mm 예상. 교집합 작업 영역이 여기서 결정된다 |
| 3 | 용기 후보 선정 | 지름 30~50mm, 자중 50g 이하, 나사산 뚜껑. **손으로 돌려 필요한 토크를 먼저 가늠하고 서보 스펙 안에 드는 것을 고른다** |
| 4 | USB 4포트 + 카메라 동시 운용 | 대역폭·전원. 카메라는 버스를 분리한다 |
| 5 | 그리퍼가 원통을 미끄러짐 없이 잡는지 | 실패 시 마찰재 필요 |

**순서가 중요하다.** 용기를 먼저 정하고 로봇이 되기를 바라면 안 된다. 서보 토크를 확인하고, 손으로 뚜껑을 돌려 필요한 토크를 재고, 그 안에 드는 용기를 고른다.
