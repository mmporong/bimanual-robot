# 고정 위치 컵 IK 픽앤플레이스 실행 전 준비

## 1. 범위와 완료 기준

SmolVLA로 성공했던 작업셀을 유지하고 왼팔 순정 SO101 죠의 IK 기준선을 비교한다.
이번 준비에는 실물 이동·토크 ON·재보정·EEPROM 쓰기를 포함하지 않는다.
현행 `calibration/bi_follower/arms_left.json`·`arms_right.json`은 그대로 사용한다.

구현 순서:

`시작 상태 → 위쪽 접근 → 컵 중간 수평 정렬 → 접근 → 닫기 → 상승 → 다른 위치로 이송 → 내려놓기 → 열기 → 후퇴 → 위쪽으로 빠지기`

- `tools/ik_pick_place.py`: 실측 입력 검증, IK 중간점, 보정/raw 바인딩, 로봇 경로 감사, 6축 mock, 읽기 snapshot, 명시 실행.
- `tools/simulate_fixed_ik_pick_place.py`: 같은 packet의 양자화된 목표를 Isaac 순정 죠 접촉 시험으로 전달한다. 컵을 손에 부착하거나 이동시키지 않는다.
- `config/ik/fixed_cup_pick_place_simulation.json`: 합성 회귀 입력. 실물 실행에는 사용할 수 없다.
- 실행 packet·snapshot·결과는 저장소 밖에 남기며 코드·규격만 커밋한다.

소프트웨어 순서 완성과 실물 성공은 다르다. 서보가 목표에 도달해도 컵이 손에 없거나 책상 위에서 밀렸을 수 있다.
`sequence_completed`와 `physical_grasp_verified`·`physical_task_verified`를 분리한다.
후자의 두 필드는 이 실행기에서 자동으로 참이 되지 않는다. 영상·실물 관측으로 별도 판정한다.

## 2. 필요한 실측 입력

실행기에는 없는 실측값을 추정해 채우지 않는다. `template`은 미확인 값을 `null`로 만든다.
좌표 원점은 URDF의 `base_footprint`, 길이는 m다. 카메라 좌표·팔 베이스 좌표를 섞지 않는다.

| 설정 | 입력 방법/의미 |
|---|---|
| `cup_center_m` | 컵 몸통 중간 XYZ. Z = 작업대 윗면 + 컵 높이/2 |
| `place_center_m` | 놓을 위치의 컵 중간 XYZ. 현재는 같은 높이의 같은 작업대만 지원 |
| `table_surface_z_m`, `cup_height_m`, `cup_radius_m` | 실물 작업대·컵 치수. 물체 충돌 계산 완료를 뜻하지 않음 |
| `contact_center_tool_m` | 순정 죠가 컵 중간을 잡는 접촉 중심의 `left_tool0` 상대 위치. 시뮬레이션 후보를 실측 TCP로 바꾸지 않음 |
| `start_joint_deg`, `start_gripper_percent` | 왼팔 읽기 snapshot 값. 임의 RESET 자세를 현재 자세로 쓰지 않음 |
| `right_parked_deg`, `right_gripper_percent` | 오른팔 읽기 snapshot 값. 실행 중에도 오른팔은 쓰지 않고 대조만 수행 |
| `right_gripper_m` | 오른손의 현재 개구에 대응하는 URDF 직선 관절값. percent와 m는 서로 다른 단위 |
| `open_percent`, `close_percent` | 같은 컵·죠에서 확인할 실물 개구 목표. 컵을 관통하는 완전 닫힘 목표를 강요하지 않음 |
| `gripper_open_rad`, `gripper_close_rad` | 위 두 percent 목표에 대응하는 순정 왼손 URDF 회전 관절값. percent=rad 자동 변환 금지 |
| 접근·상승·후퇴 거리 | `reorient_backoff_m`, `reorient_height_m`, `pregrasp_backoff_m`, `pregrasp_height_m`, `lift_distance_m`, `withdraw_distance_m`. 기구·작업대 여유에 맞게 지정 |
| `lowering_offset_m` | 놓는 목표의 추가 하강 여유. 0~3 mm만 허용. 실물에서는 TCP·개구 대응 오차와 받침 상태를 확인해 지정 |
| `provenance` | `status=user_measured`, ISO 날짜 `measured_at`, 적용 기체·배치·죠를 적은 `valid_for` |

캘리브레이션 JSON은 관절 인코더 대응값이며 작업대 좌표·TCP·그리퍼 물리 개구를 측정한 파일이 아니다.
현재 저장소에는 이 실행기에 필요한 실측 작업셀 설정이 없으므로 이를 채우기 전에는 연결만으로 실행 준비가 끝났다고 말하지 않는다.
상단 RGB 카메라 1대와 손목 RGB 2대의 자동 인식은 이번 고정 좌표 기준선의 필수 조건이 아니다.

## 3. 포트 없이 전체 소프트웨어 검증

```bash
cd "$HOME/bimanual-robot"
mkdir -p "$HOME/.local/state"
IK_RUN_DIR="$(mktemp -d "$HOME/.local/state/ik-pick-place.XXXXXX")"
python3 tools/ik_pick_place.py template --output "$IK_RUN_DIR/workcell.json"
python3 tools/ik_pick_place.py prepare \
  --config config/ik/fixed_cup_pick_place_simulation.json \
  --output "$IK_RUN_DIR/simulation-plan.json"
python3 tools/ik_pick_place.py mock \
  --plan "$IK_RUN_DIR/simulation-plan.json" --output "$IK_RUN_DIR/mock-result.json"
python3 -m pytest -q tools/test_ik_pick_place.py tools/test_cup_contact_place.py
```

`prepare`가 경로 감사에 실패하면 packet과 첫 실패 sample을 저장하고 exit 2로 끝낸다.
실패 packet도 mock에서 상태기계·정지 처리를 시험할 수 있지만 실물 실행에는 사용할 수 없다.
기존 파일은 덮어쓰지 않는다. 재시험에는 새 파일명을 사용한다.
빠른 Isaac 진입에는 `prepare --ik-only`를 사용할 수 있다. 이 packet의 CPU 감사는 `not_run`이며,
실물 실행 전에는 `check` 또는 실행 전 감사가 완료돼야 한다. 생략 상태를 통과로 표시하지 않는다.

Isaac 시험은 같은 packet을 사용한다. 이 환경에서는 설치된 Isaac 5.1 Python을 쓴다.

```bash
PYTHONNOUSERSITE=1 "/data/$USER/conda-envs/leisaac/bin/python" \
  tools/simulate_fixed_ik_pick_place.py --plan "$IK_RUN_DIR/simulation-plan.json" \
  --output-dir "$IK_RUN_DIR/isaac" --headless
```

연속 영상 프레임을 저장하지 않고 초기·최종 PNG, 계획·결과·USD를 남긴다.
이 시험은 가정 TCP·마찰·강체 컵·고정 베이스·시뮬레이터 정답 좌표 조건이며 실물 정밀도 검증이 아니다.
Isaac 접촉 시험의 자가충돌은 비활성화돼 있다. 별도의 CPU 로봇 경로 감사 결과와 합쳐 읽는다.
실제 모터 추종 시간과 Isaac 물리 드라이브 시간도 같다고 보장하지 않는다.
실물 버스에는 6축 목표를 순차 전송한다. 모터의 시간 동기 추종과 보간 샘플 사이의 실제 궤적은 실물 비교에서 확인해야 한다.

## 4. 연결 후 읽기 확인과 실측 계획 생성

다음은 이후 연결 시 사용할 명령이며 이번 작업에서 실행하지 않는다.
포트가 둘이므로 `/dev/serial/by-id/`의 왼팔·오른팔 경로를 각각 지정한다.
아래 변수에 실제 경로를 넣어 사용한다. 카메라와 다른 프로그램의 모터 포트 점유는 별도로 정리한다.

```bash
cd "$HOME/bimanual-robot"
mkdir -p "$HOME/.local/state"
IK_RUN_DIR="$(mktemp -d "$HOME/.local/state/ik-pick-place.XXXXXX")"
LEFT_ARM_PORT="/dev/serial/by-id/왼팔보드"
RIGHT_ARM_PORT="/dev/serial/by-id/오른팔보드"
python3 tools/ik_pick_place.py snapshot --port "$LEFT_ARM_PORT" \
  --calibration calibration/bi_follower/arms_left.json --output "$IK_RUN_DIR/left-state.json"
python3 tools/ik_pick_place.py snapshot --port "$RIGHT_ARM_PORT" \
  --calibration calibration/bi_follower/arms_right.json --output "$IK_RUN_DIR/right-state.json"
python3 tools/ik_pick_place.py template --output "$IK_RUN_DIR/workcell.json"
```

snapshot은 6축 위치·토크·저장 homing offset을 읽는다. 온도·부하를 읽거나 쓰기 명령을 보내지 않는다.
offset이 저장소 보정과 다르면 중단하고 차이를 보고한다. 자동 재보정·offset 재기록은 하지 않는다.
snapshot의 값과 실측 작업셀 값을 `workcell.json`에 채운 뒤 아래를 실행한다.

```bash
python3 tools/ik_pick_place.py prepare --config "$IK_RUN_DIR/workcell.json" \
  --output "$IK_RUN_DIR/plan.json"
python3 tools/ik_pick_place.py check --plan "$IK_RUN_DIR/plan.json" \
  --output "$IK_RUN_DIR/check.json"
python3 tools/ik_pick_place.py mock --plan "$IK_RUN_DIR/plan.json" \
  --output "$IK_RUN_DIR/mock.json"
```

보정·URDF·설정·packet 해시와 모든 중간점/raw를 대조한다. 보정이나 시작 자세가 바뀌면 같은 packet을 재사용하지 않는다.
5축 degree 변환에서는 보정 중점을 사용하고 offset을 다시 더하지 않는다.
그리퍼는 LeRobot `RANGE_0_100`의 drive mode 방향을 적용한다. 5축 DEGREE에 이 반전을 덧붙이지 않는다.
arm raw 반올림과 gripper raw 절삭은 각각 기존 실행기·LeRobot 규약을 유지한다.
그리퍼 rad 대응은 양자화된 두 raw 끝점으로 계산해 닫힘의 절삭 오차가 음수 각도로 번지지 않게 한다.
오른손 percent/m 대응과 왼손 percent/rad 대응은 같은 개구에서 확인한 값으로 함께 기록해야 한다.
실측 대응값을 제공했다는 `user_measured` 기록 외에 자동 개구 측정은 하지 않는다.
각 중간점은 raw로 양자화한 뒤 FK 위치·수평 자세 오차도 다시 검사한다.
새 경로의 IK 수렴 기준은 모델 내부 위치 0.1 mm·수평축 0.1도다. 실물 정밀도 수치가 아니다.
재정렬·접근은 검증된 명목 끝점 사이 관절 경로를 쓰고, 상승·이송·하강·후퇴는 5 mm 이하 Cartesian 중간점을 풀어 연결한다.
Python/NumPy 환경 간 미세 부동소수 차이는 작은 각도·위치 허용오차로 비교하지만 raw 명령은 정확히 대조한다.

## 5. 실제 실행 단계의 동작

실물 이동을 요청받은 다음에만 `execute`를 사용한다. 이번 준비 작업에서 이 명령은 실행하지 않았다.

```bash
python3 tools/ik_pick_place.py execute --plan "$IK_RUN_DIR/plan.json" \
  --port "$LEFT_ARM_PORT" --right-port "$RIGHT_ARM_PORT" --observed-workcell \
  --output "$IK_RUN_DIR/physical-result.json"
```

- 실측 설정, 서로 다른 좌우 포트, 로봇 샘플 경로 감사 통과를 먼저 검사한다.
- 왼팔 6축 시작 위치는 계획과 15 tick 이내이고 토크가 모두 꺼져 있어야 한다. 시작 위치가 다르면 토크 ON 전에 거절한다.
- 오른팔 offset·raw·토크 상태를 읽고 기준과 대조한다. 이동 waypoint 전에도 다시 대조하며 오른팔 명령은 쓰지 않는다.
- 첫 접근부터 단계별 관측 확인을 받는다. 상승 전에는 파지, OPEN 전에는 책상 지지, 후퇴 전에는 분리를 확인한다. 자동 영상 판정은 아니다.
- Isaac은 접촉 센서로 책상 지지를 확인하면 하강 목표에 도달하기 전 멈춘다. 실물 실행기는 같은 힘 센서가 없어 이 동작을 자동 재현하지 않는다. 하강 여유·컵 지지는 감독자가 확인한다.
- 확인 입력은 30초 제한이다. `q`, EOF, 확인 거절, Ctrl-C·SIGTERM, 통신 실패, 목표 readback 실패, 위치 발산, 스톨은 다음 단계로 진행하지 않는다.
- 온도·부하를 읽거나 해당 값으로 멈추지 않는다. 목표 미도달 0.5초 스톨·도달 timeout은 정지한다. CLOSE의 목표 미도달도 파지 성공으로 바꾸지 않는다.
- 성공·실패 모두 현재 위치를 목표로 보내고 토크 OFF, 원래 speed·accel 복원 및 readback을 수행한다. 일부 ID가 응답하지 않아도 다른 ID의 정지를 시도하고 `stop_errors`에 남긴다.
- 토크 OFF에서 팔·컵이 떨어질 수 있으므로 실물 시험에서는 받침·빈 컵·주변 확보가 필요하다. 소프트웨어 정지가 기체를 물리적으로 지지하지는 않는다.

실행 시 물체·외부 책상 충돌은 관측 확인에 의존한다. CPU 감사는 로봇 링크·상판·마스트·LiDAR 및 반대 팔을 10 tick 간격으로 검사한다.
샘플 사이의 연속 충돌 부재, 컵과 모든 링크의 접촉 허용 집합, 실제 TCP 오차·컵 변형·그립 힘은 아직 검증하지 않는다.
따라서 이 버전은 감독형 고정 셀 시험기이며 완전 무인 실행기는 아니다. `--observed-workcell`만으로 미검증 항목을 통과했다고 기록하지 않는다.

## 6. 실패 데이터와 다음 비교

실행 결과에는 완료한 phase, 관측 거절/통신/위치 증상, raw 도달 기록, 정지·복원 오류를 남긴다.
모터 움직임 로그에 물리 성공을 억지로 채우지 않는다. 컵 원위치·놓은 위치와 그리퍼/컵이 함께 보이는 영상을 별도로 보존한다.

실제 첫 비교는 SmolVLA 성공 배치의 컵·죠·카메라를 유지한 고정 컵 한 건이다.
IK의 목표 위치 오차, 파지 전 밀림, 상승 중 미끄러짐, 놓기 중 접촉, 분리 후 컵 안정성을 관찰한다.
실패 원인은 우선 연결·좌표·로직·데이터·측정 순서로 배제한다. 실패 원본을 성공 IL 시연으로 섞지 않는다.
RGB 인식·평면 보정과 오른팔 물붓기·주행 연동은 이 기준선의 실물 비교 뒤 진행한다.
