# 모델별·데이터 개수별 비교 실험 계획
 
동일 태스크(물병과 컵을 각각 들어 물을 따른 후 물병 원상복구 & 컵은 지정된 위치로 place)를 여러 모방학습 모델과 여러 데이터
개수로 학습·평가해서 "어떤 모델이, 데이터가 얼마나 있을 때 잘 되는지"를 표로 정리하기 위한 실험 계획.

## 왜 이 실험을 하는가

팀이 목표로 하는 직무(휴머노이드 모방학습 엔지니어)의 채용 요건에 ACT, LeRobot, OpenPi,
GR00T, Gemini Robotics 등 여러 VLA(Vision-Language-Action) 모델 경험이 명시돼 있다. 
지금까지 ACT 1개, SmolVLA 1개 모델만 각각 한 가지 데이터 양으로 학습해봤는데, 이것만으로는 "모델 선택"과
"데이터 양"이 성능에 각각 얼마나 영향을 주는지 구분할 수 없다. 
그래서 모델과 데이터 개수를 축으로 격자(그리드)를 만들어 체계적으로 비교한다.

## 실험 대상 모델 (4개)

| 모델 | 왜 골랐나 | 비고 |
|---|---|---|
| **ACT** | 채용 요건에 명시. 이미 이 프로젝트에서 1회 학습·롤아웃 완료 | VLA가 아닌 가벼운 모델 — 비교의 기준점(베이스라인) 역할 |
| **SmolVLA** | LeRobot에 기본 내장된 VLA. 이미 1회 학습 경험 있음 | 가장 가벼운 VLA (약 4.5억 파라미터) |
| **pi0** (OpenPi 계열) | 채용 요건에 명시("OpenPi") | SmolVLA보다 큰 모델. Physical Intelligence 사에서 공개 |
| **GR00T** | 채용 요건에 명시. 직무명(휴머노이드)과 가장 직결 | NVIDIA의 로봇 파운데이션 모델 |

**실험에서 뺀 모델과 이유**

- **Gemini Robotics**: 구글의 비공개(폐쇄형) API 모델이라, 우리 로봇 데이터로 직접 파인튜닝할 방법이 없다.
 "검토는 했으나 접근 불가"로만 문서에 남기고 실제 실험은 하지 않는다.
- **OpenVLA**: 채용 요건 중 "우대사항"에만 있어 필수는 아니고, 모델 크기가 커서(약 70억파라미터) 
 지금 GPU(RTX 4090, 팀원과 공유)로 통째로 파인튜닝하기 부담스럽다. 
 4개 모델 실험을 끝내고 여유가 되면 추가로 시도해보는 정도로 남겨둔다.

**실제로 시도했으나 하드웨어 제약으로 중단한 모델**

- **GR00T**: 백본(`nvidia/GR00T-N1.7-3B`) 자체는 접근 가능했으나, 학습 가능 파라미터를 최소화해도
  (LLM·비전 인코더 프리즈) 1B 이상이 남아 서버 GPU(24GB)에서 batch=1조차 OOM. LoRA로 우회하려 했으나
  이 lerobot 버전은 "이미 파인튜닝된 체크포인트 위에서만 LoRA 적용 가능"하도록 막혀 있어(처음부터
  LoRA로 학습하는 경로 자체가 없음), 이 서버 한 대로는 GR00T-20/GR00T-40 둘 다 학습 불가로 판단하고
  중단했다.

## 데이터 개수 (2단계)

**20개 / 40개** 에피소드로 나눠서 각각 학습한다.

- 20 → 40으로 두 배 늘려서, 데이터가 늘수록 성능이 어떻게 변하는지 비교한다.
- **20개 세트는 40개 세트에 완전히 포함**시킨다 (즉 20개 세트 ⊂ 40개 세트) 
  에피소드 구성 자체가 달라지면 "데이터가 늘어서 좋아진 건지, 다른 에피소드라서 달라진 건지" 구분이 안 되기 때문이다.
- 지금 이미 20개(`bimanual_tilt2`)를 모아둔 상태라, 40개까지만 추가로 모으면 2단계가 모두 준비된다.

## 실험 매트릭스

모델 4개 × 데이터 2단계 = **총 8번의 학습**을 진행한다. 
실험ID는 `모델-데이터개수` 형식으로 부른다 (예: `SmolVLA-20`).

| | 20개 | 40개 |
|---|---|---|
| ACT | ACT-20 (완료) | ACT-40 (중단, 재시작 예정) |
| SmolVLA | SmolVLA-20 (완료) | SmolVLA-40 (완료) |
| pi0 | pi0-20 (학습 완료, 로컬 롤아웃 불가) | pi0-40 (학습 완료, 로컬 롤아웃 불가) |
| GR00T | GR00T-20 (실행 불가) | GR00T-40 (실행 불가) |

pi0·GR00T는 SmolVLA보다 모델이 커서 학습 속도가 더 느릴 수 있다. 
GPU를 팀원과 같이 쓰는 상황이라, 8번을 다 돌리는 데 며칠이 걸릴 수 있다는 점을 미리 감안해서 
서버 사용 시간을 조율해두는 게 좋다.

## 평가 방법 (모든 실험에 동일하게 적용)

실험마다 조건이 달라지면 표가 의미 없어지므로, 아래 항목은 8번의 실험 내내 똑같이 고정한다.

1. **평가 시행 횟수**: 학습이 끝난 모델마다 실제 로봇으로 같은 횟수(예: 10회)만큼 반복 시행한다.
2. **성공 판정 기준**: 잡기 성공 여부 / 붓기 성공 여부 / 흘림 여부를 각각 따로 기록한다 —
   "성공/실패"만으로는 어디서 실패했는지 못 보기 때문이다.
3. **체크포인트 선택 기준**: 학습 중 eval_loss가 3번 연속 좋아지지 않으면 자동으로 멈추는
   기능(early stopping)을 8번 실험 모두에 동일하게 적용해서 "각 모델이 낼 수 있는 최선"을
   공정하게 비교한다. 채택하는 체크포인트는 항상 **"가장 최근"이 아니라 "eval_loss가 가장
   낮았던 시점"**의 것으로 고른다 (조기 중단은 그 이후 몇 스텝이 더 진행된 뒤에 걸리므로).
4. **eval_loss만으로 판단하지 않는다**: eval_loss가 낮다고 실제 로봇에서도 잘 된다는 보장은
   없다 (실제로 ACT 모델에서 이런 괴리를 겪었다). 최종 표에는 eval_loss와 실제 성공률을
   **둘 다** 적는다.
5. **하드웨어를 실험 도중 바꾸지 않는다**: 그리퍼 교체·재캘리브레이션처럼 하드웨어가 바뀌면
   그 전/후 실험 결과를 서로 비교할 수 없게 된다. 8번 실험이 끝날 때까지 하드웨어는 그대로
   둔다.
6. **파인튜닝 방식을 표에 같이 적는다**: pi0·GR00T는 모델이 커서 비전 인코더를 얼려두거나
   LoRA 같은 경량 파인튜닝을 써야 할 수도 있다. "모델 자체의 성능"과 "얼마나 열심히
   파인튜닝했는지"가 섞이지 않도록, 어떤 방식으로 학습했는지도 표에 명시한다.
7. **롤아웃 시작 자세를 고정한다**: 매 시행 전 로봇을 녹화 때와 같은 시작 자세로 되돌린 뒤
   시행한다. 시작 자세가 다르면 정책이 분포 밖(OOD) 상태에서 시작해 실제 모델 성능과 무관한
   이상 동작이 나올 수 있다.

## 데이터 품질에 더 신경 써야 하는 이유

20개짜리 세트는 나쁜 에피소드 1개가 전체의 5%를 차지한다. 지금까지 겪었던 카메라 크로스토크
오염이나 인코더 워밍업으로 인한 시작 프레임 밀림([`20260922_녹화_시작프레임_밀림_문제.md`](20260922_녹화_시작프레임_밀림_문제.md)
참고) 같은 결함이 데이터가 적을수록 더 크게 영향을 준다. 
특히 20개 단계 데이터는 평소보다 더 꼼꼼히 검수한다.
