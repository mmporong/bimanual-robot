# 텔레옵 · IL 녹화 사용법 — SO-101 + ggao50 그리퍼

작성 2026-09-10. 이 문서만 보고 **전원 켜기 → 텔레옵 → 녹화 → 학습**까지 가도록 쓴다.
왜 이렇게 하는지는 [`20260909_그리퍼_서보_Phase반전_사고분석.md`](20260909_그리퍼_서보_Phase반전_사고분석.md)에 있다.

순정 그리퍼를 단 두 번째 팔은 [`20260911_순정그리퍼_SO101_텔레옵_IL_사용법.md`](20260911_순정그리퍼_SO101_텔레옵_IL_사용법.md)가 따로 있다. 두 문서를 섞어 쓰면 안 된다.

## 0. 이 구성의 특이점 세 줄

1. 팔로워 그리퍼는 ggao50 랙-피니언이고, 그 서보(ID 6)는 **Phase 76** 이다. 형제 서보(12)와 맞추면 안 된다.
2. 그리퍼는 리더와 방향이 반대라 팔로워 캘리브레이션 JSON 에 **`gripper drive_mode: 1`** 이 들어 있다.
3. lerobot 은 **로컬 패치**가 필요하다 — 연결 때 그리퍼 토크를 50 % 로 낮추는 코드를 끈다 (3절).

## 1. 준비물

| 항목 | 값 |
|---|---|
| 팔로워 보드 | `/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D046653-if00` (12 V) |
| 리더 보드 | `/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D047908-if00` (7.4 V) |
| 파이썬 | `~/miniforge3/envs/lerobot/bin/python` (lerobot 0.6.1, `~/lerobot` 소스 설치) |
| 서보 도구 | `~/bimanual-robot/tools/servo/` (시스템 python3 + pyserial) |
| 캘리브레이션 JSON | **리포 안** `calibration/so_follower/follower.json`, `calibration/so_leader/leader.json` — lerobot 에 `--robot.calibration_dir` / `--teleop.calibration_dir` 로 이 경로를 준다. 복사할 필요 없다 |

포트 번호(`ttyACM0`)는 꽂는 순서에 따라 바뀌므로 **항상 by-id 경로**를 쓴다. 보드가 4개까지 있으니 시리얼(`5B3D046653` 등)로 구분한다.

## 2. 캘리브된 상태로 받기 — 새 기기·새 팀원

캘리브레이션은 두 곳에 있고 둘 다 넘어온다. 서보 EEPROM(오프셋·한계·Phase)은 하드웨어에
붙어 따라오고, lerobot 이 읽는 JSON 은 이 리포 `calibration/` 에 있다. 그래서 새 기기에서는:

```bash
git clone git@github.com:mmporong/bimanual-robot.git ~/bimanual-robot     # 또는 git pull
cd ~/lerobot && git apply ~/bimanual-robot/tools/servo/lerobot_gripper_protection.patch   # 3절 참조
```

이게 전부다. 아래 모든 명령은 `--robot.calibration_dir` / `--teleop.calibration_dir` 로 리포의
JSON 을 직접 가리키므로 `~/.cache` 에 복사하지 않는다. 재캘리브레이션은 그리퍼를 다시
물리거나 서보를 바꿨을 때만(4절) 하고, 그 결과 JSON 을 커밋하면 다음 사람에게 넘어간다.

## 2-1. 매번 켤 때

```bash
# 1) 팔로워 12 V 어댑터 → USB 순서로 꽂는다. 리더도 전원 → USB.
ls -l /dev/serial/by-id/            # 두 보드가 보이면 OK

# 2) 서보와 JSON 이 일치하는지 (읽기 전용, 5초)
cd ~/bimanual-robot/tools/servo
python3 servo_check_calibration.py --port /dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D046653-if00 --json ~/bimanual-robot/calibration/so_follower/follower.json
python3 servo_check_calibration.py --port /dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D047908-if00 --json ~/bimanual-robot/calibration/so_leader/leader.json
```

둘 다 `결과: 일치` 면 3절로. `JSON≠서보` 가 나오면 누군가 서보를 만진 것이다 — 4절로 다시 잡는다.

## 3. 텔레옵

### lerobot 로컬 패치 (기기마다 한 번)

lerobot 은 연결할 때 그리퍼 모터에 토크 50 %·과부하 25 % 를 쓴다(스톡 그리퍼 소손 방지). ggao50 은 닫는 데만 35 % 가 필요해서 이걸 켜 두면 힘이 빠진다. 패치는 이 저장소에 있다.

```bash
cd ~/lerobot
git apply ~/bimanual-robot/tools/servo/lerobot_gripper_protection.patch   # 이미 적용돼 있으면 "patch does not apply"
```

적용되면 `SOFollowerRobotConfig` 에 `gripper_protection: bool = False` 가 생긴다. 스톡 그리퍼 팔에서는 `--robot.gripper_protection=true` 로 되돌린다.

### 시작

```bash
/home/lim/miniforge3/envs/lerobot/bin/lerobot-teleoperate \
  --robot.type=so101_follower --robot.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D046653-if00 --robot.id=follower \
  --robot.calibration_dir=$HOME/bimanual-robot/calibration/so_follower \
  --teleop.type=so101_leader  --teleop.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D047908-if00 --teleop.id=leader \
  --teleop.calibration_dir=$HOME/bimanual-robot/calibration/so_leader
```

- 켜지는 순간 팔로워 6축에 토크가 들어가 **리더 자세로 이동**한다. 시작 전에 리더를 팔로워와 비슷한 자세로 두고, 그리퍼는 편 채로
- `Mismatch between calibration values` 가 뜨면 서보와 JSON 이 다른 것 — **여기서 `c` 를 누르지 말고** Ctrl+C 후 2절 점검
- **끝낼 때**: Ctrl+C 하면 토크가 풀려 팔이 떨어진다. 리더로 팔로워를 받침대에 얹은 뒤 끈다

정상 기준: 리더를 쥐면 팔로워가 닫히고, 95 mm 여닫는 데 1 초 안팎, 자세가 리더와 같다.

## 4. 재캘리브레이션 — 그리퍼를 다시 물렸거나, 자세가 어긋나거나, 서보를 바꿨을 때

lerobot 의 `lerobot-calibrate` 는 이 버스에서 범위가 오염됐다(깨진 패킷이 MIN 0 / MAX 4095 로 박힘). 같은 절차를 검증 붙여서 하는 도구가 `tools/servo/` 에 있고, 결과 JSON 은 lerobot 과 같아서 녹화·학습에 그대로 쓰인다.

**한 팔씩** 한다. 아래는 팔로워 기준이고 리더는 포트·JSON 경로만 바꾼다(그리퍼 옵션은 팔로워에만).

```bash
cd ~/bimanual-robot/tools/servo
F=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D046653-if00
J=~/bimanual-robot/calibration/so_follower/follower.json
```

**① 0점** — 팔을 손으로 들어 **각 관절이 양 끝 사이 대충 중간**인 자세로 만들고(상완 수직, 하완 수평, 손목 일직선, 그리퍼 반쯤 열림) 실행. 1초면 끝난다. 정확할 필요 없고 두 팔이 같을 필요도 없다 — 값이 0/4095 를 안 넘게 하는 용도다.

```bash
python3 servo_home.py --port $F --execute
```

**② 범위** — 실행하면 관절별 MIN/POS/MAX 표가 실시간으로 뜬다. 각 관절을 **끝에서 끝까지** 천천히(손목 롤 제외), 그리퍼는 완전 열림~완전 닫힘. Enter.

```bash
python3 servo_record_ranges.py --port $F --out $J --gripper-drive-mode 1 --gripper-margin 40 --execute
```

`0~4095 오염` 표시가 붙은 관절은 ①에서 그 관절이 중간이 아니었던 것이다. 그 관절만 다시:

```bash
python3 servo_home.py --port $F --only wrist_flex --execute        # 손목을 일직선으로 들고
python3 servo_record_ranges.py --port $F --out $J --only wrist_flex --gripper-drive-mode 1 --gripper-margin 40 --execute
```

**③ 두 팔의 범위 끝을 같게** — lerobot 은 `use_degrees` 모드에서 **기록된 범위의 한가운데를 0점**으로 쓴다. 리더와 팔로워를 **같은 물리적 끝**까지 훑어야 자세가 맞는다. 폭이 서로 10 % 이상 다르면 어느 쪽이 덜 갔는지 확인.

**④ 확인 → 재부팅 → 텔레옵**

```bash
python3 servo_check_calibration.py --port $F --json $J
git -C ~/bimanual-robot add calibration/ && git -C ~/bimanual-robot commit -m "chore(calibration): 팔로워 재캘리브레이션" && git -C ~/bimanual-robot push
```

JSON 을 커밋해야 다음 사람이 캘리브된 상태로 받는다.

**오프셋을 바꿨으면 12 V 를 껐다 켠다.** 켜진 채로 오프셋을 쓰면 재부팅 전까지 제어가 꼬인다(실측). 그다음 3절 텔레옵으로 확인.

## 5. IL 녹화 (`lerobot-record`)

### 카메라 확인

```bash
/home/lim/miniforge3/envs/lerobot/bin/lerobot-find-cameras opencv
```

외부 캠 2대의 `index_or_path`(예: `/dev/video4`)를 적어 둔다. 노트북 내장 캠(`ASUS FHD webcam`, `IR camera`)은 쓰지 않는다. by-path 로 고정하려면 `ls -l /dev/v4l/by-path/`.

### 녹화

```bash
HF_USER=mmporong
/home/lim/miniforge3/envs/lerobot/bin/lerobot-record \
  --robot.type=so101_follower --robot.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D046653-if00 --robot.id=follower \
  --robot.calibration_dir=$HOME/bimanual-robot/calibration/so_follower \
  --robot.cameras="{ front: {type: opencv, index_or_path: /dev/videoX, width: 640, height: 480, fps: 30}, wrist: {type: opencv, index_or_path: /dev/videoY, width: 640, height: 480, fps: 30} }" \
  --teleop.type=so101_leader  --teleop.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D047908-if00 --teleop.id=leader \
  --teleop.calibration_dir=$HOME/bimanual-robot/calibration/so_leader \
  --dataset.repo_id=${HF_USER}/<데이터셋이름> \
  --dataset.single_task="<한 문장 과제 설명, 영어>" \
  --dataset.num_episodes=30 \
  --dataset.episode_time_s=30 --dataset.reset_time_s=10 --dataset.fps=30 \
  --dataset.push_to_hub=false \
  --dataset.streaming_encoding=true --dataset.encoder_threads=2 \
  --display_data=true
```

| 인자 | 뜻 |
|---|---|
| `single_task` | 데이터셋 전체에 붙는 과제 문장. 한 데이터셋 = 한 과제 |
| `num_episodes` | 에피소드 수. 처음엔 2~3개로 짧게 돌려 카메라·프레임 확인 |
| `episode_time_s` / `reset_time_s` | 한 에피소드 녹화 시간 / 물체 되돌려 놓는 시간 |
| `push_to_hub=false` | 로컬(`~/.cache/huggingface/lerobot/${HF_USER}/…`)에만 저장. 올릴 땐 true + `huggingface-cli login` |
| `display_data=true` | rerun 창으로 카메라·관절 실시간 확인 |

녹화 중 키: **→** 에피소드 조기 종료, **←** 방금 에피소드 버리고 다시, **ESC** 전체 종료. 저장은 자동.

### 녹화 전 체크

- 2절 `servo_check_calibration.py` 두 팔 모두 `일치`
- 카메라 2대가 `find-cameras` 에 뜨고 프레임이 나옴
- 텔레옵으로 과제를 한 번 끝까지 해 봄 (그리퍼 방향·자세)
- 팔로워가 정지 자세에 있을 때 **정지 프레임이 길면 학습이 흔들린다** — 에피소드는 동작으로 시작해 동작으로 끝내고, `episode_time_s` 를 과제 길이에 맞춘다

## 6. 학습 (ACT)

```bash
/home/lim/miniforge3/envs/lerobot/bin/lerobot-train \
  --dataset.repo_id=${HF_USER}/<데이터셋이름> \
  --policy.type=act \
  --policy.device=cuda \
  --output_dir=outputs/train/<이름> \
  --job_name=<이름> \
  --steps=50000 --batch_size=8 --save_freq=10000 \
  --wandb.enable=false
```

- 데이터셋이 로컬에만 있으면 `--dataset.root=~/.cache/huggingface/lerobot/${HF_USER}/<데이터셋이름>` 을 함께 준다
- 체크포인트는 `outputs/train/<이름>/checkpoints/` 에 `save_freq` 마다. `last` 는 심볼릭 링크라 **`rm -rf` 하지 말 것**(대상까지 지워진다)
- 0.6 부터 정규화는 정책 프로세서 안에서 한다. 롤아웃 코드에서 직접 정규화하지 않는다

## 7. 자율 실행 (녹화한 정책 돌리기)

```bash
/home/lim/miniforge3/envs/lerobot/bin/lerobot-record \
  --robot.type=so101_follower --robot.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D046653-if00 --robot.id=follower \
  --robot.calibration_dir=$HOME/bimanual-robot/calibration/so_follower \
  --robot.cameras="{ ...녹화 때와 같은 이름·경로... }" \
  --policy.path=outputs/train/<이름>/checkpoints/last/pretrained_model \
  --dataset.repo_id=${HF_USER}/eval_<이름> --dataset.single_task="<같은 문장>" \
  --dataset.num_episodes=5 --dataset.push_to_hub=false
```

카메라 이름(`front`, `wrist`)이 녹화 때와 **같아야** 정책이 입력을 찾는다. 첫 실행은 팔로워 옆에 손을 두고 12 V 를 바로 뽑을 수 있게.

## 8. 하지 말 것

| 금지 | 이유 |
|---|---|
| 서보 Phase(18번) 를 형제와 맞추기 | ID 6 은 76 이 맞다. 12 로 두면 목표 반대로 달아나 그리퍼가 빠진다 |
| 리더-팔로워 방향을 서보 레지스터로 뒤집기 | JSON `drive_mode` 로만. 서보를 건드리면 제어 루프까지 뒤집힌다 |
| 오프셋 바꾼 뒤 재부팅 없이 이동 | 재부팅 전까지 제어가 꼬인다 (실측) |
| 12 V 켜진 채 서보 커넥터 착탈 | 보드가 죽는다 (09-09 에 1대) |
| `lerobot-calibrate` 로 범위 기록 | 이 버스에선 0/4095 오염. 4절 도구 사용 |
| 텔레옵 중 서보 도구 실행 | 같은 포트를 둘이 열면 둘 다 깨진다 |
| `servo_goto.py --speed` 값 남기기 | 구버전이 SRAM 에 속도를 남겨 텔레옵이 느려졌다. 현재는 자동 원복 |

## 9. 문제 해결

| 증상 | 확인 |
|---|---|
| 텔레옵 시작 시 `Mismatch … calibration` | `servo_check_calibration.py` 로 어느 모터가 다른지. 서보를 만졌으면 4절 |
| 팔로워 자세가 리더와 다름 | 두 팔 범위 폭 비교(`servo_check_calibration.py` 표). 다르면 4절 ②③ |
| 그리퍼가 느림 | `servo_read.py --id 6` 에서 Goal_Speed 가 0 인지. 아니면 12 V 재부팅 |
| 그리퍼가 닫을 때 힘이 빠짐 | lerobot 패치 적용 여부(3절). `servo_read.py` 로 ID 6 MaxTq 1000 / OvldTq 80 인지 |
| 어느 축이 목표 반대로 달아남 | 그 서보 Phase 가 바뀌었는지 (`eeprom_after_fix.json` 과 대조) |
| `device reports readiness to read but returned no data` | USB 빠짐 또는 다른 프로그램이 포트 점유 |
| 카메라가 `find-cameras` 에 없음 | 허브 말고 본체 포트, `ls /dev/video*` |
