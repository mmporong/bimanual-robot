# 로컬 카메라 인덱스 매핑

> 기준일: 2026-10-01
> 확인 방법: `pygrabber`(DirectShow 디바이스 열거, cv2.VideoCapture(index, cv2.CAP_DSHOW)와 같은 순서) + Windows PnP 장치 목록 대조
> 이 매핑은 **이 노트북에서 지금 연결된 상태 기준**이다. USB 포트를 바꿔 꽂거나 다른 PC에서 열면 인덱스 순서가 바뀔 수 있다.

## 인덱스 — 이름 매핑

| 인덱스 | 이름 | 비고 |
|---|---|---|
| 0 | ASUS FHD webcam | 노트북 내장 카메라 |
| 1 | USB 2.0 PC Cam | 외장 USB 카메라 (손목캠 후보) |
| 2 | USB 2.0 PC Cam | 외장 USB 카메라 (손목캠 후보) |

## 주의 — 인덱스 1·2는 이름이 동일하다

Windows가 두 대 모두 "USB 2.0 PC Cam"으로 같은 이름을 보고하기 때문에, 이름만으로는 어느 쪽이 왼쪽 손목캠이고 어느 쪽이 오른쪽인지 구분이 안 된다. DeviceID로는 구분 가능하다:

| 인덱스 추정 | DeviceID |
|---|---|
| (둘 중 하나) | `USB\VID_090C&PID_B371&MI_00\8&268B1CAD&0&0000` |
| (둘 중 하나) | `USB\VID_090C&PID_B371&MI_00\7&19691188&0&0000` |

DeviceID와 인덱스(1번/2번)의 정확한 대응은 이 스크립트로는 확정하지 못했다 — **실제로 어느 인덱스가 왼팔/오른팔 손목캠인지는 카메라를 하나씩 손으로 가려보면서 영상이 끊기는 쪽을 눈으로 확인**해야 한다(`python -c "import cv2; cap=cv2.VideoCapture(1); ..."`로 미리보기 띄워서 확인).

## 감지됐지만 영상 캡처 장치가 아닌 것들 (제외)

PnP 목록에는 떴지만 DirectShow 비디오 입력 장치로는 안 잡힌 것들 — 영상 캡처용이 아니므로 인덱스가 없다:

- **ASUS IR camera** — Windows Hello 얼굴인식용 적외선 카메라
- **Camera DFU Device** — IR 카메라의 펌웨어 업데이트 모드, 일반 영상 스트림 아님
- **Windows Studio Effects Camera** × 2 — Windows가 물리 카메라 위에 얹는 가상 효과 레이어, 실제 하드웨어 아님

## 참고

- 저장소에서 계획 중인 **Orbbec Astra S(RGB-D)**는 이번 확인 시점에 이 노트북에 연결되어 있지 않아 목록에 없다. 연결 후 같은 방식으로 재확인 필요.
- 재확인 명령: `python -c "from pygrabber.dshow_graph import FilterGraph; [print(i,n) for i,n in enumerate(FilterGraph().get_input_devices())]"` (conda 환경 `so101_env`의 python 기준, `pygrabber` 패키지 필요)
