# 컵 파지 실패의 오프라인 재검토와 실물 재개 조건

기준일: 2026-09-18. 대상은 9월 17일 왼팔 FinRay 컵 접근 시험이다.
이번 작업은 저장 파일만 사용한다. 팔·베이스·카메라에 접속하지 않으며 토크·레지스터·
캘리브레이션 값을 변경하지 않는다. 실물 파지 성공, 새 물리 모델 검증, 하드웨어 동기 제어 완료를
주장하지 않는다.

> 2026-09-22 결정으로 FinRay는 현행 구성에서 제외됐다. 이 문서는 당시 실패의 근거와 원인
> 분리 기록으로만 보존한다. 순정 죠의 재개 조건은 ID 6 재캘리브레이션, 순정 TCP 확인,
> 마른·젖은 컵 파지 재시험이며 FinRay 범위 `1454~2831`을 재사용하지 않는다.

## 1. 먼저 정정하는 판단

**파지가 성공하지 못했다는 사실과 그 원인을 구분한다.** 이전 인계의 “TCP 정렬 오차로 실패”는
확정 원인이 아니라 가설이다. 다음 문제가 동시에 남아 있다.

| 항목 | 확인된 근거 | 아직 확정하지 못한 것 |
|---|---|---|
| 컵 목표 위치 | 계획은 왼팔 명목 장착 위치에 전방 0.300 m·좌우 0 m를 더한 `(0.320, 0.170)` m 사용 | 사용자가 말한 중앙·전방의 원점/축, 컵 재배치 후 실제 좌표 |
| 카메라 검출 | 저장 사진에서 컵과 병의 좌우 위치가 바뀜. 재배치 계획의 컵 바닥 픽셀은 약 `(103.83, 279.18)` | 검출 픽셀의 미터 단위 좌표. 해당 실행은 픽셀 좌표로 목표를 산출한 것이 아님 |
| FinRay TCP | 당시 실물 손가락은 80 mm TPU, 당시 URDF는 stock jaw 프록시 | 장착 기준 변환, 열림별 유효 파지 중심, 접촉 시 변형 |
| 관절 추종 | 저장 pregrasp 자세는 계획 대비 최대 2.73° 차이 | 움직이는 동안의 모든 관절 시간 궤적 및 동시 도달 |
| 토크 해제 이후 | 뒤의 저장 자세는 pregrasp 계획과 최대 37.98° 차이 | 차이 전부를 중력 처짐만으로 설명할 수 있는지. 컵 재배치·사용자 접촉과 시간 간격을 분리하지 못함 |
| 그리퍼 범위 | ID 6 끝점 재기록 후 저장 범위 `1454~2831`; 닫힘 근처 엔코더 도달 | 컵을 감싼 정도, 접촉력, 안정 파지. 범위 재기록만으로 해결됐다고 할 수 없음 |
| 성공 여부 | 안정 파지·들어 올림을 확인하지 못했고 운반하지 않음 | 영상 가림 때문에 정확한 접촉 위치와 미끄럼 시작 순간은 미확인 |

영상에서 추정한 좌우 약 −0.307 m도 실측값이 아니다. 성공 좌표나 보정 상수로 사용하지 않는다.
IK의 0.14/0.17 mm는 **명목 모델의 풀이 잔차**이며 실제 컵 중심을 그 정확도로 맞췄다는 뜻이 아니다.

## 2. 실물 없이 재현한 비교

`tools/replay_cup_pick.py`는 저장 JSON의 왼팔 5축 순서·유한 숫자를 검증하고 현행 URDF로 FK를
계산한다. 원본 JSON·사진·사용 URDF를 새 출력 폴더에 복사하며 SHA-256 manifest와 HTML을 만든다.
이미지를 수정하거나 카메라를 열지 않는다. 사진과 엔코더의 시간 동기화는 확인되지 않았으므로
옆에 나란히 보여줄 뿐, 사진 위에 TCP를 투영하지 않는다.

같은 pregrasp 계획을 기준으로 한 비교 결과:

| 저장 상태 | 최대 관절 차이 | 계획 자세 FK와 저장 자세 FK 사이 거리 |
|---|---:|---:|
| `holdflow_left_at_pregrasp.json` | 2.7257° | 16.02 mm |
| `holdflow_left_cup_replaced_state.json` | 37.9785° | 150.14 mm |

두 번째 행은 pregrasp 도달 오차가 아니라 **나중에 기록된 다른 자세와의 비교**다. 두 거리 모두
stock TCP 모델상의 차이이며 실물 컵 위치 오차가 아니다. 모델 잔차가 작아도 실행 자세가 달라질 수
있다는 증거로 사용한다. 이 자료만으로 “TCP를 16 mm 고치면 해결” 같은 결론은 낼 수 없다.

재현 명령(출력 폴더가 이미 있으면 덮어쓰지 않고 거부):

```bash
cd ~/bimanual-robot
python3 tools/replay_cup_pick.py \
  --plan /tmp/holdflow_cup_replaced_plan.json \
  --state /tmp/holdflow_left_at_pregrasp.json \
  --state /tmp/holdflow_left_cup_replaced_state.json \
  --image /tmp/holdflow_top_at_pregrasp.jpg \
  --image /tmp/holdflow_top_cup_replaced.jpg \
  --image /tmp/holdflow_top_after_recal_close.jpg \
  --output-dir logs/offline_cup_pick_20260918/replay
```

이번 호스트의 보존 결과는 `logs/offline_cup_pick_20260918/replay/index.html`과 `report.json`이다.
`/tmp`가 사라진 뒤에는 보존 폴더의 `plan.json`, `state_00.json`, `state_01.json`, `image_*.jpg`,
`fk_model.urdf`를 입력으로 써서 다른 새 출력 폴더에 재생할 수 있다. 보존 URDF는 FK 추적용이며
메시가 포함된 독립 시뮬레이터 패키지는 아니다. 로그·사진은 저장소 정책에 따라 Git에 올리지 않는다.
다른 팀원은 코드만 받아서는 이 로컬 사진을 볼 수 없다. 데이터 공유는 별도 승인된 private 경로로 한다.

## 3. FinRay 모델에서 지금 할 수 있는 것과 없는 것

선정 파일은 `design/gripper/finray_80mm_lip3_selection.yaml`이다. 명목 길이 80 mm·립 3 mm·
외곽 80×24.75×24.09 mm만으로 장착 후 TCP를 확정할 수 없다. 기존 65 mm 또는 67 mm와의 길이
차이를 그대로 TCP에 더하는 방식도 쓰지 않는다. 두 손가락은 서로 다른 장착 링크를 따라 움직이고,
유연한 접촉면은 물체에 닿을 때 변형되기 때문이다.

- 오프라인 완료 범위: 현재 TCP에서 가정한 로컬 XYZ 오프셋별 FK 차이와 후보 프레임을 비교한다.
- 실물 모델 반영 전 필요한 값: 고정·가동 손가락의 장착 원점과 축, 열림/닫힘의 무부하 형상,
  접촉 중심, 한 쌍 실측 질량 및 질량중심·관성 추정 근거, 최대 변형 외곽.
- 출처 라이선스 확인 전 원본 STL·파생 G-code를 커밋하지 않는다.
- 후보 프레임은 측정값이 아니다. active URDF의 collision·inertial·TCP를 가정값으로 바꾸지 않는다.
- 충돌 프록시를 나중에 만들더라도 정적 프록시는 TPU 변형·접촉력·젖은 컵 마찰의 검증을 대신하지 않는다.

로컬 선택 STL을 읽어 확인한 외곽은 `80.0×24.74545×24.087 mm`였고 YAML의 SHA-256과 일치했다.
해시 일치는 올바른 파일을 찾았다는 의미이며 라이선스·실물 장착 적합성을 검증한 것은 아니다.
다음 명령은 현행 `left_tool0` 기준 0 mm와 Z +10 mm라는 **민감도 비교용 가정**을 만든다.
현재 모델에서는 `left_cup_tcp`와 `left_tool0` 원점이 같다. +10 mm는 보정 권장값이 아니다.

```bash
cd ~/bimanual-robot
python3 tools/preview_finray_tcp.py \
  --offset-mm 0 0 0 --offset-mm 0 0 10 \
  --joint-deg 0 -25.54 31.56 48.93 -0.09 \
  --output-urdf logs/offline_cup_pick_20260918/finray_candidates.urdf \
  --output-json logs/offline_cup_pick_20260918/finray_candidates.json
```

출력 URDF는 기존 모델 복사본에 빈 고정 프레임만 추가한다. 새 프레임에는 물리·시각 형상이 없고,
기존 모델의 형상은 그대로다. 기본 STL 탐색은 `~/Downloads` 아래에서 파일명과 해시로 수행하며
다른 위치의 파일은 `--stl`로 지정한다. 파일이 없으면 미발견으로 기록하고 가정 프레임 비교만 한다.
기존 출력과 입력·활성 URDF를 출력 대상으로 지정하면 거부한다. 재실행은 새 출력 파일명을 사용한다.

## 4. 감사 경로와 실제 실행을 구분한다

기존 감사는 관절 공간에서 시작→pregrasp→grasp를 보간해 검사한다. 기존 실물 실행기는 각 서보에
같은 속도값으로 목표를 순차 전송한다. 움직이는 각도가 다른 관절에 같은 속도를 주면 공통 진행률을
따라간다고 보장할 수 없다. 목표 도달만 확인해도 중간 경로가 감사 경로와 같아지는 것은 아니다.

또한 당시 감사는 초기 4개 샘플에 충돌·한계 여유 위반을 기록했다. `continuous_path_ready_for_preview`
또는 `--strict` 성공은 초기 접촉 쌍 수가 줄어드는 복구 후보까지 포함한다. 관통 깊이를 확인한 것이
아니며, 거리 `null`과 우측 팔 0° 가정도 실물 간섭 없음의 증거가 아니다.

새 오프라인 스케줄은 단계별 시작·끝을 보존하고 모든 관절에 공통 시간 진행률을 사용한다.
이는 **제어기 입력 후보를 검토하는 단계**다. 실제 버스의 동시 쓰기·통신 지연·관절 추종 오차를
검증하거나 실물 실행기를 교체한 것은 아니다. 시작 자세 차이를 큰 허용치로 덮거나 넓은 도달
허용치로 단계 완료를 인정하면 경로 증거가 끊어진다. 자세가 바뀌면 새 시작 상태로 다시 감사한다.

```bash
cd ~/bimanual-robot
python3 tools/build_pick_schedule.py \
  --plan /tmp/holdflow_pre_move_plan.json \
  --audit /tmp/holdflow_pre_move_audit.json \
  --max-joint-speed-deg-s 20 \
  --sample-period-s 0.1 \
  --output logs/offline_cup_pick_20260918/time_schedule.json
```

20°/s와 0.1 s는 계산 예시 입력일 뿐 승인된 실물 속도·통신 주기가 아니다. 구간별 선형 보간은
속도 상한만 다루며 가속도·jerk 제한은 제공하지 않는다. 실제 추종용 시간법은 별도 검토가 필요하다.
`waypoints`는 감사 시작점과 두 단계 끝점을 보존하고, `samples`에는 공통 진행률·관절각·시각이 있다.
초기 접촉 복구 감사의 출력은 `path_review.classification=start_recovery_only`, `collision_free=false`다.
계획-감사 간 5축 대응·유한 숫자·샘플 수 상한을 검사하지만 모델·보정 파일의 최신성을 인증하는
형식은 아니다. 원본 감사에 모델/보정 해시가 없으므로 저장 산출물을 새 모델의 실행 승인에 재사용하지 않는다.
스케줄과 기존 실행 준비 도구는 입력 계획·감사 파일 및 기존 출력을 덮어쓰지 않는다.

기존 `prepare_pick_execution.py`는 향후 승인된 실물 실행기의 입력을 준비하는 도구로 유지했다.
`ready_for_explicit_motion_approval=true`는 승인 **검토 준비**이지 사용자 승인을 받았다는 뜻이 아니다.
이번 변경은 입력 검증과 복구/무위반 구분만 보강했으며 이 출력을 실물 실행기에 넘기지 않았다.
새 스케줄·FK 재생·TCP 후보 도구에는 하드웨어 실행 기능이 없다.

## 5. 다음 실물 세션에서 한 번씩 분리해 확인할 것

1. **컵 좌표:** 고정된 카메라와 작업대에서 보정 대응점을 잡고, 별도 검증점으로 픽셀→작업대
   오차를 확인한다. 투명컵 bbox 바닥은 실제 접점과 다를 수 있으므로 컵 위치 기준 표식도 함께 기록한다.
2. **그리퍼 모델:** 열린 손가락 사이 기준점과 장착 변환을 측정한다. ID 6 개폐 범위와 TCP 보정은
   별개의 작업이며 팔 1~5축을 이유 없이 다시 캘리브레이션하지 않는다.
3. **빈 공간 추종:** 컵 없이 접근 경로의 명령·관측 관절값을 동일 시간축으로 기록한다. 실행 중 경로와
   감사 경로의 차이를 확인한 뒤 접촉 단계로 간다. 오프라인 스케줄만으로 실물 승인을 대신하지 않는다.
4. **컵 접근·파지:** 컵 위치를 고정한 짧은 시험에서 접근 위치, 감쌈, 닫힘, 유지, 들어 올림을 각각
   판정한다. 파지가 확인되기 전 들어 올림·물 붓기로 넘어가지 않는다.

그때 기록할 최소 묶음은 시도 ID, 모델/계획/보정 해시, 좌표 출처, 컵 재배치 여부, 단계별 시각,
명령·관측 관절값, 원본 상단/손목 영상, 관측 증상과 원인 가설이다. `grasp_missed` 같은 관측 실패와
`tcp_offset` 같은 가설을 분리하고, 원인 하나를 바꾼 뒤 같은 조건으로 비교한다. 손상·가림·시각 불일치가
있는 영상도 원본은 보존하되 성공 판단/학습 포함 근거로 쓰지 않는다.

이번 작업은 실물 재개 요청이 아니다. 카메라 보정·장착 실측·실제 버스 추종은 다음 승인된 실물 세션에
남긴다. 모터 온도·부하를 새로 읽거나 보호 설정을 변경하지 않았다.

검증 명령은 `cd ~/bimanual-robot` 후 `python3 -m pytest -q tools tests -rs`다. 이번 결과는
153 passed·2 skipped이며, 두 생략은 시스템 OpenCV에 ChArUco 보드 생성 API가 없어 발생했다.
신규 오프라인 도구 시험은 모두 실행했다. 저장 자료 CLI 재생·후보 생성·시간 스케줄 생성도 통과했지만,
이는 실물 동작·충돌 안전·파지 성공 검증이 아니다.
