기준일: 2026-09-18. 목적은 로봇 전체와 책상·컵·병을 화면에서 확인하고 저장 자세를 비교하는 것이다.
실물 팔·베이스·카메라·ROS 그래프에는 접속하지 않는다.

> 2026-09-19 추가: 아래 기존 프리뷰와 별개로 **강체 패드 컵 접촉 실험**을 추가했다.
> 실행법과 검증 범위는 문서 마지막 절에 있다. 프리뷰의 빈손 회전과 컵 파지는 서로 다른 실행기다.

> 같은 날 사용자 확인 뒤 수정: 컵 관통과 잘못된 접근 방향이 드러나 기본 자동 재생을 껐다.
> 현재 실행기는 팔 관절 한계와 물체·책상·반대 팔 외곽 겹침을 확인한 후보만 표시한다.
> 실패 후보는 마지막 통과 자세를 유지하며 실패 상태를 표시한다. 물리 접촉 검증은 아니다.
> 현행 작업은 [몸통 중간 측면 파지 재설계](20260918_컵중간_양팔_측면파지_재설계.md)를 따른다.

> 2026-09-22 현행 구성 변경: 왼손은 TPU FinRay를 사용하지 않고 SO-101 순정 회전식 죠를
> 사용한다. 기본 URDF는 이미 순정 죠이므로 형상 교체가 필요 없다. 아래 80 mm 강체 패드와
> FinRay 검토 절은 당시 실험 재현 기록이며 현행 순정 죠 성능 근거가 아니다.

## 실행 범위

- 설치된 Isaac Sim 5.1.0.0을 사용한다. 기존 6.0 importer는 변경하지 않았다.
- 전체 URDF를 import하고 이름으로 5축 관절을 매핑한다. 각도는 degree→radian으로 변환한다.
- 계획 pregrasp/grasp와 명시적으로 제공한 저장 관절 상태를 개별 표시한다.
- 자세 사이 연결은 화면용 cubic 보간이다. 실제 기록된 시간 궤적이나 충돌 감사된 경로가 아니다.
- 오른팔은 가정한 대기 자세로 고정한다. 오른팔 실측 자세나 양팔 협동 실행을 재현하지 않는다.
- 베이스 고정, 로봇 중력 제외, 접촉 제외 상태다. 4점 접촉·전도·파지·물 붓기 동역학 검증이 아니다.
- 실제 센서/그리퍼 구성과 다른 부분, 물체 가정 치수는 GUI와 manifest에 표시한다.

이번 실행기는 [5.1 URDF command API](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/py/source/extensions/isaacsim.asset.importer.urdf/docs/index.html)를 사용한다.
설치본에는 기존 6.0용 스크립트의 `URDFImporter/URDFImporterConfig`가 없다.
`set_joint_positions`는 구동 제어가 아니라 자세를 즉시 배치하는 API이므로, 목표 관절값 일치는
물리 추종 성능이 아니다. [공식 articulation 설명](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/python_scripting/robots_simulation.html) 참조.

## 실행

이 호스트의 설치 Python은 아래 변수로 지정한다. 다른 장비에서는 설치된 **Isaac Sim 5.1**의 Python
경로로 바꾼다. 시스템 Python은 `--check-only`와 단위 시험에만 사용한다.

```bash
cd ~/bimanual-robot
ISAAC_PYTHON="/data/$USER/conda-envs/leisaac/bin/python"
"$ISAAC_PYTHON" tools/simulate_urdf_workcell.py \
  --plan logs/offline_cup_pick_20260918/replay/plan.json \
  --state logs/offline_cup_pick_20260918/replay/state_00.json \
  --state logs/offline_cup_pick_20260918/replay/state_01.json \
  --output-dir logs/isaac_workcell_20260918/manual_01
```

실행 때마다 새 출력 디렉터리를 지정한다. 기존 출력은 덮어쓰지 않는다.
입력 기록이 없는 다른 PC에서는 `--plan`과 `--state`를 생략할 수 있으며, 이 경우 `ASSUMED`
명목 자세 한 개를 표시한다. `/tmp` 자료를 자동으로 찾아 읽지 않는다.
명목 자세는 파지 계획이 아니다.

- `Play / Pause`: 과거 자세 모드에서만 화면용 보간 재생/정지. 기본은 정지이며 외곽 겹침 후보에서 멈춘다.
- `--body-plan`: 새 양팔 몸통 파지 후보 모드. 경로 미검증이므로 자동 보간은 하지 않는다.
- `Next pose`: 보간을 멈추고 다음 개별 자세 표시.
- `Reset`: 양팔 명목 초기 자세로 복귀. 실물 엔코더 홈이 아니다.
- `Empty-hand check`: 팔 들기·손목 방향 확인·복귀만 수행. 컵 접근·닫기·상승은 하지 않는다.
- `--demo --record-demo`: 빈손 검사 자동 실행·녹화. 실행마다 `demo_recordings/run_NNNN/`에
  프레임과 manifest를 분리한다. Reset·재시작·시간 종료·예외는 미완료와 사유로 기록한다.
- `Overview / Front / Top`: 전체·정면·상면 시점.
- `--seconds 20`: 초기 캡처 완료 후 20초 재생하고 종료. 생략하면 창을 닫을 때까지 유지.
- `--headless --seconds 2`: 창 없이 캡처·장면 저장과 짧은 재생 검증.
- `--check-only`: 입력 계약·URDF collision 외곽 로딩을 확인. Isaac 기동·import·렌더 또는 경로 검증을 뜻하지 않는다.

ROS Bridge와 실제 카메라 드라이버는 켜지 않는다. GUI를 닫아도 실물 로봇에는 명령이 전송되지 않는다.

## 산출물과 검증 의미

출력 폴더에는 아래 파일을 만든다. 생성 장면·이미지·로그는 Git 제외이며 코드를 받아도 함께 내려오지 않는다.

| 파일 | 내용 |
|---|---|
| `hold_flow_preview.urdf` | 메시 경로를 확인한 import 사본, 선택한 하단 배치 보정 포함 |
| `workcell.usda` | Isaac 장면. 저장 직후 다시 열어 로봇·책상·컵·병 존재 확인 |
| `pose_00.png` 이후 | 각 입력 자세의 viewport 캡처 |
| `manifest.json` | 원본 해시, 입력 기록 해시, DOF 이름, 가정 치수, 프리뷰 제약, 캡처 결과 |

관절 배치 오차는 입력값을 시뮬레이터 상태에 넣은 결과의 수치 대조일 뿐, 실제 서보 추종 오차가 아니다.
현행 버전은 표시할 팔 자세의 관절 한계를 검사하지만 연속 경로와 전체 충돌 안전은 검증하지 않는다.
초기 `gui_final` 기록의 `joint_limits_validated=false`는 당시 실행 범위를 보존한 것이다.
물체를 들거나 물을 따르지 않는다. 캡처 완료 신호 뒤 PNG 비동기 쓰기가 이어질 수 있어 PNG 끝까지
저장된 것을 확인한다. 실행 로그의 `HOLD_FLOW_SCENE_READY`와 manifest 생성 모두를 확인해야 한다.
프로세스 시작 또는 창 표시만으로 완료 판정하지 않는다.

URDF의 질량 없는 TCP/optical frame에는 importer가 기본 관성을 부여했다는 경고가 나올 수 있다.
이 경고를 실측 모델 완성으로 숨기지 않는다. 아직 물리 검증 모델이 아니다.

GPU는 이 호스트에서 RTX 5050 Laptop, VRAM 약 8GB로 확인했다. 단일 장면 프리뷰가 실행됐다는
사실과 공식 요구사양 충족은 다르다. [Isaac Sim 요구사양](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/installation/requirements.html)을
참고하고, 다중 환경·센서 렌더·학습 성능으로 결과를 확대하지 않는다.

## 강체 패드 컵 접촉 실험 — 2026-09-19

### 무엇을 검증하는가

`tools/simulate_cup_contact.py`는 **수평 정렬 → 컵 중간 접근 → 닫기 → 양측 접촉 유지 → 60 mm 상승 → 유지**를
실행한다. 오른팔은 대기한다. 초기 자세 설정 뒤에는 관절 드라이브 목표만 보내고, 컵의 위치를
다시 쓰거나 손과 컵 사이 고정 조인트를 만들지 않는다. 컵은 중력·충돌·마찰로 움직인다.

- 원본 URDF와 실물 보정 파일은 보존한다. 로그 폴더의 `contact_proxy.urdf`에만 실험 모델을 만든다.
- 왼손의 **원래 회전식 그리퍼 관절**은 유지하고, 손가락을 프로젝트 작성 직육면체 패드로 대체한다.
  길이 80 mm의 강체 실험 프록시이며 선정된 FinRay STL이나 TPU 변형 모델이 아니다.
- 장착 오프셋·마찰·패드 질량·컵 질량은
  `config/simulation/cup_contact_experiment.json`의 **가정**이다. 실측값으로 사용하지 않는다.
- 빈 TCP 좌표 프레임은 고정 링크 병합으로 처리한다. 좌표 표시용 프레임에 importer 기본 관성이
  생겨 팔의 동역학에 추가되는 것을 피한다.
- 기존 프리뷰의 책상 높이 693.1 mm·컵 x=320 mm와 달리, 실험은 책상 720 mm·컵 x=390 mm다.
  y=170 mm, 컵 지름 70 mm·높이 120 mm도 가정이다. 초기 질량 50 g 시험 뒤 사용자 피드백으로
  기본 질량을 **10 g**으로 낮추고 5·10·20 g 민감도 시험을 구분했다. 기존 위치에서 성공했다고 해석하지 않는다.
- 실제 카메라 인식은 연결하지 않았다. 장면의 알려진 컵 좌표를 사용한다.
- 베이스 고정, 로봇 자가충돌 제외다. 상류 오른손 충돌 형상 겹침·전체 로봇 충돌·전도 검증은 남는다.
  원본의 센서 모델도 실물 RGB 3대 배치와 다르다.
- 얇은 플라스틱 컵의 찌그러짐과 TPU 변형은 재현하지 않는다. 접촉력은 강체 실험값이며 실물 허용 파지력이 아니다.

### 성공과 실패 판정

가벼운 컵을 접근 중 스쳐 밀어놓고도 기존 좌표로 닫는 상황을 별도 실패로 분류한다.
열린 고정측 손가락의 명목 여유를 3 mm 늘렸으며, **닫힘 전**에는 다음을 확인한다.

- 어느 한쪽 손가락 바디에서 접촉력 0.02 N 이상: `premature_cup_contact`
- 시작 관측 위치보다 컵 수평 이동 3 mm 초과: `cup_displaced_before_close`

둘 중 하나라도 발생하면 닫기·상승을 계속하지 않는다. 이는 시뮬레이션 실패 분류이며, 실물에
힘 센서가 있다는 뜻이 아니다. 기본 실행은 실험을 멈춰 원인을 기록한다.
`--recover`를 선택하면 아래의 제한된 **시뮬레이터 좌표 재관측·재계획**을 실행한다.
RGB 재인식·재계획은 아직 연결하지 않았다.
실물에서는 접근 전·접근 후·닫힘 직전 RGB에서 컵 위치를 갱신하고, 카메라 좌표를 보정한 뒤
밀린 물체의 새 위치로 재계획해야 한다. 이 피드백 제어 자체에 IL 데이터는 필수가 아니다.

상승 전 마지막 0.5초 동안 양쪽 손가락 바디의 접촉과 컵 중간 높이 정렬을 확인한다.
0.02 N은 **접촉 존재를 확인하는 임계값**이지 무게를 지탱할 수 있다는 계산값이 아니다.
상승 후 마지막 1초의 모든 샘플이 아래 조건을 만족해야 `rigid_proxy_lift_pass=true`다.

- 시작보다 40 mm 이상 상승
- 양측 접촉 유지
- 명령 대비 팔 관절 오차 0.12 rad 이하
- TCP와 컵 중심의 높이 차이 및 3D 거리 각각 15 mm 이하
- 컵 수평 이동 20 mm 이하, 기울기 15° 이하

물리 tick마다 실제 관절값·FK 접촉 중심·컵 위치·기울기·접촉력·물리 시간을 남긴다.
렌더링과 PNG 저장은 물리를 추가 진행하지 않으며 tick 증가량을 대조한다.
미달·중단은 성공으로 처리하지 않는다. 실행 완료와 파지 PASS는 별도 필드다.
최종 화면은 결과를 보존하기 위해 물리 진행을 멈춘 상태다.

### 재실행

```bash
cd ~/bimanual-robot
ISAAC_PYTHON="/data/$USER/conda-envs/leisaac/bin/python"
"$ISAAC_PYTHON" tools/simulate_cup_contact.py \
  --stay-open --output-dir logs/cup_contact/new_run
```

새 출력 경로가 필요하다. `--headless`는 창 없이 같은 실험을 실행하고, `--plan-only`는
시스템 Python으로 가정 모델과 IK 계획만 생성한다. `--stay-open`과 `--headless`는 함께 쓰지 않는다.

`--cup-mass-kg 0.005`로 5 g 조건을 시험할 수 있다.
`--spawn-y-offset-mm -5`는 계획상의 목표 좌표를 바꾸지 않고 물체의 초기 위치만 5 mm 옮기는
오차 주입이다. 실제 카메라 정밀도나 분포를 뜻하지 않는다.
**최종 영상은 양팔 물 서빙 전체가 완성된 뒤 촬영한다.** 현재 명령은 영상을 녹화하지 않는다.
`--record`는 선택 기능으로 남지만 단일 왼팔 실험을 최종 제품 시연으로 사용하지 않는다.

| 산출물 | 의미 |
|---|---|
| `plan.json` | 설정·소스/모델 해시·TCP·IK 단계 |
| `contact_proxy.urdf`, `scene.usda` | 실험용 로봇과 초기 장면 |
| `initial.png`, `final.png`, `frames/` | 렌더 이미지, record 옵션의 10 fps 프레임 |
| `result.json` | 완료 여부·중단 사유·강체 실험 판정·물리 상태 샘플 |

### IL 데이터가 필요한가

이 실험은 IK와 단계별 제어이므로 **IL 시연 데이터 없이 실행**된다.
IK에는 관절 구조·한계·TCP·목표 좌표가 필요하고, 접촉 검증에는 충돌 형상·질량·마찰이 필요하다.
IK가 컵을 인식하거나 마찰을 학습하는 것은 아니다.
[Isaac Sim 5.1 조작 예제](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/core_api_tutorials/tutorial_core_adding_manipulator.html)도
컨트롤러 기반 pick/place 흐름을 제공한다.

ACT 비교 단계에서는 카메라 영상·관절 상태·행동 명령이 동기화된 시연이 필요하다.
[LeRobot ACT 문서](https://huggingface.co/docs/lerobot/act)는 다중 RGB·관절 상태 입력과
사용자 데이터셋을 통한 학습을 설명한다. IL과 IK는 비교 가능한 대안이며 IK 성공이 모든 IL의
필수 선행 조건은 아니다. 다만 현재 프로젝트에서는 모델·좌표 문제와 정책 성능을 분리하는 기준선으로
IK 실험을 먼저 둔다.

이 로그는 가정 강체 모델의 진단 증거다. 실물 FinRay 성공 데이터나 ACT 학습 데이터로 자동 편입하지 않는다.
실물 적용 전에는 장착 변환·열림별 접촉 중심·질량·TPU 변형·카메라 좌표를 보정해야 한다.

### 위치 오차 후 후퇴·재계획 실험

`--recover`는 접촉 실패를 성공으로 지우지 않고 `result.json.events`에 남긴 뒤 복구를 시도한다.
기본 동작은 다음과 같으며 모든 수치는 `config/simulation/cup_contact_experiment.json`의 가정이다.

1. `ALIGN_MIDDLE` 또는 `APPROACH`에서 닫힘 전 접촉/밀림을 감지하면 닫기·상승을 보류한다.
2. 이번 시도의 실제 관절 이력을 역순으로 따라 마지막 `PREGRASP_ABOVE` 자세까지 후퇴한다.
   그리퍼는 열린 상태를 유지한다. 이력은 0.1초 간격으로 선택하고 구간 시간을 1.5배로 늘린다.
   관절 보간 경로이며 컵 위치가 바뀐 뒤의 연속 충돌 회피를 보증하지 않는다.
3. 후퇴 중 접촉력 2 N 초과, 최초 관측 위치 기준 수평 이동 30 mm 초과, 기울기 15° 초과는 복구 실패다.
   실물 센서값·힘 제한이 아니라 강체 실험 중단 기준이다.
4. `REOBSERVE`의 연속 0.5초 동안 접촉 해제, 위치 변화 1 mm 이하, 기울기 3° 이하,
   원래 컵 중심 높이와 차이 3 mm 이하를 확인한다. **시뮬레이터 정답 좌표를 읽으며 RGB 검출이 아니다.**
5. 관측 위치 평균과 현재 실제 관절값으로 IK를 다시 계산한다. 초기 홈 자세로 순간이동하지 않으며
   열린 손으로 새 접근 경로를 실행한다. 컵 위치는 초기 배치 이후 쓰지 않는다.
6. 재접근은 기본 1회까지다. 다시 닫힘 전 접촉이 발생하면 `recovery_retry_limit`로 종료한다.
   후퇴 이력이 없거나 컵이 쓰러졌거나 접촉이 해제되지 않거나 IK가 실패한 경우에도 성공으로 처리하지 않는다.

재시도마다 `attempt`를 분리한다. 상승 판정은 마지막 시도의 샘플과 재관측 위치를 기준으로 계산하고,
첫 실패·후퇴·새 목표·새 계획은 이벤트에 보존한다. `cup_displacement_from_start_m`는 최초 관측 대비,
`cup_displacement_from_observation_m`는 해당 시도의 관측 대비 이동이다. 재시도 사이에도
`time_s`와 `physics_time_s`는 앞으로 증가한다. 재시도 시작의 `RESET` 이름은 현재 자세 유지 구간이며,
최초 홈 자세로 이동한다는 뜻이 아니다.

```bash
cd ~/bimanual-robot
ISAAC_PYTHON="/data/$USER/conda-envs/leisaac/bin/python"
"$ISAAC_PYTHON" tools/simulate_cup_contact.py --recover --headless \
  --cup-mass-kg 0.005 --spawn-y-offset-mm -5 \
  --output-dir logs/cup_contact/recovery_new_run
```

`--spawn-x-offset-mm`는 전후 오차, `--spawn-y-offset-mm`는 좌우 오차다. 둘 다 계획의 초기 목표를
그대로 두고 물체 초기 위치에만 적용한다. `--recover`를 빼면 기존 중단 기준선과 비교할 수 있다.
설정의 `recovery.max_retries=0`도 재시도를 끈다. 실행 로그는 Git 제외이며 녹화는 기본 꺼져 있다.
과거 v1 설정에 `recovery`가 없으면 저장소 기본 설정을 채워 `plan.json`에 기록한다.
명시된 `recovery` 객체의 필수 항목 누락이나 잘못된 값은 기본값으로 덮지 않고 거부한다.

5 g·동일 가정 장면의 오차 시험 결과는 다음과 같다. 반복 시험은 동일한 초기조건의 재현 확인이며,
무작위 환경의 성공률이나 실제 카메라 오차 허용치를 뜻하지 않는다.

| 초기 위치 오차 | 실행 수 | 복구 횟수/실행 | 결과 | 최종 상승 |
|---|---:|---:|---|---:|
| y=−5 mm | 3 | 1 | 접촉 감지→후퇴→재관측→재접근→PASS | 약 60.18 mm |
| y=+5 mm | 1 | 0 | 첫 접근에서 PASS | 약 60.17 mm |
| x=−5 mm | 1 | 0 | 첫 접근에서 PASS | 약 60.19 mm |
| x=+5 mm | 1 | 0 | 첫 접근에서 PASS | 약 60.17 mm |

y=−5 mm 실행은 6.425초에 최초 접촉을 감지하고 7.600초에 새 계획을 만들었다.

컵의 전체 이동은 닫기·상승 중 이동도 포함한다. 이 결과를 무접촉 후퇴나 무밀림 파지로 표현하지 않는다.
근거는 Git 제외 로컬 `logs/cup_recovery_20260919/{minus5_fix,ym5_r2,ym5_r3,yp5,xm5,xp5,nominal}/`다.

### 과거 FinRay 후보를 적용하지 않은 이유

선택 파일 `design/gripper/finray_80mm_lip3_selection.yaml`의 SHA-256과 로컬 STL을 다시 대조했고,
외곽은 `80.0×24.74545×24.087 mm`로 일치했다. 확인한 파일은
`~/Downloads/SO101_TPU_FinRay_80mm/SO101_finray_80mm_lip3_reinforced_TPU95A.stl`이다.
그러나 형상이 존재하는 것과 장착된 로봇 모델이 확정되는 것은 다르다.

- 고정측·이동측 링크에 대한 장착 위치/회전과 개폐 각도별 접촉 중심이 미측정이다.
- 출력물 질량·무게중심·TPU 변형 특성이 미확정이다. 기존 스톡 죠 질량을 실제 FinRay 질량으로 재사용하지 않는다.
- 원본 배포처·라이선스가 기록되지 않아 선정 정책상 메시와 파생 G-code를 저장소에 넣지 않는다.

따라서 당시 복구 시험도 기존 강체 패드에서 수행했다. 2026-09-22 FinRay 후보는 현행 구성에서
제외됐으므로 이후 순정 죠 시험에 이 프록시를 사용하지 않는다. 메시 모양만 바꾼 결과를 실물
파지 검증으로 표시하지 않는다. 대조 결과는 Git 제외 로컬 실행 로그
`logs/cup_recovery_20260919/finray_inspection.json`에 보존했다. 다른 PC에서는
`tools/preview_finray_tcp.py`와 선정 YAML, 해당 STL로 해시·외곽 검사를 다시 실행해야 한다.

### 컵 내려놓기·손 분리 (`--place`)

`--place`를 선택하면 기존 파지·60 mm 상승 검증 뒤 **같은 책상의 원래 위치로 내려놓기**를 잇는다.
선반으로 옮기기, 다른 테이블에 전달하기, 오른팔 병 파지나 물붓기를 구현한 것은 아니다.
`--recover`와 함께 쓰면 초기 파지 오차를 복구한 뒤 내려놓기까지 실행한다.

```bash
cd ~/bimanual-robot
ISAAC_PYTHON="/data/$USER/conda-envs/leisaac/bin/python"
"$ISAAC_PYTHON" tools/simulate_cup_contact.py --place --recover --stay-open \
  --cup-mass-kg 0.005 --spawn-y-offset-mm -5 \
  --output-dir logs/cup_contact/place_new_run
```

진행 순서와 판정은 다음과 같다.

1. `LOWER`: 마지막 상승 유지 구간이 통과했을 때만 내려간다. 원래 파지 높이보다 2 mm 아래는
   계획 탐색 하한이지 반드시 도달할 목표가 아니다. 컵-책상 접촉의 월드 +Z 성분이
   가정 컵 무게의 40% 이상으로 관측되면 현재 관절값에서 하강을 끝낸다.
   책상 지지 전 양측 파지를 잃거나 컵이 손에서 이탈하면 실패다. 접지를 확인하지 못한 채
   계획 하한에 도달하면 `table_contact_not_observed_before_lower_limit`로 끝낸다.
   하한 뒤에 뒤늦게 생긴 지지를 근거로 접지 이벤트 없이 성공 처리하지 않는다.
2. `TABLE_SETTLE`: 접촉 시 관절값을 유지하고 마지막 0.5초 동안 책상 지지, 컵 중심 높이 오차
   3 mm 이하, 수평 위치 오차 20 mm 이하, 기울기 3° 이하, 구간 위치 변화 1 mm 이하를 확인한다.
   지지가 없으면 `table_support_not_observed_before_open`으로 끝내고 손을 열지 않는다.
3. `OPEN → RELEASE_HOLD`: 손을 열고 마지막 0.5초 동안 양쪽 손가락 접촉이 0.02 N 미만인지,
   실제 개방 각도가 명령에서 0.05 rad 이내인지, 책상 지지와 정지가 유지되는지 확인한다.
   통과하지 못하면 `release_not_observed_before_withdraw`이며 손을 빼는 동작으로 넘어가지 않는다.
4. `WITHDRAW → CLEAR_ABOVE`: 수평으로 65 mm 물러난 뒤 80 mm 위로 올라간다. 손 분리 이후
   손가락 접촉이 다시 0.02 N 이상 발생하면 `post_release_hand_contact`로 즉시 중단한다.
5. `PLACE_HOLD`: 마지막 1초 동안 지지·정지·기울기·개방·무접촉 조건과 손 접촉 프레임의
   컵 중심 거리 60 mm 이상을 모두 만족해야 내려놓기 PASS다.

컵 위치는 여전히 초기 배치 이후 쓰지 않으며 손에 부착하지 않는다. 책상은 정적 충돌체이고,
컵 contact filter에 책상을 추가해 지지력을 손가락 접촉과 별도로 읽는다. 중력은 설정의
`placement.gravity_m_s2=9.81`과 물리 장면에 동일하게 적용한다. `placement`가 없는 과거 v1 설정은
현재 기본값을 채워 실행 manifest에 남기며 명시적으로 잘못된 값은 거부한다.

결과 필드도 구분한다.

- `lift_stage_pass`: 기록된 상승 유지 구간의 통과 여부. 이후 손 분리에서 실패해도 이 근거는 남는다.
- `rigid_proxy_place_pass`: 실행 완료·상승 검증·현재 시도 접지 이벤트·최종 책상 위 안정 상태가 모두 참일 때만 true.
- `task_pass`: `--place` 실행에서는 내려놓기 판정, 기본 실행에서는 기존 상승 판정이다. 프로세스 종료 코드도 이를 따른다.
- `events`의 `touchdown`: 하강을 끝낸 접촉 시점·책상 접촉력·실제 관절 기반 후속 계획.
- `table_contact_force_world_n`, `table_support_force_n`: 책상 접촉 벡터와 +Z 지지 성분.

초기 25 mm 후퇴 경로는 손을 위로 뺄 때 재접촉해 실패했다. 10 g 컵의 27.7초 시점에서
고정측 손가락 접촉력 약 0.0215 N이 관측됐으며 성공으로 처리하지 않았다.
후퇴를 65 mm로 늘리고 접촉 후 하강 종료를 적용한 시험은 같은 10 g 장면에서 완료됐다.
이는 연속 충돌 회피 증명이 아니며, 다른 배치에서는 실행 중 접촉 검사로 실패할 수 있다.
수정 코드에서 후퇴 거리만 25 mm로 되돌린 대조 시험도 PASS였다. 따라서 최초 실패를
후퇴 거리 하나의 문제로 확정하지 않는다. 하강 종료와 후속 IK 경로 변경의 영향을 아직 분리하지 않았고,
실패 레코드의 원인 상태는 가설로 남긴다. 이 대조는 기존 분석에 사용한 조건이지 독립 holdout이 아니다.

**접촉 후 하강 종료는 힘 제어가 아니다.** 10 g 수정 시험에서 최초 접지력은 약 0.208 N이었지만,
닫힌 손의 지지 확인 구간 마지막에는 약 1.33 N이 남았다. 손을 연 뒤에는 약 0.0981 N과
손가락 접촉 0 N으로 안정됐다. 팔의 위치 제어와 강체 모델 결과이며, 얇은 컵의 찌그러짐이나
실물 허용 힘이 검증됐다는 뜻이 아니다. 실제 적용에는 FinRay/컵 변형·장착·지지 확인 방법을 별도로 검증해야 한다.

복사하고 해시를 보존했다. 성공/실패 로그 모두 BC 시연 데이터로 자동 편입하지 않는다.

## 순정 ggao 오른손 병 접촉 실험 · 2026-09-21

오른손 순정 평면 죠의 접근·닫힘·상승·같은 책상 복귀 계획을 추가했다. 현재는 IK 계획만 통과했고,
물리 실행은 닫기 전 비파지 링크 접촉으로 실패한다. 병 파지·들기·복귀 성공으로 표시하지 않는다.
이 설명은 기본 설정의 기존 조립 모델에 해당한다. 후속 교체 조립 가정 시험은 아래 절에서 구분한다.

### 모델과 가정

- 원본 `hold_flow.urdf`와 캘리브레이션은 유지한다. 로그 디렉터리의 URDF 사본에서만
  ggao 베이스·양쪽 죠의 충돌 박스를 기존 시각 박스와 일치시킨다. 원본 STL 디지털 트윈이 아니다.
- 죠 두께는 기존 시각 모델의 12 mm로 맞추고, 베이스의 넓은 단일 충돌 박스를 기존 레일·연결판
  박스 둘로 나눈다. 각 죠의 랙 충돌도 포함한다. 패드·홈·인서트·테이프는 추가하지 않는다.
- 장착 변환·관절 한계·관성은 원본 명목값을 유지한다. 접촉 프레임만 `right_tool0`의
  `(0, −15, 0) mm`에 추가하며 이 위치도 실측 보정값은 아니다.
- 병은 지름 60 mm·높이 200 mm·질량 35 g의 강체 원기둥, 중심 `(390, −170, 820) mm`,
  책상 높이 720 mm, 마찰계수 0.3으로 가정한다. 뚜껑·목·찌그러짐·물의 유동은 모델링하지 않았다.
- 오른손은 각 죠의 직선 이동 `q=10~43.3 mm`, 명목 개구 `2q=20~86.6 mm`다.
  왼손 회전식 그리퍼의 rad/N·m와 섞지 않고 m/N으로 제어한다. kp=300 N/m, kd=10 N·s/m,
  죠별 힘 상한 5 N 역시 실험 가정이며 실물 서보 성능을 검증한 수치가 아니다.
- 로봇 자체 충돌은 여전히 꺼져 있다. 물체와 두 죠·책상·나머지 로봇 링크의 접촉은 켜고 계측한다.
  비파지 링크 접촉이 0.02 N 이상이면 실패다. 관절 보간 전 구간의 충돌 회피 보증은 아니다.

```bash
  --output-dir logs/bottle_contact_plan_check
```

그 전에 접촉 실패로 끝난다. `--bottle-mass-kg`는 병+내용물의 합산 가정 질량이고 액체 시뮬레이션이 아니다.

- 서보 크기 30×40×45 mm와 중심 `(0, 25, 0) mm`(ggao 기준)는 가정값이다.

- 기존 원본 URDF·보정·기본 `bottle_contact_experiment.json`은 변경하지 않는다.
  결과의 `assembly_mode=replacement_hypothesis_proxy`, `model_calibrated=false`로 범위를 표시한다.


`replacement01`의 35 g 시험은 약 58.91 mm 상승, `replacement235`의 합산 235 g 시험은 약 54.66 mm
상승 후 내려놓기·손 분리를 통과했다. 각각 1회이며 마지막 손가락 접촉은 0 N, 책상 지지력은
약 0.34335/2.30535 N이었다. 전체 구간 비파지 링크 접촉은 0 N이었다.
235 g은 병+내용물의 등가 강체 질량이다. 액체 유동·붓기·실물 파지·전체 로봇 자가충돌 검증이 아니다.
여러 조립 요소를 함께 바꾼 대안 시험이므로 어떤 부품 하나의 수정만으로 해결됐다고 결론내리지 않는다.
실물 정합 전까지 이 결과는 조립 가설과 IK 동작 연결을 시험한 것으로만 사용한다.

최종 코드 재시험은 `replacement_final_35`·`replacement_final_235`에 따로 보존했다. 두 실행 모두
상승·접지·내려놓기 PASS이며 `result.json`에도 `assembly_mode=replacement_hypothesis_proxy`,
`model_calibrated=false`, `physical_grasp_verified=false`가 있다. 앞의 초기 성공 로그와 덮어쓰지 않는다.
따라서 질량별로 초기 시험 1회와 최종 재시험 1회가 있지만, 같은 가정 장면의 재현 시험일 뿐
물체 배치·마찰·조립 오차를 달리한 일반 성공률이나 독립 holdout 평가는 아니다.

설정 출처를 보강한 최신 실행은 `provenance_35`·`provenance_235`다.
`plan.json`의 `source_config_sha256`은 입력 파일, `effective_config_sha256`은 기본값과 CLI 변경을
적용한 `config` 전문의 정렬된 JSON 지문이다. 기존 `config_sha256`은 입력 파일 해시의 호환 별칭이다.
`runtime_overrides`에는 질량(kg)과 배치 오프셋(mm)의 명시적인 CLI 변경을 남긴다.
따라서 같은 설정 파일을 사용한 35 g·235 g 실행도 유효 설정 해시로 구분할 수 있다.
