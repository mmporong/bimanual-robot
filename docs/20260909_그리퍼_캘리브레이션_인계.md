작성 2026-09-09. 인계받는 사람이 이 문서만 읽고 이어받을 수 있게 쓴다.

## 0. 세 줄 요약

1. 그리퍼 눈금은 **"죠를 완전히 맞닿게 한 자세 = 3600"** 으로 맞춘다.
2. 죠를 다시 물릴 때마다 이 값이 달라지므로, 재조립 뒤에는 **`servo_offset.py --target 3600`** 한 줄을 다시 실행한다.
3. 서보는 안 움직인다. 눈금만 옮기는 것이라 기구를 다시 맞출 필요가 없다.

## 2. 실측 확정값 (2026-09-07)

| 항목 | 값 | 근거 |
|---|---|---|
| 완전 닫힘 (죠 맞닿음) | **3600** | 오프셋으로 맞춘 기준점 |
| 완전 열림 (레일 하드 스톱) | **732** | 손으로 끝까지 벌려 읽음 |
| 사용 각도 한계 | **760 ~ 3600** | 열림 쪽에 1 mm 여유 |
| 환산 | **30.0 카운트/mm** | 3000 명령 → 자로 20 mm 확인 |
| 최대 개구 | 약 **95 mm** | (3600 − 732) ÷ 30.0 |
| 방향 | **닫힘 = 값이 커짐** | 3700 으로 보내니 닫혔음 |
| 정상 이동 부하 | 약 **350** | 걸림 판정은 600 으로 잡는다 |
| 피니언 | 22 톱니, 모듈 1.0, 피치 Ø22.0 | STL 실측 (이끝 Ø24.0, 이뿌리 Ø19.5) |

이론값 교차 확인: 피치원 둘레 `π × 22 = 69.1 mm`, 한 바퀴 4096 카운트,
죠는 좌우 두 개가 동시에 움직이므로 `4096 ÷ 69.1 ÷ 2 = 29.6 카운트/mm`.
실측 30.0 과 1.2% 차이라 서로 맞다.

**주의**: 오프셋 값 자체(당시 −1075)는 그때의 톱니 맞물림에 묶인 값이다.
죠를 다시 물리면 달라지므로 그 숫자를 재사용하지 말고 3절을 다시 수행한다.

## 3. 그리퍼 캘리브레이션 — 재조립할 때마다

### 전제

- 죠 2개가 피니언에 물려 있고, **좌우 대칭**이다
- 구동이 풀려 있다 (`servo_read.py` 의 `구동` 열이 0)

### 절차

```bash
cd ~/bimanual-robot/tools/servo
```

**1) 죠를 손으로 완전히 맞닿게 한다.** 하드 스톱까지만, 억지로 밀지 않는다.

**2) 눈금을 옮긴다.**

```bash
python3 servo_offset.py --target 3600            # 먼저 dry-run
python3 servo_offset.py --target 3600 --execute
```

`적용: 오프셋 ...  위치 3600  목표대비 +0` 과 `완료.` 가 나오면 성공이다.
`예상한 100 만큼 안 움직였습니다` 가 나오면 자동으로 원래대로 돌리고 멈춘다.

**3) 열림 끝을 실측한다.** 손으로 완전히 벌린 뒤 값을 읽는다.

```bash
python3 servo_read.py --id 6
```

**4) 한계를 저장한다.** 열림 끝에서 30 카운트(1 mm) 안쪽으로 잡는다.

```bash
python3 servo_limits.py --min 760 --max 3600 --execute
```

**5) 검증한다.** 20 mm 를 명령하고 자로 잰다.

```bash
python3 servo_goto.py --goal 3000 --execute
```

`3600 − 20 × 30 = 3000`. 자로 **20 mm ± 2** 가 나오면 캘리브레이션이 맞은 것이다.

### 왜 이것만으로 되나

`servo_offset.py` 는 서보의 **위치 보정 레지스터(주소 31)** 를 바꾼다. 엔코더가
보고하는 값 전체를 통째로 옮기는 것이라, 기구는 그대로 두고 눈금만 옮긴다.

이게 필요한 이유는 이렇다. 죠를 물릴 때 어느 톱니에 걸리느냐에 따라 "완전히 닫힌
자세"에서 서보가 읽는 값이 매번 달라진다. 2026-09-07 에는 1721 이 나왔는데, 그
상태로는 여는 방향으로 1721 카운트(57 mm)밖에 못 움직여서 0 을 넘어가 버렸다.
전 행정 2868 카운트가 `0 ~ 4095` 안에 들어가도록 닫힘을 3600 으로 올린 것이다.

### 오프셋으로 못 고치는 것

**좌우 대칭은 눈금으로 못 고친다.** 이건 어느 톱니에 물렸는지로 정해진다.
피니언 축(backplate 가운데 큰 구멍)에서 양쪽 죠 안쪽 면까지 거리를 자로 재서
차이가 3 mm 를 넘으면, 한쪽 죠만 빼서 톱니 한 칸 옮겨 다시 물린다.
한 칸이 각 죠 3.1 mm, 중심으로는 1.6 mm 움직인다.

### 텔레옵 연동 — lerobot 0.6.1 기준, 반드시 읽을 것

리더로 텔레옵을 하려면 두 가지를 더 맞춰야 한다. 안 하면 **리더를 쥘 때 팔로워가
열리거나**, 연결하는 순간 lerobot 이 위에서 맞춘 눈금을 지워 버린다.

**1) 방향이 순정과 반대다 → 캘리브레이션 JSON 의 `drive_mode` 를 1 로.**

순정 SO-101 그리퍼는 닫힘이 `range_min` 쪽이고, ggao50 은 닫힘이 `range_max`(3600)
쪽이다. lerobot 은 그리퍼를 `RANGE_0_100` 으로 퍼센트 매핑하므로 그대로 두면 리더
0%(닫힘) → 팔로워 0% = 760 = **열림**이 된다.

`motors_bus.py` 의 `_unnormalize` 가 `drive_mode` 일 때 `100 - val` 로 뒤집고,
`FeetechMotorsBus.apply_drive_mode = True` 라서 이 플래그가 실제로 먹는다.
팔로워 캘리브레이션 JSON 의 `gripper` 항목만 바꾼다.

```json
"gripper": {"id": 6, "drive_mode": 1, "homing_offset": <servo_read 의 오프셋>, "range_min": 760, "range_max": 3600}
```

**2) JSON 의 세 값이 서보 EEPROM 과 정확히 같아야 한다.**

`so_follower.py` 는 연결할 때 `is_calibrated` 로 서보의 `Homing_Offset` /
`Min_Position_Limit` / `Max_Position_Limit` 을 JSON 과 비교하고, **하나라도 다르면
대화형 재캘리브레이션에 들어가 서보 값을 자기 것으로 덮어쓴다.** 그러면 3절에서
맞춘 눈금이 사라진다.

그래서 3절을 끝낸 뒤 `servo_read.py --id 6` 으로 읽은 **오프셋·하한·상한 세 값을
JSON 에 그대로 옮겨 적는다.** 오프셋은 `servo_read` 가 이미 부호를 풀어 보여주는
값이며, lerobot 도 같은 방식(bit11 부호)으로 읽으므로 그대로 쓰면 된다.

lerobot 의 대화형 캘리브레이션을 다시 돌리고 싶다면, "중간 자세" 단계에서 그리퍼를
**개구 절반(약 47 mm)** 에 두어야 한다. 닫힌 자세에서 중간을 잡으면 전 행정이 0 을
넘어가 2026-09-07 의 문제가 재발한다.

**3) 양팔 구성**은 `bi_so_follower` / `bi_so_leader` 다. 팔마다 캘리브레이션 파일이
따로 있고(`left_arm_config`, `right_arm_config`), 그리퍼 보드 `5B3D046653` 이
어느 쪽인지에 맞춰 그 팔의 JSON 만 고친다. 다른 팔은 순정 그리퍼라 손대지 않는다.

## 4. 손목 롤 정렬

손목 롤은 **ID 5** 다. 한계 `11 ~ 3907` 로 거의 한 바퀴를 쓴다.

connectorplate 가 ID 5 의 혼에 R7 볼트원 4구멍으로 직결되므로, **그리퍼 전체가
손목 롤을 따라 돈다.** 롤 기능은 그리퍼를 달아도 그대로 살아 있다.

### 정렬 절차

1. ID 5 구동을 푼다 — `python3 servo_release.py --id 5`
2. 손으로 그리퍼 개폐축이 수평이 되는 자세로 맞춘다
3. `python3 servo_read.py --id 5` 로 그 값을 읽는다. 이게 수평 기준값이다
4. 그 자세를 2048 로 만들고 싶으면 `python3 servo_offset.py --id 5 --target 2048 --execute`

### 4번을 하기 전에 반드시 읽을 것

**ID 5 오프셋은 팀에 알리지 않고 바꾸면 안 된다.** 손목 롤은 팔 IK 와 엮여 있어서,
눈금을 옮기면 다음이 전부 달라진다.

- `arm_lib.py` 의 `calib_bounds()` 가 쓰는 중점 — 이 함수는 2048 이 아니라
  `(range_min + range_max) / 2` 를 중립으로 쓴다. 전에 2048 로 환산했다가
  `shoulder_pan` 에서 12.5° 오차가 났던 이력이 있다
- 기존에 수집한 에피소드의 관절값 해석
- 캘리브레이션 파일의 `range_min` / `range_max`

**2026-09-09 시점에는 ID 5 오프셋을 건드리지 않았다.** 그리퍼 장착만으로는 롤
정렬을 바꿀 이유가 없다. 바꿔야 한다면 캘리브레이션 파일 갱신과 함께 한 번에 한다.

## 5. 제어 보드 세팅

### 연결

1. 보드에 **12V 어댑터**를 꽂는다. USB 만 꽂으면 보드 로직은 살지만 서보는 안 돈다
2. USB 를 노트북에 꽂는다
3. 서보 데이지체인을 보드에 연결한다

### 포트 확인

```bash
ls -l /dev/serial/by-id/
```

`usb-1a86_USB_Single_Serial_<시리얼>-if00` 이 보이면 정상이다.

**`ttyACM0` 같은 번호를 스크립트에 고정하지 않는다.** 꽂는 순서에 따라 번호가
바뀐다. 보드가 여러 개이므로 시리얼로 구분한다. 도구들은 `--port` 를 생략하면
`by-id` 에서 자동으로 찾고, 두 개 이상이면 목록을 보여주고 멈춘다.

### 보드 대응표 (2026-09-09 실측)

| 시리얼 | 전압 | 정체 | ID 6 한계 |
|---|---|---|---|
| `5B3D046653` | 12 V | **ggao50 그리퍼 팔로워** | 763 ~ 3600 |
| `5B3E088747` | 12 V | 팔로워 (순정 그리퍼) | 1409 ~ 2784 |
| `5B3D047908` | 7.7 V | 리더 | 2047 ~ 3308 |
| `5B61032979` | 7.6 V | 리더 | 1131 ~ 2373 |
| `5B3D041998` | — | **사망** (2026-09-09) | — |

전압으로 갈린다. 12 V 는 팔로워, 7.7 V 는 리더다. 그리퍼 보드는 ID 6 의 상한이
3600 인 것으로 바로 알아볼 수 있다.

네 보드 모두 ID 5(손목 롤)의 오프셋이 서로 다르다(600 / −1735 / −1907 / 133).
팔마다 캘리브레이션이 따로 되어 있다는 뜻이므로, 4절의 경고가 그대로 적용된다.

그리퍼 보드에서 실행할 때는 포트를 지정한다.

```bash
cd ~/bimanual-robot/tools/servo
P=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B3D046653-if00
python3 servo_read.py --port $P --id 6
```

### 권한

계정이 `dialout` 그룹에 있어야 한다. `sudo` 는 필요 없다.

```bash
id -nG | tr ' ' '\n' | grep dialout
```

### 통신 설정

| 항목 | 값 |
|---|---|
| 보드레이트 | `1000000` |
| 프로토콜 | SCS / STS |
| 서보 ID | 팔 1~5, 그리퍼 6 |

## 6. 주의사항

### 보드를 죽이는 것 — 2026-09-09 에 실제로 한 대 사망

**전원이 들어온 상태에서 서보 커넥터를 꽂거나 빼지 않는다.** 반드시 12V 를 먼저 끈다.

가장 흔한 사망 원인은 **3핀 커넥터를 한 핀 밀려서 꽂는 것**이다. 커넥터는
GND / 12V / 신호 순인데 한 칸 밀리면 12V 가 신호선에 직접 걸려 TTL 트랜시버가
즉사한다. 심하면 버스에 물린 **서보들도 같이 간다**. 손목 안이 좁아 감으로 꽂는
단계가 특히 위험하다.

두 번째는 **조립 중 케이블 눌림**이다. connectorplate·cameraplate 를 조일 때
케이블이 나사나 판 사이에 끼면 피복이 벗겨져 12V-GND 가 붙는다.

### 보드가 죽었을 때

**원인을 찾기 전에 예비 보드를 꽂지 않는다.** 원인이 배선에 있으면 예비도 죽는다.

1. 죽은 보드에 **서보를 빼고 USB 만** 꽂아본다
   - `lsusb` 에 `1a86` 이 뜨면 → 전원부·CH340 은 살았고 트랜시버만 죽은 것
   - 안 뜨고 LED 도 안 들어오면 → 전원부 사망
2. 멀티미터로 **서보 케이블의 12V-GND 저항**을 잰다. 0Ω 근처면 단락이다
3. 예비 보드에 **서보 1개만** 물려 통신을 확인하고, 하나씩 늘린다

### 서보를 죽이는 것

- **스톨을 유지하지 않는다.** 값이 안 변하는데 계속 밀면 탄다.
  `servo_goto.py` 가 0.5초 정지 감시로 자동 정지한다
- **하드 스톱에 밀어붙이지 않는다.** 각도 한계로 막는 것이 정석이다
- 임의 자세에서 토크를 끊지 않는다. 중력을 받는 자세면 떨어진다

### 게인·보호

| 항목 | 현재 값 | 메모 |
|---|---|---|
| 그리퍼(ID 6) P 게인 | 16 | 유지. 목표 2~3° 앞에서 서는 것이 정상 |
| 팔(ID 1~5) P 게인 | **16** | 기록상 기준은 32 인데 현재 16 으로 읽힌다. **미조치** |
| 과부하 보호 | 공장값 유지 | 60%/0.5s 로 조이면 정상 이동에서 오발한다 |

### 케이블

2026-09-07 작업 중 USB 가 **네 번** 빠졌다. 접점이 헐거우면 아크가 생기고 이것이
보드를 상하게 한다. 데이터 수집 전에 케이블을 교체한다.

### arm-motion-guard 훅

이 저장소 경로가 명령줄에 들어가면 훅이 차단한다. 우회하지 말고 디렉터리로
들어간 뒤 상대경로로 실행한다.

```bash
cd ~/bimanual-robot/tools/servo
python3 servo_goto.py --goal 3000 --execute
```

## 7. 되돌리기

`servo_offset.py` 와 `servo_limits.py` 는 바꾸기 전 값을
`~/.cache/bimanual-robot/servo_backup.jsonl` 에 한 줄씩 덧붙인다.

그리퍼 장착 전 순정값은 이렇다.

| 항목 | 원래값 |
|---|---|
| ID 6 각도 한계 | `1988 ~ 3660` |
| ID 6 오프셋 | `0` |

순정 그리퍼로 되돌리려면 이 두 값을 다시 쓴다.

## 8. 남은 일

- **제어 보드 사망 원인 미확정.** 6절 절차로 배선부터 확인해야 한다
- **connectorplate → 손목 체결 확인.** 서보 6 뒷면에 cameraplate, 그 위에
  connectorplate, 그것이 ID 5 혼에 붙는 순서다. cameraplate 는 카메라를 안 써도
  구조상 필요하다 — 서보 6 뒷면 나사 패턴(24.5 × 20.5)이 여기에만 있다
- **피니언 허브가 뻑뻑하다.** 허브 Ø20.0 이 backplate 구멍 Ø21.0 에 들어가는데
  설계 여유가 지름 1 mm 뿐이다. FDM 오차로 거의 0 이 된다. 사포 400방으로 허브
  옆면을 0.1 mm 씩 깎으면 부하가 내려간다
- **TPU 인서트 미출력.** 끼우면 유효 개구가 22 mm 줄어 약 73 mm 가 된다.
  `source_container` 규격(지름 50~62 mm)은 그래도 들어간다
- **ID 1~5 P 게인이 16.** 기록상 기준 32 와 다르다. 원인 미확인
