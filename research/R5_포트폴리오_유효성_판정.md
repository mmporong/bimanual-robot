# R5 — 포트폴리오 유효성 판정

작성 2026-08-19 · 입력: [R4_양팔로봇_회사와_태스크.md](R4_양팔로봇_회사와_태스크.md) + `~/physical-ai-lab` 기존 전략 문서

## 결론 먼저

**양팔이라는 사실을 포트폴리오의 주어로 삼지 않는다.** 국내 양팔 SW 직무가 신입에게 닫혀 있다는 것이 실측으로 재확인됐으므로, "양팔 로봇을 만들었습니다"는 신입 지원에서 살 사람이 없다. 기존 무게 제외 판정이 뒤집히지 않는다.

**대신 조작 데이터 파이프라인을 주어로 삼는다.** 신입에게 열린 공고들이 실제로 요구하는 것은 조작작업 데이터셋 구축(KIST), manipulation dataset 학습 파이프라인 설계·운영과 전처리·라벨링 워크플로우(엔젤로보틱스), 매니퓰레이터 제어 로직(아이로브)이다. 양팔은 그 파이프라인이 다루는 **대상**이지 주장의 **내용**이 아니다.

**따라서 별도 산출물을 만들지 않고 N2에 흡수시킨다.** N2가 이미 "SO-101 모방학습 데이터 파이프라인"이고, 양팔 팀 프로젝트는 그 파이프라인의 적용 대상이 하나 늘어난 것으로 서술된다. 신규 개수를 늘리지 않는 확정 원칙과도 맞는다.

**시점을 나눠 봐야 한다.** 지원 슬레이트 스냅샷은 10/15인데 M07은 10/14 시작이라, **이 프로젝트는 지원용이 아니라 면접용 자산**이다. 서류에는 N2가 단팔 기준으로 들어가고, 면접 시점(11월 이후)에는 양팔 확장분이 붙어 있다. 이 구분을 전제로 계획을 짜야 한다.

## 1. 후보 태스크 6축 채점

G0는 게이트다. 통과하지 못하면 나머지를 채점하지 않는다.

### 채점 근거

**① 픽앤플레이스 1단계** — 팀이 이미 마일스톤으로 확정했고 반드시 통과해야 하므로 채택 여부를 묻는 대상이 아니다. 다만 R4에서 확인했듯 이것은 B0 등급이라 양팔의 근거가 되지 않고, 부트캠프 수료생 다수가 낼 산출물이라 차별화가 하(下)다. **기준선으로만 쓰고 이것 자체를 포트폴리오의 주장으로 삼지 않는다.**

**② 양팔 peg-insertion** — 양팔 필요성 근거가 가장 강한 B2 태스크다. 참조 수치가 시연 60회로 성공률 80%인데, 이는 조건을 고정한 상태의 값이고 배치를 랜덤화하면 더 필요하다. 실기체 사용이 10/13에 끝나므로 픽앤플레이스를 통과시킨 뒤 남는 기간에 60회 이상을 추가로 모으는 것은 시간상 빠듯하다. **R1(양팔 동시 텔레옵) 결과가 좋게 나오면 재검토한다.**

**③ 천 접기** — 유연물이라 목표 자세 정의가 성립하지 않아 IK 경로가 아예 없고, 데이터 수집량이 가장 크다. 시간과 수집창 양쪽에서 탈락.

**④ 핸드오버** — 한 팔이 집어 다른 팔에 넘기는 B1 태스크. 픽앤플레이스에서 한 단계만 올린 것이라 시간 부담이 작고, **넘기는 순간의 위치 오차를 수치로 잴 수 있어** 측정 축이 강하다. 양팔 근거는 절반짜리지만 "왜 양팔인가"에 최소한의 답은 된다. 2단계 태스크 후보로 권한다.

**⑤ 음성 명령 태스크 분해** — G0에서 탈락시킨다. 회의에서 "구현 난이도 대비 효과가 좋다"는 평이 있었고 데모 완성도는 확실히 올라가지만, 이 작업의 산출물을 메인 축 어휘로 서술하면 "STT API를 붙이고 LLM에 프롬프트를 보냈다"가 된다. C++·ROS2·Linux·검증 어느 쪽으로도 할 말이 생기지 않는다. **팀 데모에는 넣되 내 포트폴리오 항목으로는 세우지 않는다.** 담당 파트도 아니다.

**⑥ 양팔 텔레옵 수집 파이프라인 + 에피소드 품질 판정** — 이것이 주 산출물이다. 근거는 R4의 신입 개방 공고 문장들이다. 엔젤로보틱스가 "manipulation dataset 학습 파이프라인 설계 및 운영", "데이터 수집 세션 연동 — 학습 데이터 전처리·라벨링 워크플로우 구축"을 신입 개방 업무로 적었고, KIST가 "조작작업 데이터셋 구축"을 적었다. **내가 어제 만든 데이터 규격이 이 문장들과 그대로 대응한다.**

**⑦ IK 대 IL 동일 격자 비교** — 두 번째 주 산출물이다. 담당 파트 두 축을 하나의 측정 서사로 묶는다. 3단 판정(문제·해결·결과 수치)을 가장 자연스럽게 충족하고, 팀 프로젝트에서 내 기여를 분리해 서술하기도 쉽다. 결과가 어느 쪽으로 나오든 산출물이 된다 — IK가 이기면 "학습이 필요한 조건을 데이터로 규명했다"가 되고, IL이 이기면 "학습이 이기는 조건을 규명했다"가 된다.

## 2. 무게 제외 판정과의 관계

| 관측 | 판정과의 관계 |
|---|---|
| 양팔 SW 직무 2건이 모두 신입 불가(경력 6년↑ / 석사↑) | **판정을 지지한다.** 양팔 개인 산출물의 무게 제외는 실측과 정합 |
| 레인보우로보틱스 양팔로봇 SW 공고가 실재하고 포트폴리오 PPT를 요구 | 판정과 충돌하지 않음. 그 직무는 신입 대상이 아니다 |
| 신입 개방 공고에 조작 데이터셋·모방학습 파이프라인·매니퓰레이터 제어가 등장 | **판정 밖의 새 관측.** IK·뎁스·양팔이 아니라 데이터 파이프라인 층이 열려 있다는 신호 |

## 3. N2 흡수안 대 별도 산출물안

계획이 흡수안을 선호한다고 미리 적었으므로, 반대 방향을 먼저 세워 검증한다.

### 별도 산출물안의 논거

양팔은 단팔과 물리적으로 다른 문제다. 좌우 좌표계 정합, 양팔 타임스탬프 동기, 협응 태스크의 액션 표현이 단팔에는 없던 요소다. N2를 SO-101 단팔로 이미 규정했다면 양팔을 억지로 밀어 넣는 것은 두 프로젝트를 흐린다. 게다가 팀 프로젝트라 산출물 소유가 나 혼자가 아니어서, 개인 대표작 N2에 팀 산출물을 섞으면 "본인의 기여" 서술이 복잡해진다.

### 흡수안의 논거

N2의 정의는 로봇 기체가 아니라 **파이프라인**이다. "텔레옵 수집 → 에피소드 품질 판정 → LeRobot IL 학습 → 평가 프로토콜"이라는 구조에서 기체가 단팔이냐 양팔이냐는 대상의 차이일 뿐 구조의 차이가 아니다. 오히려 **같은 파이프라인을 두 기체에 적용했다**는 것이 파이프라인의 재사용성을 입증한다 — 합격자 사례에서 강한 신호였던 "직접 만든 재사용 가능한 단일 산출물"에 정확히 해당한다.

신규 개수를 늘리지 않는다는 확정 원칙도 흡수안을 지지한다. 그리고 시간 예산상 별도 산출물을 3단 판정까지 끌어올릴 여력이 없다.

### 판정 — 흡수안 채택, 단 조건부

흡수하되 **N2의 정의 문장을 기체 중립으로 다시 쓴다.** "SO-101 모방학습 데이터 파이프라인"이 아니라 "**조작 시연 데이터 파이프라인 — 단팔·양팔 두 기체에 적용**"으로 바꾼다. 이렇게 하면 양팔이 부록이 아니라 일반화의 증거가 된다.

**본인의 기여 분리**는 README 첫 화면 규칙(기존 전략 문서에 이미 있음)을 그대로 적용한다. 팀 산출물 중 내 몫은 데이터 규격·품질 판정 기준·검증 도구·IK 대 IL 비교 하네스이고, 이건 어제 만든 `~/bimanual-robot/data/schema/` 와 `tools/validate_episode_meta.py` 로 이미 증거가 남기 시작했다.

## 5. 팀 회의(금요일 16:00)에 가져갈 것

취업 전략 부분을 뺀 기술 논점만 추린다.

1. **픽앤플레이스는 양팔의 근거가 되지 않는다.** 상용 양팔 플랫폼 제조사도 pick and place를 단팔 충분 태스크로 분류한다. 1단계는 기준선으로 유지하되, 발표에서 "왜 양팔인가"에 답하려면 2단계에 B1 이상 태스크가 필요하다
2. **2단계 후보로 핸드오버를 제안한다.** 천 접기나 peg-insertion보다 시간 부담이 작고, 넘기는 지점의 위치 오차라는 측정 축이 명확하다
3. **데이터 수집량 기준선은 태스크당 시연 60회다.** ACT 참조 수치이며 조건을 랜덤화하면 더 늘어난다. 이 숫자로 일정을 역산해야 한다
4. **수집 마감은 M07 시작 전이다.** 실기체 사용 가능 기간이 M07보다 먼저 끝나므로, 수집을 M07 안에 하려는 계획은 성립하지 않는다
5. **양팔 state/action 표현 규약을 수집 전에 확정해야 한다.** 나중에 바꾸면 이전 에피소드가 전부 무효가 된다
