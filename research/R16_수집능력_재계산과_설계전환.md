# R16 — 수집 능력 재계산과 설계 전환

작성 2026-08-20 · 계기: "시연은 여러 번 할 수 있다"는 지적. R15의 200 에피소드 전제를 재검토한다

## 결론 먼저

**데이터는 병목이 아니었다.** R15에서 잡은 200 에피소드는 근거 없는 보수적 추정이었고, 실제 수집 능력은 **수천 단위**다.

| 시나리오 | 총 시간 | 복잡 태스크 | 중간 | 단순 |
|---|---:|---:|---:|---:|
| 보수 (주말만, 하루 4h) | 64h | **1,920** | 3,291 | 5,760 |
| 표준 (주말 + 평일 저녁 2회) | 128h | **3,840** | 6,582 | 11,520 |
| 적극 (주말 + 평일 저녁 4회) | 192h | **5,760** | 9,874 | 17,280 |

기간은 8/20~10/13(실기체 마감 전) 8주 기준이고, 에피소드당 소요는 조작+리셋을 단순 40초·중간 70초·복잡 120초로 잡았다.

**ALOHA Unleashed가 실기 5태스크에 26,000 시연을 썼으니 태스크당 5,200이다. 적극 시나리오면 그 규모에 도달한다.** 앞서 "신발끈·셔츠 걸기는 원천 불가"라고 한 판단은 데이터 규모 측면에서는 틀렸다.

**그러나 병목이 사라진 게 아니라 옮겨갔다. 이제 하드웨어 자유도가 상한이다.**

---

## 1. 무엇이 바뀌었나

### 데이터 규모 제약 해제

R15의 계층표에서 우리 위치가 올라간다.

| 시연 규모 | 종전 판정 | 재판정 |
|---|---|---|
| 50~60 | 가능 | 가능 (기준선) |
| 수백~수천 | 검토 안 함 | **주력 구간** |
| 5,200 (ALOHA Unleashed 태스크당) | **불가** | **적극 시나리오로 도달 가능** |
| 100만+ (π₀) | 불가 | 불가 (파인튜닝으로만) |

### 새 병목 — 하드웨어 자유도

데이터를 아무리 모아도 **5축 + 그리퍼로 못 하는 동작은 못 한다.**

| 태스크 | 데이터로 해결되나 | 실제 병목 |
|---|---|---|
| 신발끈 묶기 | **아니오** | 다단계 매듭에 **손목 자유도 부족**. ALOHA 2는 팔당 7자유도 |
| 셔츠 걸기 | 아니오 | 옷 무게·크기가 페이로드 초과 |
| 넥타이 매기 | 아니오 | 자유도 |
| **케이블 라우팅** | **예** | 없음 — 동작은 단순하고 다양성이 어려움의 원천 |
| **다양한 물체 파지·삽입** | **예** | 없음 |

**여기서 태스크 선정 기준이 바뀐다.**

> **동작이 복잡한 태스크는 자유도 때문에 불가능하고, 조건이 다양한 태스크는 데이터로 풀린다. 우리는 후자를 골라야 한다.**

즉 **어려움의 원천을 "동작의 복잡도"가 아니라 "조건의 다양성"에 두는 태스크**가 우리 하드웨어와 데이터 능력에 맞는다.

---

## 2. 그래서 설계가 어떻게 바뀌나

### 종전 (R15)

태스크 2종 × 50~60 시연 → 네 경로(scratch·파인튜닝·증강·시뮬사전학습) 비교

**문제**: 데이터가 적다는 것을 전제로 깔았는데, 그 전제가 틀렸다.

### 전환

**데이터량과 조건 다양성을 축으로 하는 성능 곡선을 그린다.**

| 축 | 값 |
|---|---|
| **데이터량** | 50 · 200 · 500 · 1,000 · 2,000 에피소드 |
| **조건 다양성** | 물체 종류 1종 → 3종 → 5종, 배치 격자 좁음 → 넓음 |
| **방법** | scratch ACT · π₀/SmolVLA 파인튜닝 |
| **평가** | 학습에 없던 조건에서의 성공률(일반화) |

이렇게 하면 **"몇 개를 모아야 충분한가"와 "무엇을 다양화해야 효과가 큰가"에 답하는 곡선**이 나온다. 이건 우리 팀이 실제로 알아야 하는 것이면서, 동시에 논문 수치와 비교 가능한 결과다.

**핵심 질문 셋**

1. 조건을 고정하면 60회로 80%가 나온다(ACT). **조건을 다양화하면 몇 배가 필요한가?**
2. 사전학습 파인튜닝은 그 곡선을 얼마나 왼쪽으로 옮기는가? (같은 성능에 데이터 몇 분의 일)
3. 다양성을 늘리는 것과 같은 조건을 더 찍는 것 중 무엇이 성능에 더 기여하는가?

3번이 특히 실무적이다. **수집 시간이 유한할 때 어디에 쓸지의 문제**이고, 답이 데이터로 나온다.

---

## 3. 데이터를 늘릴 때 실제로 걸리는 것

데이터 규모가 풀렸다고 무한정 좋은 게 아니다. 늘리면 다른 비용이 붙는다.

| 항목 | 추정 | 대응 |
|---|---|---|
| **저장 공간** | 카메라 3대·30초·640x480 기준 에피소드당 5~10MB → **2,000개면 10~20GB, 5,000개면 25~50GB** | 문제 없음. HF Hub private 업로드도 가능 |
| **학습 시간·GPU 비용** | 데이터가 10배면 학습도 길어진다. 클라우드 시간당 과금 | **여기가 실질 병목.** R3(GPU 비용) 조사가 급해짐 |
| **조작자 피로** | 텔레옵 집중력은 하루 4~6시간이 한계 | 팀원 교대. 단 **조작자별 스타일 차이가 데이터에 섞인다** |
| **품질 저하** | 후반부로 갈수록 시연이 거칠어진다 | 에피소드 메타데이터에 조작자·시각 기록 → 품질 판정에 사용 |
| **같은 것만 반복** | 많이 찍어도 조건이 같으면 정보량이 안 는다 | **조건 다양성을 수집 계획에 미리 설계** |
| **로봇 1대** | 리더-팔로워 2세트 = 로봇 1대. **동시 수집 불가** | 인원이 많아도 병렬이 안 된다. 시간만 늘릴 수 있다 |

**조작자별 스타일 차이**는 양면적이다. 정책의 강건성을 높이기도 하고, 일관성을 해쳐 학습을 어렵게도 한다. 메타데이터에 조작자를 남기면 **"조작자 수가 성능에 미치는 영향"**이라는 측정 축이 하나 더 생긴다.

## 4. 다시 열린 태스크와 여전히 닫힌 태스크

| 태스크 | 판정 | 사유 |
|---|---|---|
| **케이블 라우팅 (다종·다경로)** | **최적** | 동작 단순 + 다양성이 어려움의 원천. 데이터가 그대로 성능이 된다 |
| **엉킨 케이블 분리** | **가능** | 엉킴 패턴 다양성. 참조 성공률 91.2% 존재 |
| **다종 물체 삽입·조립** | 가능 | 공차 설계 필요하나 다양성 축이 명확 |
| 봉지 열어 담기 | 가능 | 석션 조달 시 |
| 보호필름 박리 | 가능 | 필름 모서리 파지가 관건 |
| 수건 개기 | **조건부** | 2D 자기가림. 데이터로 풀 수 있으나 소형 천으로 한정 |
| 양말 짝 맞추기 | **조건부** | 뒤집기 동작이 자유도를 요구 |
| **신발끈 묶기** | **불가** | **자유도** — 데이터로 해결 안 됨 |
| **넥타이·리본 매듭** | **불가** | 자유도 |
| 셔츠 걸기 | 불가 | 페이로드·크기 |

**정리**: 데이터 규모로 막혔던 것들이 열렸지만, **자유도로 막힌 것은 그대로 막혀 있다.** 앞서 대중형 후보들이 부적합했던 진짜 이유가 데이터가 아니라 자유도였다.

## 5. 권고

**태스크는 케이블 계열을 유지하되, 설계 주제를 "데이터 효율"에서 "데이터-다양성 스케일링"으로 바꾼다.**

| 항목 | 내용 |
|---|---|
| 주 태스크 | 케이블 라우팅 (클립 삽입) — 케이블 종류·경로·배치를 다양성 축으로 |
| 보조 태스크 | 핸드오버 — RoboTwin `handover_block`과 직접 비교용 기준선 |
| 목표 수집량 | **주 태스크 1,500~2,500, 보조 300~500** (표준 시나리오 안) |
| 측정 | 데이터량 5구간 × 다양성 3수준 × 방법 2종의 성공률 곡선 |
| 대조군 | 단팔 · 귀무 정책 · 학습에 없던 조건 |

**이 구성의 강점은 결과가 어떻게 나와도 결론이 있다는 것이다.** 곡선이 일찍 포화하면 "이 태스크는 N개면 충분하다", 계속 오르면 "더 모을수록 이득이 있다", 다양성이 데이터량보다 효과가 크면 "수집 시간은 다양화에 써야 한다"가 된다. 전부 팀과 후속 작업에 쓸모 있는 답이다.
