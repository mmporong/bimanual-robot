# R15 — 데이터 예산과 사전학습: 태스크 선정의 재구성

작성 2026-08-20 · 해외 사례와 논문을 뼈대로 태스크 선정 문제를 다시 세운다

## 결론 먼저

**지금까지 태스크를 잘못된 축으로 골라 왔다.** "무엇이 흥미로운가"나 "어느 회사가 하는가"가 아니라 **"시연 몇 개로 되는 태스크인가"**가 먼저 정해져야 했다.

해외 사례의 데이터 규모를 나란히 놓으면 이게 드러난다.

| 시연 규모 | 태스크 | 출처 |
|---|---|---|
| **50~60** | 조건이 고정된 단일 협응, 삽입 | ACT(양팔 peg-insertion 60회로 80%), Mobile ALOHA(co-training 시 50회로 80%) |
| 2,000 (시뮬) | 시뮬 태스크 3종 | ALOHA Unleashed |
| **26,000** | **신발끈 묶기, 셔츠 걸기, 기어 삽입, 로봇 수리, 주방 청소** | **ALOHA Unleashed** (실기 5개 태스크) |
| 100만+ | 햄퍼에서 빨래 접기, 골판지 박스 조립 | π₀ (7종 로봇·68 태스크 + Open X-Embodiment) |

**우리 예산은 태스크당 50~60회, 총 200~300 에피소드다.** 그러면 첫 줄에 있는 것만 된다. 앞서 낸 대중형 후보(신발끈·넥타이·리본·종이접기)는 전부 26,000 시연 급이라 원천적으로 불가능하다. R14가 설득력이 없었던 이유가 이것이다.

**그런데 이 계층을 우회하는 길이 있다.** 처음부터 학습하지 않고 **사전학습된 정책을 파인튜닝**하면 된다. 그리고 그 도구가 이미 우리 손에 있다.

---

## 1. LeRobot에 최신 VLA가 전부 들어 있다

`~/lerobot/src/lerobot/policies/` 를 직접 확인한 결과다.

| 정책 | 성격 |
|---|---|
| `act` | Action Chunking Transformer — 양팔 ALOHA 기준 설계 |
| **`pi0`, `pi05`, `pi0_fast`** | **Physical Intelligence의 범용 정책.** π₀는 7종 로봇·68 태스크로 학습, π₀.₅는 이종 태스크 co-training으로 새 환경 일반화 |
| **`smolvla`** | 경량 VLA — 회의에서 후보로 언급된 그 모델 |
| `groot` | NVIDIA GR00T |
| `diffusion`, `vqbet`, `tdmpc`, `xvla`, `wall_x`, `evo1` 외 | 그 밖의 정책군 |

**즉 우리는 scratch 학습과 사전학습 파인튜닝 중에서 고를 수 있다.** 그리고 이 선택 자체가 M05(허깅페이스 활용 로봇 전이학습, 9/7~9/22) 커리큘럼과 정확히 겹친다.

π₀의 어노테이션 프로토콜에 **"산업 조립 — 삽입, 케이블 라우팅, 부품 결합"**이 포함돼 있다는 점도 눈여겨볼 만하다. 케이블 라우팅 계열은 사전학습 분포 안에 있을 가능성이 있다.

---

## 2. 데이터 부족을 메우는 네 갈래

논문에서 확인된 경로다. 넷 다 우리 예산에서 시도 가능하다.

| 경로 | 방법 | 근거 | 우리 적용 |
|---|---|---|---|
| **A. 사전학습 파인튜닝** | 대규모로 학습된 VLA를 우리 태스크에 맞춤 | π₀ / π₀.₅ — 새 환경 일반화가 목표 | LeRobot `pi0`·`pi05`·`smolvla` 바로 사용 |
| **B. 자동 데이터 증강** | 소수 시연에서 궤적 합성 | **DexMimicGen** `2410.24185` | 50회 찍고 수백 개로 늘림 |
| **C. 단팔 정책 전이** | 사전학습 단팔 정책을 양팔로 확장 | **AnyBimanual** `2412.06779` | 기존 `~/so101_tools` 단팔 자산 활용 |
| **D. 시뮬 사전학습** | 시뮬 데이터로 학습 후 실기 이전 | **RoboTwin 2.0** — 양팔 50 태스크·10만 궤적·LeRobot v3.0 스키마 | M06(MuJoCo·Isaac) 기간에 수행 |

**이 넷을 비교하는 것 자체가 실험이 된다.** 같은 태스크·같은 평가 격자에서 scratch / 파인튜닝 / 증강 / 시뮬사전학습의 성공률을 재면, 그 표가 곧 산출물이다. 데이터 예산이 작다는 약점이 오히려 주제가 된다.

## 3. 해외 사례가 실제로 하는 태스크 (데이터 규모와 함께)

앞선 문서들에서 모은 사례를 **규모 축**으로 다시 정렬한다.

| 사례 | 태스크 | 규모·성격 | 우리 재현 가능성 |
|---|---|---|---|
| **ACT / ALOHA** | 양팔 peg-insertion, 배터리 슬롯 삽입 | **60 시연 80%** | **가능** — 기준선 그 자체 |
| **Mobile ALOHA** | 와인 닦기, 계란 깨기, 팬 헹구기 | 50 시연 + co-training | **부분 가능** — co-training 필요 |
| **RoboTwin 2.0** | 양팔 50 태스크(핸드오버·냄비 들기·스테이플러 누르기 등) | 시뮬, 태스크당 50 demo·100 평가 | **가능** — 프로토콜 차용 |
| **ALOHA Unleashed** | **신발끈 묶기, 셔츠 걸기, 기어 삽입** | **26,000 시연** | **불가** — 규모 초과 |
| **π₀ / π₀.₅** | 햄퍼 빨래 접기, 박스 조립 | 100만+ | **불가**(scratch) / **가능**(파인튜닝) |
| **Dexterity Mech** | 트레일러 상하차 | FedEx 실배치, 두 팔 59kg | **불가** — 페이로드 |
| **ABB YuMi** | 소형 부품 조립, 실험실 시료 취급 | 상용 10년 | 부분 가능 |
| **Apple Daisy** | 아이폰 분해 시간당 200대 | 전용 설비 5팔 | 부분 가능(클립 결합 한정) |
| **Telexistence** | 음료 진열, 자율 98% + VR 원격 개입 | 300개 매장 | 아키텍처만 차용 |

**표에서 읽어야 할 것**: 우리가 재현 가능한 것은 **ACT·RoboTwin 계열의 50~60 시연 태스크**뿐이다. 그 위 계층은 사전학습을 끼워야 손이 닿는다.

## 4. 이 관점에서 다시 고른 태스크

기준을 셋으로 좁힌다. **50~60 시연으로 학습 가능 · 양팔 필수 · 사전학습 분포에 가까움.**

### 1순위 — 케이블 라우팅 (클립 삽입)

| 축 | 근거 |
|---|---|
| 규모 | 삽입 계열이라 ACT의 peg-insertion(60회 80%)과 같은 난이도대 |
| 양팔 | 안정화 팔이 장력을 유지하지 않으면 형상이 무너진다 |
| **사전학습** | **π₀ 어노테이션 프로토콜에 "케이블 라우팅"이 명시돼 있다.** 파인튜닝 전이 가능성이 높다 |
| 벤치마크 | **DLO-Lab** `2606.04206` — 케이블 전용 벤치마크로 평가 프로토콜 차용 가능 |
| 선행 | Cable Routing with Tactile Motion Primitives `2303.11765` |
| 하드웨어 | 회전 불필요, 수십 g, 백래시를 케이블이 흡수 |

### 2순위 — 핸드오버 (한 팔에서 다른 팔로)

| 축 | 근거 |
|---|---|
| 규모 | **ACT 기본 설정의 레퍼런스 태스크가 "transfer"**다. 60회 급 |
| 양팔 | 정의상 양팔 |
| 벤치마크 | RoboTwin에 `handover_block`, `handover_mic`가 있다 — **직접 비교 가능** |
| 하드웨어 | 가장 무난 |

### 3순위 — 양팔 peg-insertion

| 축 | 근거 |
|---|---|
| 규모 | **ACT 논문의 바로 그 태스크. 60회로 80%** |
| 양팔 | 안정화 + 삽입 |
| 하드웨어 | **백래시가 걸림** — 공차를 크게 설계한 전용 부품 필요(3D 프린팅, M07 강의 트랙 ③) |
| 강점 | **논문 수치와 1:1 비교가 되는 유일한 태스크** |

## 5. 새 프로젝트 구성안

태스크 하나를 고르는 대신 **"데이터 예산이 작을 때 무엇을 할 수 있는가"**를 주제로 삼는다.

**제목 후보: 저비용 양팔 플랫폼에서의 데이터 효율 비교**

| 단계 | 내용 |
|---|---|
| 1 | 태스크 2종 선정 — 핸드오버(RoboTwin 비교 가능) + 케이블 라우팅(DLO-Lab 비교 가능) |
| 2 | 태스크당 50~60 시연 수집. **공통 평가 격자와 판정 기준 확정** |
| 3 | **네 경로 비교**: scratch ACT / π₀·SmolVLA 파인튜닝 / DexMimicGen 증강 / RoboTwin 시뮬 사전학습 |
| 4 | 단팔 대조군·귀무 정책 대조로 수치 신뢰도 확보 |
| 5 | HIL 개입 데이터로 재학습, before/after |

**이 구성의 강점**

- **데이터가 적다는 제약이 주제가 된다.** 부족을 숨기지 않고 정면으로 다룬다
- 모든 수치에 **비교 대상이 존재한다** — ACT 60회 80%, RoboTwin 프로토콜, DLO-Lab
- **M05(허깅페이스 전이학습)와 M06(시뮬)이 그대로 실행 단계**가 된다
- 태스크가 평범해도 **비교 자체가 산출물**이라 "튜토리얼 따라한 것"으로 보이지 않는다
- 결과가 어느 쪽으로 나오든 결론이 있다 — 파인튜닝이 이기면 "저비용 플랫폼은 사전학습을 써야 한다", scratch가 이기면 "이 규모에서는 사전학습 이득이 없다"

## 6. 확인해야 할 것

| # | 항목 | 왜 |
|---|---|---|
| 1 | π₀·SmolVLA 파인튜닝의 VRAM 요구 | 회의에서 "20GB 이상"이 언급됐다. 클라우드 필요 여부와 비용이 갈린다 |
| 2 | LeRobot의 `pi0`·`smolvla`가 SO-101 양팔 구성을 그대로 받는지 | 액션 차원이 다르면 어댑터가 필요하다 |
