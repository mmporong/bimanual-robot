# 1. 하드웨어 실측

## 1-1. 구성과 사양

| 항목 | 값 | 출처 |
|---|---|---|
| 구성 | **SO-101 리더 2 + 팔로워 2 (총 4대)** | 사용자 확정 |
| 자유도 | **5축 + 그리퍼** — `shoulder_pan` · `shoulder_lift` · `elbow_flex` · `wrist_flex` · `wrist_roll` · `gripper` | `lerobot/robots/so_follower` |
| 서보 | Feetech **STS3215**, 감속비 **1:345**. 표준킷 7.4V **16.5 kg·cm** / 프로킷 12V **30 kg·cm** | SO-ARM100 BOM |
| 링크 길이 | 상완 **112.6 mm** · 전완 **134.9 mm** · 손목→TCP **98.1 mm** | URDF 실측 |
| **최대 리치** | **약 346 mm / 팔** | 위 합산 |
| 관절 한계 | pan ±110° · lift ±100° · elbow ±96.8° | `LIMITS` |
| 실효 페이로드 | **수백 g** (기어 효율·모멘트 암으로 실제는 더 낮음) | 공개 사양 |
| 팔 자중 | 약 800 g | 공개 사양 |
| **특기** | **`wrist_roll`이 `full_turn_motor` — 전회전 가능** | `so_follower.py:135` |
| **협응 영역** | 베이스 간격 250~300 mm에서 **폭 약 200 mm** (미실측 추정) | R8 |

## 1-2. 확정된 하드웨어 제약

| 제약 | 실측 근거 |
|---|---|
| **그리퍼 닫힘 약 15초** | 정착 폴링 필요. 고정 sleep은 덜 문 채 들어올린다 |
| **과부하 보호 빈발** | 파지 후 목표를 현재값으로 되쓰지 않으면 보호가 걸려 열기가 거부된다 |
| **절대각 명령만 안전** | delta 방식은 이중 개방 사고를 낸다 (개방 55·폐쇄 1) |
| **depth가 얇은 물체를 못 봄** | 체스말형 물체에서 **컬러 250px 대비 유효 깊이 화소 22~44개(4%)**. 깊이 창이 넓어져 **배경 중앙값을 반환**, 잔차 std 40 mm |
| **회전 토크 전달 한계** | 마찰 파지로 전달 가능한 토크 **약 0.32 N·m** (μ=0.7·파지력 15N·r=15mm 가정). 일반 병뚜껑은 **1.0~1.5 N·m** 필요 |
| 사이클 타임 영향 | 에피소드당 그리퍼 개폐 4회 = 60초. **200 에피소드면 3.3시간이 대기** |

**대응 가능한 것**: 큰 지름·고무 패킹으로 마찰 개선, 형상 결합(3D 프린팅 어댑터), 석션 전환(단 회전 불가), RGB+테이블 평면 투영으로 depth 우회.

# 2. 소프트웨어 — 확정 사항

## 2-1. 양팔 지원 (LeRobot)

**양팔 동시 텔레옵은 미검증 영역이 아니라 공식 지원 기능이다.**

| 항목 | 내용 |
|---|---|
| 로봇 | `bi_so_follower` (SO-100/101) · `bi_openarm_follower` · `bi_rebot_b601_follower` |
| 텔레옵 | `bi_so_leader` · `bi_openarm_leader` · `bi_openarm_mini` · `bi_rebot_102_leader` |
| 공통 | `lerobot/utils/bimanual.py`의 `BimanualMixin` — 연결·캘리브레이션 생명주기 |
| **조작 방식** | **조작자 1명이 양손으로 리더암 2대**를 잡는다 (ALOHA 방식). 조작자 2명도, 순차 녹화도 아니다 |
| **좌우 표현 규약** | **`left_*` / `right_*` 접두어.** 좌우 공용 카메라는 접두어 없음. concat 아님 |
| 동기화 | 별도 장치 없음. **한 제어 루프의 같은 틱에서 좌우를 순차 처리**하므로 타임스탬프가 하나. 실제 위험은 좌우 어긋남이 아니라 **틱 전체가 밀리는 주기 지터** |
| 데이터 포맷 | **LeRobot v3.0** (`CODEBASE_VERSION = "v3.0"`) |

## 2-2. HIL 개입 재학습

`bi_so_leader`가 공식 지원 대상이다. 정책이 자율 주행하다 사람이 리더암으로 넘겨받아 교정하고 돌려준다. 한 에피소드 안에서 여러 번 오갈 수 있고 개입해도 리셋하지 않아 **자율·복구·교정이 하나의 연속 궤적**으로 남는다.

`BiSOLeader.send_feedback()`이 전환 시 **양쪽 리더암을 팔로워의 현재 자세로 명령해 불연속을 제거**한다.

이론 배경: **DAgger**(2011, 학습자가 방문하는 상태에서 교정) → **HG-DAgger**(2019, 필요할 때만 개입) → **RaC**(2025, 개입을 복구와 교정으로 분해).

## 2-3. 내장 정책

`~/lerobot/src/lerobot/policies/` 에 있는 것:

`act` · **`pi0` · `pi05` · `pi0_fast`** (Physical Intelligence) · **`smolvla`** · `groot` (NVIDIA) · `diffusion` · `vqbet` · `tdmpc` · `xvla` · `wall_x` · `evo1` · `eo1` · `fastwam` · `lingbot_va` · `molmoact2` · `multi_task_dit` · `rtc` · `vla_jepa` · `gaussian_actor`

**scratch 학습과 사전학습 파인튜닝 중에서 고를 수 있다.** 이 선택이 M05(허깅페이스 전이학습, 9/7~9/22) 커리큘럼과 겹친다.

## 2-4. 시뮬 자산

- **RoboTwin 2.0** — 양팔 태스크 **50종**, Aloha-AgileX(14 DOF), 평가 프로토콜 **태스크당 100 에피소드·demo_clean 50개**, 공개 데이터 **10만 궤적·79.6GB·Apache 2.0**, **이미 LeRobot v3.0 스키마**
- **MuJoCo 미러** — `~/so101_tools/sim`, qpos = URDF q 직결, 28자세 Kabsch RMS 0.00mm. **실물 없이 자세 검증 가능**

# 4. 양팔 필요성 — 판정 프레임

## 4-1. 3등급

| 등급 | 정의 | 판별 |
|---|---|---|
| **B0 병렬** | 두 팔이 독립적으로 다른 물체 | 한 팔로 두 번 해도 결과가 같은가 → **양팔 근거 없음** |
| **B1 순차** | 한 팔의 결과를 다른 팔이 이어받음 | 시간 간격을 둬도 성립하는가 |
| **B2 동시** | 두 팔이 같은 물체에 동시 구속 | 한쪽만 멈추면 즉시 실패하는가 |

## 4-2. 산업에서 양팔이 필요한 세 갈래

| 근거 | 문제 | 대표 |
|---|---|---|
| **(a) 무게·부피** | 한 팔로 물리적으로 못 든다 | Dexterity Mech — 두 팔 59kg |
| **(b) 고정 + 작업** | 한 손이 잡아야 다른 손이 일한다 | ABB YuMi 소형 조립, Mobile ALOHA |
| **(c) 사람 작업장 그대로** | 설비를 못 바꿔 사람 형상이 필요 | Figure · Agility · Apptronik |

**우리가 쓸 수 있는 것은 (b)뿐이다.** (a)는 페이로드 불가, (c)는 하드웨어가 다르다.

## 4-3. 학술 용어

**acting arm(작업 팔) / stabilizing arm(안정화 팔)** 역할 분리. VoxAct-B `2407.04152`, BUDS가 이 프레임을 쓴다.
