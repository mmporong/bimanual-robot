# R32 — IL과 IK의 결합 구조, 정책 선택, 실행 모드

작성 2026-09-03 · 근거: 로컬 실측(2026-08-26 ACT 롤아웃), 저장소 R13·R15·R16·R31, 외부 논문
범위: `HOLD THE FLOW` 양팔 붓기의 학습 파이프라인 설계 판정

## 1. 가장 큰 발견 — 언어조건 정책이 필요 없다

R26이 명령 문장을 3종으로 고정했다.

```
Move the red cup to the left tray     (move)
Hand over the blue cup to the other arm (handover)
Pour the bottle into the held cup      (pour)
```

**후보가 3개면 정책 하나가 언어를 이해할 필요가 없다.** 스킬마다 ACT를 따로 학습하고, 음성이 어느 정책을 부를지만 정하면 된다.

```
음성 → STT → 슬롯 파싱 → 스킬 선택 → 해당 스킬 전용 ACT
```

이 구조의 이점은 다음과 같다.

- ACT는 언어조건 정책이 아니다. 한 모델로 3태스크를 시키려면 SmolVLA·π₀ 같은 VLA가 필요한데, 그러면 8 GB VRAM에서 VLM 동결 같은 제약이 붙는다
- 스킬별 정책은 각자 짧아 데이터 효율이 높고, 한 스킬이 실패해도 나머지를 재학습하지 않는다
- 어느 스킬에서 실패했는지가 구조적으로 분리돼 평가표를 그대로 쓸 수 있다

VLA는 "명령 어휘를 열어야 할 때" 도입한다. 지금은 그 요구가 없다.

## 2. 현재 프로젝트 상태

R31이 이미 결정한 것과 실측으로 확인된 것을 분리한다.

| 항목 | 상태 |
|---|---|
| Nav2와 조작 분리 | 결정 (한 정책으로 합치지 않음) |
| 조작 기준선 | IK + 상태기계 먼저, ACT는 그 뒤 |
| 역할 분리 | 컵 팔 `STABILIZE`, 병 팔 `ACT` |
| 유입량 판정 | 도킹 저울 전후 질량차. FSR은 접촉·과압만 |
| ACT 입력 | RGB 3시점 + 관절 상태. **뎁스는 G0에서 제외** |
| 앙상블 vs 청크 | **실측 완료** — 5절 |
| 정규화 경로 | **실측 완료** — `make_pre_post_processors` 필수 |
| 파지 판정 | **실측 완료** — 그리퍼 각도는 증거가 아님 |

## 3. IL과 IK를 섞는 네 층위

문헌과 구현을 정리하면 결합 방식은 넷이다.

| 층위 | 구조 | 데이터 요구 | 안전 경계 | 판정 |
|---|---|---|---|---|
| **L1 직렬 분리** | 구간을 나눠 IK 구간과 IL 구간을 순서대로 실행 | 낮음 | 명확 | **채택 (기본)** |
| **L2 계층** | 정책이 도구공간 목표를 내고 IK가 관절로 변환 | 중간 | IK 특이점 처리 필요 | 조건부 |
| **L3 잔차** | IK 기준선 궤적에 정책이 보정량을 더함 | 낮음 | 기준선이 경계 | **채택 (붓기 구간)** |
| **L4 통합** | 전 구간을 하나의 VLA가 담당 | 매우 높음 | 없음 | 제외 |

### L1을 기본으로 두는 이유

붓기 태스크는 결정론적으로 풀리는 부분과 학습이 필요한 부분이 깨끗하게 갈린다.

| 구간 | 성격 | 담당 |
|---|---|---|
| `APPROACH` | Nav2 목표 도달 | IK 아님, Nav2 |
| `ALIGN` | RGB-D·AprilTag로 상대 자세 갱신 | 결정론 |
| `GRASP_BOTH` | 물체 위치 변동에 대한 강건성이 필요 | **IL** |
| `PRETILT_SLOW` | 기하학적으로 결정 | IK |
| `POUR_CALIBRATED` | 매체·잔량에 따라 기울기·정지시점이 변함 | **IL 또는 잔차** |
| `RETURN_UPRIGHT` | 기하학적으로 결정 | IK |
| `PLACE_BOTH` | 도킹 패드 좌표 고정 | IK |

전 구간을 IL로 배우면 IK로 이미 정확한 부분까지 데이터로 다시 배워야 한다. 데이터 예산을 학습이 실제로 필요한 두 구간에 몰아주는 편이 낫다.

### 붓기 구간에 잔차를 쓰는 이유

`POUR`는 목표 궤적이 대략 알려져 있고(기울임 각도-시간 보정표), 남는 문제는 잔량·매체에 따른 미세 보정이다. 이런 구조가 잔차 정책의 전형적 적용 조건이다. 기준선이 존재하는 상태에서 보정만 배우면 탐색 범위가 기준선 근방으로 줄고, 기준선 자체가 안전 경계 역할을 한다.

`ResiP`는 동결한 청크 BC 모델 위에 폐루프 잔차 정책을 얹어 정밀 조립의 반응성과 분포 이동 문제를 다뤘다. 우리 경우는 BC 대신 IK 기준선 위에 얹는 형태가 된다.

**단, 잔차는 2차 목표다.** 잔차 정책은 보통 RL로 학습해 실기 시행이 필요하다. G2 기준선이 통과하기 전에 착수하지 않는다.

### 액션 공간 — 결정 필요

ACT 기본은 관절 공간이다. SO-101은 5축이라 도구공간 6자유도를 만들 수 없으므로 관절 공간이 자연스럽다. 다만 붓기는 **두 팔의 상대 자세**가 성패를 가른다.

제안: 병 팔의 목표를 절대 관절값이 아니라 **컵 팔 그리퍼 기준 상대 좌표**로 표현한다. `Stabilize to Act`가 역할을 분리해 정책 차원을 줄인 것과 같은 논리이며, 컵 팔이 조금 흔들려도 병 팔의 목표가 따라간다. 이 표현 규약은 **본수집 전에 확정해야 한다.** 나중에 바꾸면 이전 에피소드가 전부 무효가 된다.

## 4. 정책 선택

| 정책 | 성격 | 8 GB VRAM | 5축 적합 | 추론 지연 | 판정 |
|---|---|---|---|---|---|
| **ACT** | 청크 예측 BC | 학습 가능 (배치 8) | 관절공간 그대로 | 낮음 | **기준선 채택** |
| Diffusion Policy | 다봉 분포에 강함 | 가능 | 가능 | 디노이징 스텝만큼 느림 | WiFi 왕복 예산에 불리 |
| SmolVLA | 경량 VLA, 언어조건 | VLM 동결 조건부 | 가능 | 중간 | 어휘 확장 시 |
| π₀ / π₀.₅ | 대규모 사전학습 VLA | 파인튜닝도 빠듯 | 가능 | 높음 | 제외 |

ACT를 기준선으로 두는 근거는 세 가지다. 양팔 삽입을 60 시연으로 80%까지 올린 선례가 있어 우리 데이터 예산과 맞고, 관절 공간 출력이 5축 SO-101에 그대로 얹히며, 이미 로컬에서 학습·롤아웃까지 한 번 돌려 봤다.

Diffusion Policy는 붓기처럼 연속적인 제어에 이론적 장점이 있지만, 정책 추론이 WiFi 너머에 있는 우리 구성에서는 디노이징 스텝이 그대로 왕복 예산을 먹는다. ACT 기준선이 통과한 뒤 같은 데이터로 비교하는 편이 안전하다.

### 비교 실험 자체가 산출물이다

R15가 정리한 네 갈래(사전학습 파인튜닝 / 데이터 증강 / 단팔 전이 / 시뮬 사전학습)를 **같은 태스크·같은 평가 격자**에서 비교하면 그 표가 곧 결과물이 된다. 데이터 예산이 작다는 약점이 주제로 바뀐다.

## 5. 실행 모드 — 앙상블을 끈다

### 우리 실측 (2026-08-26, 손목단독 ACT 60k, 스크립트 시연 22 에피소드)

| 모드 | 결과 |
|---|---|
| `--ensemble` (매 스텝 재예측·가중평균) | **60초 내내 큐브 위 맴돌기. 그리퍼 한 번도 안 닫음** |
| `--replan 15` (1.5초 청크 실행) | **스스로 하강·닫기 → 첫 자율 파지 성공** |

원인은 시연의 정지 구간이다. IBVS 정렬 대기와 그리퍼 정착 대기가 **같은 관측에 "기다려"와 "전환해"를 동시에 라벨한다.** 화면 한 장을 보는 정책이 평균을 내면 '정지'가 이기고, 청크를 통째로 실행하면 그 안의 전환이 그대로 나간다.

### 문헌이 같은 원인을 지목한다

`PACE`는 고정 재계획 지평의 문제를 이렇게 정리한다. 실제 시연에는 로봇이 자세를 유지하거나 멈추는 가변 길이 구간이 있는데, 고정 청크 길이는 자연스러운 태스크 경계를 넘어 커밋하거나 정지 구간에서 불필요하게 재계획하도록 강제한다. 시연 구조와 추론 절차의 불일치가 성능을 떨어뜨린다는 진단이다. PACE는 행동 분산이 작은 정지 구간을 탐지해 그 구간에서 청크를 늘리는 방식으로 대응한다.

원 ACT 논문의 절제 실험도 같은 축을 보여준다. `k=1`(청킹 없음)에서 1%였던 성공률이 `k=100`에서 44%로 올랐고, `k=200~400`(개루프에 근접)에서 다시 소폭 떨어진다. 반응성 부족과 긴 시퀀스 모델링의 어려움이 이유다.

### 채택 규칙

| 조건 | 실행 모드 |
|---|---|
| 스크립트 시연으로 학습한 정책 | **`--replan 10~15` 고정.** 앙상블 금지 |
| 사람 텔레옵 시연 (정지 구간 짧음) | 앙상블 재평가 가능 |
| 데이터 처방 | `prune_stationary`(정지 연속 3프레임 초과 솎아냄)로 학습셋 재구성 후 재학습 |

우리 태스크는 사람 텔레옵 수집이므로 정지 구간이 스크립트보다 짧을 것이다. 그래도 **첫 기준선은 청크 모드로 잡고, 앙상블은 별도 실험으로 분리한다.** 두 모드를 같은 체크포인트로 비교한 표를 남긴다.

## 6. 학습을 어떻게 나누는가

### 스킬 3분할

| 스킬 | 구간 | 종료 조건 | 실패 격리 |
|---|---|---|---|
| `S1 GRASP_BOTH` | 접근 완료 → 양손 파지 확인 | FSR 접촉 + 미세 들기 통과 | 파지 실패는 여기서만 |
| `S2 POUR` | 예비 기울임 → 직립 복귀 | 잔류 낙하 종료 | 유입량·흘림은 여기서만 |
| `S3 RETURN_PLACE` | 도킹 패드 반환 | 저울 판정 | 배치 오차는 여기서만 |

전이는 상태기계가 맡는다. 정책이 전이를 배우지 않으므로 각 스킬의 시작 조건이 명확해지고, 5절의 정지 구간 문제도 줄어든다.

### 데이터 배분

R16이 8주 기준 수천 에피소드가 가능하다고 재계산했다. 다만 실제로 필요한 것은 총량이 아니라 **평가 격자의 균형**이다.

| 축 | 값 |
|---|---|
| 용기 | 기준 / 변화 |
| 상대 배치 | 중앙 / 오프셋 |
| 매체 | 건식 1종부터 |

`UMI-Bench`의 2×2 평가 셀 구성을 그대로 가져오되, 시연 규모(1,600)와 평가 횟수(50)는 벤치마크 기준이므로 우리 필수량으로 간주하지 않는다. 스킬당 200~500에서 시작해 셀별 성공률을 보고 부족한 셀만 채운다.

### 성공·실패를 같은 스키마에

`COFFAIL`은 실물 모바일 양팔 로봇의 성공과 이상 실행을 함께 기록하고, 이상 구간의 시작·끝과 설명을 남겼다. 안전을 위해 액체 대신 작은 건면 조각을 썼다는 점도 우리 G0 매체 선택과 같다. 실패 구간을 시간 범위로 라벨링해 두면 나중에 학습형 실패 감지기로 바로 넘어갈 수 있다.

### 판정 지표

- **30스텝 지평 MAE로 본다.** 1스텝 MAE는 "현자세 유지" 귀무모형이 원리상 이기므로 신호가 없다
- 학습 손실만으로 채택하지 않고 실물 반복 평가로 판정한다
- 파지 성공은 그리퍼 각도로 판정하지 않는다. 정책은 시연의 닫힘값을 명령으로 재생하므로 빈 손도 같은 각도에서 선다. 사람 확인, 추가 닫기 프로브, 물체 소실 확인 중 하나를 쓴다

## 7. 액체 인지 논문의 적용 판단

팀에서 찾아 둔 두 편을 평가한다.

| 연구 | 방법 | 적용 판단 |
|---|---|---|
| Transparent Liquid Segmentation (ICRA 2022) | 착색 액체 영상을 생성모델로 투명 액체로 변환해 라벨 없이 분할 학습. 투명 컵의 액체 높이를 보고 붓기 제어 | **유입량 추정에는 미채택** |
| PourIt! (ICCV 2023) | 이미지 수준 라벨만으로 CAM 기반 액체 영역 검출, 3D 복원으로 액체-용기 거리를 폐루프 제어에 사용 | **흘림 감지에만 채택 후보** |

미채택 근거는 R31이 `Pouring by Feel`에서 끌어낸 것과 같은 논리다. **저가 센서로 유입량을 추정하지 않는다.** 여기에 우리 조건이 더해진다.

- G0 매체는 액체가 아니라 건식이다. 액체 분할이 적용될 대상이 아직 없다
- 카메라가 뎁스 320×240, 손목캠 320×240으로 제한된다. 투명 액체 분할은 이 해상도에서 어렵다
- PourIt!은 용기 6-DoF 자세 추정 네트워크에 의존한다. 그 정확도가 전제 조건인데 우리 파이프라인에 없다
- 1차 판정기는 이미 도킹 저울의 전후 질량차로 정해져 있고, 이쪽이 훨씬 강건하다

**쓸 수 있는 자리는 흘림 감지다.** "컵 밖에 액체가 있는가"는 이진 판정이라 정밀 추정보다 훨씬 쉽고, 도킹 저울이 못 보는 정보를 준다. `spill_detected` 플래그의 근거로 G3 이후에 검토한다.

## 8. 현업은 어떻게 하는가

### 산업 현장

Universal Robots는 `UR AI Trainer`를 리더-팔로워 구성으로 만들고, **나중에 그 모델을 돌릴 바로 그 산업용 로봇에서 데이터를 수집**한다. 모방학습이 규모 있게 실용화되려면 데이터가 실제 조건의 생산 하드웨어에서 잡혀야 한다는 판단이다.

우리에게 주는 함의는 명확하다. **수집 하드웨어와 배포 하드웨어를 같게 유지한다.** 텔레옵 리그와 실기 구성이 다르면 그 차이가 그대로 분포 이동이 된다.

### 학계·산업의 수렴

순수 모방학습은 시연 품질에 갇히고 실패에서 배우기 어렵다. 실물 RL은 느리고 비싸며 위험하다. 그래서 2026 시점의 실무는 하이브리드로 수렴한다 — **결정론적 골격을 세우고, 변동이 실제로 존재하는 구간에만 학습을 넣는다.** R31이 이미 그 구조를 택했다.

π₀·Figure처럼 전 구간 E2E VLA를 쓰는 곳도 있지만 데이터 규모가 100만 단위로 다르다. 우리 예산에서는 파인튜닝 경로로만 접근 가능하며, 그조차 8 GB VRAM 제약을 받는다.

## 9. 실행 순서

| 게이트 | 내용 | 통과 조건 |
|---|---|---|
| G0 | IK + 상태기계 결정론 기준선 | 건식 매체로 전 구간 통과 |
| G1 | 텔레옵 수집 파이프라인 | 좌우 키·영상·state 시간축 정합, 드랍 로깅 |
| G2 | `S1 GRASP_BOTH` ACT | 청크 모드로 평가 격자 통과 |
| G3 | `S2 POUR` ACT | 저울 판정으로 유입량·흘림 수치화 |
| G4 | 앙상블·정지프레임 솎기 비교 실험 | 같은 체크포인트로 모드별 성공률 표 |
| G5 | 잔차 보정 (선택) | G3 통과 후에만 착수 |

## 10. 하지 않을 것

- Nav2와 조작을 한 정책으로 합치지 않는다
- 논문 성공률을 우리 예상 성공률로 전용하지 않는다. ACT의 60시연 80%, PourIt!의 결과 모두 다른 하드웨어의 값이다
- 스크립트 시연 정책에 앙상블을 켜지 않는다
- `select_action`을 직결하지 않는다. lerobot 0.6은 정규화가 프로세서 파이프라인에 있어 `make_pre_post_processors`를 반드시 물린다
- 그리퍼 각도로 파지 성공을 주장하지 않는다
- 1스텝 MAE로 정책 품질을 판정하지 않는다
- 상태·행동 표현 규약(좌우 분리 대 상대좌표)을 확정하기 전에 본수집하지 않는다
