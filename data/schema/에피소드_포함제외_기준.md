# 에피소드 포함/제외 기준

현행 대상은 물 서빙의 `policy 1`과 `policy 2`다. 정의되지 않은 policy 3, Nav2 이동,
커넥터·음성·범용 3태스크 데이터는 이 기준으로 판정하기 전에 데이터셋 자체를 분리한다.

수집한 에피소드를 전부 학습에 넣지 않는다. 이미테이션 러닝은 시연을 그대로 흉내내므로, 나쁜 시연은 나쁜 정책이 된다. 아래 기준은 **수집 후 판정용**이며, 제외한 에피소드도 지우지 않고 `include=false`와 사유 번호를 남긴 채 보관한다. 나중에 기준을 바꿔 다시 판정할 수 있어야 하기 때문이다.

## 제외 기준 (하나라도 해당하면 제외)

| 번호 | 기준 | 근거 |
|---|---|---|
| E1 | 태스크 실패 원본 에피소드 | 원본은 학습에서 제외하고 failure bank에 보존한다. 복구 학습은 성공을 확인한 사람 개입 구간만 잘라 별도 데이터셋에서 다시 판정한다 |
| E2 | `servo_stall` 발생 | 스톨 구간의 명령-실제 괴리가 크다. 모델이 "명령을 넣어도 안 움직인다"를 학습한다 |
| E3 | `teleop_desync` 발생 — **제어 루프 주기가 목표를 못 맞춘 구간** | ✎ 2026-08-19 재정의(R1 반영): LeRobot 양팔은 한 제어 루프의 같은 틱에서 좌우를 순차 처리하므로 좌우 타임스탬프가 따로 존재하지 않는다. 실제 증상은 좌우 어긋남이 아니라 **틱 전체가 밀리는 주기 지터**다. 시리얼 통신이 느려지면 관측과 액션의 대응이 흐트러진다 |
| E4 | `frame_drop`이 전체 프레임의 5%를 넘음 | 관측 결손이 액션과 어긋난 쌍을 만든다 |
| E5 | 조작자 실수로 인한 재시도 구간 포함 | 목표와 무관한 궤적이 섞인다. 잘라낼 수 있으면 잘라내고 재판정 |
| E6 | 캘리브레이션 파일이 다른 에피소드와 불일치하고 변환 불가 | 같은 관절값이 다른 자세를 의미하게 된다 |
| E7 | 수집 조건 메타데이터 누락 (필수 필드 미기입) | 조건별 분석이 불가능해 나중에 원인 귀속을 못 한다 |
| E8 | `verified_by`가 `log_string` | 성공 판정의 근거가 부실하다. 실물·실좌표 재판정 전까지 보류 |
| E9 | policy ID·checkpoint·action 표현·캘리브레이션 해시 중 필수 추적값 누락 | 재학습 전후와 실행 조건을 재현할 수 없다 |
| E10 | policy 1인데 물 양 판정 또는 건식 여부가 없음 | 붓기 단계의 성공과 실패를 구분할 수 없다 |
| E11 | 실패 episode인데 `failure_stage`·관측 `failure_code`·`failure_record_id`가 없음 | 증상 집계와 상세 원인 분석을 연결할 수 없다 |

## 포함하되 표시해 두는 것

| 번호 | 상황 | 처리 |
|---|---|---|
| W1 | `depth_hole` (투명·반사 물체로 depth 결손) | 포함하되 태그. IK 경로 성능 저하의 원인 후보로 따로 집계 |
| W2 | `object_slip` 후 성공 | 포함. 복구 행동이 오히려 유용한 데이터일 수 있다 |
| W3 | 소요 시간이 중앙값의 2배 초과 | 포함하되 태그. 느린 시연이 다수면 정책도 느려진다 |
| W4 | `liquid_not_visible`·`cup_occluded` 뒤 성공 | 포함하되 별도 집계. 가림이 반복되면 카메라 또는 장면을 고친다 |
| W5 | HIL에서 사람이 개입해 최종 성공 | 원본 성공 시연과 다른 HIL dataset ID에 포함한다 |

## 판정 원칙

- **판정 근거를 남기고 검사한다.** 담당자가 관측·계측에 근거해 `include`와 사유 번호를 기록하고 검증기가 모순·누락을 검사한다. 현재 도구는 영상을 판독하거나 include 값을 자동 결정하지 않는다.
- **제외율을 기록한다.** 조건별 제외율이 크게 다르면 그 조건에서 수집 절차 자체에 문제가 있다는 신호다.
- **기준을 바꾸면 데이터셋 버전을 올린다.** 같은 이름으로 다른 필터가 걸린 데이터셋이 돌아다니면 성능 비교가 무의미해진다.
- 실패 원본·스톨·보정 오류·근거 부족·추적값 누락은 첫 학습부터 제외하거나 보류한다. 표본 수를 채우려고 E5~E11을 생략하지 않는다. 품질 임계값을 비교할 때에도 안전·추적성 조건은 유지한다.
- `split=holdout_eval, include=true`는 평가용 데이터로 포함한다는 뜻이다. BC 학습 후보는 `split=train`과 `include=true`를 모두 만족해야 한다. 실패 rollout은 include=false라도 평가의 실패 횟수에서 삭제하지 않는다.

## 실패 데이터 활용 판정

학습 포함 여부와 실패 데이터 보존 여부는 별개다. `include=false`여도 원본과 메타데이터를
삭제하지 않는다. 상세 진단은 `failure_record_id`로
[`failure_record.schema.json`](failure_record.schema.json) 형식의 실패 레코드에 연결한다.

| 실패 데이터 | BC 학습 | 별도 활용 |
|---|---:|---|
| 자율 rollout 실패 원본 | 제외 | failure bank, 단계·증상·원인 분포, 회귀 평가 |
| 센서·캘리브레이션·Nav2·기구·서보 실패 | 제외 | 시스템 수정과 같은 checkpoint 재시험 |
| 조작자 실수 시연 | 제외 | 수집 절차 수정 근거 |
| 실패 직전부터 사람이 복구한 HIL 구간 | 별도 dataset에서만 포함 | 복구 정책 학습·평가 |
| 성공했지만 미끄러짐을 복구한 시연 | 조건 태그 후 판정 | 복구 행동 분석 |
| 원인 미확정 실패 | 제외 | `unresolved`로 보존하고 추가 진단 |

`UNDER_FILL`, `CUP_GRASP_MISS`, `TIMEOUT` 같은 코드는 관측 결과다. 이를 바로 정책 데이터
부족으로 간주하지 않는다. Nav2 도착 오차, TF 최신성, 인지 confidence, 캘리브레이션,
관절·action 추종, 안전 상태를 대조한 뒤 데이터 보강 여부를 정한다.
