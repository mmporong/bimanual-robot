# data — 데이터셋 규격과 인덱스

**이 폴더에는 실데이터가 들어가지 않는다.** 에피소드·영상·가중치는 HuggingFace Hub(private)에 두고, 여기에는 어디에 무엇이 있는지의 인덱스와 데이터를 만드는 규격만 둔다.

## 1. 저장 위치 인덱스

| 데이터셋 | HF repo | 에피소드 수 | 수집 기간 | 상태 |
|---|---|---|---|---|
| (아직 없음) | | | | |

수집을 시작하면 이 표에 한 줄씩 추가한다. 표에 없는 데이터셋은 팀 기준으로 존재하지 않는 것으로 본다.

## 2. 포맷

LeRobot 데이터셋 포맷 **v3.0** 을 기준으로 한다 (`~/lerobot` 기준 `CODEBASE_VERSION = "v3.0"`). 디렉터리 규약은 이렇다.

```
<dataset_root>/
├── meta/
│   ├── info.json          데이터셋 전역 정보 (features, fps, 로봇 타입, 총 프레임 수)
│   ├── stats.json         피처별 통계 (정규화에 쓰임)
│   ├── tasks.parquet      태스크 문자열 테이블
│   └── episodes/…parquet  에피소드 인덱스
├── data/chunk-000/file-000.parquet     관측·액션 시계열
└── videos/<video_key>/chunk-000/file-000.mp4
```

버전을 v3.0으로 못 박는 이유는 v2와 메타 파일 형식이 달라(구 버전은 `meta/tasks.jsonl`·`meta/episodes_stats.jsonl`) 섞이면 로더가 조용히 다른 경로를 읽기 때문이다. 다른 버전으로 만든 데이터를 받으면 변환 후 인덱스에 버전을 명시한다.

## 3. 양팔 표현 규약 (확정 — 2026-08-19)

**우리가 정할 것이 아니라 LeRobot에 이미 정해져 있다.** 리서치 [R1](../research/R1_양팔_동시_텔레옵.md)에서 확인했다. `bi_so_follower` / `bi_so_leader`가 쓰는 규약은 **키 접두어 방식**이며 단일 벡터 concat이 아니다.

| 대상 | 키 형태 | 예시 |
|---|---|---|
| 관절 상태·액션 | `left_*` / `right_*` | `left_shoulder_pan.pos`, `right_gripper.pos` |
| 팔별 카메라 | `left_*` / `right_*` | `left_wrist`, `right_wrist` |
| 좌우 공용 카메라 | 접두어 없음 | `top` |

한쪽 팔만 쓰는 에피소드에서도 반대쪽 키를 그대로 기록한다. 스키마가 에피소드마다 달라지면 데이터셋이 깨지기 때문이다.

이 규약을 따르면 LeRobot 수집·학습 파이프라인이 그대로 돌아가므로 커스텀 로더가 필요 없다. **본수집 보류 조건은 해제됐다.**

## 4. 수집 조건 메타데이터 (필수)

에피소드마다 수집 시점의 조건을 남긴다. 나중에 "이 조건에서만 성능이 떨어진다"를 추적하려면 수집 시점에만 기록 가능한 정보가 필요하고, 사후에는 복원할 수 없다.

스키마: [schema/episode_metadata.schema.json](schema/episode_metadata.schema.json)
LeRobot 표준 메타에 없는 항목이므로 **사이드카 파일**로 관리하고 `episode_index`로 조인한다.

## 5. 에피소드 포함/제외 기준

수집한 것을 전부 학습에 넣지 않는다. 기준과 근거: [schema/에피소드_포함제외_기준.md](schema/에피소드_포함제외_기준.md)

## 6. 평가셋 홀드아웃

**평가셋은 수집 전에만 뗄 수 있다.** 다 모은 뒤 나누면 학습 조건과 이미 섞여 있어 일반화를 재는 의미가 없다. 수집 시작 전에 아래를 정한다.

- 홀드아웃 축: 무엇을 학습에서 빼둘 것인가 (물체 위치 특정 구역 / 특정 조명 / 특정 시각대 / 특정 물체)
- 홀드아웃 비율과 최소 에피소드 수
- 평가 반복 횟수와 성공 판정 방법

정하기 전에는 본수집을 시작하지 않는다.
